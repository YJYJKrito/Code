## 0. 三条红线（违反即出局，任何情况下不妥协）

- [ ] **P1 稳定性**：冷启动不 ANR、不黑屏、不崩。TapTap 上 P1 = 禁止上线，没有申诉空间。

## 3. 程序

### 3.1 目录与程序集结构

```
Assets/
├─ Sim/                ← asmdef: noEngineReferences ✓  禁浮点 禁 Unity API
│   Rng.cs  TagBits.cs  SimTypes.cs  PackPair.cs  AtomicWrite.cs  World.cs
├─ Diag/               ← asmdef: 允许浮点 允许 UnityEngine（只读统计，不进包）

│   Render/  Input/  UI/  Save/  Audio/

    ├─ EditMode/       ← 直接从 ../../_tests/EditMode/ 拷进来，一字不改
    └─ PlayMode/       ← 真机冒烟
```

- [ ] **`Sim` 的 asmdef 勾上 `noEngineReferences`** —— 这是把"纪律"变成"编译器强制"的唯一办法。任何 `UnityEngine` 泄漏会直接编译不过。
- [ ] `Diag` 单独一个 asmdef。**它存在的原因**：`Stat()` 用了 `Math.Sqrt`，留在 `Sim/` 里会让"Sim 层禁浮点"这条规则无法用文本扫描证明（要么开白名单让它腐烂，要么规则形同虚设）。

### 3.5 三条会毁掉项目的技术细节

**① tick 循环绝不能跑在协程里。**
Android 上协程里的未捕获异常会**静默杀掉该协程**——如果 tick 跑在协程里，一次异常 = 游戏永久卡住但**不崩溃**，用户报"卡死"你拿不到任何堆栈。
→ 用累加器 + `bool _running` 守卫驱动 tick，外面包 try/catch，异常打到屏幕可见的横幅。

**② 存档：`File.Replace` 首次保存必抛 `FileNotFoundException`。**
参考实现里的 `AtomicWrite.Write` 已经修了（不存在时退化为 `Move`）。**直接用它，不要重写。**
→ 另外：`JsonUtility` 用在 `Dictionary` 上会**安静地**存成 `{}`，`ValueTuple` 存成空。手写 DTO，只用扁平字段。

**③ `ReadPixels` 有一个时机陷阱。**
必须 `WaitForEndOfFrame` 之后再调，且渲染完立刻 `Destroy(rt)`——写成 `try/finally`。不然每次存长图泄漏 16MB。

### 3.6 `CLAUDE.md` 硬约束（AI 每次都会忘，必须写死在仓库里）

```
- Sim 层禁 float/double/Mathf/Math./System.Linq/Time./UnityEngine.Random
- 所有溢出算术显式 unchecked
- 随机只用 Rng.For / Rng.Range / Rng.Chance，禁自写 PRNG、禁 System.Random
- 遍历只用定长数组和 List<T>，禁 Dictionary/HashSet 迭代
- 排序必须给全序比较器（四个键都要比）
- UGUI 禁 LayoutGroup / ContentSizeFitter / ScrollRect / Instantiate 进列表
- 存档只用扁平字段 DTO；禁 Dictionary、ValueTuple、属性、二进制
- 新增任何 Sim 字段，必须显式声明是否进 HashState（T03_05 会拦你）
```

> 而且这些**不是靠自觉**：`noEngineReferences` 挡 Unity API，`_tests/T08` 挡浮点/字典/时间源，`T03_05` 挡"新字段忘了进哈希"。

## 5. 音乐与音效

> **已放弃最佳视听奖**，所以这里的目标是"**不显得坏**"，不是"好听"。全静音的游戏会让玩家以为它坏了。

### 5.1 音乐（2 条）

> **对外需求书见《音乐需求书-给音乐》**（可直接发给音乐那边）。

- [ ] **主循环 BGM**：1 条，60–120 秒可无缝循环。氛围向、少节奏、无强旋律（要能听 20 分钟不烦）。
- [ ] **危机变奏**：**不要单独做一条**。用同一条 BGM 叠一层低音/降低音高/加滤波来实现——成本几乎为零，效果足够。

### 5.2 音效（12 条以内，做减法）

| 事件 | 备注 |
|---|---|
| 点村民 | 最高频，必须最轻 |
| 立法 / 废法 | 各一条，要有分量 |
| 威信归零停摆 | **全场最重要的一条**，玩家必须一听就知道出事了 |
| 有人死亡 | 克制。不要用惨叫，用一声闷响/钟声 |
| 讣告弹出 | 纸的声音 |
| 审议完成 | 轻提示音 |
| UI 点击 / 返回 | 通用两条 |
| 倍速切换 | 可选 |

- [ ] 全部转成 **OGG Vorbis**（Unity 对 OGG 支持最好，体积小）。
- [ ] 音乐用 `Streaming`，音效用 `Decompress On Load`。
- [ ] **提供全局静音开关**，且状态存进存档。

### 5.3 音频代码的三条纪律

- [ ] **不要每 tick 调 `AudioSource.Play`** —— 死亡音效要在死亡**事件**里触发一次。
- [ ] 音效池化，不要 `Instantiate`。
- [ ] 切后台时暂停 BGM（`OnApplicationPause`）。

## 6. 文案 —— 这是**内容工作**，不是"填字"

> 讣告是这款游戏唯一被玩家反复阅读的文本。它值得单独排期。
>
> **判据很硬**：找 3 个不认识这个项目的人，读 10 篇讣告，如果他们说"像人话"，才算过。

- [ ] **12 套段落模板**（不是 12 句） + **30 条短语语料**。
- [ ] 每篇讣告必须能引用：**死因** + **死因对应的律法槽** + **个人史**（被抢过几次/被喂过几次/身上的伤疤）。
- [ ] **去重账本**：同一个模板不要连续出现。用牌堆抽取（抽完洗牌），不要纯随机。
- [ ] 讣告**措辞要克制**。这类题材一旦用力过猛就变成笑话。
- [ ] 8 条律法的**卡面文案**：每条法要写清「条件 / 效果 / 代价」，让玩家在**贴上去之前**能预判它可能会杀谁。
- [ ] 村民 20 个：姓名 + 一句怪癖。**这是性价比最高的一批文字**（对应 §3.3 的第一项）。

> ⚠️ **一条从测试里掉出来的设计约束**：`私刑倾向` 的生效前提是"这人身上已经有伤疤"，而伤疤要靠**别的法**（`饥则抢`）打出来。**它不能自举。**
> → 所以：**反应式律法不能单独出现在第一幕的法池里**。玩家选了它、村里却永远不触发，他的体感就是"这条法是坏的"。
> → 卡面文案上要写出这层依赖（例：「适用于已有污名之人」）。

### 7.1 分区布局（已修订，按这个走）

| 区 | 高度 | 内容 |

### 7.2 Canvas 拆分（**性能的关键不是"每 tick"，是"每帧"**）

| Canvas | 内容 | 何时脏 |
|---|---|---|
| `Canvas_Static` | 底板边框、20 个头像 + 20 个姓名、律法槽名称 | **只在死亡状态变化时**（一场 ≤20 次） |
| `Canvas_Hud` | 威信数字 + 净速率 + 徽章 | 每 tick，**带值判脏** |
| `Canvas_Dock` | 20 格 × 3 条数值条 | 每 tick，**带值判脏** |
| `Canvas_FX` | 审议进度环、命中闪烁、停摆滤镜、字幕 | **允许每帧** |
| `Canvas_Modal` | 讣告 / 村民卡 / 结算 | 打开时一次性构建 |

> **最重要的一刀**：把"头像 + 姓名"放进永不脏的 `Canvas_Static`。村民条的 100 个元素里只有 60 个数值条会变，这一刀让每次 rebuild 从 100 降到 60。

- [ ] **禁止**：动态容器上挂 `LayoutGroup` / `ContentSizeFitter`；`ScrollRect` 用 `Instantiate` 加行；审议进度环每帧改 `fillAmount`（**它会每帧重建整个 Canvas**）。
- [ ] **禁止 AI 生成 UI 布局代码**——这是它系统性的失败区。你手写 RectTransform 位置表，AI 只填内容逻辑。
- [ ] 触控目标 ≥ **120×120**（手指，不是鼠标）。
- [ ] 所有可点元素要有按下反馈（缩放或变色），否则手机上手感是"没点到"。

### 7.3 三个必须做的可用性细节

- [ ] **倍速 [1x][2x][3x]** —— 这是个观看型游戏，必须有倍速。
- [ ] **讣告横幅不冻结 tick**。定版已经砍掉了"死刑强制暂停"，理由是它和 40 tick 审议延迟耦合起来会让玩家被迫看完 8 次自己修不了的事故。
- [ ] **全局"关闭动效"开关**（给低端机和晕动症玩家）。

## 8. 双端与 TapPlay

- [ ] **两个 Build Profile**：Android（IL2CPP + **仅 ARM64**）与 Windows x64。
- [ ] **版本号两端一致**，`BuildScript.BuildAll` 一条命令出双包。
- [ ] **TapPlay 的 P1 只可能来自四件事，D2 一个下午能全堵**：

| P1 风险 | 规避 |
|---|---|
| 冷启动 ANR | 首帧只做最小初始化；重活延到第二帧之后 |
| IL2CPP 剥离导致 `MissingMethodException` | `link.xml` 保住反射用到的类型；**用真代码试，不要用空包试** |
| 首帧 IO 到不可写路径 | 首帧绝不碰文件；`Application.persistentDataPath` 只在需要时用 |
| Vulkan 黑屏 | 优先 GLES3，或做好回退 |

- [ ] **P2 也要堵**：坏档分级兜底**必须真写**；切后台回来只弹汇总，**绝不逐帧补**（`OnApplicationPause` → 跳结果）。
- [ ] **TapPlay 下持久化不保证跨会话** ← 这是要在 D2 当天实测确认的第一个问题。若不保证：存档功能降级为"单次会话内有效"，并**在 UI 上明确告知**，不要做一个看起来存了其实没存的功能。

## 11. 风险与丢车保帅

### 丢的顺序（任何一天滑期就按此丢，**绝不顺延**）

① 裁决书长图降级版 → ② 请愿信 → ③ 审议进度环（保留红字 + 秒数）→ ④ 停摆全屏滤镜。合计 ≈2 天弹性。

### D5 硬 gate 不通过怎么办

`T05_01 / T05_03 / T05_04` 任一红了，说明**涌现退化**。此时不要往下写内容——**在 D5 改方案只要 1 天，D8 之后改就是重做。**

两条降级路径：
- **方案 A（storylet 化）**：把律法效果改为"触发一组手工写的事件卡"，用卡的数量换复杂度。
- **方案 B（讣告推理）**：接受律法层是浅的，把复杂度全部转移到讣告生成——玩家感知到的"因果深"来自文本，而不是模拟。

### D15 Android 决策门

任一 P1 且 1 天修不掉 → **砍 Android 保 PC**。宁可交一款完整的 PC 游戏，不要交一款两端都不能玩的游戏。

### 地图接入带来的变动

> **已全部移到 `地图生成-实现规格.md`。排期以那份文档的 §16 为准。**
> 包括：相机可砍（≈−0.4 人天）、新增 P0/P2 工作（≈+1.1 人天）、以及时间不够时的**五级降级路径**（那份的 §15.2）。

**这里不再复述**——同一件事写在两个地方，改了一处忘另一处，正是这个项目一路在防的东西。

### 已知环境问题（不是代码 bug）

**在同一目录下并发跑 `dotnet build` 与 `dotnet test` / `dotnet run`，会让进程随机崩溃并抛 `AccessViolationException` / `NullReferenceException`，栈指向 `World.Tick`，崩点每次漂移。**

本次验证中出现过 4 次，独立复现不出来（最重的测试单独跑 7 次全过）。**运维规则：一次只跑一个 dotnet 命令；崩了就重跑一次。**
