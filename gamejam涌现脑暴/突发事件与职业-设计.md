# 突发事件 × 职业 · 设计

> 先说清楚：**我不打算做事件卡库。**
> 你文档夹里那份 205KB 的《事件卡机制规格》自己已经给出了判决，我同意它：
>
> > **「他们死于你写的法律」承诺的是 agency，设计交付的是 causality。**
> > **玩家在 tick 0 拉了一下开关，然后什么都没做。**
> > 内容量黑洞 —— fatal。
>
> 所以这份设计走另一条路：**参数驱动的事件表（~14 个），不是故事卡库。**

> **→ 给程序的实现文档（代码级）：**
> - 《突发事件-实现方案-给程序》—— 14 个事件的权重 / 效果 / 兆头期 / 存档改动
> - 《职业烙记-实现方案-给程序》—— 13 个职业的获取条件 / 计数器 / 插入点

## 0. 一句话

```
事件不给玩家新按钮 —— 它给玩家「提前知道要出事，然后改法」的压力。
职业不新做一套系统 —— 它就是把已经写好、但全是死的 19 个烙记接上。

三个资源不是被"用"，是被"花"：
  税库 是防灾预算，威信 是信用额度，恐惧 是你欠下的账。
```

## 1. 三条硬约束（都来自实测，不是估计）

### ① 事件必须能追到「粮仓」或「人口」，否则是装饰品

实测：**30 年结局只由粮食和人口决定**。恐惧/税库/威信本身不杀人。

所以每个事件的效果，**必须最终落到粮仓、出生、或死亡上**。只动资源的那些事件，要等《三个资源接通》落地之后才有意义（§7 我逐条标了）。

### ② 三个资源现在都是死的，事件接上去之前得先通

| 资源 | 实测 | 没修的话，事件会怎样 |
|---|---|---|
| 恐惧 | p50=5 · p99=41 · 衰减 **−91/年** | 「恐惧 > 40 才触发」的事件**永远不触发** |
| 税库 | **30 年恒为 48** | 「税库 ≥ 100」的事件**永远不触发** |
| 威信 | **95% 顶在 300** | 「威信 < 40」的负面事件**永远不触发** |

**→ 事件设计必须排在《三个资源接通》之后。** 不然你会写一堆永远不触发的条件。

### ③ 玩家没有按钮，所以「兆头期」是唯一的动词

详见 §3。**这是这份设计里最重要的一件事。**

## 2. 事件的结构：复用律法的 DSL

游戏里已经有 `LawCond`（21 种条件）+ `LawEffect`（13 种效果）。**事件直接用同一套**，不新造轮子。

```csharp
public sealed class EventDef
{
    public int id;
    public string name;          // 「蝗灾」
    public string omen;          // 兆头文本：「田里的蚂蚱比往年多。」
    public string burst;         // 爆发文本：「蝗群落下，半年的粮没了。」

    // ★ 注意：没有 conds —— 见 §4，条件写法实测 9/14 永不触发，改成了权重
    public WeightTerm[] weight;  // 权重项（恒 >= 1）
    public LawEffect[] effects;  // 爆发效果（复用律法的）

    public int omenYears;        // ★ 兆头提前几年
    public int cooldownYears;    // 冷却

    // ★ 职业修正：村里有某烙记的人 → 效果打折/放大
    public ProfessionMod[] mods;
}

// 权重项：base + 某个量的倍数，最后 Math.Max(1, 总和)
public struct WeightTerm { public int field; public int mul; }

public struct ProfessionMod
{
    public uint mark;            // 用现成的 Mark 位
    public int  needCount;       // 村里至少几个
    public int  scalePercent;    // 效果 × N%（50 = 减半）
}
```

**和律法共用 DSL 的三个好处**：
1. 不用新写求值器
2. **律法和事件可以互相读**（法条改事件的结果 = 你最想要的那种涌现）
3. 调试工具、确定性哈希、存档全都复用

## 3. ★ 兆头期：把 causality 变成 agency 的**唯一**手段

既有规格里最致命的一条是「玩家只是在读」。它给的解法是**加一个 UI 动词（听证）**——但那违背"你只操作法律"。

**我的解法不用新 UI：事件分两段。**

```
第 N 年    兆头出现   →  HUD 弹一条：「北边的蝗虫比往年多。」（只有文本，没有效果）
                       玩家看到 → 有时间改法
第 N+1 年  爆发       →  效果结算（粮仓 −80 / 死人 / …）
```

**为什么这能把 causality 变成 agency**：

| | 没有兆头 | **有兆头** |
|---|---|---|
| 玩家体验 | 粮仓突然掉 80，不知道为什么 | **「我看到蝗虫了 → 我该换条法 → 我换了『耕作』→ 蝗灾来的时候粮仓只掉了 40」** |
| 因果 | 带伞导致下雨 | **你判断对了** |

**玩家的动词是「换法」**——这个动词**本来就存在**（法槽可以随时换），只是现在没有任何理由去用。**事件给了理由。**

> **实现成本**：一个"预警中"列表 + HUD 一行文本。没有新面板、没有新按钮。

## 4. ★ 事件用「权重」，不用「条件」—— 这是**实测逼出来的**

> 我最初写的是「条件门槛」。**跑测试之后，14 个里 9 个永不触发。整个推翻重来。**

### 4.1 第一轮：条件写法下 9 / 14 永不触发

| 事件条件 | 默认 | 开垦系 | 不装法 |
|---|---|---|---|
| 蝗灾 平均饥饿 > 25 | 33% | **0%** | 19% |
| **民变 威信<60 且 平均恐惧>40** | **0%** | **0%** | **0%** |
| **大赦 威信>200 且 平均恐惧>40** | **0%** | **0%** | **0%** |
| 贪墨 税库 > 250 | **0%** | **0%** | **0%** |
| 商队 税库 > 60 | **0%** | **0%** | **0%** |
| 名医 税库 > 80 | **0%** | **0%** | **0%** |
| 匪患 有劫匪 ≥1 | **0%** | **0%** | **0%** |
| 回流 人口 < 20 | **0%** | **0%** | 41% |

**⚠ 最刺眼的是「民变 / 大赦」：我把恐惧条件写成 `> 40`，而恐惧实测 p50=8、p99=41、最高 46。**
**那正是我在同一份文档 §1 里警告过的事 —— 我自己踩了。**

### 4.2 根因：**三个玩法的参数区间几乎不相交**

第二轮我把参数的**实际分布**量了出来：

| 参数 | 默认 p50 | 开垦系 p50 | 不装法 p50 |
|---|---|---|---|
| 平均饥饿 | 19 | **0（恒定）** | 15 |
| 人口 | 37 | **68** | 21 |
| 税库 | 48 | **0** | **0** |
| **最高恐惧** | **30** | **30** | **30** |
| **威信** | **300** | **300** | **300** |

**两个致命的观测：**

1. **`最高恐惧` 三组恒为 30** —— 那是「懦弱」词条的恐惧基准值。
   **任何用「最高恐惧」当门槛或权重的设计，那一项都是常数。**
2. **任何绝对值门槛，必然在某些玩法下恒不成立。** 「平均饥饿 > 25」在开垦系是死条件（开垦系的平均饥饿**恒为 0**）。

> **修门槛是没用的** —— 我按分布重定了一版门槛，还是错。
> **要换的不是阈值，是机制。**

### 4.3 改法：条件 → 权重

**每个事件永远可抽（权重恒 ≥ 1），只是权重随状态变。**

```csharp
// 权重 = 状态好坏的函数，不是门槛
蝗灾   = 1 + 平均饥饿 / 4
民变   = 1 + (300 − 威信) / 12 + 平均恐惧 / 3
匪患   = 1 + 金币<10的人数 / 5
贪墨   = 1 + 税库 / 100
丰年   = 1 + max(0, 40 − 平均饥饿) / 4
商队   = 1 + 税库 / 60
...
```

**三个好处：**
- **没有"永不触发"** —— 权重恒 ≥ 1
- **天然变奏** —— 这场闹蝗灾、那场闹瘟疫，是状态决定的，不是掷骰子决定的
- **可解释** —— 「你越饿，越容易闹蝗灾」，玩家能理解

### 4.4 实测结果：**死事件 0–1 / 14，而且配比讲得通**

| 事件 | 默认 | 开垦系 | 不装法 | **苛政** |
|---|---|---|---|---|
| **民变** | 4.4% | 7.6% | 7.2% | **38.6%** ← 苛政威信低、恐惧高 |
| **匪患** | 8.0% | **23.5%** | 5.2% | 2.8% ← 开垦系穷人最多（47–113 人金币<10）|
| 蝗灾 | 12.7% | 2.8% | 11.2% | 3.6% ← 饿的村子才闹蝗 |
| 丰年 | 11.2% | **18.7%** | 12.0% | 13.1% ← 富的村子常丰收 |
| 乡绅 | 9.2% | 4.4% | 8.8% | 1.2% |
| 新生儿潮 | 14.3% | 13.5% | 15.1% | 10.0% |
| 名医 | 2.0% | **0.4%** ⚠ | 2.8% | 2.4% |

**每局触发 20.9 次**（30 年），约 1.4 次/年。

> ⚠ 这张表是 **12 个种子**跑的。**看趋势可以，看具体百分比不可靠** —— 见 §4.7 的教训。

> ⚠ **`名医` 在开垦系是 0.4%** —— 因为它的权重依赖税库，而税库在修好之前**恒为 0**。
> 这正是 §7 说的依赖：**《三个资源接通》不落地，税库类事件就是摆设。**

  → 45% 概率触发（实测：每局 20.9 次事件）

### 4.7 ★ 效果层实测：**「量级 ×2」这条建议是错的，撤回**

触发层测完之后，把效果真的实现出来跑了一遍。
**12 个种子得出的结论是错的 —— 40 个种子才看清。**

**40 种子 × 30 年，末人口（最小/中位/最大）**

| 配置 | 不装法 | 默认 | 开垦系 | 苛政 |
|---|---|---|---|---|
| **关**（基线）| 6/10/15 | 26/**37**/60 | 94/120/126 | 6/13/17 |
| ×1.0 · **无**职业 | 4/10/16 | 16/**28**/53 | 42/120/132 | 0/10/17 |
| **×1.0 · 有职业** | 5/10/22 | 23/**34**/52 | 42/120/127 | 6/12/22 |
| ×1.5 · 无职业 | **0**/9/23 | 11/**24**/50 | 35/106/125 | **0**/7/15 |
| **×1.5 · 有职业** | 5/10/18 | 21/**33**/59 | 77/120/128 | 5/12/22 |
| ×2.0 · 有职业 | 5/10/18 | 23/**31**/58 | 70/120/128 | 0/12/22 |

#### ★★ 最重要的发现：**职业修正的影响 > 灾害量级的影响**

默认三法，相对基线 37：

| | 无职业 | **有职业** |
|---|---|---|
| ×1.0 | −9 | **−3** |
| ×1.5 | −13 | **−4** |
| ×2.0 | — | −6 |

**灾害从 ×1 加到 ×1.5，只多掉 4 人；而「村里有没有医师/游侠」直接差 6 人。**

> **这正是设计想要的：灾害多大是运气，村里有没有医师是玩家通过法律决定的。**
> **玩家的选择比随机事件更重要。**

#### 而且「无职业 + ×1.5」会灭村

| | 不装法 最小 | 苛政 最小 |
|---|---|---|
| ×1.0 有职业 | 5 | 6 |
| **×1.5 无职业** | **0（灭村）** | **0（灭村）** |

**职业系统不是装饰，是缓冲。**

#### 结论

- **量级保持 ×1.0（原始值）** —— 不要 ×2
- **力气全花在职业系统上**

**验证成功的两条，保留：**

| 改动 | 效果 |
|---|---|
| 新生儿潮 权重降到 1/3 | 4.3 次/局 → **1.7 次/局** ✅ |
| 事件链（灾后 2 年民变权重大涨）| 民变 2.0 次/局 → **4.5 次/局** ✅ |

#### ⚠ 方法论教训

**12 个种子得出的表是噪声。** 我基于它建议了「量级 ×2」，40 种子跑下来是错的。

> **以后所有"改完再测"的结论，至少 40 种子。**
> 测试台 `eveff` 跑 40 种子约 9 分钟 —— 比基于噪声下结论便宜得多。

## 4.8 ★★ 对口法律：让「你写的法律」**直接改写事件的结果**

> 这是 §2 承诺的「律法和事件互相读」。**不做这一条，事件就只跟状态和职业有关，跟玩家装了什么的法是隔了一层的。**

### 4.8.1 设计

每个事件配 1–3 条「对口法律」。装了 → **效果乘一个折扣**。多条同时装 → 相乘。

| 事件 | 对口法律（减轻 / 增益）| 反向法律（加重）|
|---|---|---|
| 蝗灾 | 耕作 ×50% · 开垦 ×50% | — |
| 疫病 | 医药 ×50% · 公共卫生 ×40% | — |
| 边患 | 兵役征召 **×0%（全免）** | 威权 ×150% |
| 民变 | 安抚 ×50% · 济贫 ×70% | 连坐 ×150% |
| 贪墨 | 盐铁专卖 ×50% | — |
| 寒潮 | 屯粮 ×50% | — |
| 匪患 | 宵禁 ×40% · 雇佣护卫 ×0% | 饥则抢 ×150% |
| 丰年 | 耕作 ×150% | — |
| 商队 | 平粜 ×150% · 售粮 ×150% | 盐铁专卖 ×60% |
| 乡绅 | 捐纳 ×150% | — |
| 人口回流 | 流民法 ×150% | — |
| 名医 | 医药 ×0%（免费）| — |
| 大赦 | 祭祀 ×150% · 安抚 ×130% | — |
| 新生儿潮 | 婚育补贴 ×150% · 幼童口粮 ×130% | — |

**职业修正和对口法律是两层，可以叠加**（先职业 ×50%，再法律 ×50% → ×25%）。

### 4.8.2 ★ 必须先解决的一件实现约束：**粮仓类事件要按比例扣**

实测第一版用绝对值扣（蝗灾 −150），结果：

| | 折扣 | 实际打击 |
|---|---|---|
| 疫病（扣人）| 50% | 死 5.0 → **2.0** ✅ |
| 民变（扣人）| 50% | 死 4.8 → **2.0** ✅ |
| **蝗灾（扣粮）** | **50%** | 粮 39 → **37** ❌ |

**因为粮仓常年只有 40 上下 —— `max(0, 40 − 150)` 和 `max(0, 40 − 75)` 都是 0。**
**扣到 0 之后再打几折都一样。**

改成**按比例扣**之后：

```csharp
// ❌ 绝对值：粮仓低时折扣失效
d.granaryFood = Math.Max(0, d.granaryFood - 150 * scale / 100);
// ✅ 按比例：折扣永远生效
d.granaryFood = Math.Max(0, d.granaryFood - d.granaryFood * 60 / 100 * scale / 100);
```

**正面事件同理** —— 不是 `+120`，而是「补向粮仓上限的 35%」，
否则粮仓接近 500 时收益全被上限吃掉。

### 4.8.3 实测结果（隔离测试）

**方法**：强制**同一个事件**反复触发，只改「装不装对口法」。
差值**完全来自律法改写**，不含法条自身的其他效果。

20 种子 × 30 年：

| 事件 | 对口法 | 没装 | 装了 | 实际折扣 | 实际打击 | 判定 |
|---|---|---|---|---|---|---|
| 蝗灾 | 耕作 | 粮 17 | 粮 11 | **50%** | **×0.63** | ✅ |
| 疫病 | 医药 | 死 5.0 | 死 2.0 | **50%** | **×0.40** | ✅ |
| 边患 | 兵役征召 | 死 2.4 | 死 **0.0** | **0%** | **×0.00**（全免）| ✅ |
| 民变 | 安抚 | 死 4.8 | 死 2.0 | **50%** | **×0.42** | ✅ |
| 寒潮 | 屯粮 | 粮 23 | 粮 10 | **50%** | **×0.43** | ✅ |
| 匪患 | 宵禁 | 恐惧类 | — | 40% | — | 判据未覆盖 |

**5 / 6 有效**（第 6 个是恐惧类事件，我的判据只统计了粮和死亡）。

### 4.8.4 ★ 必须让玩家看见 —— 否则又变成「感知不到的涌现」

**兆头文本里点名**：

```
「北边的蝗虫比往年多。」
          ← 玩家看到，然后去检查自己的法槽

爆发时：
「蝗群落下。你写的『耕作』保住了半仓粮。」     ← 点名
「蝗群落下。半年的粮没了。」                  ← 没装对应法
```

**这一条不做，整个 4.8 就白做了** —— 这是你们自己的铁律。

## 5. 职业：不是新系统，是**把 19 个死烙记接上**

### 5.1 为什么直接用烙记

| | 新做一套职业系统 | **复活烙记** |
|---|---|---|
| 存档 | 要加字段、升版本 | **已经在存了**（`villagerMarks`）|
| 面板显示 | 要新写 | **已经显示了**（`DescribeMarks`）|
| 讣告记录 | 要新写 | **已经在记了**（`obituaryMarks`）|
| 内容 | 要新写 | **13 个名字和叙事已经写好了** |
| 现在状态 | — | **19 个里只有 2 个会发生** |

**你说过"死内容先别删，后续可能会用到" —— 这就是那个用。**

### 5.2 ★ 补完后的获取规则（全部实测过，不是估计）

**原则不变：每个职业都是「你写的法律 × 村里有人处于某种状态」。**
补完之后多了三条硬性要求，都是从踩过的坑里长出来的：

| 要求 | 为什么 |
|---|---|
| **门槛必须落在参数的实际区间内** | 原设计「恐惧 > 70」，实测个人恐惧 p99 = 30、max 49 —— **和事件条件踩的是同一个坑** |
| **要有「连续 / 累计」计数器** | 只看瞬时值的话，一个瞬间的饥饿就让全村拿到；而且**槽位是回收复用的**，不归零会跨代传染 |
| **装了对口法和没装，结果必须能分开** | 否则门槛就是装饰品 —— 这一条现在有实测两列盯着 |

### 5.3 13 个职业的最终门槛

| 烙记 | 职业名 | **什么时候获得** | 需要的新计数器 |
|---|---|---|---|
| 罪人 `Sinner` | 罪人 | 装了**私刑倾向**(7)，且他恐惧 > 40 | — |
| 劫匪 `Bandit` | 劫匪 | 装了**饥则抢**(2)，且他饥饿 > 55 | — |
| 逃兵 `Deserter` | 逃兵 | 装了**兵役征召**(15)，且 14–40 岁、恐惧 > 25 | — |
| 劳损 `Worn` | 劳损 | 装了**劳役**(11)，且 ≥ 40 岁、饥饿 > 56 | — |
| 债户 `Debtor` | 债户 | 装了**买粮**(26) 或 **丁税**(27)，≥ 25 岁、**金币 = 0 且曾经有 ≥ 30 金** | `villagerWealthPeak` |
| 巫祝 `Shaman` | 巫祝 | 装了**祭祀**(35)，且他恐惧 > 30 | — |
| 恩主 `Patron` | 恩主 | **捐纳**累计触发 ≥ 3 次（全村），给捐过的人 | `villagerDonations` |
| 屠者 `Butcher` | 屠者 | **任何致死的法条**处决过人 —— 给「**最不害怕的成年人**」 | `executions` |
| 绝户 `LastHeir` | 绝户 | ≥ 45 岁，**曾有子女但一个都没活下来** | `villagerChildrenAlive` + 父母槽位 |
| 光棍 `Bachelor` | 光棍 | ≥ 50 岁且**从未有过子女** | — |
| 积怨 `Bitter` | 积怨 | 饥饿 > 50 **连续 ≥ 0.25 年** | `villagerHungryTicks` |
| 尸亲 `Mourner` | 尸亲 | **邻居死亡累计 ≥ 15 次** | `villagerNeighborDeaths` |
| 徙民 `Settler` | 徙民 | **移民进村的那一刻直接烙** | — |

**三个反直觉的决定，都是被实测逼出来的：**

1. **屠者不看「处决法」，看「任何致死法条」。** 因为 **36 逐客 / 64 刑戮 到现在一次都没触发过**
   （36 要「有人恐惧 > 85」，64 要「4 人恐惧 > 60」—— 都落在区间外）。
   而 54 减口 这种法**真的在杀人**（40 局杀了 3004 人）。所以判据改成
   `cause == "律法"` —— 只要有法条杀人，村里就有人动过手。
2. **屠者同一时刻只保留一个人。** 执刑的是同一个刽子手；他死了，下一个最不害怕的人才接刀。
   否则 3004 次处决会把全村每一个人都烙成屠者（实测：不加这条，持有率会到 100%）。
3. **债户从「金币连续 3 年为 0」改成「曾经有钱、现在归零」。**
   前者实测持有率 **75.7%** —— 因为村民金币本来就常年是 0。改判「破产过」之后降到 **11.4%**。

### 5.3.1 ★ 实测：13 / 13 全部拿得到，而且法条门槛真的起作用

**40 种子 × 30 年 × 9 种玩法**（每 60 tick 判定一次）：

| 职业 | 最好玩法 | 出现率 | 持有率 | 第一次出现 | 判定 |
|---|---|---|---|---|---|
| 罪人 | 苛政 | **100%** | 12.3% | 第 0.0 年 | ✅ |
| 劫匪 | 荒年 | **100%** | 18.6% | 第 0.1 年 | ✅ |
| 逃兵 | 兵役系 | **100%** | 20.8% | 第 0.0 年 | ✅ |
| 劳损 | 劳役系 | **100%** | 30.5% | 第 5.5 年 | ✅ |
| 债户 | 捐纳系 | **100%** | 11.4% | 第 0.3 年 | ✅ |
| 巫祝 | 祭祀系 | **100%** | 21.7% | 第 0.0 年 | ✅ |
| 恩主 | 捐纳系 | **100%** | 22.2% | 第 0.0 年 | ✅ |
| 屠者 | 苛政 | **100%** | 9.1% | 第 1.2 年 | ✅ |
| 绝户 | 苛政 | **100%** | 14.9% | 第 1.5 年 | ✅ |
| 光棍 | 默认三法 | **100%** | 25.6% | 第 0.0 年 | ✅ |
| 积怨 | 苛政 | 78% | 12.7% | 第 5.8 年 | ✅ 稀有 |
| 尸亲 | 苛政 | **100%** | 18.6% | 第 1.9 年 | ✅ |

**「装了 vs 没装」—— 7 个有法条门槛的，全部是 100% / 0%：**

| 职业 | 装了对口法 | 默认三法（没装） |
|---|---|---|
| 罪人 · 劫匪 · 逃兵 · 劳损 · 债户 · 巫祝 · 恩主 | **100%** | **0%** |

> 这是整份设计里最强的一条证据：**同一个村子，只因为你在法槽里放没放那一条法，
> 三十年后村里出现的是完全不同的一批人。**

**徙民 69.2% 不是 bug。** 苛政下 40 局来了 2423 个移民 —— 村子是靠移民续命的，
所以村里**本来就大多数是外来人**。这不是「职业烂大街」，这是「村子已经换过一遍人了」。
其余 12 个职业的持有率都在 10–30% 之间。

### 5.3.2 ⚠ 实现时最容易错的一条：**槽位回收必须清零**

村民的槽位是 `FindFreeVillagerSlot` 返回的第一个死人位 —— **新村民会继承死人的槽位**。
所有新计数器（邻居死亡、捐纳、在世子女、饥饿连续……）在 `AppendChild` / `AppendImmigrant`
里**必须清零**，否则一个 90 岁老人的"邻居死了 40 次"会传给他刚出生的孙子。

这条在测试台里真的踩到了（`ProfRules.ResetSlot`）。

### 5.4 必须让它看得见

**这是最关键的一条**。既有规格说「感知不到的涌现等于没做」，所以：

- [ ] **村民面板**：烙记那一栏改成「职业」标题（现有 `DescribeMarks` 已经在显示了）
- [ ] **HUD 加一行**：「村里有 2 名医师 · 1 名游侠」（只列影响事件的职业，按人数排序）
- [ ] **讣告**：已经记了（`obituaryMarks`），只要把中文名写对
- [ ] **事件文本里点名**：「村里的医师拦住了大半」/「没有人懂医术」
- [ ] **结算/存档摘要**里带上村里最著名的职业

## 7. ⚠ 诚实标注：哪些事件现在是装饰品

## 8. 触发节奏与确定性

```csharp
// 每 1800 tick（225 天 ≈ 0.6 年）检查一次
if (tick > 0 && tick % 1800 == 0)
{
    int roll = (int)(Rng.For(data.rngSeed, tick, ChannelEvent, 0) % 100);
    if (roll < EventChancePercent)          // 比如 50%
    {
        // 1. 先看有没有"兆头已到期"的 → 爆发
        // 2. 没有的话，按权重从"条件满足且不在冷却"的事件里抽一个 → 挂上兆头
    }
}
```

- **通道要挑空的**（现用：1/2 移动、8/9/11/12 地图、21–28 地块、31/32 退化、3000+/4000+/4300-4500/5000+/5400 模拟）
- **一局大约 24 次事件**（30 年 / 1.25 年一次），其中一半是兆头、一半是爆发
- **同一事件有冷却**（比如 5 年），避免蝗灾连着来三次
- **兆头列表要存档**（哪些兆头挂着、还剩几年）→ **存档版本 +1**

## 9. 内容成本：为什么这条路比卡库便宜

| | 故事卡库（既有规格）| **参数化事件表（本设计）** |
|---|---|---|
| 要写的东西 | 每张卡的条件+效果+文本+分支，**30 张起** | **14 条表行** + 每条 2 句文本 |
| 文本量 | 每张卡 200–800 字 | 每条 **20–40 字**（兆头 + 爆发）|
| 分支 | 每张卡 2–5 个 branch | **0**（职业修正代替分支）|
| 内容复用 | 低（每张卡是独立故事）| **高**（14 事件 × 15 职业 = 交互矩阵）|
| 玩家看到的 | 读一个故事 | **一次判断 + 一次改法** |

> **14 × 15 = 210 个交互格**，但只需要写 14 条表 + 15 个职业定义。
> 而故事卡库写完 30 张也只有 30 个故事。

## 13. 一句话

> **事件不该是"给玩家读的故事"，是"给玩家一个提前知道、然后改法的机会"。**
> **兆头期是这份设计里唯一真正新东西 —— 它把 30 分钟前的复选框，变成了一次判断。**
>
> **职业不该是新系统，就是把那 19 个已经写好、全是死的烙记接上。**
> **每个职业的获得条件都是"你写了某条法" —— 这条链玩家看得懂。**
