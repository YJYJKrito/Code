## 1. ★ 修正一：威信接进逻辑 ★

### 1.1 为什么

`prestige` 现在**全项目只有一处写入**——`Normalize` 里的 `Mathf.Clamp`。

**HUD 上最显眼的数字从头到尾不动。** 它是唯一能回答"贴完法之后干什么"的机制。

### 1.2 代码

**① `VillageSaveData` 加一个字段**

```csharp
public bool tyrantMode;
public bool prestigeSuspended;      // ★ 新增
```

**② `VillageLifecycleService.HasLaw` 加一行**

```csharp
private static bool HasLaw(VillageSaveData data, int lawId)
{
    if (data.prestigeSuspended) return false;    // ★ 停摆时所有法失效
    return FindLawSlot(data, lawId) >= 0;
}
```

**③ `LawEngine.Tick` 的调用点**（`VillageLifecycleService.SimulateTick` 里）

```csharp
// ── 原 ──
LawTickResult lawTickResult = LawEngine.Tick(data, tick, num);

// ── 改 ──
LawTickResult lawTickResult = data.prestigeSuspended
    ? default(LawTickResult)
    : LawEngine.Tick(data, tick, num);
```

**④ 结算**——插在 `SimulateTick` 的 `data.tick = tick + 1;` **之前**

```csharp
// ★ 威信结算（每 60 tick 一次）
if (tick > 0 && tick % 60 == 0)
{
    int act = 0;
    for (int k = 0; k < data.lawIds.Length; k++)
        if (data.lawIds[k] > 0) act++;                  // 活跃法数量

    int sf = 0;
    for (int k = 0; k < data.villagerAlive.Length; k++)
        if (data.villagerAlive[k]) sf += data.villagerFear[k];
    int af = population == 0 ? 0 : sf / population;     // 平均恐惧

    int reg = (population / 4) + Math.Max(0, 30 - af) / 10;

    if (data.prestigeSuspended)
    {
        data.prestige += reg;
        if (data.prestige >= 40) data.prestigeSuspended = false;   // 迟滞，防抖
    }
    else
    {
        data.prestige = data.prestige - 2 * act + reg;
        if (data.prestige <= 0) { data.prestige = 0; data.prestigeSuspended = true; }
    }
    if (data.prestige > 300) data.prestige = 300;       // 软上限
}
```

**⑤ 立法消耗（UI 层）**——`LawSelectionController` 里贴上一条法时

```csharp
currentSave.prestige -= 30;
if (currentSave.prestige < 0) currentSave.prestige = 0;
```

### 1.3 这套数字跑出来的效果

```
威信轨迹（5 年）
  0 条法      300 → 300 → 300 → 300 → 300    停摆  0%
  3 条法      189 → 300 → 300 → 300 → 300    停摆  0%
  5 条法       27 →   7 →  12 →  14 →  16    停摆 14%
```

**3 条以内恢复到上限（300），贴满 5 条会在三年内耗尽然后间歇停摆。**

这条设计是自洽的——**村子越大能养的法越多**。开局 24 人时贴满 5 条撑不住，等村子长到 40 人以上才养得起。

### 1.4 可调的旋钮

| 参数 | 现值 | 调它意味着 |
|---|---|---|
| 维持费（`2 * act`） | 2/法/60tick | 立法越多的惩罚 |
| 回复（`population / 4`） | 人口供养威信的速度 | 村子要多大才养得起法 |
| 停摆线 / 恢复线 | 0 / 40 | 迟滞宽度，太窄会抖 |
| 上限 | 300 | 软上限，防止无限积累 |

## 2. ★ 修正二：粮食产出一行 ★

### 2.1 病灶

`VillageLifecycleService.AdvanceGranary`

```csharp
int num4 = population * 2 + val;   // 产出
int num5 = population / 3;         // 消耗
// 净 = +5pop/3 → 粮仓永远顶死
```

**连锁反应**：粮仓永远满 → 个人存粮被持续补满 → **饥饿永远是 0** → 所有读饥饿的法条件永不成立；金币吃光后永远是 0 → 税收条件也永不成立。

### 2.2 改动

```diff
- int num4 = population * 2 + val;
+ int num4 = population * 120 / 100 + val;
```

### 2.3 为什么是 120%

30 年跨度的标定曲线（每档 150 seed）：

| 产出 | 好法 | 默认 | 不作为 | 恶法 | 好−不作为 |
|---|---|---|---|---|---|
| 90% | 22.7 | 18.4 | **0.0**（12/12 灭村） | 0.0 | 22.7 |
| 100% | 24.6 | 19.9 | 7.8 | 4.2 | 16.8 |
| 110% | 32.7 | 20.2 | 8.7 | 3.9 | 24.0 |
| **120%** | **48.2** | **20.2** | **10.1** | **4.3** | **38.1** |
| 130% | 53.2 | 21.1 | 13.1 | 4.8 | 40.1 |
| 140% | 58.9 | 21.2 | 16.8 | 5.7 | 42.1 |

**90% 太苛刻**（不作为必灭，没有容错），**140% 开始逼近人口上限且好法一家独大**。**120% 的阶梯最分明。**

## 3. ★ 修正三：验收必须跑 30 年 ★

### 3.1 我踩过的坑

我第一次试的是 **80%**，**5 年数据看着很好**（律法分得很开）。跑 **30 年**才发现那是个 **subsistence 陷阱**：

```
tick │存活│ 粮仓 │均饥饿│均存粮│能生者│生育
   1 │  24│   220│    23│    25│     8│   0
 401 │  31│    39│     0│     4│     0│   8   ← 8 个生育爆发后彻底停止
4000 │  25│     7│    40│     0│     0│   8
```

**粮仓常年为 0 → 个人存粮归零 → `CanGiveBirth` 的 `food >= 2` 永不成立 → 零生育**；同时饥饿卡在 40 到不了 99 → **也零饿死**。**村子冻结 27 年**，只有老死缓慢减员。

**这个陷阱在 5 年尺度上看不出来。**

### 3.2 验收脚本

```
对每个参数值：
    跑 150 seed × 30 年 × 8 组律法组合
    记录：终局存活 / 灭村率 / 累计生育 / 累计死亡 / 终局威信 / 停摆占比
```

**通过判据**

- [ ] 好法 与 不作为 的差距 **≥ 20 人**
- [ ] 好法的 **累计生育 ≥ 30**（不是冻结）
- [ ] **灭村率：不作 > 0%，好法 < 5%**（能输也能赢）
- [ ] 不作为的 **累计生育 ≥ 10**（不是死水）
- [ ] 恶法组的**停摆占比 > 50%**（威信真的在惩罚）
- [ ] 好法/默认的**停摆占比 < 60%**（不是永久停摆）

## 4. ★ 修正四：讣告频率 ★

### 4.1 改前

```
死亡 8.3/年  ÷  18.5 秒/年  =  每 2.2 秒一条讣告
而横幅显示 6 秒  →  屏幕上永远挂着 3 条互相覆盖
```

### 4.2 改完之后自动好转

修正二把出生率和婴儿夭折一起压下来之后（死因 97% 是夭折），30 年实测：

```
默认法：30 年死亡 23 人  →  0.77 死/年  →  每 25 秒一条讣告
```

**横幅的问题自然消失了。** 这是修正二的副产品。

### 4.3 但仍建议做批量（约 0.2 天）

**理由是大屠杀局面**——恶法组 30 年死亡 29 人，且集中在少数几个窗口。

**现在的实现**（`VillageUiController`）

```csharp
while (_tickAccumulator >= 1f && num < MAX)
{
    int oc = currentSave.obituaryCount;
    Advance(currentSave, 1);
    if (currentSave.obituaryCount > oc)
        ShowMessage(obituaryTexts[...], obituary: true, 6f);   // ★ 帧内可被覆盖
    ...
}
```

**改成攒到循环外统一显示**

```csharp
int before = currentSave.obituaryCount;
while (_tickAccumulator >= 1f && num < MAX) { Advance(currentSave, 1); ... }
int newDeaths = currentSave.obituaryCount - before;
if (newDeaths == 1)
    ShowMessage(obituaryTexts[currentSave.obituaryCount - 1].Replace("\n"," "), obituary: true, 6f);
else if (newDeaths > 1)
    ShowMessage($"本刻有 {newDeaths} 人死去。", obituary: true, 6f);
```

> **这一改顺带解决一个设计问题。** 一次死三个人，玩家该看到的是"本刻有 3 人死去"这个**事件**，而不是三条被截掉的讣告。**聚合本身比逐条推送更对。**

## 5. 改完之后的实测数据

**150 seed × 30 年**

| 律法组合 | 存活 | 灭村 | 生育 | 死亡 | 终局威信 | 停摆% |
|---|---|---|---|---|---|---|
| 好法 济贫/耕作/税收/幼童/医药 | **45.9** | 0.0% | 55 | 33 | 177 | 52% |
| 默认（开局自带） | 20.3 | 0.0% | 20 | 23 | 258 | 2% |
| 只装 济贫 | 19.7 | 0.0% | 10 | 14 | 300 | 0% |
| 只装 耕作 | 14.4 | 1.3% | 27 | 37 | 289 | 3% |
| 恶法 税收/劳役/丁税 | 11.5 | 4.0% | 21 | 34 | 79 | 74% |
| 不作为 | 8.6 | 0.0% | 14 | 29 | 300 | 0% |
| 恶法 减口/弃老 | 3.2 | 1.3% | 8 | 29 | 21 | 100% |
| 恶法 恐惧/私刑/连坐 | **2.7** | 14.0% | 8 | 29 | 21 | 97% |

**从 2.7 到 45.9，跨越 17 倍。**

**死因也归位了**（改前 97% 是夭折，与律法无关）：

```
不装济贫    →  饥饿 53%
恐惧系恶法   →  惊吓 65%
减口/弃老   →  律法 68%
好法        →  夭折 + 寿终，自然死亡为主
```

**结局梯度**：均值 17.2 · σ 5.9 · 两极 0%

## 6. 工时与顺序

| 序 | 做什么 | 工时 | 风险 |
|---|---|---|---|
| 1 | **产出一行**（`*2` → `*120/100`） | 0.05 天 | 极低 |
| 2 | **跑 30 年回归** | 0.3 天 | — |
| 3 | **威信**（4 处改动 + UI 的立法消耗） | 0.6 天 | 中，停摆逻辑要覆盖所有读法的入口 |
| 4 | **讣告批量** | 0.2 天 | 低 |
| | **合计** | **≈1.2 天** | |

**先做 1 和 2。** 产出那一行改完、30 年回归通过之后再做威信——**否则威信的效果会被"粮仓永远满"掩盖掉，你测不出它有没有用**。
