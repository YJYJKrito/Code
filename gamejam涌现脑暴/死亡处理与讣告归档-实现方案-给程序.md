# 死亡处理与讣告归档 · 实现方案（给程序）

> **来源**：用户报告「人死后尸体停在原地、点上去还能开面板」。
> 我按报告去读代码，**在修这个的过程中挖出两个更深的数据问题**，不一起修的话，改完之后讣告会显示错的信息。

---

## 0. 一句话

```
尸体不清除  ← 用户报告的，是四个小疏漏叠出来的
讣告数据错乱 ← 报告里没提，但它是"把面板信息并入讣告"这件事的真正拦路虎
```

**两个一起修，正好是同一块代码。工时 ≈0.7 天。**

---

## 1. 代码现状（逐条从反编译源码确证）

### 1.1 尸体为什么不清除

**四个疏漏叠在一起：**

**① `SetAlive` 只关子节点，不关自己**

```csharp
// VillagerWalker
public void SetAlive(bool alive)
{
    _alive = alive;
    if (visual != null)
        visual.gameObject.SetActive(alive);   // ★ 只关了 visual 这个子物体
}
```

`VillagerWalker` 的**根 GameObject 一直是 active 的**。走路停了（`Update` 里 `if (_alive && ...)`），但对象还在。

**② 点击碰撞体挂在根节点上**

```csharp
// EnsureActors 里
VillagerWalker villagerWalker = Object.Instantiate(_actorTemplate, _actorParent);
VillagerActorView component = villagerWalker.GetComponent<VillagerActorView>();   // ★ 挂在根上
```

所以 **`visual` 关掉了，碰撞体没关。**

**③ `IsKnownVillager()` 不检查死活**

```csharp
// VillagerActorView
public void OnPointerClick(PointerEventData eventData)
{
    if (IsKnownVillager() && VillagerStatusPanelController.Instance != null)
        VillagerStatusPanelController.Instance.Open(villagerIndex);
}

private bool IsKnownVillager()
{
    return villagerIndex < currentSave.villagerAlive.Length;   // ★ 只查下标范围
}
```

**死人完全满足这个条件。**

**④ `_actorByIndex` 从不清理**

`RefreshActorVisibility` 每次都对**字典里的每个**对象调 `SetAlive`，但**从不移除**。死 20 个人，场景里就多 20 个僵尸对象。

### 1.2 面板对死人是有分支的（这部分其实是好的）

```csharp
bool flag = currentSave.villagerAlive[index];
title.text = currentSave.villagerNames[index] + (flag ? "" : "（已故）");
if (flag)  stats.text = "金币…饥饿…恐惧…存粮…子女…";
else       { stats.text = BuildDeathText(currentSave, index);      // 死因/死于/法条/年龄
             tags.text = "这个人已经进入讣告历史。"; }
```

**所以现在的行为是**：尸体留在原地 → 点上去 → 弹出一个"（已故）"面板。**不是崩溃，是个设计没做完的半成品。**

## 2. ★ 两个更深的问题（报告里没提，但必须一起修）★

### 2.1 ★★ 村民下标会被复用，讣告是悬垂引用 ★★

```csharp
// VillageLifecycleService
private static int FindFreeVillagerSlot(VillageSaveData data)
{
    for (int i = 0; i < data.villagerAlive.Length; i++)
        if (!data.villagerAlive[i]) return i;      // ★★ 复用死者的下标 ★★
    return data.villagerAlive.Length;
}
```

**新生儿直接占用第一个死者的下标。**

而 `KillVillager` **不清空死者的个人数据**：

```csharp
private static void KillVillager(VillageSaveData data, int index, string cause, int lawIndex)
{
    if (data.villagerAlive[index])
    {
        data.villagerAlive[index] = false;
        AppendObituary(data, index, cause, lawIndex);
        // ★ villagerGold/Hunger/Fear/Food/Children/Innate/Marks 一个都不动
    }
}
```

**连锁后果：**

| 谁 | 读的是 | 结果 |
|---|---|---|
| `DescribeInnate(save, i)` | `save.villagerInnate[i]` | **活数组，按下标** |
| `DescribeMarks(save, i)` | `save.villagerMarks[i]` | 同上 |
| 面板的性别 | `save.villagerGenders[i]` | 同上 |
| `FindObituary(save, i)` | 倒序找 `obituaryVillagerIndices[i]` | 同一下标**可能有多条讣告** |

> **所以：点开一条老讣告，看到的是"现在占着那个下标的活人"的词条。**
>
> **这个 bug 现在被掩盖着**——因为讣告视图只显示 `obituaryTexts[]`（一段静态字符串），**根本没显示词条**。
> **但你要求"把面板信息并入讣告"，一显示就会暴露。**

### 2.2 这条数据在讣告里已经有了一半

**讣告已经存了**：名字、年龄、死因、tick、致死的法、villagerIndex、是否幼儿、正文。

**面板对死人显示的**：死因、死于、法条、年龄、**先天词条**、**烙记词条**。

**差的就是最后两项**——而它们恰好是按下标读活数组的那两个。

## 3. 方案

### 3.1 尸体清除（改三处）

**① `EnsureActors` 只给活人创建**

```diff
  for (int i = 0; i < save.villagerAlive.Length; i++)
  {
-     if (!_actorByIndex.ContainsKey(i))
+     if (save.villagerAlive[i] && !_actorByIndex.ContainsKey(i))
      { ... Instantiate ... }
  }
```

**② `RefreshActorVisibility` 里销毁死者**

```csharp
private void RefreshActorVisibility(VillageSaveData save)
{
    EnsureActors(save);

    List<int> dead = null;
    foreach (var kv in _actorByIndex)
    {
        int key = kv.Key;
        VillagerWalker w = kv.Value;
        if (w == null) { (dead ??= new List<int>()).Add(key); continue; }

        if (key >= save.villagerAlive.Length || !save.villagerAlive[key])
        {
            (dead ??= new List<int>()).Add(key);      // ★ 死了
            continue;
        }
        w.SetTint(Traits.TintColor(save, key));
        if (key < save.villagerNames.Length) w.SetName(save.villagerNames[key]);
    }

    if (dead != null)
        foreach (int k in dead)
        {
            if (_actorByIndex[k] != null) Object.Destroy(_actorByIndex[k].gameObject);
            _actorByIndex.Remove(k);
        }
}
```

> ⚠️ **不能在 `foreach` 里直接删字典。** 先收集再删。
> ⚠️ **`SetAlive` 之后就不需要了**（活人永远 alive）。但**保留它**——万一以后要做死亡动画，它是入口。

**③ `IsKnownVillager` 加死活检查**（防御性，多加一道）

```csharp
private bool IsKnownVillager()
{
    var save = GameSession.CurrentSave;
    return save != null && villagerIndex >= 0
        && villagerIndex < save.villagerAlive.Length
        && save.villagerAlive[villagerIndex];      // ★ 加了这一条
}
```

> **三处都要改。** 只改①的话，已经存在的僵尸对象不会被清；只改②的话，读档时会先创建再销毁（浪费，且有一帧闪烁）。

### 3.2 ★ 讣告自包含（这是这次真正的活）★

**原则：讣告是历史记录，历史记录必须自包含，不能靠下标反查活数组。**

**加三个字段**（`VillageSaveData`）：

```csharp
public int[]  obituaryGenders = new int[0];    // 0 女 / 1 男
public uint[] obituaryInnate  = new uint[0];   // ★ 死亡那一刻的先天词条快照
public uint[] obituaryMarks   = new uint[0];   // ★ 死亡那一刻的烙记快照
```

**`AppendObituary` 里一起写**（和现有七个数组完全同构）：

```csharp
Array.Resize(ref data.obituaryGenders, obituaryCount + 1);
Array.Resize(ref data.obituaryInnate,  obituaryCount + 1);
Array.Resize(ref data.obituaryMarks,   obituaryCount + 1);
...
data.obituaryGenders[obituaryCount] = data.villagerGenders[villagerIndex];
data.obituaryInnate[obituaryCount]  = data.villagerInnate[villagerIndex];   // ★ 快照
data.obituaryMarks[obituaryCount]   = data.villagerMarks[villagerIndex];    // ★ 快照
```

**成本**：`4 + 4 + 4 = 12 字节 / 条讣告`。跑 30 年死 100 人 → **1.2 KB**。

**然后 `BuildDeathText` 改成读讣告，不读活数组**：

```csharp
// 现在：BuildDeathText(save, villagerIndex) → FindObituary → 但词条读活数组
// 改成：BuildDeathText(save, obituaryIndex) → 全部读讣告
string text = "死因\t" + save.obituaryCauses[n]
            + "\n死于\t" + VillageTime.FormatFull(save.obituaryTicks[n])
            + "\n法条\t" + ...obituaryLawIndices[n]...
            + "\n年龄\t" + save.obituaryAges[n] + " 岁";

// ★ 新增两行（从快照读）
traits.text = "【先天】\n" + Traits.DescribeInnate(save.obituaryInnate[n])
            + "\n\n【烙记】\n" + Traits.DescribeMarks(save.obituaryMarks[n]);
```

> **需要一个重载**：`Traits.DescribeInnate(uint bits)` —— 现有的那个是 `DescribeInnate(save, index)`。
> **改动很小**：现有实现第一步就是 `uint bits = d.villagerInnate[i];`，把这一步提到外面就是新重载。**顺便让现有那个变成对新重载的一行包装。**

### 3.3 讣告条目可点击

**现在讣告历史只显示两行文本**（`header` + `body`）。既然信息都进讣告了，就得有个入口。

**两个选择：**

| | 做法 | 工时 |
|---|---|---|
| **A（推荐）** | 讣告条目加一个「详情」按钮，点开复用现有的 `VillagerStatusPanelController`，但**喂讣告下标而不是村民下标** | 0.15 |
| B | 讣告条目就地展开，显示完整信息 | 0.2 |

**推荐 A**：复用现有面板的布局和样式，**代码量最小、视觉最一致**。

**面板要改成一个双入口的组件**：

```csharp
public void OpenVillager(int villagerIndex)   // 点活人
public void OpenObituary(int obituaryIndex)   // 点讣告  ← 新增
```

内部用一个 `_obituaryIndex`（-1 = 看活人）区分，所有读数据的地方走同一套取值函数。

### 3.4 存档兼容

```
VillageSaveData.CurrentVersion: 6 → 7
```

**三个新数组用现有的 `ResizeArray` 模式补齐**（和 `obituaryVillagerIndices` 一样的写法）：

```csharp
data.obituaryGenders = ResizeArray(data.obituaryGenders, data.obituaryCount, 0);
data.obituaryInnate  = ResizeArray(data.obituaryInnate,  data.obituaryCount, 0u);
data.obituaryMarks   = ResizeArray(data.obituaryMarks,   data.obituaryCount, 0u);
```

> ⚠️ **老存档的讣告，词条会是空的**（补的默认值是 `0u`，`DescribeInnate(0)` 返回空串）。
> **这个填不回来**——那些人的村民数据早被复用了，信息已经丢了。
> **在 UI 上写"（旧版本存档，无词条记录）"比留空白好。**

## 4. 验收

- [ ] **人死后尸体消失**（场景里 `Villager_NN` 对象被销毁，不是只隐藏）
- [ ] **尸体消失之后，在原位置点击没有任何反应**（不会弹出"（已故）"面板）
- [ ] 活人点击照常开面板，行为和现在完全一样
- [ ] **讣告历史里能点开某一条，看到完整信息**（死因/死于/法条/年龄/先天/烙记）
- [ ] ★ **验证下标复用不再出错**：跑一局到死 10 人以上 → 让新生儿占掉死者的下标 → **打开那条老讣告，词条必须是死者的，不是新生的**
- [ ] ★ **存档往返**：存→读→打开老讣告，信息和存之前一致
- [ ] 读一个**版本 6 的旧存档**：不崩，老讣告显示"（旧版本存档，无词条记录）"
- [ ] `_actorByIndex` 在长局里**不增长**（死 20 人后字典大小应等于活人数）

## 6. 一句话

> **尸体不清除是四个小疏漏叠出来的，半天能修。**
>
> **但真正要小心的是它背后那条：村民下标会被新生儿复用，而讣告只记了下标。**
> **你今天想显示的"词条"，恰恰是唯一还在按下标读活数组的那一项——**
> **一显示就会看到新人的词条挂在老讣告上。**
>
> **所以：先让讣告自包含（12 字节/条），再拆尸体。**
