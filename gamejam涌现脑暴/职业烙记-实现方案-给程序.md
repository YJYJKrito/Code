# 职业（烙记）· 实现方案 — 给程序

> **一句话**：19 个烙记里现在只有 3 个会亮。这份文档把剩下 13 个职业接上，
> 让它们变成「**你写的法律 → 村里出现了这种人**」。
>
> 规则全部在测试台跑过：40 种子 × 30 年 × 9 种玩法。
> 结果：**13 / 13 都能拿到，有法条门槛的 7 个全部「装了 100% / 没装 0%」。**
>
> **配套文档**：
> - 《突发事件-实现方案-给程序》（14 个事件的权重 / 效果 / 兆头期）
> - 《三个资源接通-实现方案-给程序》（职业门槛依赖的恐惧/税库/威信要先接通）

---

## 1. 为什么必须做这个

现有 19 个烙记里，**只有 3 个真的会发生**（绝粮 256 / 惊魂 512 / 劳损 1024），
其余 16 个是死内容。而烙记已经接好了三件事：

- 存档（`villagerMarks` 已经在存）
- 面板显示（`DescribeMarks` 已经在显示）
- 讣告（`obituaryMarks` 已经在记）

**所以不需要新系统，只需要补「什么时候给」。**

---

## 2. 存档改动

### 2.1 新增字段（加在 `VillageSaveData` 里）

```csharp
// ── 职业计数器 ──
public int   executions;                              // 累计处决次数（法律驱动的死亡）
public int[] villagerNeighborDeaths = new int[0];     // 每人累计「邻居死了」的次数（尸亲）
public int[] villagerDonations     = new int[0];     // 每人累计捐纳次数（恩主）
public int[] villagerChildrenAlive = new int[0];     // 每人**在世**子女数（绝户）
public int[] villagerMother        = new int[0];     // 母亲槽位，-1 = 无
public int[] villagerFather        = new int[0];     // 父亲槽位，-1 = 无
public int[] villagerWealthPeak    = new int[0];     // 曾经拥有过的最高金币（债户）
public int[] villagerHungryTicks   = new int[0];     // 饥饿 > 50 的连续 tick 数（积怨）
```

> **`villagerChildrenAlive` 和原有的 `villagerChildren` 不是一回事。**
> `villagerChildren` 是「累计生过几个」（只加不减，现有代码就是这么用的）；
> 新的是「现在还活着几个」。**两个都要保留。**

### 2.2 存档版本升级

按现有的迁移写法，加一个版本号。旧存档读进来时：

- 新增数组**按 `villagerAlive.Length` 补齐**，全部填 0（`villagerMother/Father` 填 **-1**）
- `executions = 0`
- 不需要回溯计算（老存档的村史补不出来，也不重要）

### 2.3 数组补齐（关键）

现有 `EnsureLifecycleArrays` 里每一行 `EnsureLength` 后面，补上这几个数组。
**任何一个漏了，读档就会越界。**

## 3. 六个插入点

规则本体建议单独一个文件（例如 `VillagerProfessions.cs`），
下面六个函数里各加**一行调用**。这样规则和模拟层解耦，以后改门槛不用动大文件。

| # | 位置（现有函数） | 插入 | 什么时候 |
|---|---|---|---|
| 1 | `EnsureLifecycleArrays` | `Professions.Ensure(data, length);` | 读档 / 扩容 |
| 2 | `AppendChild`（`data.totalBirths++` 附近） | `Professions.OnBirth(data, child, mother, father);` | 有人出生 |
| 3 | `AppendImmigrant`（`villagerMarks[num] = 0u;` **之后**） | `Professions.OnImmigrant(data, num);` | 移民进村 |
| 4 | `KillVillager`（`villagerAlive[index] = false;` 之后） | `Professions.OnDeath(data, index, cause, lawIndex);` | 任何人死 |
| 5 | `LawEngine` 的法条生效处（`ApplyAll(...)` 之后） | `Professions.OnLawFired(data, i, lawDefinition.id);` | 某条法在某个人身上生效 |
| 6 | `SimulateTick`（`Traits.SurvivorScan(data, tick);` 之后） | `Professions.Scan(data, tick);` | **每 60 tick** |

> 插入点 3 必须在 `villagerMarks[num] = 0u;` **之后**，否则刚烙上的「徙民」会被清掉。

## 4. 13 个职业的判定

**全部在 `Scan()`（每 60 tick）里判。** 格式：条件 → 烙记。
一旦烙上就永久保留（这 13 个标记都在永久位 0–15，**不要用可清除位**）。

| 职业 | 条件 | 说明 |
|---|---|---|
| 罪人 `Sinner` | 装了法 7 **且** 恐惧 > 40 | |
| 劫匪 `Bandit` | 装了法 2 **且** 饥饿 > 55 | |
| 逃兵 `Deserter` | 装了法 15 **且** 年龄 14–40 **且** 恐惧 > 25 | |
| 劳损 `Worn` | 装了法 11 **且** 年龄 ≥ 40 **且** 饥饿 > 56 | 和现有 SurvivorScan 的劳损**合并**（见 §6） |
| 债户 `Debtor` | 装了法 26 **或** 27 **且** 年龄 ≥ 25 **且** 金币 ≤ 0 **且** `WealthPeak ≥ 30` | 破产过 |
| 巫祝 `Shaman` | 装了法 35 **且** 恐惧 > 30 | |
| 恩主 `Patron` | 全村捐纳累计 ≥ 3 **且** 此人捐过 ≥ 1 次 | |
| 屠者 `Butcher` | `executions > 0` → 给**最不害怕的成年人**（见 §5） | |
| 绝户 `LastHeir` | 年龄 ≥ 45 **且** `villagerChildren > 0` **且** `ChildrenAlive = 0` | 曾有子女、全死光 |
| 光棍 `Bachelor` | 年龄 ≥ 50 **且** `villagerChildren = 0` | 从未有过子女 |
| 积怨 `Bitter` | 饥饿 > 50 **连续 ≥ 730 tick**（≈0.25 年） | |
| 尸亲 `Mourner` | `NeighborDeaths ≥ 15` | |
| 徙民 `Settler` | **移民进村那一刻直接烙**（不经过 Scan） | |

### 4.1 计数器怎么维护

| 计数器 | 在哪里改 |
|---|---|
| `executions` | `OnDeath`：`cause == "律法"` 时 +1 |
| `villagerNeighborDeaths` | `OnDeath`：死者的**左右邻居**（槽位 ±1 环绕，和 `NeighborNext/Prev` 同一套）各 +1 |
| `villagerDonations` | `OnLawFired`：`lawId == 28` 时 +1 |
| `villagerChildrenAlive` | `OnBirth`：父母各 +1；`OnDeath`：死者父母各 −1（下限 0） |
| `villagerMother/Father` | `OnBirth`：写入；`OnImmigrant`：写 -1 |
| `villagerWealthPeak` | `Scan`：`if (gold > peak) peak = gold;` |
| `villagerHungryTicks` | `Scan`：`hunger > 50 ? +60 : 0` |

### 4.2 ⚠ 必须做的清理

**槽位是回收复用的**（`FindFreeVillagerSlot` 返回第一个 `!villagerAlive[i]`）。
所以 `AppendChild` 和 `AppendImmigrant` 里，**这 7 个计数数组的新槽位必须清零**
（`Mother/Father` 填 -1）。不清零的话，一个 90 岁老人的"邻居死了 40 次"
会传给他刚出生的孙子，尸亲瞬间满村。

## 5. 屠者：只有一个刽子手

**设计**：只要村里有法律处决过人（`executions > 0`），
就烙给「**最不害怕的成年人**」（恐惧最低，并列取槽位最小）。

**同一时刻只保留一个人**：如果现存屠者 ≥ 1 人，就不再给。
他死了，下一个最不害怕的人才接刀。

> 为什么不是「每次处决给一个人」：苛政玩法下 40 局处决了 3004 次，
> 那样会让**全村每一个人**都变成屠者（实测持有率会冲到 100%）。
> 「刽子手只有一个」既更真实，也保住了区分度（实测 9.1%）。

**为什么判据是「任何致死的法条」而不是只看 36/64**：
36 逐客 要「有人恐惧 > 85」、64 刑戮 要「4 人恐惧 > 60」——
**这两条在 30 年 × 40 局里一次都没触发过**（恐惧 p99 = 30）。
而 54 减口 这种法是真的在杀人。所以判据用 `cause == "律法"`。

## 6. 和现有 `SurvivorScan` 的关系

现有代码里：

```csharp
if (HasMark(d, i, Corvee) && !HasMark(d, i, Worn) && Rng.Chance(...)) AddMark(d, i, Worn);
```

**问题**：`Corvee` 这个标记**没有任何一条法在授予**，所以这条永远不成立。

**处理**：删掉这条，劳损改由 §4 的规则给（装法 11 + 年龄 ≥ 40 + 饥饿 > 56）。
这样「劳役 → 劳损」的链条才真的存在。

---

## 7. 确定性

- **不需要随机数**：所有判定都是确定性的比较。
- 屠者「最不害怕」并列时**取槽位最小的**（全序，不能用字典）。
- `villagerMother/Father` 用槽位号，槽位回收后旧关系失效 —— 靠 §4.2 的清零处理。

## 9. 实测数据（直接引用，不用重跑）

**40 种子 × 30 年 × 9 种玩法，每 60 tick 判定一次：**

| 职业 | 最好玩法 | 出现率 | 持有率 |
|---|---|---|---|
| 罪人 | 苛政 | 100% | 12.3% |
| 劫匪 | 荒年 | 100% | 18.6% |
| 逃兵 | 兵役系 | 100% | 20.8% |
| 劳损 | 劳役系 | 100% | 30.5% |
| 债户 | 捐纳系 | 100% | 11.4% |
| 巫祝 | 祭祀系 | 100% | 21.7% |
| 恩主 | 捐纳系 | 100% | 22.2% |
| 屠者 | 苛政 | 100% | 9.1% |
| 绝户 | 苛政 | 100% | 14.9% |
| 光棍 | 默认三法 | 100% | 25.6% |
| 积怨 | 苛政 | 78% | 12.7% |
| 尸亲 | 苛政 | 100% | 18.6% |
| 徙民 | 苛政 | 100% | **69.2%** |

**「装了 vs 没装」—— 7 个有法条门槛的全部 100% / 0%。**

> 徙民 69.2% 是**故意的**：苛政下 40 局来了 2423 个移民，
> 村子是靠移民续命的，所以村里大多数本来就是外来人。

## 11. 一个已知的、不在这份文档范围内的问题

**36 逐客 / 64 刑戮 永远不触发**（门槛：恐惧 > 85 / 4 人恐惧 > 60）。
这不是职业系统的问题，是**恐惧参数区间与法条门槛不匹配**——
和《三个资源接通》里那 11 条法条是同一个病。

屠者不依赖它们（见 §5），但这两条法本身需要单独修门槛。
