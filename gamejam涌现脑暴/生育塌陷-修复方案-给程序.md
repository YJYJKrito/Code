# 生育塌陷 · 修复方案（给程序）

> **这份方案里的每一个数字都是跑出来的**，不是估的。
> 测试台：把反编译源码里的 22 个模拟类抽出来独立编译，**30 年 × N 种子全扫 9 秒**。
>
> ⚠️ **先说一件事：我上一轮给你的三条判断，实测下来两条是次要的，一条方向反了。**
> §2 是那次翻车的记录。**真正有效的是 §4 那个新机制。**

## 0. 一句话

```
病根不是生育上限，是「崩溃不可逆」。

村子里一旦没有能生育的人，它就永远回不来了 —— 但粮食、耕地、房子都还在。
所以 33 条法里有 27 条装上去和不装一模一样：
   因为结局在第 19 年就锁死了，你装什么法都改不了。

修法是让村子「能喘回来」：给村里补人。
实测：8 个法条组里活下来的从 4 个变成 9 个（全活），末人口从「全是 1」变成 7–55 的真实分布。
```

## 2. 我上一轮判断错了什么

我给你的三条是：**放开子女上限 / 初始年龄跨两代 / 粮仓预留线随人口缩放**。

实测结果：

| 我的判断 | 实测 |
|---|---|
| ① 子女上限 6 是根因 | **次要。** 它确实是"幸存村子的天花板"（末人口被压在 26，放开到 12 后同样法条组变 38），**但它不决定谁死谁活** —— 放开后「不装法/生育系/苛政/恐惧系」照样塌到 1 |
| ② 初始年龄是一代人 | **基本无关。** 三种年龄分布（原版 / 跨两代 / 跨两代且随种子）的末人口差异在 3 人以内 |
| ③ 粮仓预留线 40 饿死村民 | **方向反了。** 预留我试了 `40 / 20 / 人口÷2 / 人口 / 0` —— **调到 0 反而全村饿死**（粮仓归零后再也没粮可发）。预留线不是主因 |

**另外两条之前的结论也要修正：**

| 之前说 | 实测 |
|---|---|
| ❌「饥饿基本不会动」 | 完全说反 —— **饥饿是唯一的死因** |
| ❌「粮仓顶死在 500」 | 它钉在 **40**（预留线），不是 500 |

## 3. ★ 真正的崩溃链 ★

```
耕地每 2400 tick 退化 3%
   ↓  耕地 414 → 132（30 年），产出系数被钳到下限 250
人均产出腰斩（默认法条组实测：194 → 79，只用 12 年）
   ↓
粮仓常年钉在 40（预留线），村民只能靠「金币买粮」和法条取粮
   ↓
金币耗尽（平均 2.7），饥饿开始爬
   ↓
饥饿到 99 → 饿死       ← 实测死因几乎全是「饥饿」
   ↓
★★★ 头 3 年生的孩子被饿死后，村里再也没有能生育的人 ★★★
   ↓
崩溃不可逆：粮食在、地在、房子在，但村子永远停在 1 个人
```

**最后那一步才是致命的。** 前四步只是让村子变穷；第五步把它锁死。

### 3.1 证据

**「不装任何法」逐年死因：**

| 年 | 人口 | 死因 |
|---|---|---|
| 1 | 49 | 夭折 8 |
| 2 | 43 | 夭折 14 · 寿终 1 |
| 3 | 37 | 夭折 9 · **饥饿 1** |
| 5 | 24 | **饥饿 4** |
| 9 | 14 | **饥饿 4** · 寿终 1 |
| 14 | 5 | **饥饿 2** |
| 19 | **1** | —— |
| 20–30 | **1** | **什么都不再发生** |

**「合格母亲数」逐年：**

```
年 1: 育龄女 8  冷却OK 4  子女<6 8   → 出生 +33
年 2: 育龄女 8  冷却OK 6  子女<6 5   → 出生 +9
年 3: 育龄女 7  冷却OK 6  子女<6 0   → 出生 0     ← 8 位女性各生满 6 个
年 4+: 育龄女 7  冷却OK 7  子女<6 0   → 永远 0
```

**单条法扫描（33 条各自单独装，120 种子）：**

| | 末人口中位 |
|---|---|
| 济贫 / 公共卫生 / 抚孤 | 26 |
| 开垦 | 21 |
| 多子 | 10 |
| 常平 | 0（98% 灭村，它是反向法条：全员饥饿 **+2**）|
| **其余 27 条** | **1（与"不装法"逐位相同）** |

**退化解剖（这是决定性的一刀）：**

| 耕地退化率 | 活下来的法条组 |
|---|---|
| **0%** | **4 / 6** |
| 1% | 2 / 6 |
| 2% | 2 / 6 |
| **3%（当前）** | **2 / 6** |
| 5% | 1 / 6 |

我把退化率、退化下限、产出系数全试了一遍（8 种组合）—— **没有一个能把活下来的法条组推到 3 个以上。**

> **因为问题不在"村子会不会变穷"，在"穷下去之后回不回得来"。**

## 4. ★ 修复：村里要能来人 ★

> **这条不是新设计。法 17「流民法」的卡面上本来就写着「允许外来者加入」。**
> **但实现里只有 `Add All Hunger −4`，一个人都没加过。**

### 4.1 实测结果

| 设置 | 不装法 | 默认 | 生育系 | 开垦系 | 苛政 | 恐惧系 | 流民法 | 流民+开垦 | 活下来的组 |
|---|---|---|---|---|---|---|---|---|---|
| **关闭（现状）** | 1 | 26 | 1 | 60 | 1 | 1 | 25 | 31 | **4/8** |
| 门槛人口 15 | 10 | 26 | 8 | 60 | 13 | 8 | 25 | 31 | 6/8 |
| **门槛人口 25** | **11** | **26** | **11** | **60** | **14** | **11** | **26** | **31** | **8/8** |
| 门槛人口 35 | 1 | 27 | 1 | 60 | 1 | 1 | 26 | 38 | 4/8 |

**40 种子复核（门槛 25）：**

| 法条组 | 末人口 最小/中位/最大 | 灭村率 | 全程最低人口 |
|---|---|---|---|
| 不装法 | 5 / 8 / 11 | 0% | 7 |
| 生育系 | 2 / 7 / 13 | 0% | 4 |
| 苛政 | 6 / 12 / 16 | 0% | 6 |
| 恐惧系 | 5 / 8 / 13 | 0% | 6 |
| 默认 | 25 / 27 / 43 | 0% | 27 |
| 流民法 | 25 / 26 / 41 | 0% | 26 |
| 流民+开垦 | 25 / 30 / 46 | 0% | 29 |
| **开垦系** | **25 / 55 / 81** | 0% | 40 |
| **满槽6条** | **27 / 45 / 80** | 0% | 35 |

**9/9 全活，0% 灭村，末人口 7–55 有真实跨度。**
注意「全程最低人口」那一列：村子**会掉到 4–7 人，然后爬回来** —— 这就是我们要的。

### 4.2 参数（都是测出来的，不是拍的）

```csharp
// 每 2400 tick（= 300 天）检查一次
if (tick % 2400 == 0)
{
    // ★ 无条件，不挂在任何法律上（见 §5）
    if (CountAlive(data) < 25 && data.granaryFood > 20)
    {
        // 一次来 2 人，但不超过阈值
        for (int q = 0; q < 2 && CountAlive(data) < 25; q++)
            AppendImmigrant(data);
    }
}
```

| 参数 | 值 | 为什么是这个 |
|---|---|---|
| **阈值人口** | **25** | 测过 15 / 25 / 35：15 太晚（只剩 2 人时来不及），35 太早（村子没掉下去就被补满，反而失去张力）。**25 是唯一让 8 个组全活的值** |
| **粮仓门槛** | **20** | ★ 我一开始写 150，**移民一次都没触发过** —— 因为粮仓常年就是 40。**必须是村民真正够得到的水平** |
| **每次人数** | **2** | 一次 2 人，配合阈值刚好能补回一对育龄男女 |
| **周期** | **2400 tick（300 天）** | 复用退化周期，一年一次，玩家能注意到 |

### 4.3 `AppendImmigrant` 怎么写

照抄 `AppendChild`（`VillageLifecycleService:5828`），只改赋值部分：

```csharp
public static void AppendImmigrant(VillageSaveData data)
{
    int num = FindFreeVillagerSlot(data);
    if (num >= data.villagerAlive.Length)
    {
        // ★ 13 个数组一起 Resize —— 和 AppendChild 一模一样，一个都不能漏
        Array.Resize(ref data.villagerNames, num + 1);
        Array.Resize(ref data.villagerGenders, num + 1);
        Array.Resize(ref data.villagerAges, num + 1);
        Array.Resize(ref data.villagerAgeTicks, num + 1);
        Array.Resize(ref data.villagerAlive, num + 1);
        Array.Resize(ref data.villagerGold, num + 1);
        Array.Resize(ref data.villagerHunger, num + 1);
        Array.Resize(ref data.villagerFear, num + 1);
        Array.Resize(ref data.villagerFood, num + 1);
        Array.Resize(ref data.villagerBirthCooldown, num + 1);
        Array.Resize(ref data.villagerChildren, num + 1);
        Array.Resize(ref data.villagerInnate, num + 1);
        Array.Resize(ref data.villagerMarks, num + 1);
    }

    data.villagerNames[num]  = GetVillagerName(data.rngSeed, 5000 + data.tick + num);
    data.villagerGenders[num] = Rng.Range(data.rngSeed, data.tick, 4300 + num, 0, 2);
    data.villagerAges[num]    = 16 + Rng.Range(data.rngSeed, data.tick, 4400 + num, 0, 24);  // ★ 16–39，直接是育龄
    data.villagerAgeTicks[num] = 0;
    data.villagerAlive[num]   = true;
    data.villagerGold[num]    = 10 + Rng.Range(data.rngSeed, data.tick, 4500 + num, 0, 30);
    data.villagerHunger[num]  = 10;
    data.villagerFear[num]    = 10;
    data.villagerFood[num]    = 4;
    data.villagerBirthCooldown[num] = 0;
    data.villagerChildren[num] = 0;
    data.villagerInnate[num]  = Traits.RollInnate(data.rngSeed + num, num);
    data.villagerMarks[num]   = 0u;
    // ⚠️ 不增加 data.totalBirths —— 移民不是出生
    // ⚠️ 不动 villagerChildren[母亲] —— 没有母亲
}
```

> ★ **年龄必须给 16–39（育龄）**，不能像 `AppendChild` 那样给 0 岁。
> 否则补进来的人要等 18 年才能生育 —— **等于没补**。
>
> ⚠️ **`Rng` 的通道号别和现有的撞**（`Rng.For/Range/Chance` 是全工程共用的）。
> 现用的：4000+num（性别）、5000（词条）、5400（老死）、3000+i（生育）、31/32（退化）、5xxx（词条掉落）。
> 我用的 4300/4400/4500 是空的。

## 5. 为什么**不能**挂在「流民法」上

我测了「需要装流民法才会来移民」这个版本：

| 设置 | 活下来的组 |
|---|---|
| 无条件 · 门槛 25 | **8/8** |
| **需要流民法 · 门槛 25** | **4/8** ← 和不开移民一样 |

原因很简单：**正在崩的那几组（不装法 / 生育系 / 苛政 / 恐惧系）本来就没有流民法。**
把它挂在法律上，等于**只有活得好的村子才能拿到救命绳**。

> **移民应该是基础规则（安全网），不是政策。**
>
> 但**法律可以让它变得更有意思** —— 这是后面的事（见 §7.2）：
> 「流民法」提高移民速度、「苛政」降低、「兵役」抢走年轻人。

## 6. 配套（次要，但建议一起做）

这两条**不改变谁死谁活**，但会明显改善手感：

| # | 改动 | 现状 → 改后 | 实测效果 |
|---|---|---|---|
| 1 | **子女上限 6 → 12**（`CanGiveBirth`）| 8 位女性 3 年就生满 → 生育只持续 8 年 | 同一法条组末人口 26 → 38；开垦组 60 → 82。**注意 `Normalize:6717` 也把这个字段钳到 12，两边要一致** |
| 2 | **耕地退化慢一点**（3% → 2%）| 30 年耕地 414→132 | 单看没有决定性效果，但配合 #1 能让产出曲线平缓些 |

> ⚠️ **#1 会让人口更容易顶到 80 上限**（实测开垦组会到 81/82）。如果不想顶死，同时把 `MaxPopulation` 提到 120 或让上限可被法律提高（`MaxPopulation` 这个常量现在是死的，代码里写死 80）。

## 7. 验收

**核心**
- [ ] 不装任何法律跑 30 年，**末人口不再是 1**（目标 ≥ 5）
- [ ] 8 个法条组里有 **≥ 7 组**末人口 ≥ 5
- [ ] 30 年内**灭村率 ≤ 5%**
- [ ] 移民来的时候**玩家能看见**（HUD 事件文本：「有流民在村口停下了。」）

**回归**
- [ ] `totalBirths` **不因移民而增加**（讣告和统计不能把流民算成出生）
- [ ] 移民不会挤爆数组（跑到人口 80 附近确认 13 个数组长度一致）
- [ ] 存档往返后移民的村民数据完整（读档 → 再看这个人）
- [ ] 迁入的村民**能生育**（年龄 16–39，不是 0）

**标定（做完再跑一次）**
- [ ] 33 条法各单独装，**有多少条的末人口和不装法不同**
      → **改之前是 6/33。目标是 ≥ 15/33**（现在 27 条是摆设）
