### 1.1 恐惧门槛：×50 → ×70（10 个数字）

**先核对**：如果程序是照旧文档那张表改的，代码里现在应该是「现在」这一列。

| id | 法条 | **现在（×50）** | **改成（×70）** |
|---|---|---|---|
| 35 | 祭祀 | 25 | **35** |
| 47 | 整肃 | 25 | **35** |
| 7 | 私刑倾向 | 30 | **42** |
| 37 | 立威 | 30 | **42** |
| 64 | 刑戮 | 30 | **42** |
| 34 | 诛心 | 32 | **45** |
| 18 | 起义豁免 | 35 | **49** |
| 22 | 瘟疫隔离 | 40 | **56** |

**为什么退到 ×70 —— 触发次数 / 30 年末人口：**

| 法条 | ×100（原版） | **×70（本方案）** | ×50（现在） |
|---|---|---|---|
| 祭祀 35 | 18 / 19 | **5233 / 20** | 98499 / 19 |
| 整肃 47 | 500 / 18 | **1694 / 18** | 3646 / 18 |
| 私刑 7 | 1972 / 16 | **15294 / 16** | 20737 / **13** |
| 立威 37 | 41 / 17 | **264 / 16** | 1108 / **15** |
| 刑戮 64 | 19 / 17 | **103 / 16** | 204 / **15** |
| 诛心 34 | 238 / 16 | **1858 / 14** | 2032 / **13** |
| 起义豁免 18 | 10 / 19 | **27 / 18** | 119 / 18 |
| 瘟疫隔离 22 | 2 / 18 | **23 / 18** | 85 / 16 |
| 示众 50 | 10 / 18 | **1022 / 18** | 3541 / 16 |
| 逐客 36 | 2 / 18 | **34 / 18** | 178 / 16 |

**×70 的代价**：人口 14–20（原版 16–19，同一区间）。

### 1.2 税库：人口÷8 → 人口÷3

现在的代码：

```csharp
if (tick > 0 && tick % 2400 == 0)
    data.treasuryGold += VillageLifecycleService.CountAlive(data) / 8;   // ← 改成 / 3
```

**扫出来的档：**

| 人口 / N | 30 年末 最小 / 平均 / 最大 | 能买到 ≥60 金的局的占比 |
|---|---|---|
| /2 | 0 / 210 / 1289 | 71% |
| **/3 ← 改成这个** | **0 / 131 / 832** | **58%** |
| /4 | 0 / 94 / 514 | 51% |
| /6 | 0 / 73 / 390 | 41% |
| **/8 ← 现在** | **0 / 57 / 278** | **36%** |

> **这一条只解决「进项」，没解决「出口」。**
> 实测：不装平粜/常平的玩法，68–79% 的月份税库 ≥ 200 —— **钱是死的**。
> 出口方案见《**税库出口-实现方案-给程序**》（官吏俸禄，一行代码）。

### 1.3 威信：加一条软上限

**这是唯一能把「顶 300」压到 25% 以下的手段。**
不加软上限，维持费怎么加最多只能到 26%，而且归零率会飙到 17%。

现在（已落地）的代码：

```csharp
int num8 = num / 4 + (12 - num7) / 2;
data.prestige = data.prestige - 4 * num5 + num8;
```

改成：

```csharp
int num8 = num / 4 + (12 - num7) / 2;

// ★ 新增：威信超过 200 之后，进项线性衰减到 0
if (data.prestige > 200)
    num8 = num8 * (300 - data.prestige) / (300 - 200);

data.prestige = data.prestige - 4 * num5 + num8;
```

**含义**：200 之前不衰减；250 时进项减半；逼近 300 时进项趋近 0。
**威信能逼近 300，但永远到不了** —— 不是硬钳，是自然的饱和。

> 如果 `300` 在代码里是常量 `PrestigeCapV`，把字面量换成它，别写死。

**扫出来的档：**

| 维持费 | 恐惧项 | 顶 300 占比 | 归零占比 | 平均威信 | |
|---|---|---|---|---|---|
| 3/条 | (30−恐惧)/10 | 50% | 1% | 166 | 原版 |
| 4/条 | (12−恐惧)/2 | 38% | 8% | 129 | **现在** |
| 5/条 | (12−恐惧)/2 | 28% | 15% | 91 | ⚠ 归零太多 |
| 6/条 | (12−恐惧)/2 | 26% | 17% | 85 | ⚠ 归零太多 |
| **4/条** | **(12−恐惧)/2 · 软上限 200** | **0%** | **9%** | **105** | ✅ **改成这个** |
| 4/条 | (12−恐惧)/2 · 软上限 150 | 0% | 9% | 93 | 也可以 |

### 1.4 给做事件的时候预备：扣税库必须 clamp

这一条现在**不影响**（事件系统还没做），但做事件的时候一定会踩：

```csharp
// ❌ 边患：税库 150 时减 250 → −100
if (d.treasuryGold >= 150) d.treasuryGold -= 250 * lawPct / 100;
// ✅
if (d.treasuryGold >= 150) d.treasuryGold = Math.Max(0, d.treasuryGold - 250 * lawPct / 100);
```

**所有扣资源的写法都要 `Math.Max(0, …)`。** 测试台里就是这条把税库扣成过 −229。
