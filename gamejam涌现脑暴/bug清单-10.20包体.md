## P1 · 逻辑问题

### B1 · 哭丧/厚葬只能看到“前面法槽”的击杀

**现象**：把「哭丧(60)」放在第 1 条、「减口(54)」或「刑戮(64)」放在第 2 条，第 2 条杀人后，哭丧在同一 tick 不会触发；下一 tick `DeathsThisTick` 已经归零，于是这次死亡**永远不会**被哭丧看到。

**原因**：`LawEngine.Tick` 按法槽 1→6 顺序结算；`deathsSeen` 只累加已经结算过的法条击杀。`LawCondKind.DeathsThisTick` 读的是当前累计值。同理，「厚葬(61)」也会漏掉后面法槽造成的死亡。

**实测**：2 个村民恐惧 70，其余 10；「哭丧(60) → 刑戮/逐客类(36)」顺序，平均恐惧 15.0→6.6；「36 → 60」顺序，15.0→10.6，差值正好是哭丧的 +4。

**影响**：死亡 → 恐惧 → 更多死亡的正反馈链在多数布局下断掉；两张死亡主题法条的实际价值取决于玩家把哪条法放在前面，而 UI 没有任何提示。

**修复建议**（二选一）：

1. 两阶段结算：先结算所有不含 `DeathsThisTick` 的法，再结算含 `DeathsThisTick` 的法；
2. 在 tick 末尾对 60/61 做一次后处理，用最终 `report.deaths` 再判定一次。

**验收**：法槽 1=哭丧、法槽 2=减口；减口杀 1 人后，哭丧在同一 tick 触发一次。

### B2 · 「赦令(49)」在全 0 强度时会废止第一个其他法

**现象**：所有法的 `lawStrength` 都是 0 时，赦令会选第一个“其他活跃法”并置 −100。新开局常见结果是直接废掉「济贫」或「耕作」；玩家只看到一句“『济贫』被赦令废止”，但并不知道为什么是它。

**原因**：`DisableStrongestLaw` 用 `strength` 取最大；全 0 时第一个槽位胜出。

**影响**：这是一条高威信（>90）才会触发的法，触发时往往已经进入中后期；误废粮源可能直接导致崩盘。是否“全 0 时应有动作”属于设计口径，需要产品确认。

**修复建议**：

- 若希望“没有最强法就不废”：全 0 时返回 null，不扣威信、不进冷却；或
- 若希望“总要废一条”：在事件文本里明确“没有强度最高的法，改废第 X 条”，并在法律选择界面给玩家预览。

## P2 · 健壮性 / 文案

### B3 · 主菜单的空引用兜底被删掉了一部分

10.20 包体把 10.19 修复版里的这些兜底删掉了：

- `MainMenuController.ResolveMissingReferences()` 整个方法；
- `OpenSlots` 里 `slotsTitle / slotsMessage / newSaveButton` 的判空；
- `GetDisplayedSlot` 里 `slots == null || slots.Length == 0` 的保护；
- `RefreshSlots` 里 `saveSlotUiBinding.meta / status / accent / deleteButton` 的判空；
- `RefreshSlots` 对 `slots` 的保护保留了一部分，但 `emptySlotsLabel` 被重复判空两次（无害）。

**实测**：在 10.20 包体上注入诊断日志后启动，`continue/new/load/settings` 全部为 true，`slots` 长度 5，5 个存档槽的 `primary/delete/title/meta/status/accent` 也全部为 true。**当前场景不会触发 NRE**，所以这条不是现存崩溃，而是**健壮性回退**：以后改场景、删按钮、换语言或复用到别的构建时容易复发。

**修复建议**：把 10.19 修复版的判空和 `ResolveMissingReferences` 合并回来；这些不改变玩法，只防崩溃。

### B4 · 流民法(17) 的卡面把“触发条件”和“被动移民条件”混在一起

当前卡面：

> 人口 < 60，每 240 tick（移民：人口 < 25 且粮仓 > 20）

实际逻辑：

- **法条触发**：人口 < 60 且 tick % 240 == 0 → 全体饥饿 −4；
- **被动移民**：每 2400 tick，人口 < 25 且粮仓 > 20 → 基础 +2，装流民法 +3。

括号里的“移民条件”不是这条法的触发条件，而是另一套 2400 tick 的被动规则。玩家容易读成“人口 <25 才触发减饥饿”。

**修复建议**：拆成两行：

```
触发：人口 < 60，每 240 tick（全体饥饿 −4）
附加：每 2400 tick，人口 < 25 且粮仓 > 20 时，移民 +2 → +3
```

### B5 · 医药(12) 卡面写成“瘟病”，事件里叫“疫病”

### B6 · 阴气(62)/香火(63) 的解锁提示与触发阈值差 1

- 阴气：解锁条件 `totalDeaths >= 20`，触发条件 `TotalGt(TotalDeaths, 20)` 即 **>20**。第 20 人死亡时法条出现，但第 21 人才开始触发。
- 香火：解锁 `>=1`，触发 `>1`；第 1 人死亡解锁，第 2 人起触发。

**建议**：要么把卡面/解锁提示写成“累计死亡 20 人后解锁，之后每次死亡触发”，要么把 cond 改成 `>=`。属于文案/口径问题。

### B7 · 赦令(49) 在没有可废目标时仍然扣 10 威信并进冷却

如果玩家只装了赦令（或其余法都已被废止），`DisableStrongestLaw` 返回 null，但 `Add(Prestige, −10)` 仍然执行，冷却 240 tick 也照常进入。

**建议**：没有目标时跳过整条法（不扣威信、不进冷却），或在卡面写明“至少需要另一条活跃法”。

---

### B8 · 缓征(46)/整肃(47)/苛敛(45) 在没有目标法时仍会触发并进冷却

- 缓征：改税收/济贫强度；如果这两条都没装，`ModifyStrengthByLawId` 找不到目标，整条法是空转。
- 整肃：改医药/劳役；目标没装时同样空转。
- 苛敛：改税收/耕作；目标没装时空转。

**建议**：给这些法加 `HasLaw(target)` 条件，或在 UI 上标“需要先装 X”。目前它们会消耗一个法槽并周期性进入冷却，玩家会误以为“这条法没用”。

---

### B9 · 法改法只能寻址 law ID 0–15（结构性限制）

`ModifyLawStrength` / `DisableLaw` 把 `LawEffect.field`（0–15）直接当 law ID 用。当前 44–47 的目标都在 0–15 内（1/3/5/11/12），所以现在没问题；但以后新增的法（如 71 开垦、48 威权）**无法被任何法改法指定**。

**建议**：如果以后要做“强化开垦/威权”的法，需要给 `LawEffect` 增加一个独立的 `targetLawId` 字段，而不是复用 `field`。
