# 村民漫游范围：从出生点附近 → 整个村庄（给程序）

> **这是纯表现层的改动**，碰不到模拟层。
> ⚠️ 所以**测试台验不了它** —— 验收只能靠肉眼。见 §5。

---

## 0. 一句话

```
村民现在只在自己出生点 ±0.75 格 的范围内打转。
      ↓
改成：在「村庄范围内、可居住的地面上」自由走动。
面积从 1.5 × 1.5 格（≈2 格）变成 43 × 35 格（≈1500 格）—— 差约 700 倍。
```

**`patrolRange = (24, 16)` 是像素。** 而：

```
地图内容    3072 × 2048 px
一格        32 px（3072 / 96）
村庄范围    37 × 29 格  = 1184 × 928 px
```

**→ 村民实际活动范围 = 1.5 × 1.5 格 ≈ 村庄面积的 0.2%。**

---

## 2. 村庄范围在哪

`VillageMapGenerator.PlaceSpawns` 铺的是一个 **10 × 8 的网格**，中心在格子 (47, 31)：

```
x: 47 − 18 + j*4   (j = 0..9)  →  x ∈ [29, 65]   跨 37 格
y: 31 − 14 + i*4   (i = 0..7)  →  y ∈ [17, 45]   跨 29 格
```

80 个出生点全部落在这个矩形里。**这就是"村庄范围"。**

## 3. 改法

### ① `MapViewBinder`：预先算一份「可漫游格」清单

在 `Apply` 结尾（`_map` / `_terrain` 都已经就绪）：

```csharp
private int[] _roamTiles;      // 村庄范围内可居住的格子

private void BuildRoamTiles()
{
    _roamTiles = new int[0];
    if (_map == null || _map.spawnTiles == null || _map.spawnTiles.Length == 0) return;
    if (_terrain == null || _terrain.Length != VillageMap.TileCount) return;

    // 出生点的包围盒
    int minX = int.MaxValue, maxX = int.MinValue, minY = int.MaxValue, maxY = int.MinValue;
    for (int i = 0; i < _map.spawnTiles.Length; i++)
    {
        int x = _map.spawnTiles[i] % VillageMap.Width;
        int y = _map.spawnTiles[i] / VillageMap.Width;
        if (x < minX) minX = x;
        if (x > maxX) maxX = x;
        if (y < minY) minY = y;
        if (y > maxY) maxY = y;
    }

    // 向外扩 SpawnMargin 格，然后收集矩形内所有可居住格
    const int SpawnMargin = 3;
    minX = Mathf.Max(0, minX - SpawnMargin);
    maxX = Mathf.Min(VillageMap.Width  - 1, maxX + SpawnMargin);
    minY = Mathf.Max(0, minY - SpawnMargin);
    maxY = Mathf.Min(VillageMap.Height - 1, maxY + SpawnMargin);

    var list = new List<int>();
    for (int y = minY; y <= maxY; y++)
        for (int x = minX; x <= maxX; x++)
        {
            int t = y * VillageMap.Width + x;
            if (TerrainType.Habitable(_terrain[t])) list.Add(t);
        }
    _roamTiles = list.ToArray();
}
```

**★ 必须按 `Habitable` 过滤，不能直接用矩形。**
地图上有 191 格水 + 146 格冰；`Habitable` 排除了水(0)和冰(6)，留下草地/耕地/沙漠/荒地/雪。

> **`_roamTiles` 不会失效** —— 开垦和退化只在
> 草地(1) / 荒地(4) / 耕地(2) 之间转换，这三种都是 `Habitable`。
> 所以算一次就够，不用跟着 `terrainRevision` 重算。

### ② 暴露取目标点的 API

```csharp
private const int ChannelRoam = 7;      // ★ 通道 7 是空的（现有移动用 1 和 2）

public Vector2 GetRoamTarget(int index, int seed, int step)
{
    if (_roamTiles == null || _roamTiles.Length == 0 || mapContent == null)
        return Vector2.zero;
    int tile = _roamTiles[Rng.Range(seed, step, ChannelRoam, index, 0, _roamTiles.Length)];
    // 和 GetSpawnPosition 完全一样的换算
    int x = tile % VillageMap.Width;
    int y = tile / VillageMap.Width;
    return new Vector2(
        (((float)x + 0.5f) / VillageMap.Width  - 0.5f) * mapContent.rect.width,
        (0.5f - ((float)y + 0.5f) / VillageMap.Height) * mapContent.rect.height);
}
```

**均匀分布**：`Rng.Range(..., 0, _roamTiles.Length)` 在清单上均匀取样，
而清单本身是村庄矩形里逐格扫出来的 —— 所以**面积均匀**，不是"每个出生点均匀"。

### ③ `VillagerWalker`：改成向 binder 要目标

```csharp
// 新增字段
private MapViewBinder _mapBinder;

// BindRuntime 加一个参数
public void BindRuntime(int index, Vector2 homePosition, MapViewBinder binder,
                        int seed, float moveSpeed, Vector2 range)
{
    _mapBinder = binder;
    villagerIndex = index;
    randomSeed = seed;
    speed = moveSpeed;
    patrolRange = range;
    if (body == null) body = (RectTransform)transform;
    PlaceAt(homePosition);
}

private void ChooseTarget()
{
    _step++;
    if (_mapBinder != null)
    {
        Vector2 v = _mapBinder.GetRoamTarget(villagerIndex, randomSeed, _step);
        if (v != Vector2.zero)
        {
            _target = v;
            ClampToWalkArea();
            return;
        }
    }
    // 拿不到 binder 时保底走老逻辑
    int tick = _step * 97 + villagerIndex * 31;
    int num  = Rng.Range(randomSeed, tick, 1, -(int)patrolRange.x, (int)patrolRange.x + 1);
    int num2 = Rng.Range(randomSeed, tick, 2, -(int)patrolRange.y, (int)patrolRange.y + 1);
    _target = home + new Vector2(num, num2);
    ClampToWalkArea();
}

private void ClampToWalkArea()
{
    if (walkArea == null) return;
    Rect rect = walkArea.rect;
    _target.x = Mathf.Clamp(_target.x, rect.xMin + 40f, rect.xMax - 40f);
    _target.y = Mathf.Clamp(_target.y, rect.yMin + 55f, rect.yMax - 55f);
}
```

调用点（`EnsureActors:3576`）同步改：

```csharp
villagerWalker.BindRuntime(i, homePosition, _mapBinder, 1701 + i * 97,
                           VillagerSpeed(i), new Vector2(24f, 16f));
```

### ④ ★ 速度必须一起改（否则会变慢动作）

**这是最容易漏掉的一条。**

```
现在     3.2 – 6.0 px/s  =  0.10 – 0.19 格/秒
横穿村庄（37 格）需要     195 – 370 秒  ← 真机时间 3–6 分钟
```

范围放大 480 倍而速度不变的话，村民会变成**极慢地直线漂移**，比现在更难看。

```csharp
private float VillagerSpeed(int i)
{
    const float TilesPerSecond = 2.5f;                     // ★ 起点值，要目测调
    float pxPerTile = (mapContent != null && mapContent.rect.width > 0f)
                    ? mapContent.rect.width / VillageMap.Width
                    : 32f;                                  // 兜底
    return (TilesPerSecond + (i % 5) * 0.3f) * pxPerTile;   // 2.5 – 3.7 格/秒
}
```

**为什么用 2.5 格/秒**：

```
默认缩放 0.62（ComputeDefaultZoom 算出来的）
→ 屏幕可视区域 ≈ 45 格宽
→ 村民横穿一个屏幕 ≈ 18 秒
```

> **这个数只能目测。** 我给的 2.5 是"横穿一屏约 18 秒"倒推出来的起点值。
> 太快像瞬移，太慢像静止 —— **先按 2.5 做，跑起来再调一个数就行。**

## 4. ⚠ 一个已知的视觉问题

**村民是直线走向目标点的**（`Vector2.MoveTowards`），没有寻路。

从"出生点附近"改成"整个村庄"之后，单段路程变长，**直线更容易横穿水面**（地图 3% 是水）。

- **不处理**：偶尔有个村民走过一小段水面。可能能接受
- **要处理**：`GetRoamTarget` 里加一次视线检查（Bresenham 扫一遍直线上的格子，遇到水就重掷，最多试 3 次）

**建议先不处理**，跑起来看。真的显眼再加 —— 别在没看到问题之前就上寻路。

## 5. 验收

> ⚠️ **测试台验不了这个改动。** 它只抽了模拟层，不跑 `MonoBehaviour`。
> 这条只能**在真机/编辑器里肉眼看**。

**必须肉眼确认：**

- [ ] **村民散布在整个村子**，不再挤在出生点那一小撮
- [ ] **没有村民站在水里或冰上**
- [ ] 走进粮仓/房子/树的**视觉上不违和**（它们是装饰，没有碰撞）
- [ ] 速度看起来**像"在活动"**，不是瞬移也不是静止
- [ ] 人口 120 的时候**帧率没有明显下降**（120 个小人各自 `MoveTowards`，开销应该可忽略）
- [ ] 开垦让耕地变多之后，村民的活动范围**没有异常**（`_roamTiles` 不重算）

**可以断言的（打印一次确认）：**

```csharp
// BuildRoamTiles 末尾打一条
Debug.Log($"可漫游格 {_roamTiles.Length} / 村庄矩形 1505 格，"
        + $"每格 {mapContent.rect.width / 96f:F1} px");
// 期望：约 1450–1505 格（矩形 43×35 = 1505 格，扣掉少量水/冰）
```

**格数是怎么来的**（对不上就说明算错了）：

```
出生盒       x ∈ [29, 65] 37 格 · y ∈ [17, 45] 29 格  = 1073 格
外扩 3 格后  x ∈ [26, 68] 43 格 · y ∈ [14, 48] 35 格  = 1505 格
```
