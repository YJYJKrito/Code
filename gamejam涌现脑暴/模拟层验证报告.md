## 1. ★ 一号问题：`population * 2` 让律法完全失效 ★

### 1.1 病灶

`VillageLifecycleService.AdvanceGranary`

```csharp
int num4 = population * 2 + val;   // 产出
int num5 = population / 3;         // 消耗
data.granaryFood += num4 - num5;   // 净 = +5pop/3
```

**净产出是人口的 1.67 倍，粮仓永远顶死在上限。**

连锁反应

```
粮仓永远满
  → 每 56 tick 把每个村民的个人存粮补到 12
  → 饥饿永远是 0
  → 所有读饥饿的法（济贫、减口、多数新法）条件永不成立
金币被吃光后永远是 0
  → 税收的条件 gold > 60 永不成立
```

### 1.2 对照实验

同一份代码，**只改这一行**，跑 300 seed × 5 年：

| 产出 | 默认法存活 | 不作为存活 | 好法存活 | 恶法存活 |
|---|---|---|---|---|
| **200%（当前）** | 25.5 | **26.1** | — | 7.2 |
| 150% | 26.3 | 22.9 | — | 5.8 |
| 120% | 20.2 | 10.1 | **48.2** | 4.3 |
| 100% | 19.9 | 7.8 | 24.6 | 4.2 |
| 80% | 14.5 | 0.3 | 22.7 | 0.0 |

**当前值下「装法 25.5」和「完全不装法 26.1」没有区别——律法组成了装饰品。** 不作为甚至比装法还高。

### 1.3 修正

```diff
- int num4 = population * 2 + val;
+ int num4 = population * 120 / 100 + val;
```

**为什么是 120%。** 30 年跨度的标定曲线：

| 产出 | 好法 | 默认 | 不作为 | 恶法 | 好−不作为 |
|---|---|---|---|---|---|
| 90% | 22.7 | 18.4 | **0.0**(12/12 灭村) | 0.0 | 22.7 |
| 100% | 24.6 | 19.9 | 7.8 | 4.2 | 16.8 |
| 110% | 32.7 | 20.2 | 8.7 | 3.9 | 24.0 |
| **120%** | **48.2** | **20.2** | **10.1** | **4.3** | **38.1** |
| 130% | 53.2 | 21.1 | 13.1 | 4.8 | 40.1 |
| 140% | 58.9 | 21.2 | 16.8 | 5.7 | 42.1 |

**90% 太苛刻**（不作为必灭，没有容错），**140% 开始逼近人口上限且好法一家独大**。**120% 的阶梯最分明。**

### 1.4 我踩过的坑，写下来免得别人再踩

我第一次试的是 **80%**，5 年数据看着很好（律法分得很开）。但跑 **30 年**才发现那是个 **subsistence 陷阱**：

```
tick │存活│ 粮仓 │均饥饿│均存粮│能生者│生育
   1 │  24│   220│    23│    25│     8│   0
 401 │  31│    39│     0│     4│     0│   8   ← 8 个生育爆发后彻底停止
4000 │  25│     7│    40│     0│     0│   8
```

**粮仓常年为 0 → 个人存粮归零 → `CanGiveBirth` 的 `food >= 2` 永不成立 → 零生育**；同时饥饿卡在 40 到不了 99 → **也零饿死**。村子冻结 27 年，只有老死缓慢减员。

**这个陷阱在 5 年尺度上看不出来。** 任何调参都该用 30 年跑。

## 2. 修正后的结果

### 2.1 律法阶梯（200 seed × 5 年）

| 律法组合 | 存活 | 灭村 | 年均死 | 死因分布 |
|---|---|---|---|---|
| 好法 济贫/耕作/税收/幼童/医药 | **34.2** | 0.0% | 1.9 | 夭折 92% 寿终 7% |
| 默认（开局自带）济贫/耕作/税收 | 24.2 | 0.0% | 2.5 | 夭折 91% 寿终 8% |
| 只装 济贫 | 23.2 | 0.0% | 1.7 | 夭折 87% 寿终 12% |
| 恶法 税收/劳役/丁税 | 16.7 | 0.5% | 4.5 | 夭折 61% **饥饿 35%** |
| 不作为（无法状态） | 13.0 | 0.0% | 4.1 | **饥饿 53%** 夭折 43% |
| 恶法 饥则抢/阋墙/夺产 | 9.1 | 7.5% | 4.9 | **惊吓 57%** 夭折 37% |
| 恶法 减口/弃老 | 5.9 | 0.0% | 5.2 | **律法 68%** 饥饿 18% |
| 恶法 恐惧/私刑/连坐 | **3.3** | 13.5% | 5.6 | **惊吓 65%** 夭折 23% |

**从 3.3 到 34.2，跨越十倍。而且每条律法路线都产生了它该产生的死因**——这是最能说明问题的一处：

- 不装济贫 → **饥饿**成为主死因（53%）
- 恐惧系恶法 → **惊吓**成为主死因（65%）
- 减口/弃老 → **律法本身**直接杀死 68%

### 2.2 结局梯度（56 种 8选5 组合 × 25 seed）

```
均值 18.8   σ 6.0   档位 16   最小 4.4   最大 24.4
两极（0 或 ≥48）占比 0%
```

**σ 6.0 / 均值 18.8，16 个档位，两极占比 0%。** 比我之前在参考实现里调出来的（σ 7.2、15 档位、12% 两极）还要干净——**完全没有两极**。

### 2.3 老死分布

```
寿终中位 83–84 岁（各组合一致）
```

对应 `OldAgePercent` 的 `(age-60)²×100/3500` 封顶 20%。**实现是对的。** 中位略高于目标 80，可接受。

## 3. 仍存在的问题

### 3.1 68 条可换法里 52 条是装饰

基准 = 济贫 + 耕作（存活 24.2），逐条加一条法测位移：

```
载荷 10 · 弱 6 · 装饰 52

载荷法（全部是减益）：
  #51 常平      -24.20      #60 哭丧     -22.23
  #53 丁税宏观   -20.39      #42 老权     -19.85
  #54 减口      -13.93      #41 丁役     -10.05
  #58 光棍       -9.44      #55 绝户      -5.14
  # 4 恐惧蔓延    -4.01      #62 阴气      -3.43
```

**这是一个结构性的不对称：能测出来的法全是"减益法"。**

原因不是这些增益法写得不好，而是**基准已经贴近天花板**——济贫+耕作 24.2，而 5 条法的最好组合也才 34.2。增益法能加的空间只有约 10 点，分到每一条法上就落到噪声里。

**换句话说：现在的村庄是"能活，但没有富余"。** 增益类法需要"村庄还能显著变好"的空间才测得出来。

### 3.2 生育率偏低

120% 下 30 年累计生育 56（好法）到 13（不作为）。理论上 12 个育龄女性 × 30 年 ÷ 480 tick 冷却 = 上千次机会。

实际偏低的原因还是**个人存粮**：`CanGiveBirth` 要求 `food >= 2`，而 `AdvanceGranary` 的分粮条件是 `granaryFood > population`——**只有公仓宽裕时才分粮**。人口一多，这条线就越不过去。

### 3.3 两套律法系统并存

**60 条法走 `LawEngine`（数据驱动的 `conds`/`effects`），10 条老法仍是硬编码的 if 分支。**

`LawEngine.Tick` 会 `continue` 跳过没有 `effects` 的法，所以**不会双跑**。但代价是：

- 那 10 条法**无法参与守卫条件、无法被 `DisplayLaw` 类 UI 反查"当前影响了谁"**
- 两套系统并存意味着**两套都要维护**

### 3.4 一处死代码

```csharp
data.villagerBirthCooldown[i] = (Traits.HasInnate(data, i, 256u) ? 480 : 480);
//                                                             ↑ 两个分支一样
```

「多产」这个先天词条没有生效。

### 3.5 三处没接上 / 没做

| 项 | 状态 |
|---|---|
| `Innate.Generous`（慷慨） | **0 次读取** |
| `Mark.Bitter`（积怨） | 0 次读取 |
| `arableCount`（地图可耕地） | 算了但**全项目零引用**——地图仍是纯装饰 |
| 村民角色 | 仍是场景手摆（`FindObjectsOfType<VillagerWalker>`），80 个要手动摆 |

## 4. 建议（按优先级）

| 优先级 | 动作 | 依据 |
|---|---|---|
| **P0** | `population * 2` → `population * 120 / 100` | §1，单行改动，律法从无效变成主导 |
| **P0** | 改完**用 30 年跑一次回归** | §1.4，5 年尺度会漏掉 subsistence 陷阱 |
| **P1** | 放开分粮条件：`granaryFood > population` 改成更宽松的阈值 | §3.2，直接决定生育率 |
| P2 | `? 480 : 480` 改成 `? 360 : 480` | §3.4 |
| P2 | 把 10 条老法迁到 `LawEngine` | §3.3，消除双系统 |
| P3 | 给 `慷慨` 接上实现（金币 > 50 时向最穷者转移 3） | §3.5 |
| P3 | 逐条复核 52 条装饰法，能补则补，不能补就删 | §3.1 |

> **P0 的两条是一体的。** 改参数不难，难的是**知道要用 30 年去验**——5 年尺度上 80% 看着是"最佳值"。
