# 开垦机制重做：优先开荒 · 双倍粮 · 花税库金币（给程序）

> **所有数值都是跑出来的。** 测试台：`测试台/`，12–15 种子 × 30 年。
> 前置阅读：《耕地荒地机制体检》（问题）、《三个资源接通》§2（税库进项）。

---

## 0. 一句话

```
现状：荒地 743 格，30 年只被开垦掉 20 格 —— 因为 FindFrontierTile 不区分草地和荒地，
      而草地是荒地的 5 倍，所以它永远先挑到草地。

改法：优先挑荒地 + 荒地粮食成本翻倍 + 都花税库金币 + 耕地扩到开局 3 倍就停。
实测：荒地 30 年被开垦掉 112 格（15%），其中开荒占一半。
```

---

## 1. 病根：不是够不着，是没被挑中

实测（8 个种子）：**荒地距离最近农田全部 = 1 格**，可开垦的荒地一直存在（年1 有 37 格，年30 有 55 格）。

```csharp
// 现在的 FindFrontierTile：只看"是不是可开垦"，不看是草还是荒
if (TerrainType.Tillable(data.terrain[i]))   // 草地 1 和荒地 4 都算
{
    ... 四邻有耕地就返回 ...
}
```

**草地 3919 格、荒地 737 格。行优先扫描几乎永远先撞到草地。**

→ **一行都不改的话，荒地永远轮不上。**

## 2. 改法

### ① 优先开垦荒地

`FindFrontierTile` 拆成两遍：**先找荒地，找不到再找草地**。

```csharp
public static bool TryTill(VillageSaveData data)
{
    if (!HasLaw(data, 71)) return false;

    // ★ 先荒地，再草地
    int kind = 4;
    int num = FindFrontierTile(data, 4);
    if (num < 0) { kind = 1; num = FindFrontierTile(data, 1); }
    if (num < 0) return false;

    int costGrain = (kind == 4) ? TillCostWaste : TillCostGrass;   // 30 / 15
    int costGold  = (kind == 4) ? TillGoldWaste  : TillGoldGrass;  //  4 /  2
    if (data.granaryFood  < costGrain) return false;
    if (data.treasuryGold < costGold)  return false;

    // ★ 扩到开局耕地的 3 倍就停
    if (CountFarmland(data) >= data.arableBaseline * 3) return false;

    data.terrain[num] = 2;
    data.granaryFood  -= costGrain;
    data.treasuryGold -= costGold;
    data.terrainRevision++;
    return true;
}

private static int FindFrontierTile(VillageSaveData data, byte kind)   // ★ 多一个参数
{
    int num = 96, num2 = 64;
    for (int i = 0; i < data.terrain.Length; i++)
    {
        if (data.terrain[i] != kind) continue;      // ★ 只要这一种地形
        ... 原来那套四邻判断 ...
    }
    return -1;
}
```

> ⚠️ **尺寸是 96 / 64**（地图已经放大过），`num`/`num2` 别写回 48/32。

### ② 常量

```csharp
public const int TillCostGrass = 15;   // 草地：粮
public const int TillCostWaste = 30;   // 荒地：粮 = 草地的 2 倍
public const int TillGoldGrass = 2;    // 草地：税库金币
public const int TillGoldWaste = 4;    // 荒地：金币也是 2 倍
public const int TillArableMult = 3;   // 耕地上限 = 开局基线 × 3
```

### ③ ★ 必须先做：《三个资源接通》§2 的税库进项要**加强**

原方案是 `每 2400 tick += 人口/8`（30 年约 180 金币）。**加了开垦费之后不够用**：

| 税库进项 | 30 年总进账 | 末税库 | 荒地减少 | 开垦次数 |
|---|---|---|---|---|
| 每 2400t +人口/8（原案）| ≈180 | **1** ← 榨干 | −60 | 97 |
| 每 2400t +人口/4 | ≈360 | 8 | −110 | 224 |
| **每 2400t +人口/2** | **≈720** | **636** | **−112** | **288** |

→ **改成 `每 2400 tick += 人口/2`。**

## 3. 实测结果（推荐档）

**进项 每 2400t +人口/2 · 草地 15 粮 2 金 · 荒地 30 粮 4 金 · 上限 3 倍**

| | 改前 | **改后** |
|---|---|---|
| 30 年末耕地 | 164（且是最后 10 年才涨上去）| **225**（= 基线 × 2.7）|
| 30 年末荒地 | 723 | **631** |
| **荒地 30 年被开垦** | **20 格** | **112 格** |
| 开垦次数 | 153 | 288 |
| **其中开荒（荒地）** | 极少 | **145 次（一半）** |
| 末税库 | 48（恒定）| 636 |

**逐年轨迹（荒地 743 → 631，是一条持续下降的曲线，不是突然塌）**

**平衡**：7 个法条组全部正常，不装法 10 人、开垦系 121 人 —— **和改之前一样**。

## 4. ⚠ 两个实测出来的反直觉结论

**① 粮食成本（15 / 30）实际上不构成约束。**

| 草地粮 / 荒地粮 | 荒地减少 | 开垦次数 |
|---|---|---|
| 15 / 30 | −112 | 288 |
| 10 / 20 | −112 | **288** |

**完全一样。** 因为粮仓一直不缺粮（产出 > 消耗），15 和 30 都付得起。

> **"荒地双倍粮"这条规则可以留着（叙事上说得通），但要清楚它现在不减慢任何东西。**
> 真正的约束是**金币**和**耕地上限**。

**② 金币成本在 0–2 之间对开垦量几乎没有影响。**

| 草地金 / 荒地金 | 荒地减少 | 末税库 | 税库到 60 的年份 |
|---|---|---|---|
| 0 / 0 | −112 | 1523 | 第 3 年 |
| **1 / 2** | −112 | 1079 | **第 10 年** |
| **2 / 4** | −112 | **636** | **第 20 年** |
| 3 / 6 | −111 | 257 | 第 27 年 |

**选 2 / 4 的理由**：它不减少开垦量，但把税库从"没用"变成"要攒"——
**稀有法（40 / 60 金币）变成第 20 年前后才买得起的中期目标**，而不是开局就有。

> 如果你希望稀有法早点能买，用 **1 / 2**（第 10 年）。
