# 自然老死 · 实现方案

> **目标**：自然老死的人平均寿命 **80 岁**；死亡概率**封顶 20%**、**没有"超过多少岁必死"**；判定**每年一次**。
> **下面是模拟出来的数据**（150 万样本），不是估算。

---

## 1. 现状。问题不在均值

```
【现状】75 岁起 / 每 60 tick 检查一次

均值 75.4    p10=75    p50=75    p90=76
```

| 指标 | 值 | 说明 |
|---|---|---|
| 均值 | 75.4 | 离 80 不算远 |
| **p10 到 p90** | **75 到 76** | ★ **这才是问题** |

**所有人的死亡年龄挤在同一年里。** 玩家会看到一波集体倒下，而不是一代人自然更替。**均值只是表象，分布宽度才是这个函数的质量。**

---

## 2. 根因。检查频率错了 23 倍

```
ResolveOldAge 每 60 tick 跑一次
1 年 = 2400 tick  →  一年检查 40 次
Rng.Chance(seed, tick, channel, percent) 的粒度是整数百分比
```

75 岁那一档代码写的是 `3 + (age - 75)`，即"每次检查 3%"。而**实际年死亡率**是

```
1 − (1 − 0.03)^40 = 70%
```

**名义值 3% 和实际年死亡率 70% 差了 23 倍。** 这就是全部问题。

80 岁那档写 `100`，被 `Math.Min(50, ...)` 钳成 50 —— 实际年死亡率 `1 − 0.5^40 ≈ 100%`。

### 修法

> **改成每人每年检查一次**，放在他生日那天。

`AdvanceAge` 里已经有生日检测（`ageTicks >= 2400` → `age++`），把判定挂在那里。**一年一次之后，整数百分比的粒度正好是"每年百分之几"，曲线才可能平滑。**

---

## 3. 曲线的形状。三种形态的实测对比

| 形态 | 参数 | 均值 | p10 | p50 | p90 | 过90 | 过100 | 过110 |
|---|---|---|---|---|---|---|---|---|
| **二次封顶** | **D=35 cap20** | **80.2** | **72** | **80** | **89** | **8.7%** | **0.94%** | **0.098%** |
| 二次封顶 | D=30 cap20 | 79.2 | 71 | 79 | 87 | 6.4% | 0.70% | 0.074% |
| 二次封顶 | D=40 cap20 | 81.1 | 72 | 81 | 90 | 11.3% | 1.21% | 0.128% |
| 有理饱和 | H=16 cap20 | 75.0 | 65 | 73 | 88 | 7.7% | 1.87% | 0.395% |
| 指数饱和 | k=0.10 cap20 | 70.5 | 63 | 69 | 79 | 1.2% | 0.14% | 0.017% |
| 二次**无**封顶 | div=3400 | 80.0 | 72 | 89 | — | 7.6% | 0.10% | 0.000% |

**结论：用二次曲线封顶 20%。**

- **有理饱和和指数饱和都被否掉**。它们在低龄段爬得太快，均值只有 70 到 75，而且 p10 掉到 63 到 65 —— 一群人六十出头就死，那是病不是老
- **无封顶版**均值也能到 80，但它是靠"到某个年龄必死"来清尾巴的。**你要的不是这个**

### 封顶带来的代价，要如实说

| | 无封顶 div=3400 | **封顶 20% div=3500** |
|---|---|---|
| 均值 | 80.0 | 80.2 |
| p10 / p50 / p90 | 72 / 80 / 89 | 72 / 80 / 89 |
| 过 90 | 7.6% | 8.7% |
| **过 100** | **0.10%** | **0.94%** |
| 过 110 | 0.000% | 0.098% |

**均值和分位数几乎一样，但 100 岁以上的比例涨了约 10 倍。**

这是"去掉必死年龄"的直接代价——**没有硬上限，就必然有长尾**。

150 万样本里观测到的**最大年龄是 145 岁**（发生概率约千万分之一）。游戏里一个村子几十人、跑几十个游戏年，**实际碰不到这个量级**。但数学上确实没有上限，这一点要接受。

## 4. 最终函数

```csharp
private const int OLD_AGE_ONSET = 60;    // 从这个年龄开始有自然死亡
private const int OLD_AGE_DIV   = 3500;  // 调它 = 调平均寿命
private const int OLD_AGE_CAP   = 20;    // ★ 年死亡率上限，永远不达到必死

/// <summary>自然老死的年死亡率（百分数）。只在生日那天判定一次。</summary>
private static int OldAgePercent(int age)
{
    if (age < OLD_AGE_ONSET) return 0;
    int d = age - OLD_AGE_ONSET;
    int p = d * d * 100 / OLD_AGE_DIV;
    return p > OLD_AGE_CAP ? OLD_AGE_CAP : p;
}
```

### 这条曲线长什么样

| 年龄 | 60 | 65 | 70 | 75 | 80 | 85 | 90 | 95 | 100 | 105 | 110 | 115 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| **年死亡率** | 0% | 0% | 2% | 6% | 11% | 17% | **20%** | **20%** | **20%** | **20%** | **20%** | **20%** |

**90 岁封顶，之后永远是 20%。** 也就是任何年龄都有 80% 的概率再活一年——**没有必死的那一天。**

### 实测分布（150 万样本）

```
均值 80.2    p10=72   p50=80   p90=89   p99=99

  60-69 岁死   4.9%
  70-79 岁死  43.0%    ← 主力
  80-89 岁死  43.4%    ← 主力
  90-99 岁死   7.8%
 100-109 岁死  0.84%
 110 岁以上    0.10%
```

**86% 的人死在七十或八十岁。** 这才是寿命分布该有的样子。

### 调参口诀

| `OLD_AGE_DIV` | 均值 | 过90 | 过100 |
|---|---|---|---|
| 2500 | 78.1 | 4.6% | 0.50% |
| 3000 | 79.2 | 6.4% | 0.70% |
| **3500** | **80.2** | **8.7%** | **0.94%** |
| 4000 | 81.1 | 11.3% | 1.21% |
| 5000 | 83.0 | 19.0% | 2.12% |

**DIV 变大 = 人活得更久。** `OLD_AGE_CAP` 一般不要动；要动的话注意**它压得越低，尾巴越粗**（因为高龄段死亡率被削了）。

## 5. 代码怎么改

### 5.1 `AdvanceAge` 改成返回"是否生日"

```csharp
// ── 原 ──
private static void AdvanceAge(VillageSaveData data, int index)
{
    data.villagerAgeTicks[index]++;
    if (data.villagerAgeTicks[index] >= TicksPerYear)
    {
        data.villagerAgeTicks[index] = 0;
        data.villagerAges[index]++;
    }
    if (data.villagerBirthCooldown[index] > 0) data.villagerBirthCooldown[index]--;
}

// ── 改 ──
private static bool AdvanceAge(VillageSaveData data, int index)
{
    data.villagerAgeTicks[index]++;
    bool birthday = false;
    if (data.villagerAgeTicks[index] >= TicksPerYear)
    {
        data.villagerAgeTicks[index] = 0;
        data.villagerAges[index]++;
        birthday = true;
    }
    if (data.villagerBirthCooldown[index] > 0) data.villagerBirthCooldown[index]--;
    return birthday;
}
```

### 5.2 `SimulateTick` 里的调用点

```csharp
// ── 原 ──
if (data.villagerAlive[i])
{
    AdvanceAge(data, i);
    if (data.villagerHunger[i] >= 99) { KillVillager(data, i, "饥饿", ...); report.deaths++; }
    else if (data.villagerFear[i] >= 99) { KillVillager(data, i, "惊吓", ...); report.deaths++; }
    else AdvanceNeeds(data, i, tick, population);
}

// ── 改 ──
if (data.villagerAlive[i])
{
    bool birthday = AdvanceAge(data, i);
    if (data.villagerHunger[i] >= 99) { KillVillager(data, i, "饥饿", ...); report.deaths++; }
    else if (data.villagerFear[i] >= 99) { KillVillager(data, i, "惊吓", ...); report.deaths++; }
    else if (birthday && RollOldAge(data, i, tick)) { report.deaths++; }
    else AdvanceNeeds(data, i, tick, population);
}
```

**顺序是有意的。** 饿死和吓死排在被老死前面——一个已经饿到 99 的人，死因不该记成"寿终"。

### 5.3 判定函数

```csharp
private static bool RollOldAge(VillageSaveData data, int i, int tick)
{
    int p = OldAgePercent(data.villagerAges[i]);
    if (p <= 0) return false;

    // 医药法：降低自然死亡率
    if (HasLaw(data, 12)) p -= 5;
    // 劳损烙记：提前衰老（见 词条系统），把起龄从 60 挪到 53
    // if (HasMark(data, i, Mark.Worn)) p = OldAgePercent(data.villagerAges[i] + 7);

    if (p < 1) p = 1;
    if (p > OLD_AGE_CAP) p = OLD_AGE_CAP;      // ★ 修正项也不能突破上限

    if (!Rng.Chance(data.rngSeed, tick, CH_OLDAGE, i, p)) return false;

    KillVillager(data, i, "寿终", -1);
    return true;
}
```

**新增一个 Rng channel**

```
CH_OLDAGE = 5400
```

> ⚠️ **channel 号不能和现有的撞。** 现在代码把 `1000+i` / `2000+i` / `3000+i` / `4000+num` 当 channel 用，5400 是安全的。
>
> **`KillVillager(..., lawIndex: -1)` 里的 −1 要保留。** 老死不该归因到任何一条法，讣告会走那个分支写出「没有一条明确的法律能替他负责」。**这正是这个游戏该有的态度**——自然的死不该算到玩家头上，那样反而稀释了「他们死于你写的法律」这句话的分量。

### 5.4 要删掉的

- `ResolveOldAge` 整个方法
- `SimulateTick` 里 `if (tick > 0 && tick % 60 == 0) { ResolveOldAge(...) }` 那一段

## 6. 要一起接进去的修正

| 修正 | 怎么改 | 来源 |
|---|---|---|
| **医药法（law 12）** | `p -= 5`，**并且受 `OLD_AGE_CAP` 约束** | 现有法，见下 |
| **劳损烙记** | 判定时用 `age + 7`，等于提前 7 年进入老龄段 | `词条表.md` 的 `Mark.Worn` |
| **强健 / 病弱** | `p = p * 85 / 100` / `p = p * 115 / 100` | 词条系统，可选 |

> ⚠️ **医药法那条要单独说。** 原来它减的是"每 60 tick 的 3%"，一年 40 次，**实际效果很大**。改成"每年减 5%"之后弱了非常多。
>
> 从 §4 的表能看出，`DIV` 从 3500 涨到 5000（相当于把人活得更久）才让过 90 的比例从 8.7% 涨到 19%。**所以医药法这一点修正的值要按实测调，不能拍脑袋。**
> **改完单独测一次"有医药法"和"没医药法"的平均寿命差**，目标是差 3 到 5 岁。

## 9. 一句话

> **问题不是曲线形状，是检查频率。一年查 40 次、每次用整数百分比，等于把名义死亡率放大了 23 倍。**
>
> **改成生日那天查一次，再封顶 20%，就得到一条没有必死年龄、均值 80 的曲线。**
> **代价是尾巴——约 1% 的人能活过 100。这是"不许有必死年龄"必然换来的东西。**
