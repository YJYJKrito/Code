# 突发事件 · 实现方案 — 给程序

> **一句话**：14 个事件不该是「给玩家读的故事」，是「**给玩家一个提前知道、然后去改法的机会**」。
>
> 全部结论来自测试台：40 种子 × 30 年，触发层 / 效果层 / 职业修正 / 对口法律都单独测过。
> 本文档只写**怎么做**；为什么这么设计看《突发事件与职业-设计》。
>
> **配套文档**：《职业烙记-实现方案-给程序》（职业的获取条件）。

---

## 0. 做之前必须先知道的三件事

### 0.1 前置：《三个资源接通》—— **已经落地**，还剩三处增量

5 / 14 的事件（贪墨 / 匪患 / 大赦，以及半个边患 / 名医）**只动资源**。
在税库、威信、恐惧接通之前，它们玩家看不见 —— 等于白做。

**旧方案已经改完**；落地后重测发现三处数值没到位（恐惧改过头、税库不够、威信没压住），
增量改动见《**三个资源接通-实现方案-给程序**》（×70 / 人口÷3 / 威信软上限）。
**先把那三处改完，再做事件。** 否则事件的权重和折扣都建立在不对的数值上。

**顺序：三个资源增量 → 事件 → 职业 → 兆头期 UI。**

### 0.2 用「权重」，不要用「条件」

**第一版写的是条件门槛，14 个里 9 个永不触发。** 原因：

- 开垦系玩法里「平均饥饿」**恒为 0**
- 税库在修好之前**恒为 0**
- 「最高恐惧」三组**恒为 30**（那是词条基准值，不是状态）

**任何绝对值门槛，必然在某种玩法下恒不成立。**
所以：**每个事件永远可抽（权重恒 ≥ 1），只是权重随状态变。**

### 0.3 粮仓伤害必须**按比例**扣

第一版用绝对值（蝗灾 −150），结果粮仓常年只有 40：
`max(0, 40−150)` 和 `max(0, 40−75)` **都是 0** —— 折扣完全没意义。

改成「扣当前粮仓的 60%」之后才有效。**正面事件同理**：补向**容量**的 35%，不是补 +120。

```csharp
public sealed class EventDef
{
    public int    id;
    public string name;          // 「蝗灾」
    public string omen;          // 兆头：「北边的蚂蚱比往年多。」
    public string burst;         // 爆发：「蝗群落下。半年的粮没了。」
    public int    cooldownTicks; // 冷却 tick 数（1 年 = 2920）
}

public static class EventTable
{
    public const int Count = 14;
    public static readonly EventDef[] Defs = { /* 名字 / 文本见 §9，冷却见 §4.1 */ };
}
```

**效果不用建表，用 `switch`。** 因为律法的 `LawEffect` DSL 表达不了
「杀最年轻的 N 人」「加 N 个移民」「按比例扣粮」这三种操作，硬套要多加 3 种
effect kind，不如直接 switch 清楚。

## 2. 存档改动

```csharp
// ── 兆头期（必须存）──
public int[] omenEventIds   = new int[0];   // 挂着兆头的事件 id
public int[] omenBurstTicks = new int[0];   // 各自的爆发 tick
public int   omenCount;

// ── 冷却 ──
public int[] eventCooldownUntil = new int[14];   // 0 = 可抽

// ── 事件链 ──
```

`chainMobilize = chainPlague = 0`。

## 3. 触发循环

```csharp
// 每 1800 tick（225 天 ≈ 0.6 年）检查一次
if (tick > 0 && tick % 1800 == 0)
{
    // ① 先结算到期的兆头
    for (int k = omenCount - 1; k >= 0; k--)
        if (tick >= omenBurstTicks[k])
        {
            int e = omenEventIds[k];
            EventEffects.Burst(data, e);          // 效果结算（§5）
            eventCooldownUntil[e] = tick + Defs[e].cooldownTicks;
            RemoveOmen(k);                        // 顺序删除，不要用字典
        }

    // ② 再决定要不要挂新兆头
    if ((int)(Rng.For(data.rngSeed, tick, 62, 0) % 100) < 45)   // 45%
    {
        if (omenCount < 3)                        // HUD 最多刷 3 条
        {
            int e = PickWeighted(data);           // 见下
            if (e >= 0) AddOmen(e, tick + 2920);  // 一年后爆发
        }
    }
}
```

**`PickWeighted`：**

```csharp
int total = 0;
int[] w = new int[Count];
for (int e = 0; e < Count; e++)
{
    w[e] = Math.Max(1, Weight(data, e));
    if (tick < eventCooldownUntil[e]) w[e] = 0;      // 冷却中
    if (IsOmenPending(e))             w[e] = 0;      // 已经挂着兆头了，别抽两条
    total += w[e];
}
if (total <= 0) return -1;
int roll = (int)(Rng.For(data.rngSeed, tick, 61, 0) % (uint)total);
int acc = 0;
for (int e = 0; e < Count; e++)
{
    acc += w[e];
    if (roll < acc) return e;
}
return Count - 1;
```

**RNG 通道**：`61` = 抽事件，`62` = 判定是否触发。**这两个通道现在是空的，别被别人占用。**

## 4. 权重表（14 条，权重恒 ≥ 1）

`avgHunger` / `avgFear` = 全村存活村民的平均值；`pop` = 存活人数；
`poor` = 金币 < 10 的人数。

| # | 事件 | 权重公式 |
|---|---|---|
| 0 | 蝗灾 | `1 + avgHunger / 4` |
| 1 | 疫病 | `1 + pop / 15 + (tick < chainPlague ? 30 : 0)` |
| 2 | 边患 | `3`（定期） |
| 3 | 民变 | `1 + (300 − prestige) / 12 + avgFear / 3 + (tick < chainMobilize ? 60 : 0)` |
| 4 | 贪墨 | `1 + treasuryGold / 100` |
| 5 | 寒潮 | `3`（定期） |
| 6 | 匪患 | `1 + poor / 5` |
| 7 | 丰年 | `1 + max(0, 40 − avgHunger) / 4` |
| 8 | 商队 | `1 + treasuryGold / 60` |
| 9 | 乡绅 | `1 + prestige / 100` |
| 10 | 人口回流 | `1 + max(0, 50 − pop) / 10` |
| 11 | 名医 | `1 + treasuryGold / 80` |
| 12 | 大赦 | `1 + prestige / 120 + avgFear / 3` |
| 13 | 新生儿潮 | `1 + max(0, 15 − avgFear) / 3 + granaryFood / 600` |

> **新生儿潮除以 3 是故意的**：不降权时每局 4.3 次，太频繁（实测降到 1.7 次/局）。
> **事件链**：蝗灾 / 寒潮 会给 `chainMobilize` 续 2 年 → 民变频次 2.0 → 4.5 次/局（实测）。

### 4.1 冷却（⚠ 测试台没实现，是建议值）

```csharp
int[] cooldownTicks = { 8760, 1460, 8760, 2920, 8760, 8760, 8760,
                        5840, 5840, 5840, 8760, 8760, 8760, 8760 };  // 按事件 id
//                       蝗灾 疫病 边患 民变 贪墨 寒潮 匪患 丰年 商队 乡绅 回流 名医 大赦 新生
//                       3年 0.5年 3年  1年  3年  3年  3年  2年  2年  2年  3年  3年  3年  3年
```

**为什么民变 1 年、疫病 0.5 年：**
事件链是靠「灾后把民变/疫病的权重抬高」实现的，窗口分别是 2 年 / 1 年。
**如果冷却比窗口还长，链就被冷却自己挡掉了** —— 这是实现事件链时最容易踩的坑。

其余事件 3 年（丰年 / 商队 / 乡绅 2 年，因为它们是好事，来勤一点体验更好）。

## 5. 效果表（14 条）

### 先定义两个乘法因子

```csharp
int hpMul  = 村里有对应职业 ? 50 : 100;   // 职业修正：减半
int lawPct = LawScale(data, e);           // 对口法律：见 §7

// 恐惧 / 资源：可以为 0
int Scale(int v) => v * hpMul / 100 * lawPct / 100;

// 杀人：★ 整数截断保护 —— 只要不是「全免」，至少杀 1 个
int ScaleKill(int v) {
    if (lawPct <= 0) return 0;                    // 全免（兵役征召 / 雇佣护卫）
    int r = v * hpMul / 100 * lawPct / 100;
    return r < 1 ? 1 : r;
}
```

**两个因子叠加**（先职业 ×50%，再法律 ×50% → ×25%）。

### 14 条效果

| # | 事件 | 爆发效果 |
|---|---|---|
| 0 | 蝗灾 | `粮仓 -= 粮仓 × 60% × hp × law`；`chainMobilize = tick + 2年` |
| 1 | 疫病 | 杀死 **最年轻的** `Scale(5)` 人；全体恐惧 `+Scale(30)`；`chainPlague = tick + 1年` |
| 2 | 边患 | 若 `税库 ≥ 150` → `税库 -= 税库 × 50% × law`；**否则** 随机杀 `Scale(4)` 人 + 全体恐惧 `+Scale(25)` |
| 3 | 民变 | 随机杀 `Scale(5)` 人；`威信 -= 30` |
| 4 | 贪墨 | `税库 -= 税库 × 50% × hp × law`；`威信 -= 25` |
| 5 | 寒潮 | `粮仓 -= 粮仓 × 50% × law`；`chainMobilize = tick + 2年` |
| 6 | 匪患 | 全体恐惧 `+Scale(20)` |
| 7 | 丰年 | `粮仓 += (容量 − 粮仓) × 35% × law`（上限 = 容量） |
| 8 | 商队 | `税库 -= 50`；`粮仓 += (容量 − 粮仓) × 30% × law × (有粮商 ? 1.5 : 1)` |
| 9 | 乡绅 | `威信 -= (有职业 ? 15 : 30)`；`粮仓 += (容量 − 粮仓) × 25% × law` |
| 10 | 人口回流 | 加 `4 × law / 100 + (有徙民 ? 2 : 0)` 个移民 |
| 11 | 名医 | `税库 -= (有职业 ? 0 : 税库 × 30%)`；**夭折率 −50% 持续 1 年** |
| 12 | 大赦 | 全体恐惧 `-= (有职业 ? 40 : 30)`；`威信 -= 40` |
| 13 | 新生儿潮 | **出生率 ×1.5 持续 2 年**（占位实现：全体恐惧 −5） |

### 5.1 需要的三个工具函数

```csharp
// 杀最年轻的 N 个
public static void KillYoungest(VillageSaveData d, int n) {
    for (int k = 0; k < n; k++) {
        int pick = -1, bestAge = int.MaxValue;
        for (int i = 0; i < d.villagerAlive.Length; i++)
            if (d.villagerAlive[i] && d.villagerAges[i] < bestAge) { bestAge = d.villagerAges[i]; pick = i; }
        if (pick < 0) break;
        KillVillager(d, pick, "疫病", -1);
    }
}

// 随机杀 N 个（确定性：用 tick + k 做 seq）
public static void KillAny(VillageSaveData d, int n, int tick, string cause) {
    for (int k = 0; k < n; k++) {
        int alive = CountAlive(d);
        if (alive <= 1) break;                       // 不杀最后一个
        int pick = (int)(Rng.For(d.rngSeed, tick, 63, k) % (uint)alive);
        int seen = 0, victim = -1;
        for (int i = 0; i < d.villagerAlive.Length; i++) {
            if (!d.villagerAlive[i]) continue;
            if (seen == pick) { victim = i; break; }
            seen++;
        }
        if (victim >= 0) KillVillager(d, victim, cause, -1);
    }
}

// 加 N 个移民
public static void AppendImmigrants(VillageSaveData d, int n) {
    for (int k = 0; k < n; k++) AppendImmigrant(d);
}
```

> ⚠ **`KillAny` 的 `% alive` 依赖遍历顺序。** 必须按槽位顺序数（不要用字典/集合），
> 否则不同机器上结果不同，确定性就没了。

### 5.2 ⚠ 实测与建议的分界

下面三项**测试台里用的是绝对值，这里改成了按比例**——因为它们是同一个教训（§0.3）：

| 事件 | 测试台（绝对值） | **本方案（按比例）** | 为什么改 |
|---|---|---|---|
| 边患 | `税库 −250` | `税库 × 50%` | 税库常年 0–48，绝对值一扣就归零 |
| 贪墨 | `税库 −250` | `税库 × 50%` | 同上 |
| 名医 | `税库 −80` | 建议 `税库 × 30%` | 同上 |

**这三条没有在测试台里重新跑过**（税库本身还没接通）。

## 6. ★ 兆头期：这份设计里唯一真正新的东西

### 6.1 两段式

```
第 N 年    挂上兆头  →  HUD 出现一行：「北边的蚂蚱比往年多。」（只有文本，没有效果）
                       玩家此刻可以去改法槽
第 N+1 年  爆发      →  按**爆发这一刻**装着的法结算效果
```

**玩家的动词是「换法」—— 这个动词本来就存在（法槽随时能换），
只是之前没有任何理由用它。事件给了理由。**

### 6.2 实现要点

| 要点 | 说明 |
|---|---|
| 效果只在**爆发时**结算 | 兆头期不扣任何东西 |
| 效果按**爆发时**的法条算 | 玩家在兆头期换上去的法要生效 —— 这是全部的成就感来源 |
| 兆头列表必须存档 | 存档退出再进来不能丢 |
| 最多同时 3 条 | 防止 HUD 刷屏 |
| 同一事件不重复挂 | 正在挂兆头的事件不再被抽中 |
| 冷却 | 见 §4.1 —— **民变 / 疫病的冷却必须短**，否则事件链会被自己挡掉 |

### 6.3 HUD 文案（必须点名）

```
兆头：「北边的蝗虫比往年多。」               ← 玩家看到，去检查法槽

爆发（装了对口法）：「蝗群落下。你写的『耕作』保住了半仓粮。」
爆发（没装）     ：「蝗群落下。半年的粮没了。」
```

**这一条不做，事件就退化成「随机掉资源」，整个设计白做。**

### 6.4 ⚠ 兆头期**没有在测试台验证过**

测试台只能跑模拟层（数值、概率、效果），跑不了 UI 和时序。
**P2 做完必须在真游戏里人眼验一次：**

- 兆头出现后，粮仓/人口确实一点没变
- 玩家在兆头期换法之后，爆发伤害确实变了
- 存档退出再进来，兆头还在

这是整份设计里**唯一一个"做没做对只能靠人眼"**的部分。

## 7. 对口法律：让「你写的法律」直接改写事件结果

装了 → 效果乘一个百分比。**多条同时装 → 相乘。**

| # | 事件 | 减轻 / 增益 | 反向（加重） |
|---|---|---|---|
| 0 | 蝗灾 | 耕作 ×50% · 开垦 ×50% | — |
| 1 | 疫病 | 医药 ×50% · 公共卫生 ×40% | — |
| 2 | 边患 | 兵役征召 **×0%（全免）** | 威权 ×150% |
| 3 | 民变 | 安抚 ×50% · 济贫 ×70% | 连坐 ×150% |
| 4 | 贪墨 | 盐铁专卖 ×50% | — |
| 5 | 寒潮 | 屯粮 ×50% | — |
| 6 | 匪患 | 宵禁 ×40% · 雇佣护卫 **×0%** | 饥则抢 ×150% |
| 7 | 丰年 | 耕作 ×150% | — |
| 8 | 商队 | 平粜 ×150% · 售粮 ×150% | 盐铁专卖 ×60% |
| 9 | 乡绅 | 捐纳 ×150% | — |
| 10 | 人口回流 | 流民法 ×150% | — |
| 11 | 名医 | 医药 **×0%（免费）** | — |
| 12 | 大赦 | 祭祀 ×150% · 安抚 ×130% | — |
| 13 | 新生儿潮 | 婚育补贴 ×150% · 幼童口粮 ×130% | — |

```csharp
static readonly (int lawId, int pct)[][] LAW_MODS = {
    new[]{ (5,50),(71,50) }, new[]{ (12,50),(13,40) }, new[]{ (15,0),(48,150) },
    new[]{ (6,50),(1,70),(16,150) }, new[]{ (14,50) }, new[]{ (30,50) },
    new[]{ (10,40),(25,0),(2,150) }, new[]{ (5,150) },
    new[]{ (29,150),(31,150),(14,60) }, new[]{ (28,150) }, new[]{ (17,150) },
    new[]{ (12,0) }, new[]{ (35,150),(6,130) }, new[]{ (8,150),(9,130) },
};

static int LawScale(VillageSaveData d, int e) {
    int pct = 100;
    foreach (var (lawId, p) in LAW_MODS[e])
        foreach (var id in d.lawIds)
            if (id == lawId) { pct = pct * p / 100; break; }
    return pct;
}
```

**实测（隔离测试，只改装不装对口法）：5 / 6 正确生效。**
耕作让蝗灾 ×0.63，医药让疫病死亡 ×0.40，兵役征召让边患 ×0.00。

## 8. 职业修正：村里有对应的人 → 效果被改写

**只看「有没有 ≥ 1 人」，不看人数。**

| 事件 | 需要的职业（烙记） | 效果 |
|---|---|---|
| 蝗灾 / 丰年 | 耕者（**勤勉**词条） | 灾害 ×50% / 收益 ×150% |
| 疫病 / 名医 | 医师 | 死 5→1 / 免费 |
| 边患 / 匪患 | 游侠（**果决**词条） | 全免 / 无效 |
| 民变 / 乡绅 | 里正（恩主 `16384`） | 死 5→1 / 少亏 15 |
| 贪墨 | 账房（**节俭**词条） | ×50% |
| 寒潮 | 役夫（劳损 `1024`） | ×50% |
| 商队 | 粮商（暂用债户 `64`） | 收益 ×150% |
| 人口回流 | 徙民 `128` | +2 人 |
| 大赦 | 巫祝 `32768` | 恐惧再 −10 |
| 新生儿潮 | 稳婆（暂用绝户 `8`） | ×2 |

> **职业有两个来源**：烙记（后天的，见另一份文档）+ 先天词条（勤勉→耕者、果决→游侠、节俭→账房）。
> 两边都是现成的，不用新造。

### 8.1 ★ 为什么职业修正比事件量级更重要

40 种子实测，默认三法，基线末人口 37：

| | 无职业 | **有职业** |
|---|---|---|
| 灾害 ×1.0 | −9 | **−3** |
| 灾害 ×1.5 | −13 | **−4** |
| 灾害 ×2.0 | — | −6 |

**灾害从 ×1 加到 ×1.5 只多掉 4 人；「村里有没有医师」直接差 6 人。**
而且 **×1.5 + 无职业会灭村**（不装法、苛政两组最小人口都是 0）。

**所以：量级保持 ×1.0，不要 ×2。力气全花在职业上。**

| # | 事件 | 兆头 | 爆发 |

## 12. 验收清单

- [ ] 30 年里 14 个事件**每一个都触发过**（权重恒 ≥ 1，不该有死事件）
- [ ] 每局事件数 ≈ 20–25 次
- [ ] 兆头 → 爆发间隔约 1 年，期间粮仓/人口**一点没变**
- [ ] 在兆头期装上对口法，爆发伤害确实变小（蝗灾 ≈ ×0.5，边患 = 0）
- [ ] 村里有医师 → 疫病死亡明显变少
- [ ] 粮仓接近 0 时，蝗灾/寒潮**不会**扣成负数（按比例扣）
- [ ] 兆头期存档 → 读档 → 兆头还在，且按时爆发
- [ ] 事件文本里会出现玩家装的那条法的名字
- [ ] 同一事件不会连着来（冷却生效）
- [ ] 同一种子跑两遍，结果完全一致
