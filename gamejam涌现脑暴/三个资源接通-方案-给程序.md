## 0. 一句话

```
恐惧：那 10 条法条的门槛是 50/60/65/70/80/85，而恐惧实测 p99 = 41 → 全部永远不触发
税库：唯一进项依赖"村民金币 > 60"，而金币只减不增 → 30 年恒为 48，连 60 金币的稀有法都买不起
威信：收入随人口涨、维持费是固定值 → 人口涨上去之后收入碾压维持费 → 95% 顶在 300
```

**三条合计约 0.4 天。做完再往上加新机制。**

## 1. 恐惧：把 10 条法条的门槛砍一半

### 现状

恐惧的实测分布（556,190 个采样点）：

```
p50 = 5     p90 = 12     p95 = 27     p99 = 41     max = 93
```

而那 10 条"要多个人恐惧很高才触发"的法条用的是 **50 / 60 / 65 / 70 / 80 / 85** ——
**全部在 p99 之上。一条都不会触发。**

> 鸡生蛋：恐惧上不去 → 这些法条不触发 → 恐惧更上不去。

### 改法：门槛 × 0.5

| 法条 | 现在的条件 | **改成** |
|---|---|---|
| 35 祭祀 | 3 人恐惧 > 50 | **3 人恐惧 > 25** |
| 47 整肃 | 3 人恐惧 > 50 | **3 人恐惧 > 25** |
| 7 私刑倾向 | 自己恐惧 > 60 | **自己恐惧 > 30** |
| 37 立威 | 3 人恐惧 > 60 | **3 人恐惧 > 30** |
| 64 刑戮 | 3 人恐惧 > 60 | **3 人恐惧 > 30** |
| 34 诛心 | 3 人恐惧 > 65 | **3 人恐惧 > 32** |
| 18 起义豁免 | 3 人恐惧 > 70 | **3 人恐惧 > 35** |
| 22 瘟疫隔离 | 2 人恐惧 > 80 | **2 人恐惧 > 40** |
| 50 示众 | 3 人恐惧 > 80 | **3 人恐惧 > 40** |
| 36 逐客 | 3 人恐惧 > 85 | **3 人恐惧 > 42** |

**注意区别：有的判"自己"（SelfGt），有的判"有几个人"（CountGt）。人数不要动，只动后面的数值。**

### 实测效果

| 门槛 | 这 10 条里有几条开始有影响 |
|---|---|
| 原样（50/60/…/85）| **0 / 10** |
| ×70% | 3 / 10 |
| ×60% | 4 / 10 |
| **×50%** | **5 / 10** |
| ×40% | 5 / 10（没有更好）|

**×50% 是拐点** —— 再低不会更有效，只是让法条更容易乱触发。

### ⚠ 但只改门槛还不够

**恐惧的衰减是 −1/32 tick = −91/年**，而最强的无条件来源（连坐 +6，要求邻居本 tick 死）大约只能给 **72/年**。

**所以恐惧仍然爬不到 99。** 想让恐惧真能当"资源"用，还要动衰减或基准：

| 可选 | 现状 | 说明 |
|---|---|---|
| 衰减间隔 | 每 32 tick −1 | 改成 64 就是 −45/年，连坐的 72/年就能压过去了 |
| 个人基准 | 12（懦弱 30 / 果决 5）| 基准越高，衰减越早停下来 |

> **门槛先改（0.1 天），衰减等你确定新机制怎么用恐惧之后再定** —— 因为衰减速率取决于你希望恐惧涨多快。

## 2. 税库：加一条周期进项

### 现状

```csharp
// 唯一的进项（税收法 3）
if (tick % 240 == 0 && HasLaw(3) && villagerGold[index] > 60) {
    villagerGold[index] -= 12;  granaryFood += 3;  treasuryGold += 3;
}
```

村民金币 **只减不增**（`97 → 85 → 73 → 61 → 49`），低于 60 之后再也榨不出来；新生儿金币是 0。

**实测：30 年税库恒为 48。而稀有法要 60 / 40 金币 —— 贵的那条根本买不起。**

### 改法

```csharp
// SimulateTick 里，紧挨着生育那段
if (tick > 0 && tick % 2400 == 0)
{
    data.treasuryGold += VillageLifecycleService.CountAlive(data) / 8;
}
```

**周期复用 2400**（和退化、移民同一个节拍），数量按人口走。

### 实测：扫出来的档

| 周期 | 进项 | 30 年末 税库 最小/中位/最大 |
|---|---|---|
| 每 240 tick | 人口/16 | 517 / 787 / 951 ❌ 太宽裕 |
| 每 240 tick | 人口/32 | 158 / 405 / 423 ❌ |
| 每 240 tick | 人口/64 | 48 / 48 / 66 ❌ 等于没加 |
| 每 2400 tick | 人口/4 | 311 / 380 / 450 ❌ |
| **每 2400 tick** | **人口/8** | **164 / 206 / 244 ✅** |
| 每 2400 tick | 人口/16 | 94 / 121 / 137 ✅（更紧）|

**选「每 2400 tick + 人口/8」。**
设计目标：30 年攒到 100–300 —— **够买两条稀有法（40+60），但要等**。

> **`人口/16` 也可以**，看你想让稀有法多容易买到。

## 3. 威信：把维持费提上去，把恐惧项改成有符号

### 现状

```csharp
num8 = 人口 / 4 + Math.Max(0, 30 - 平均恐惧) / 10;
威信 = 威信 - 3 × 法条数 + num8;
```

**两个问题：**

**① 收入随人口涨，维持费是固定值 → 人口一大，收入碾压维持费**

人口 40–120 时 `人口/4` = **10–30**，而维持费最多 `3×6 = 18`。
→ 实测 **95% 的采样点顶在 300**。

**② 恐惧项是个常数，不是变量**

恐惧常年 6–23，**全在 30 以下**，所以 `max(0, 30−恐惧)/10` 恒为 **0–2**（对比人口项的 10–30）。
**"恐惧低 → 威信涨得快"这个设计意图，量级上完全没体现。**

### ★ 一个反直觉的实测结果（我先猜错了）

我一开始想"把恐惧项放大不就完了" —— **实测完全相反**：

| 恐惧项 | 顶 300 占比 |
|---|---|
| `max(0,30−恐惧)/10`（现状）| 76% |
| `max(0,30−恐惧)/2`（放大 5 倍）| **92%** ↑ 更糟 |
| `max(0,30−恐惧)/1`（放大 10 倍）| **98%** ↑ 更糟 |

**因为那是"收入"，放大它只是给威信加钱。**

### 改法

```csharp
// ① 维持费 3 → 4
// ② 恐惧项：从"永远为正的常数"改成"会摆动、能变负的量"
num8 = 人口 / 4 + (12 - 平均恐惧) / 2;
威信 = 威信 - 4 × 法条数 + num8;
```

`(12 − 平均恐惧) / 2` 的含义：**以恐惧的实际中位数（12）为基准线** ——
恐惧低于 12 加分，高于 12 减分。这样恐惧才真的推得动威信。

### 实测：扫出来的档

| 维持费 · 恐惧项 | 顶 300 占比 | 末威信 中位 |
|---|---|---|
| 现状：3/条 · max(0,30−恐惧)/10 | **76%** | 300 |
| **4/条 · (12−恐惧)/2** | **19%** | 300 |
| 4/条 · max(0,30−恐惧)/10 | 18% | 300 |
| 4/条 · (15−恐惧)/3 | 18% | 300 |

**★ 主杠杆是「维持费 3 → 4」**（76% → 18%）。恐惧项的形式对"顶不顶"影响不大，
但**只有有符号的形式能让恐惧真的推动威信** —— 所以两个一起改。

### 副作用（这是好事）

维持费 4/条之后：
```
3 条法 → 维持 12，人口 40 时收入 10  →  略亏
6 条法 → 维持 24，需要人口 ≥ 96 才养得起
```

**"装几条法"重新变成了一个要算的账。**
