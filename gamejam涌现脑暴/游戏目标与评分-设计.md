# 游戏目标 · 评分 · 通关条件 — 设计


> ⚠ **历史设计稿（30 年时代）**：当前是五十年 / 高压两种模式，评分与结束条件已变。机制以 [当前机制真实规格-修复版.md](当前机制真实规格-修复版.md) 为准；模式数值见 [两种模式-设计与数值.md](两种模式-设计与数值.md) 与 [回归对比-10.19修复.md](回归对比-10.19修复.md)。

> **先量，再定。** 这份文档里每个阈值都来自 20 种子 × 30 年 × 9 玩法的实测分布
> （180 局，见 §7），不是拍脑袋。
>
> 上一版设计被否掉的原因写在这里，避免再犯：**用威信当"治绩"** ——
> 实测威信是双峰的（p50=26，p90=272），它衡量的其实是「你装了几条法」，
> 不是治理水平。**恐惧更糟**（p50=6，p90=9，几乎没有区分度）。

---

## 0. 一句话

```
一局 = 三十年。
活到期满 → 通关。
然后给你两个数字、一个等级、一句谥号。
```

**评分只看两件事**：
- **存续**：这三十年里，村里一共活过多少人年
- **温饱**：这些人过得有多苦

**总分只描述村庄，不评价道德** —— 它量的是「活了多少人年、过得多苦」，
不是「你是个好人还是坏人」。**审判玩家的还是讣告墙。**

---

## 1. 一局的定义

| | |
|---|---|
| 时长 | **30 年**（`VillageTime.DaysBeforeYear(30) * 8` tick） |
| 现实时间 | **9.9 分钟 @1x** · 4.9 分钟 @2x · 3.3 分钟 @3x |
| 为什么是 30 年 | 所有平衡数据都是在这个尺度上测的（存活、退化、开垦、生育） |

> **30 年 = `DaysBeforeYear(30) × 8` = 10,958 天 = 87,664 tick**（含闰日）。
> `TicksPerSecond = 148` → `87664 / 148 = 592 秒`。
>
> ⚠ **不要用 `tick % 2920 == 0` 判年** —— 有闰年。用 `VillageTime.DaysBeforeYear`。

## 2. 结束条件（三种）

```csharp
// SimulateTick 末尾，data.tick = tick + 1 之后
if (CountAlive(data) == 0)
    endingKind = EndingExtinct;          // 绝户
else if (data.tick >= RunLengthTicks)
    endingKind = EndingComplete;         // 期满
else if (lowPopMonths >= 24)
    endingKind = EndingHollow;           // 名存实亡
```

| 结局 | 条件 | 含义 |
|---|---|---|
| **期满** | 活到第 30 年 | **通关** |
| **绝户** | 人口 = 0 | 失败 |
| **名存实亡** | **连续 24 个月人口 < 5** | 失败（软性） |

### 为什么要「名存实亡」

实测存在一批村子停在 **3–4 人**、靠移民和生育反复续命、永远不死的状态
（旧版「幼童口粮」就是 3 人循环）。

**这种局没有叙事价值**，玩家也不会觉得自己赢了。连续两年不足 5 人 → 直接判负，
避免玩家在一个已经死掉的村子里继续点。

```csharp
// VillageSaveData
public int lowPopMonths;   // 每 240 tick 结算一次
// tick % 240 == 0 时：
lowPopMonths = (CountAlive(data) < 5) ? lowPopMonths + 1 : 0;
```

## 3. 存续：人年（不是年末人口）

```csharp
// VillageSaveData
public int personMonths;   // 单位：人·月

// SimulateTick，每 240 tick
if (tick > 0 && tick % 240 == 0)
    data.personMonths += CountAlive(data);
```

**展示**：`人年 = personMonths / 12`。

### 为什么不用年末人口

实测年末人口 p50=15、max=50，但它**不反映过程**：
一个第 3 年就掉到 10 人、之后稳住 30 年的村子，和一个前 29 年 40 人、第 30 年团灭的村子，
年末人口可能一样。**人年记录的是整条曲线。**

> 实测人年：p25=553 · p50=685 · p75=831 · p90=935 · max=1250。

---

## 4. 温饱：饥饿 + 饥荒

```csharp
// 每 240 tick 采样
avgHungerSum += 当月平均饥饿;
hungerSamples++;

// 当月全村平均饥饿 ≥ 40 记一个「饥荒月」
if (avgHunger >= 40) famineMonths++;
```

**温饱分**（0–100）：

```csharp
int welfare = 100 - avgHunger * 2 - famineMonths / 2;
welfare = clamp(welfare, 0, 100);
```

- 平均饥饿 16（p50）→ 扣 32
- 饥荒 2 个月（p50）→ 扣 1
- 一个「吃得饱」的村子（饥饿 6、饥荒 0）→ 88 分

> **为什么不把恐惧算进去**：实测平均恐惧 p50=6、p90=9 —— 几乎没有区分度，
> 所有玩法都差不多。算进去只会稀释分数。

## 5. 总评与等级

```csharp
int life    = clamp(personYears * 100 / 1200, 0, 100);   // 人年 / 1200
int welfare = clamp(100 - avgHunger * 2 - famineMonths / 2, 0, 100);
int total   = (life * 70 + welfare * 30) / 100;
```

**7:3 的含义**：活得久比吃得饱更重要，但吃饱也算数。

### 等级线（来自实测分位）

| 等级 | 总评 | 实测占比 |
|---|---|---|
| **S** | ≥ 80 | 约 8% |
| **A** | ≥ 64 | 约 25% |
| **B** | ≥ 55 | 约 50% |
| **C** | ≥ 40 | 约 75% |
| **D** | < 40 | — |
| **F** | 未通关（绝户 / 名存实亡） | 16% 灭村 |

### 实测：不同玩法的总评

| 玩法 | 人年 | 平均饥饿 | 饥荒月 | **总评** | 灭村 |
|---|---|---|---|---|---|
| 流民法 | 948 | 4 | 0 | **82** | 0% |
| 满槽6条 | 886 | 18 | 1 | **69** | 0% |
| 劳役系 | 745 | 14 | 8 | **63** | 0% |
| 开垦系 | 642 | 13 | 0 | **59** | 5% |
| 默认三法 | 831 | 25 | 43 | **58** | 0% |
| 不装法 | 586 | 17 | 7 | **52** | 0% |
| 生育系 | 572 | 19 | 21 | **49** | 5% |
| 苛政 | 93 | 1 | 0 | **32** | **80%** |
| 恐惧系 | 544 | 20 | 3 | **31** | **50%** |

**分数确实把玩法分开了**：从 31 到 82，跨度足够大。

> ⚠ **一个要注意的异常**：`流民法` 拿了 82 分，但它本身几乎没有效果 ——
> 高分来自**移民无条件进村**（人口 <25 就来）。这意味着「移民流」是当前的最优解。
> 如果不想让一种玩法碾压其他所有玩法，需要给移民加一个门槛（比如必须装流民法），
> 否则**评分会奖励"什么都不做、等流民来"**。

## 6. 称号（谥号）

等级是"考了多少分"，**称号是"你是个什么样的官"**。两者独立。

| 称号 | 条件 | 语气 |
|---|---|---|
| **仁政** | 通关 且 温饱 ≥ 70 且 人年 ≥ 700 | 村民记得你 |
| **威权** | 通关 且 期末威信 ≥ 200 | 你让所有人服了 |
| **大兴** | 通关 且 峰值人口 ≥ 50 | 村子在你手里最大 |
| **守成** | 通关 且 以上都不满足 | 没出事 |
| **苟存** | 通关 且 人年 < 400 | 村还在，人没了 |
| **名存实亡** | 连续两年 < 5 人 | 名册还在，村子没了 |
| **绝户** | 人口 = 0 | — |

> 称号**不参与评分**，只写在结算页。多个条件同时满足时，按上表顺序取第一个。

## 7. 结算画面

```
┌──────────────────────────────────────────────┐
│                 三十年 · 治下                 │
│                                              │
│        人年 831        总评 58 · B           │
│        平均饥饿 25     饥荒 43 个月           │
│                                              │
│        人口  20 → 26   峰值 39                │
│        出生 151        死亡 195               │
│                                              │
│        谥号：守成                             │
│                                              │
│        ── 最致命的一条法 ──                   │
│        济贫 · 致死 214 人                     │
│                                              │
│   [ 再治三十年 ]        [ 回主菜单 ]          │
└──────────────────────────────────────────────┘
```

### 「最致命的一条法」—— 这条必须有

讣告里已经存了 `obituaryLawNames`（死亡当时那条法的名字）。
结算时按法名统计，取第一。

**它是整个结算页的情感核心**：不是分数，是「你写的哪条法杀了多少人」。

> 如果所有死亡都归因于同一条法（比如 `济贫`），那本身就是一句很重的话。

## 8. 实现清单

### 8.1 新增字段（存档 +1）

```csharp
public int personMonths;     // 人·月，每 240 tick += 人口
public int lowPopMonths;     // 连续人口 < 5 的月数
public int peakPopulation;   // 峰值人口
public int famineMonths;     // 平均饥饿 ≥ 40 的月数
public int hungerSum;        // 月度平均饥饿累加（用于算平均）
public int hungerSamples;    // 采样次数
public int endingKind;       // 0=进行中 1=期满 2=绝户 3=名存实亡
```

### 8.2 结算统计（派生，不进存档）

| 数据 | 来源 |
|---|---|
| 人年 | `personMonths / 12` |
| 平均饥饿 | `hungerSum / hungerSamples` |
| 出生 / 死亡 | `totalBirths` / `totalDeaths` |
| 最致命的法 | 遍历 `obituaryLawNames` 计数，取最大 **并列取先出现者**（全序，不用字典迭代） |

### 8.3 确定性

- 全部是整数累加，**不引入浮点**
- 最致命的法并列时：**按法名字典序取第一个**，不要依赖 Dictionary 遍历顺序

### 8.4 结束时

- 停止 `Advance`，`endingKind != 0` 后不再推进模拟
- 存档里记 `endingKind`，读档时直接进结算页

## 9. 阈值依据（实测）

**20 种子 × 30 年 × 9 玩法 = 180 局：**

| 指标 | p10 | p25 | p50 | p75 | p90 | max |
|---|---|---|---|---|---|---|
| 人年 | 0 | 553 | **685** | 831 | 935 | 1250 |
| 总评 | 30 | 47 | **55** | 64 | 77 | 97 |
| 峰值人口 | 0 | 31 | 39 | 43 | 47 | 64 |
| 平均饥饿 | 0 | 6 | 16 | 20 | 25 | 30 |
| 饥荒月 | 0 | 0 | 2 | 18 | 43 | 94 |
| 平均恐惧 | 0 | 4 | 6 | 8 | 9 | 15 |

**所以：**
- 1200 人年作为满分线 ≈ p95
- 80 分 = S ≈ p90
- 恐惧被排除，是因为 p50 到 p90 只差 3 点

## 10. 验收

- [ ] 每局在 30 年（或灭绝 / 名存实亡）时**一定结束**
- [ ] 结算页的六个数字与存档字段一致
- [ ] 「最致命的法」在并列时结果**确定**
- [ ] 不装法的局也能通关（评分中等）——**"什么都不做"不是一个死局**
- [ ] 苛政局大概率失败（实测 80% 灭村）
- [ ] 同一种子跑两遍，结算完全相同
