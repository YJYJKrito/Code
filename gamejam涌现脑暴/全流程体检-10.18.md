## 二、🟠 新发现的交互 bug

### Bug A：**耕者角色是默认给的，不是玩家选的**

`VillagerProfessions.Scan`：

```csharp
if (num2 >= 16 && num2 < 60 && !HasMark(1) && !HasMark(2))
    num6 |= 1;      // RoleFarmer
```

**16–60 岁的健康成年人自动成为「耕者」** —— 没有任何法律或词条门槛。

实测：**耕者持有率 86.4%**（年末存活者）。

后果：事件里的 `flag = Role(Farmer)` **永远是 true**：

```csharp
case 0: granary - (flag ? 40 : 80);   // 蝗灾永远是 40，不是 80
case 7: granary + (flag ? 180 : 120); // 丰年永远是 180
```

**「村里有没有耕者」这条职业修正，等于没有。** 这和设计原则
「职业修正必须是玩家通过法律决定的」直接冲突。

**修法**：耕者要求**勤勉**词条（`HasInnate(16u)`）——这是设计文档里本来就写的来源。

```csharp
if (age >= 16 && age < 60 && !HasMark(1) && !HasMark(2)
    && Traits.HasInnate(data, j, 16u))
    num6 |= 1;
```

**实测效果**：

| | 耕者持有率 | 蝗灾粮损（无对口法） | 蝗灾粮损（装耕作） |
|---|---|---|---|
| 现在 | **86.4%** | 147 | 71 |
| 改后 | **8.5%** | **206** | **100** |

改完之后，蝗灾的基准伤害才回到它该有的水平，**「装不装耕作」才重新有意义**。

### Bug B：**除零崩溃**

测试台把「税库进项 / 俸禄」做成可配置除数之后，`TreasuryPopDiv = 0` 直接抛
`DivideByZeroException`，整个模拟挂掉。

```csharp
data.treasuryGold += CountAlive(data) / Cfg.TreasuryPopDiv;
```

当前构建是常量 `3` / `4`，**不会崩**。但只要有人想把俸禄关掉（设 0），就会崩。

**修法**：

```csharp
data.treasuryGold += ((Cfg.TreasuryPopDiv > 0) ? (CountAlive(data) / Cfg.TreasuryPopDiv) : 0);
```

> 规则：**任何除数，只要它来自可配置项，就必须防零。**

### Bug C：**劫匪几乎拿不到**

`劫匪 = 装「饥则抢」(2) 且 饥饿 > 55`。

实测（含法 2 的玩法，30 年）：**出现率 1%**。

原因：劳动力经济下饥饿很难到 55（参数扫描 max 67，p90 40 左右）。
和之前那批「门槛落在区间外」是同一类问题，只是没那么极端。

**建议**：阈值 55 → **45**，或者改成「饥饿 > 40 且金币 = 0」。

## 五、⚠ 平衡隐患（不是 bug，但会影响手感）

| 现象 | 数据 | 说明 |
|---|---|---|
| **账房** 太普遍 | 持有率 **49.6%** | 法 3（税收）+ 年龄 ≥25 就是账房 → 贪墨的职业修正**永远生效** |
| **徙民** 太普遍 | 出现 99% · 持有 **59.5%** | 移民在人口 <25 时无条件来 → 靠移民续命的村子里大多数人都是徙民 |
| **耕者** 太普遍 | 见 Bug A | 已给修法 |

账房和徙民不一定坏（它们是「你装了这条法」的后果），
但**如果希望职业修正有区分度**，这两个门槛需要收紧（例如账房要求「节俭」词条）。
