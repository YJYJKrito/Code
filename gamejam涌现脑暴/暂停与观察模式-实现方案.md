# 局内暂停与观察模式 · 实现方案

> **要的东西**：一个能停下来看村子的暂停。时间停住、地图还能拖、能点村民、能看清现在的状态。
> **不是**打开菜单时顺带的那种时停。

---

## 0. 现状。问题出在一行代码

`GameTimePause` 本身写得没问题，是一个**引用计数的锁**

```csharp
public static bool IsPaused => Locks.Count > 0;
public static void Request(object owner)   // 打开面板时加锁，Time.timeScale = 0
public static void Release(object owner)   // 关闭时解锁
```

主循环也正确地在暂停时提前返回

```csharp
// VillageUiController.UpdateSimulation
if (currentSave == null || GameTimePause.IsPaused || Time.timeScale <= 0f) return;
```

**问题在 `MapViewBinder` 里这一行**

```csharp
private bool HasBlockingPanel()
{
    if (GameTimePause.IsPaused) return true;   // ★ 就是这一行
    foreach (var p in blockedPanels) if (p.activeInHierarchy) return true;
    return false;
}
```

`MapViewBinder.Update` 第一句是 `if (HasBlockingPanel()) { _dragging = false; return; }`。

**于是"时间停住"和"地图动不了"被绑成了同一件事。** 只要暂停，地图就死，也点不了第二个村民。

### 由此产生的实际体验

```
点村民 A  →  面板弹出  →  时间停  →  地图锁死
想看村民 B  →  必须先把 A 的面板关掉  →  时间恢复流动  →  手忙脚乱找 B
```

**这就是要修的东西。**

---

## 1. 核心改动（先把这两处拆开）

### 1.1 把「时间停住」和「面板挡住」拆成两件事

```csharp
private bool HasBlockingPanel()
{
    // ★ 删掉 if (GameTimePause.IsPaused) return true;
    if (blockedPanels == null) return false;
    foreach (var p in blockedPanels)
        if (p != null && p.activeInHierarchy) return true;
    return false;
}
```

改完之后，`blockedPanels` 成了唯一的判据——**只有真正该挡地图的面板才会挡地图**。

> ⚠️ **改之前必须确认一件事。** 打开场景，看 `MapViewBinder` 的 `blockedPanels` 数组里到底挂了几个对象。
> **如果它是空的，删掉那行之后所有菜单期间地图都会变成可拖的**，那是另一个 bug。
> 正确的内容应该是主菜单、游戏内菜单、法律选择这类**全屏模态**。村民详情**不该在里面**。

### 1.2 给暂停一个独立的身份

`GameTimePause.Request(owner)` 用 owner 当锁的键。**不要拿 `VillageUiController` 的 `this` 去请求**——它会和别的面板撞键。

```csharp
public static class PauseToken
{
    public static readonly object Inspect = new object();   // 观察暂停
}
```

两个好处。锁是引用计数的，所以**观察暂停期间再打开讣告历史**会变成 2 把锁，关掉历史回到 1 把，仍然暂停，符合直觉。

## 2. Tier 0 · 一个真正的暂停（**必做**，约 0.5 天）

### 2.1 触发方式

| 平台 | 方式 |
|---|---|
| PC | **空格键** |
| 移动端 | HUD 上一个常驻的「暂停 / 继续」按钮 |

**移动端一定要有按钮。** 这是唯一能触发这个功能的地方，藏在菜单里等于没有。

### 2.2 暂停时必须有明确的视觉反馈

**这一条比功能本身更重要。** 没有反馈，玩家会以为游戏卡死了。

要做三件事

- **全屏外框或暗角**。地图四周加一圈细边框，或者整体压一层很淡的暗色
- **状态徽章**。顶栏的「第 N 天 · 时间」旁边加一个「已暂停」
- **速度按钮显示"恢复后回到几倍速"**。`GameTimePause` 里已经有 `_resumeScale`，直接读

### 2.3 恢复时的行为

`UpdateSimulation` 在暂停期间**不累加 `_tickAccumulator`**（它在 `return` 之前就返回了），所以恢复时不会出现"追赶"的爆发。

**这一点要在验收里专门测**——暂停 30 秒再恢复，不应该看到游戏突然快进。

### 2.4 实现位置

在 `VillageUiController` 里加两个方法就够

```csharp
private void ToggleInspectPause()
{
    if (GameTimePause.IsPaused && _inspectPaused) GameTimePause.Release(PauseToken.Inspect);
    else { GameTimePause.Request(PauseToken.Inspect); _inspectPaused = true; }
}
```

> `_inspectPaused` 这个标志是必要的。玩家可能先按空格暂停、再打开菜单（锁数 1→2），这时按空格**不应该**把菜单的锁也解掉。
> 判断"当前是不是我暂停的"再决定要不要释放。

### 2.5 空格键不能和现有的键位冲突

先查一遍 `KeyBindingPanelController` 和 `VillageSettingsData` 里已经用掉的键（现在有 `mapUpKey/mapDownKey/mapLeftKey/mapRightKey`，默认 `w/s/a/d`）。**空格目前是空的，可以用。**

但如果以后要加自定义键位，记得把暂停键也纳入 `VillageSettingsData`。

## 3. Tier 1 · 先把已有的面板接完整（**强烈建议**，约 0.6 天）

> **重要更正。** 写第一版方案时我假设村民详情面板还不存在。**读完反编译之后发现它已经有了，而且做得比我预想的完整。**
> 所以这一档不是"从零做一个面板"，是"把一个已经成形的东西接完整"。工时因此从 1 天降到 0.6 天。

### 3.1 现状盘点（读代码读到的，不是猜的）

链路

```
VillagerActorView.OnPointerClick   →   VillagerStatusPanelController.Instance.Open(index)
                                   →   GameTimePause.Request(this)    时间停住
                                   →   panel.SetActive(true)
```

面板现在显示四块内容

| 区域 | 字段 | 内容 |
|---|---|---|
| 标题 | `title` | 名字 + 「（已故）」 |
| 副标题 | `meta` | 性别 · 年龄 · 存活/死亡 |
| 数值 | `stats` | 金币 / 饥饿 99 / 恐惧 99 / 存粮 40 / 子女 N 人 |
| 标签 | `tags` | 自动推导的状态词 |

`BuildAliveTags` 会自动推导这些标签

```
饥饿 > 70        → 饥民
恐惧 > 70        → 惊恐
金币 < 10        → 贫穷
年龄 < 3         → 幼儿
年龄 ≥ 65        → 老人
生育冷却 > 0     → 生育冷却约 N 天
```

**标签是推导出来的，不是写死的分类。存活和已故也分开处理了。** 这两点做得对，不要改。

### 3.2 问题一 · 它把地图锁死了

`Open` 里调 `GameTimePause.Request(this)`，而 `MapViewBinder.HasBlockingPanel()` 在 `IsPaused` 时返回 `true` → **面板一开，地图不能拖、不能缩放**。

这正是 §1.1 那行要拆开的代码。**拆完之后这一条自动解决**，不用单独改面板。

**至于"能不能直接点第二个村民"** —— 代码层面是支持的。`GameTimePause.Request(owner)` 对同一个 owner 是幂等的（`!Locks.Contains(owner)` 挡住了重复加锁），所以连续点不同村民会**直接切换内容**，不会叠锁。

**但能不能点得到，取决于场景里那个面板的射线遮挡范围。** 这一点我看不到，要打开工程实测：面板开着的时候，点地图上另一个村民，看响应的是谁。

- 如果点得到 → 只改 §1.1 那一行就够
- 如果点不到 → 把面板的底板 `Image` 的 `Raycast Target` 关掉，改成抽屉式停靠在一侧

### 3.3 问题二 · 点已故村民只给一句话 ★ 这一条最可惜 ★

现在的实现是

```csharp
tags.text = flag ? BuildAliveTags(currentSave, index) : "这个人已经进入讣告历史。";
```

**而讣告数组里明明存着这些**

| 字段 | 内容 |
|---|---|
| `obituaryTicks` | 死于第几天 |
| `obituaryCauses` | 死于什么（饥饿 / 惊吓 / 夭折 / 寿终） |
| `obituaryLawIndices` | **死于第几条法** |
| `obituaryInfants` | 是不是幼儿夭折 |
| `obituaryAges` | 死时几岁 |

**玩家点一个已故的村民，最想知道的恰恰就是这些。** 数据现成，只是没接上去。**接上去大概二十分钟。**

这是全作最便宜的一处"把已有数据变成内容"。做完之后，玩家点任何一个死人，都能读到他是怎么死的、死在第几条法上——**这就是宣传语「他们死于你写的法律」在一个 UI 动作上的落地**。

> ⚠️ **有一个必须先处理的坑。**
> `AppendObituary(data, villagerIndex, cause, lawIndex)` 存了**名字**，但**没存 `villagerIndex`**。
> 所以想把讣告对回某个人，现在只能按名字匹配——**而重名的会串**。
>
> `CreateNewGame` 的 20 个名字不重复，但 `AppendChild` 给新生儿起名 `"幼子" + (num + 1)`，理论上和手工名字不会撞。**目前是安全的，但它是靠巧合安全。**
>
> 干净的修法：给存档 DTO 加 `public int[] obituaryVillagerIndices`，**存档版本 +1**。
> 想省事就先按名字匹配，**但那是个以后会咬你的捷径**，建议顺手加掉。

### 3.4 加一行「邻居」，并且点名字能跳过去

**这是这一档里性价比最高的一小块。**

```
村民 i 的邻居 = (i + 1) % N 和 (i + N - 1) % N
```

在面板里加一行

```
邻居　　李井 / 韩麦
```

**两个名字都要能点，点了直接切到那个人的面板。**

理由和目标

- **它让邻接那条线的法条第一次变得可读。** 「比邻」「阋墙」「连坐」「守望」「共井」这五条法的行为全部建立在"相邻"上。玩家看不到数组，他看到的是一排村民——**没有这一行，这几条法在玩家眼里就是随机的**。
- 它顺带解决了 §3.2 的"点不到第二个村民"。就算地图上的射线被挡，玩家也能从面板里跳过去。

### 3.5 三处数据不存在，所以显示不了

这一节是写给"不做什么"的。想让面板显示下面这些，**得先有字段**，不要在这上面花时间。

| 想显示的 | 为什么显示不了 |
|---|---|
| 被抢过几次 / 被喂过几次 | `VillageSaveData` 里没有这类历史计数 |
| 饿过多少天 / 怕过多久 | 同上，只存当前值不存历史 |
| 谁是他配偶 | **没有婚姻状态字段**。只有性别和子女数，而子女数推不出配偶是谁 |

要显示这些，先走 `法条扩展-实现方案` 里那套"加字段"的流程，**不要为了显示而临时塞字段**。

## 4. Tier 2 · 观察覆盖层（有余力再做，约 1 天）

暂停状态最适合做的事是"看一眼全村现在什么情况"。三个小功能，按性价比排序。

### 4.1 色标切换（**最便宜，最先做**）

一个按钮循环切换，直接改每个 `VillagerWalker.visual` 的 `Image.color`

| 模式 | 着色依据 |
|---|---|
| 无 | 原色 |
| 饥饿 | 0 绿 → 99 红 |
| 恐惧 | 同上 |
| 存粮 | 0 红 → 40 绿 |

**成本极低**（改一个颜色字段），但玩家一眼就能看出"谁快饿死了"。**这是这一档里最值钱的一个。**

### 4.2 按法槽高亮

点某个法槽 → 所有**当前满足这条法条件**的村民加一个光圈或闪一下。

**实现依赖法条架构改造。** 现在条件是硬编码的 if 分支，没法反查"谁满足了"。等 `法条扩展-实现方案` 里那套 `conds` 做完之后，这个问题变成一次遍历 `EvalCond`。**所以这一条排在那份方案之后。**

### 4.3 因果连线（**不建议做**）

从法槽到当前受影响的村民拉一条线。视觉冲击最强，但要处理线的渲染层级、相机缩放、多人重叠。**九天内不值得。**

## 5. 一条设计红线

> **暂停只能显示「现在是什么样」，不能显示「接下来会发生什么」。**

这个游戏的情绪全在"等待报应落地"上。如果暂停能给出预测（谁快死了、哪条法会先出事），等待就没了，玩家变成在解一个已经知道答案的方程。

具体地说

- ✅ 可以显示：当前饥饿 87、存粮 2、邻居是谁、这条法现在影响了哪 4 个人
- ❌ 不能显示：预计还能活几天、下个 tick 谁会死、这条法累计杀了多少人（这个是结算页的事）

**"当前状态是透明的，后果是不透明的"** —— 这条界线要守住。

## 6. 验收

### Tier 0

- [ ] 按空格，时间停住；再按一次，恢复
- [ ] 暂停期间**地图可以拖动、可以缩放**
- [ ] 暂停期间**可以点村民**打开详情
- [ ] 暂停时有明确的视觉提示（外框 / 徽章 / 速度按钮状态）
- [ ] **暂停 30 秒再恢复，不出现快进追赶**
- [ ] 暂停时打开讣告历史，关掉之后**仍然是暂停状态**
- [ ] 移动端有常驻的暂停按钮，且**能点中**

### Tier 1

- [ ] 村民详情**不再挡住地图**
- [ ] 连续点 5 个村民，每次都能直接切换内容，不用先关掉
- [ ] **点已故村民，能看到死因、死于第几天、死于第几条法**
- [ ] 标签推导（饥民 / 惊恐 / 贫穷 / 幼儿 / 老人 / 生育冷却）**没有被改坏**
- [ ] 面板里有「邻居」一行，两个名字**都能点击跳转**
- [ ] 从邻居跳过去之后，那一行的邻居又正确地指向新的两个人（不会指回自己）
- [ ] 面板底部或角落显示的是**这个村民**的信息，不是上一个的残留
- [ ] 存读档之后暂停状态不会被写进存档（读档应该是运行状态）

### Tier 2

- [ ] 色标能切换，且切换后**所有村民同时变色**（不能只变一部分）
- [ ] 恢复运行时色标恢复到原色

## 7. 工时与顺序

| 顺序 | 做什么 | 工时 | 风险 |
|---|---|---|---|
| 1 | **确认 `blockedPanels` 里挂了什么** | 0.1 天 | — |
| 2 | 拆开 `HasBlockingPanel` 的 `IsPaused` 判断 | 0.1 天 | **中**，见下 |
| 3 | `PauseToken` + 空格 / 按钮 + 视觉反馈 | 0.3 天 | 低 |
| 4 | **实测**：面板开着时点地图上另一个村民，看响应的是谁 | 0.1 天 | — |
| 5 | 已故村民接上讣告内容（死因 / 第几天 / 第几条法） | 0.2 天 | 低 |
| 6 | `obituaryVillagerIndices` 字段 + 存档版本 +1 | 0.2 天 | 低 |
| 7 | 面板加「邻居」行 + 点击跳转 | 0.3 天 | 低 |
| 8 | 色标切换 | 0.3 天 | 低 |
| | **合计（Tier 0 + 1 + 2.1）** | **≈1.6 天** | |

> **第 5 到 7 步比原估的便宜**，因为面板本身已经做好了（§3.1 的盘点）。原估 1 天是把它当成从零开始做的。
>
> **第 6 步可以省。** 不加重名字匹配也能跑，只是埋了一个以后会咬人的雷。**如果时间紧，先跳过它，但要在代码里留一行注释说清楚这是临时方案。**

### 第 2 步的风险说明

删掉 `HasBlockingPanel` 里那行之后，**地图的挡板判据就完全落在 `blockedPanels` 数组上**。

如果那个数组在场景里是空的、或者漏挂了某个全屏面板，改完之后**那些面板开着的时候地图会变得可拖**。这不是崩溃，但会造成"菜单开着还能拖地图"的怪现象。

**所以第 1 步的检查不能省，而且要逐个面板试一遍。**

### 和别的方案的关系

- 和 `人口上限提升方案` **互不依赖**，可以并行
- `Tier 2.2 按法槽高亮` **依赖 `法条扩展-实现方案`** 里的 `conds` 架构，排它后面
- 和 `法条扩展` 里的**自检工具**没有关系

## 8. 一句话

> **问题的根因是「暂停」和「挡住地图」被写成了一件事。**
> **拆开它们是一行代码，而这一行之后，这个游戏才第一次允许玩家"停下来，好好看看自己的村子"。**
