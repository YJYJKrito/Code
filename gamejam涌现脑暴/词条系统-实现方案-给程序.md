## 0. 动手前必须先知道的两件事

这两条是读代码读出来的，**它们直接决定词条效果能不能接得上**。

### 0.1 `villagerGold` 只有汇没有源

全项目只有四处写它

```
3751  CreateNewGame     初值 8..90
3099  AdvanceNeeds      从公仓取粮时扣 1
3127  AdvanceNeeds      税收法（law3）扣 12
3313  AppendChild       新生儿为 0
```

**没有一处给它加钱。** 金币会单调递减到 0，然后永远停在 0。

**后果**：「贪婪」原本想接的"金币回复概率"**这个钩子不存在**。所有和"赚钱"有关的词条效果都要重新设计（见 §5.2）。

### 0.2 公仓有粮 ≠ 不会饿死 ★ 这一条更值得注意 ★

`AdvanceNeeds` 里从公仓取粮的那个分支是这样的

```csharp
else if (data.granaryFood > 0)
{
    bool flag  = HasLaw(data, 1) && data.villagerHunger[index] > 45;   // 济贫法
    bool flag2 = HasLaw(data, 9) && data.villagerAges[index] < 8;      // 幼童口粮
    bool flag3 = data.villagerGold[index] > 0;                          // 自己有钱
    if (flag | flag2 | flag3) { /* 才吃得到 */ }
}
```

**三个条件一个都不满足时，即使粮仓是满的，这个人也吃不到饭。**

也就是说

> **个人的存粮吃完了，金币也花完了，而你又没有立"济贫"这条法——粮仓再满，他也会饿死。**

这**可能是设计意图**（"没有法律授权，你不能动公家的粮"其实很符合主题），但它现在完全没有被表达出来。玩家会理所当然地以为"粮仓有粮就不会饿死"，然后看着人饿死在满仓旁边，而且不知道为什么。

**要二选一，并且明确下来**

- **当成机制保留** → 必须在 UI 上说出来。公仓旁边加一行小字「需济贫法方可取用」，或者当村里出现"断粮+无钱+无授权"的人时给一个警示
- **当成 bug 改掉** → 把 `flag3` 改成"没钱时可以向公仓赊账"，或者干脆去掉这个前置

**这一条不解决，词条里「挥霍」「节俭」这两条的效果会表现得非常奇怪**——它们影响的是"多久耗尽个人存粮"，而在当前规则下那等于"多久之后只能靠法律救济"。

### 1.3 读写 API（**必须集中，不要散在各法条里**）

```csharp
// 先天 —— 只读（除了生成函数）
public static bool HasInnate(VillageSaveData d, int i, uint bit)
    => i >= 0 && i < d.villagerInnate.Length && (d.villagerInnate[i] & bit) != 0;

// 烙记 —— 读
public static bool HasMark(VillageSaveData d, int i, uint bit)
    => i >= 0 && i < d.villagerMarks.Length && (d.villagerMarks[i] & bit) != 0;

// 烙记 —— 写
public static void AddMark(VillageSaveData d, int i, uint bit)
{
    if (i < 0 || i >= d.villagerMarks.Length) return;
    d.villagerMarks[i] |= bit;
}

// 烙记 —— 清除。★ 永久位免疫
public static void RemoveMark(VillageSaveData d, int i, uint bit)
{
    if (i < 0 || i >= d.villagerMarks.Length) return;
    d.villagerMarks[i] &= ~(bit & Mark.ClearableMask);   // ★ 这一行是唯一的保证点
}
```

**`RemoveMark` 里那个 `& Mark.ClearableMask` 是"废法是止血不是撤销"的唯一实现点。** 写错了不会报错，只会某天你发现"废掉法条之后人就好了"。**加一条测试盯它。**

## 2. 生成算法

### 2.1 开局 20 人

在 `VillageSaveService.CreateNewGame` 的循环里加。**每人抽 1–2 条，从不同的轴抽。**

```csharp
for (int i = 0; i < num; i++)
{
    // …原有的名字/性别/年龄等…
    villageSaveData.villagerInnate[i] = RollInnate(seed, i);
    villageSaveData.villagerMarks[i] = 0;
}

static uint RollInnate(int seed, int index)
{
    uint bits = 0;
    // 抽 1 或 2 条
    int count = 1 + Rng.Range(seed, 0, CH_INNATE, index * 10 + 0, 0, 2);   // 1 或 2
    // 先决定从哪几条轴抽（不重复）
    int axisA = Rng.Range(seed, 0, CH_INNATE, index * 10 + 1, 0, 8);
    int axisB = Rng.Range(seed, 0, CH_INNATE, index * 10 + 2, 0, 7);        // 0..6
    if (axisB >= axisA) axisB++;                                            // 避开 axisA

    bits |= PickFromAxis(seed, index, axisA);
    if (count == 2) bits |= PickFromAxis(seed, index, axisB);
    return bits;
}

static uint PickFromAxis(int seed, int index, int axis)
{
    var pair = Innate.Axes[axis];
    int which = Rng.Range(seed, 0, CH_INNATE, index * 10 + 100 + axis, 0, 2);
    return pair[which];
}
```

**关键点**

- **按轴抽，不按位抽。** 这一条保证了不会有同轴冲突，规则只有一条
- `axisB >= axisA` 时 `axisB++` 是标准的"从剩余里抽"写法，避免两轴相同
- 全部走 `Rng`，**同 seed 的分布必须完全一致**

### 2.2 新生儿继承

`AppendChild(data, mother, father)` **已经拿到父母下标**，直接可用。

```csharp
static uint RollInheritedInnate(VillageSaveData d, int childIndex, int mother, int father)
{
    uint bits = 0;
    uint momInnate  = d.villagerInnate[mother];
    uint dadInnate  = d.villagerInnate[father];

    // 第一条：40% 母 / 40% 父 / 20% 随机
    int roll = Rng.Range(d.rngSeed, d.tick, CH_INHERIT, childIndex, 0, 10);
    uint first;
    if (roll < 4)      first = PickOneBit(momInnate, d, childIndex, 0);
    else if (roll < 8) first = PickOneBit(dadInnate, d, childIndex, 1);
    else               first = PickFromAxis(d.rngSeed, childIndex, Rng.Range(d.rngSeed, d.tick, CH_INHERIT, childIndex * 10 + 2, 0, 8));
    first &= ExtractOneAxis(first);   // 只保留一条轴上的那一位
    bits |= first;

    // 第二条：60% 再抽一条不同轴，40% 不抽
    if (Rng.Range(d.rngSeed, d.tick, CH_INHERIT, childIndex * 10 + 3, 0, 10) < 6)
    {
        int usedAxis = AxisOf(first);
        int axis = Rng.Range(d.rngSeed, d.tick, CH_INHERIT, childIndex * 10 + 4, 0, 7);
        if (axis >= usedAxis) axis++;
        bits |= PickFromAxis(d.rngSeed, childIndex, axis);
    }
    return bits;
}
```

**新增的 Rng channel**

```
CH_INNATE   = 5000    开局先天生成
CH_INHERIT  = 5100    新生儿继承
CH_MARK     = 5200    烙记的随机判定
CH_SCAR     = 5300    幸存者伤痕判定
```

> ⚠️ **channel 号不能和现有的撞。** 现有的代码里把 `1000+i`、`2000+i`、`3000+i`、`4000+num` 当 channel 用了，所以 5000 以上是安全的。

## 3. 效果接入点（逐个函数）

**这张表是全篇最实用的部分。** 每个钩子都标了原代码长什么样、改成什么样。

### 3.1 `AdvanceNeeds` · 饥饿增速

```csharp

int num = ((data.villagerAges[index] < 3) ? 24 : 30);
if (tick % num == 0) data.villagerHunger[index]++;

// ── 改 ──
int num = ((data.villagerAges[index] < 3) ? 24 : 30);
if (HasInnate(data, index, Innate.Frail))  num -= 6;    // 30 → 24
if (HasInnate(data, index, Innate.Robust)) num += 4;    // 30 → 34
if (num < 1) num = 1;

```

### 3.2 `AdvanceNeeds` · 吃饭

```csharp
// ── 原 ──

{
    data.villagerFood[index]--;
    data.villagerHunger[index] = Math.Max(0, data.villagerHunger[index] - 5);
}

// ── 改 ──
if (data.villagerFood[index] > 0)
{
    int cost = 1;
    if (HasInnate(data, index, Innate.Wasteful)) cost = 2;
    // 节俭：每 3 次进食只扣 2 次
    if (HasInnate(data, index, Innate.Frugal) && (tick / 20) % 3 == 0) cost = 0;
    data.villagerFood[index] = Math.Max(0, data.villagerFood[index] - cost);
    data.villagerHunger[index] = Math.Max(0, data.villagerHunger[index] - 5);
}
```

```csharp
// ── 原（从公仓取粮，扣钱）──

    data.villagerGold[index] = Math.Max(0, data.villagerGold[index] - 1);

// ── 改：贪婪有 30% 概率不付钱（他藏了钱）──

{

             || Rng.Chance(data.rngSeed, tick, CH_MARK, index, 70);
```

> **「贪婪」的效果只能是这个。** 因为 §0.1 说了金币没有来源，所以"赚钱快"接不上。改成"吃饭少付钱"，效果是**他的金币撑得久，但他吃的每一口都是从公仓拿的**——等于让全村多消耗。**它有代价，不是纯赚。**

### 3.3 `AdvanceNeeds` · 恐惧

```csharp

{
```

**外因造成的恐惧增量（韧性）。** 所有 `fear += N` 的地方——**包括将来法条里的**——都走同一个函数

```csharp
public static void AddFear(VillageSaveData d, int i, int amount)
{
    if (amount <= 0) { d.villagerFear[i] = Math.Max(0, d.villagerFear[i] + amount); return; }
    int scaled = amount;
    if (HasInnate(d, i, Innate.Tough))   scaled = Math.Max(1, amount * 7 / 10);   // −30%
    if (HasInnate(d, i, Innate.Brittle)) scaled = amount * 3 / 2;                 // +50%
    d.villagerFear[i] = Math.Min(99, d.villagerFear[i] + scaled);
}
```

> **注意：`AdvanceNeeds` 里那句 `villagerFear[index]++`（恐惧蔓延法）不该走这个函数。**
> 韧性抗的是**外部冲击**，不是长期侵蚀。**法条造成的持续增长是"侵蚀"，要绕开它。**
> 这个区别要想清楚，否则「坚韧」会变成"对恐惧蔓延法免疫"，太强了。

### 3.4 `AdvanceGranary` · 产出

```csharp
// ── 原 ──
int num = population / 3;
int num2 = population / 2;

// ── 改：勤勉/懒散按人头修正 ──
int diligent = 0, idle = 0;
for (int i = 0; i < data.villagerAlive.Length; i++)
{
    if (!data.villagerAlive[i]) continue;
    if (HasInnate(data, i, Innate.Diligent)) diligent++;
    if (HasInnate(data, i, Innate.Idle))     idle++;
}
int num  = population / 3 + diligent - idle;
int num2 = population / 2;
```

> **这里有个尺度问题要注意。** `population / 3` 在 20 人时是 6。如果村里有 5 个勤勉 + 5 个懒散，正负抵消。**但如果只有勤勉没有懒散，产出会涨 80%**，那会直接掀翻数值平衡。
>
> **建议先钳位**：`diligent - idle` 的绝对值不超过 `population / 6`。**然后实测调。**

### 3.9 幸存者伤痕的写入点（新增）

在 `SimulateTick` 里加一段周期检查，**每 60 tick 一次**。

```csharp
if (tick > 0 && tick % 60 == 0)
{
    for (int i = 0; i < data.villagerAlive.Length; i++)
    {
        if (!data.villagerAlive[i]) continue;
        if (data.villagerHunger[i] >= 90 && !HasMark(data, i, Mark.Starved))
            AddMark(data, i, Mark.Starved);
        if (data.villagerFear[i]   >= 90 && !HasMark(data, i, Mark.Haunted))
            AddMark(data, i, Mark.Haunted);
        if (HasMark(data, i, Mark.Corvee) && Rng.Chance(data.rngSeed, tick, CH_SCAR, i, 10))
            AddMark(data, i, Mark.Worn);   // 长期劳役 → 劳损
    }
}
```

> **这一组是全表里最值钱的。** 它不需要任何法条就能工作，代价只有一次 60 tick 的扫描。

## 4. 状态函数的提取

现在这些判断内联在 `VillagerStatusPanelController.BuildAliveTags`（**UI 层**）里，法条读不到。

**提到 Sim 层**

```csharp
public static class Condition
{
    public static bool IsStarving (VillageSaveData d, int i) => d.villagerHunger[i] > 70;
    public static bool IsTerrified(VillageSaveData d, int i) => d.villagerFear[i]   > 70;
    public static bool IsDestitute(VillageSaveData d, int i) => d.villagerGold[i]   < 10;
    public static bool IsWealthy  (VillageSaveData d, int i) => d.villagerGold[i]   > 60;
    public static bool HasNoStores(VillageSaveData d, int i) => d.villagerFood[i]  == 0;
    public static bool IsHoarding (VillageSaveData d, int i) => d.villagerFood[i]  >= 35;
    public static bool IsInfant   (VillageSaveData d, int i) => d.villagerAges[i]   < 3;
    public static bool IsChild    (VillageSaveData d, int i) => d.villagerAges[i]  >= 3 && d.villagerAges[i] < 14;
    public static bool IsAdult    (VillageSaveData d, int i) => d.villagerAges[i]  >= 14 && d.villagerAges[i] < 50;
    public static bool IsElder    (VillageSaveData d, int i) => d.villagerAges[i]  >= 65;
    public static bool IsFertile  (VillageSaveData d, int i) => d.villagerGenders[i] == 0
                                                             && d.villagerAges[i] >= 18 && d.villagerAges[i] <= 42;
    public static bool IsChildless(VillageSaveData d, int i) => d.villagerChildren[i] == 0;
    public static bool HasMany    (VillageSaveData d, int i) => d.villagerChildren[i] >= 3;
    public static bool IsDying    (VillageSaveData d, int i) => d.villagerHunger[i] >= 95 || d.villagerFear[i] >= 95;
}
```

`VillagerStatusPanelController.BuildAliveTags` 改成调这些函数，**UI 显示不变**。

**这一步做完之后，"给饥民发粮"这种法条才写得出来**——现在「饥民」这个状态只有玩家看得到。
