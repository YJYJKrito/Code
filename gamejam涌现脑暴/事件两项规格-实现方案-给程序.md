## 0. 先说结论：让事件变多的是「兆头槽」，不是冷却

| 改动 | 每局事件数（30 年） |
|---|---|
| 原版（5 年冷却 · 1 个兆头） | **11.0** |
| 冷却改 3 年 | **11.0**（没变） |
| 冷却 3 年 + **兆头槽 3 格** | **18.3** |
| 再 + 逐事件冷却（民变 1 年 / 疫病 0.5 年） | **19.4** ✅ |

**原因**：原版 `eventOmenId` / `eventOmenTick` 是单数——兆头挂着期间不抽新事件。
所以一局最多就是「30 年 ÷ (2.92 年 + 等待)」≈ 11 次。

### 0.1 兆头槽改成 3 格（已实现并实测）

```

`Tick` 改成：

// ② 抽新兆头：有空槽才抽

```

**`Pick` 还要跳过「已经挂着兆头的事件」**，否则同一个事件会排队两次。

### 1.2 代码

```csharp
private static bool EvHasLaw(VillageSaveData data, int lawId)
{
    if (data.prestigeSuspended || data.lawIds == null) return false;
    for (int i = 0; i < data.lawIds.Length; i++)
        if (data.lawIds[i] == lawId) return true;
    return false;
}

private static int Avec(VillageSaveData data, int pct, int lawId, int p)
{
    if (!EvHasLaw(data, lawId)) return pct;
    return pct * p / 100;          // 多条相乘
}

private static int LawPct(VillageSaveData data, int id)
{
    int pct = 100;
    switch (id)
    {
    case 0:  pct = Avec(data, pct, 5, 50);  pct = Avec(data, pct, 71, 50); break;
    case 1:  pct = Avec(data, pct, 12, 50); pct = Avec(data, pct, 13, 40); break;
    case 2:  pct = Avec(data, pct, 15, 0);  pct = Avec(data, pct, 48, 150); break;
    case 3:  pct = Avec(data, pct, 6, 50);  pct = Avec(data, pct, 1, 70); pct = Avec(data, pct, 16, 150); break;
    case 4:  pct = Avec(data, pct, 14, 50); break;
    case 5:  pct = Avec(data, pct, 30, 50); break;
    case 6:  pct = Avec(data, pct, 10, 40); pct = Avec(data, pct, 25, 0); pct = Avec(data, pct, 2, 150); break;
    case 7:  pct = Avec(data, pct, 5, 150); break;
    case 8:  pct = Avec(data, pct, 29, 150); pct = Avec(data, pct, 31, 150); pct = Avec(data, pct, 14, 60); break;
    case 9:  pct = Avec(data, pct, 28, 150); break;
    case 10: pct = Avec(data, pct, 17, 150); break;
    case 11: pct = Avec(data, pct, 12, 0); break;
    case 12: pct = Avec(data, pct, 35, 150); pct = Avec(data, pct, 6, 130); break;
    default: pct = Avec(data, pct, 8, 150); pct = Avec(data, pct, 9, 130); break;
    }
    return pct;
}

/// <summary>按百分比缩放；只要不是「全免」，至少保留 1</summary>
private static int Sk(int v, int pct)
{
    if (pct <= 0) return 0;
    int r = v * pct / 100;
    return r < 1 ? 1 : r;
}
```

在 `Fire` 开头：

```csharp
int lp = LawPct(data, id);
```

然后每个效果乘 `lp`。

### 1.3 ★ 粮仓类事件必须改**按比例**

**这是实测逼出来的。** 蝗灾原来是绝对值 `−80`，而粮仓常年 40 上下：
`max(0, 40−80)` 和 `max(0, 40−40)` **都是 0** —— 折扣完全看不出来。

```csharp
// ❌ 绝对值：折扣被粮仓上限吃掉
data.granaryFood -= Sk(flag ? 40 : 80, lp);

// ✅ 按比例：折扣永远生效
int dmg = Sk(data.granaryFood * (flag ? 30 : 60) / 100, lp);
data.granaryFood = ClampGranary(data, data.granaryFood - dmg);
```

寒潮同理（`25% / 50%`）。

## 2. 事件连锁

### 2.1 设计

| 触发 | 窗口 | 效果 |
|---|---|---|
| 蝗灾 / 寒潮 爆发 | 之后 **2 年** | 民变权重 **+60** |
| 疫病 爆发 | 之后 **1 年** | 疫病权重 **+30**（二次爆发） |

### 2.2 代码

存档加两个字段（**存档版本 +1**）：

```csharp
public int chainMobilize;
public int chainPlague;
```

权重（`Weight` 里）：

```csharp
1 => 1 + num / 15 + ((data.tick < data.chainPlague) ? 30 : 0),
3 => 1 + (300 - data.prestige) / 12 + num3 / 3 + ((data.tick < data.chainMobilize) ? 60 : 0),
```

`Fire` 里设窗口：

```csharp
case 0: data.chainMobilize = tick + 5840; break;   // 蝗灾 → 2 年民变窗口
case 1: data.chainPlague   = tick + 2920; break;   // 疫病 → 1 年二次爆发
case 5: data.chainMobilize = tick + 5840; break;   // 寒潮 → 2 年民变窗口
```

### 2.3 ⚠ 冷却必须比窗口短

现在冷却统一 14600（5 年）。**如果以后给民变/疫病设更长冷却，链会被冷却自己挡掉。**
建议：

| 事件 | 冷却 |
|---|---|
| 民变 | **1 年** |
| 疫病 | **0.5 年** |
| 其余 | 3 年 |

（本方案里冷却统一 3 年，链的窗口 1–2 年，不会互相挡。）

### 2.4 实测：两种连锁写法，效果都很小

10 种子 × 30 年 × 10 玩法（**已含 3 格兆头 + 逐事件冷却**）：

| 连锁 | 民变 每局 | 疫病 每局 | 全部事件 |
|---|---|---|---|
| 关 | 5.20 | 1.75 | 19.6 |
| **权重 +60** | 5.81（+12%） | 1.76 | 19.6 |
| **直接排一条民变** | **6.08（+17%）** | 1.74 | 20.6 |

**即使把权重加到 +400，民变也只到 5.81** —— 瓶颈不是权重，是事件总数就那么多。

**所以推荐「直接排」而不是「加权重」**：

```csharp
// 蝗灾 / 寒潮 爆发时，直接往空槽排一条 1 年后的民变
if (有空的兆头槽)
{
    data.omenEventIds[free] = 3;          // 民变
    data.omenBurstTicks[free] = tick + 2920;
}
```

理由：**权重是概率，玩家看不见；直接排是规则，玩家能记住「闹完蝗灾必有民变」。**
而且它只多约 1 次/局——不会把事件表冲乱。

## 7. 一句话

> **对口法律让「你写的法」第一次能直接改写事件** —— 这是整个事件系统里
> 「玩家能影响」的那一半。没有它，事件只是随机的天气。
>
> **连锁让灾难有后效** —— 蝗灾之后跟着民变，这是玩家能记住的因果。
>
> **但两者都要建在「按比例扣」上**，否则粮仓类事件的折扣会被 40 的预留线吃掉。
