# 讣告重做 · 设计与实现 — 给程序

> **问题**：装了「幼童口粮」「医药」之后，**每一个幼儿死亡都被写成「他死于你写的第 9 条法」**。
>
> 根因：旧代码只看「**这条法装没装**」，不看「**是不是它干的**」：
>
> ```csharp
> KillVillager(data, i, "夭折", PreferredLaw(data, 9, 12));  // 装了就背锅
> ```
>
> **保护性法律被当成了死因。** 这比没有归因更糟 —— 它在诬陷玩家写的善法。

---

## 1. 新规则：三种归因，不是一种

每次死亡，按顺序问三个问题：

```
① 有没有一条「会加重这个死因」的法？     → 有：致死法
② 有没有一条「本可以救他」的法没装？     → 有：缺位法
③ 都没有                               → 无
```

| 归因 | 文案 | 颜色 |
|---|---|---|
| **致死法** | 「是你写的『劳役』。」 | 朱红 |
| **缺位法** | 「村里没有『幼童口粮』。」 | 灰蓝 |
| **无** | 「没有一条法能替他负责。」 | 淡墨 |

**核心区别**：
- 「是你写的」= 你做的事杀了人
- 「村里没有」= 你没做的事没能救人
- 两者都算因果，但**语气完全不同** —— 后者是遗憾，不是指控

### 2.6 判定顺序与确定性

```csharp
// 按表里的顺序，取「第一条装了的」加重法
for (int k = 0; k < harm.Length; k++)
    if (HasLaw(harm[k])) return Caused;

// 否则取「第一条没装的」救命法
for (int k = 0; k < help.Length; k++)
    if (!HasLaw(help[k])) return Missing;

return None;
```

- **不遍历字典**，按固定数组顺序
- 并列时**顺序即优先级**：越靠前的法越先被点名
- 全部整数，无随机

## 3. 讣告文本结构

旧文本只有三行，而且没有法名：

```
王五，34 岁。
他死于三年四月的饥饿。
他死于你写的第 2 条法。
```

**新结构四段：**

```
{姓名}，{年龄} 岁。
{死因句}
{归因句}
{个人史（可选）}
```

### 3.1 死因句

| 死因 | 文案 |
|---|---|
| 夭折 | `死于三年四月。还没满三岁。` |
| 寿终 | `死于三年四月，寿终。` |
| 其他 | `死于三年四月，饥饿。` |

> ⚠ **年份要从 1 开始**。现在 `FormatDay` 显示「0年3月」，要改成「元年」或「1年」。

### 3.2 归因句（每类 2–3 个变体，确定性轮换）

**致死法**

- 「是你写的『劳役』。」
- 「第 2 条法『劳役』，是他没熬过去的原因。」
- 「他死在你立的『劳役』之下。」

**缺位法**

- 「村里没有『幼童口粮』。」
- 「如果能早一点立『幼童口粮』……」
- 「没有『幼童口粮』，这样的孩子撑不过冬天。」

**无**

- 「没有一条法能替他负责。」
- 「他死于没有法的地方。」

> **变体选择**：`(villagerIndex * 31 + tick) % 变体数` —— 确定性，不占 RNG 通道。

### 3.3 个人史（可选，1 句）

从现有数据里取**最有信息量的一条**：

| 条件 | 文案 |
|---|---|
| 曾有子女、现在全死 | 「他没能留下一个孩子。」 |
| 邻居死亡累计 ≥ 15 | 「他送走过 N 个邻居。」 |
| 捐纳 ≥ 3 | 「他给村里捐过 N 次。」 |
| 饥饿累计 ≥ 730 tick | 「他饿了很久。」 |
| 劫匪 | 「他抢过别人的粮。」 |
| 尸亲 | 「他替别人送过葬。」 |
| 徙民 | 「他是从外面来的。」 |
| 屠者 | 「他动过手。」 |
| 巫祝 | 「他替村子求过神。」 |
| 都不满足 | 不加 |

> 一段只加一句，**不要堆**。

## 4. 实测：修前 / 修后

**10 种子 × 30 年 × 6 玩法，13,402 篇讣告。**

### 4.1 保护性法律不再背锅

| | 结果 |
|---|---|
| 修前 | 装了幼童口粮/医药后，**每一篇幼儿讣告**都写成「死于你写的医药」 |
| **修后** | ✅ **0 篇保护性法律被当成致死法** |

### 4.2 归因分布

| 死因 · 归因 | 篇数 |
|---|---|
| 饥饿 · **致死法** | 3989 |
| 夭折 · **缺位法** | 3590 |
| 惊吓 · **致死法** | 2036 |
| 天灾 · 无 | 1709 |
| 饥饿 · **缺位法** | 1504 |
| 夭折 · **致死法** | 394 |
| 寿终 · 无 | 144 |
| 律法 · **致死法** | 36 |

### 4.3 被点名的法

**致死法**：劳役 3966 · 私刑倾向 1811 · 减口 251 · 恐惧蔓延 225 · 童工 190 · 税收 12

**缺位法**：幼童口粮 2628 · 济贫 1504 · 公共卫生 962

> **这两张表本身就是一份玩家行为报告**：
> 「你装了劳役 → 3966 个人因它而死」
> 「你没装幼童口粮 → 2628 个孩子没能活过三岁」

## 5. 实现清单

### 5.1 存档字段（+1）

```csharp
public byte[] obituaryLawKinds = new byte[0];  // 0=无 1=致死 2=缺位
```

### 5.2 替换的调用点

```csharp
// ❌ 旧
KillVillager(data, i, "饥饿", PreferredLaw(data, 1, 3, 11));
KillVillager(data, i, "惊吓", PreferredLaw(data, 4, 6, 10));
KillVillager(data, i, "夭折", PreferredLaw(data, 9, 12));

// ✅ 新
KillVillager(data, i, "饥饿", ObitRules.AttributeSlot(data, "饥饿"));
KillVillager(data, i, "惊吓", ObitRules.AttributeSlot(data, "惊吓"));
KillVillager(data, i, "夭折", ObitRules.AttributeSlot(data, "夭折"));
```

`ObitRules.cs`（规则本体）：**不在生成文件里**，见测试台同名文件，可直接照抄。

### 5.3 讣告写入

```csharp
byte kind = (cause == "律法") ? ObitRules.KindCaused : ObitRules.LastKind;
string name = (lawIndex >= 0) ? data.lawNames[lawIndex]
            : (kind == KindMissing ? ObitRules.LastName : "");

data.obituaryLawKinds[count] = kind;
data.obituaryLawNames[count] = name;
data.obituaryTexts[count] = ObitRules.Build(data, i, cause, lawIndex, kind, name);
```

### 5.4 展示

| 归因 | 颜色 |
|---|---|
| 致死法 | `#A8322A` |
| 缺位法 | `#6B7A8A` |
| 无 | `#6B6257` |

**结算页的「最致命的法」也要用这套**：只统计 `kind == 致死`，不要统计缺位。

## 6. 验收

- [ ] 装「幼童口粮」后，幼儿讣告**不再**出现「死于幼童口粮」
- [ ] 装「医药」后同理
- [ ] 装「劳役」后，饥饿死亡的讣告**会**点名劳役
- [ ] 不装「济贫」时，饿死的讣告写「村里没有『济贫』」
- [ ] 律法处决的讣告点名**执行的那条法**
- [ ] 寿终不点名任何法
- [ ] 年份显示为 1 起（不是 0年）
- [ ] 同一种子跑两遍，讣告文本完全一致
