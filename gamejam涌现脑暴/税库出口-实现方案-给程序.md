# 税库出口 · 实现方案 — 给程序

> **一句话**：税库现在有进项（人口 ÷ 3 per 2400 tick），**但钱花不掉**。
> 加一条**官吏俸禄**（每 2400 tick 族库 − 人口 ÷ 4），让税库不再是一个只涨不花的数字。
>
> 一行代码。实测：默认玩法年末税库 **497 → 164**，闲置月 **68% → 0%**，
> 而且**还能买得起两条稀有法（60 + 40）**。

---

## 0. 先看清楚：出口其实**存在**，只是玩家不去用

这是做之前必须知道的一点。测试台把税库的每一笔进出都记下来了：

**20 种子 × 30 年，税库进项 = 人口 / 3 per 2400 tick：**

| 玩法 | 累计进 | 累计出 | 年末税库 | **闲置月占比** |
|---|---|---|---|---|
| 不装法 | 253 | 0 | 253 | 38% |
| **默认三法** | 497 | **0** | **497** | **68%** |
| **平粜（法 29）** | 494 | **474** | **20** | **0%** |
| **常平（法 51）** | 92 | **90** | **2** | 2% |
| **开垦系** | 958 | 0 | **958** | **73%** |
| 苛政 | 189 | 0 | 189 | 2% |
| **满槽6条** | 1003 | 0 | **1003** | **79%** |

「闲置」= 税库 ≥ 200 的月份占比。

**两个结论：**

1. **平粜 / 常平是有效的出口** —— 装上去之后，税库一年到头都在 20 上下，闲置 0%。
2. **但不装那两条法，钱就是死的** —— 默认玩法 68% 的月份钱 ≥ 200，开垦系 73%。

**所以「出口」缺的不是机制，是「钱不该一直躺着」这条规则。**
现行的稀有法购买（王权税契 60 / 雇佣护卫 40）是一次性的，买完就没有了；
而且它们都在 UI 层（`LawSelectionController.SelectVisible`），模拟层里测不到。

## 1. 改法：官吏俸禄

```csharp
// 紧挨着税库进项那一段
if (tick > 0 && tick % 2400 == 0)
{
    data.treasuryGold += VillageLifecycleService.CountAlive(data) / 3;   // 进项（已有）
    data.treasuryGold = Math.Max(0, data.treasuryGold
                                   - VillageLifecycleService.CountAlive(data) / 4); // ★ 新增
}
```

**含义**：养官要钱。村子越大，官俸越高。
**税库净进项 = 人口/3 − 人口/4 = 人口/12**（每 2400 tick）——
人口 48 的村子，一年净攒 4 金。

> 为什么用 `Math.Max(0, …)`：和三个资源那一轮同一个教训，**所有扣资源的写法都要兜底**。

---

## 2. 为什么是 ÷4

**20 种子 × 30 年，扫出来的档：**

| 人口 / N | 默认三法 年末 / 闲置 | 开垦系 年末 / 闲置 | 能用 60 金买几条稀有法 |
|---|---|---|---|
| 0（现在） | 497 / 68% | 958 / 73% | — |
| /10 | 375 / 54% | 678 / 62% | 6 条 |
| /8 | 340 / 48% | 608 / 58% | 5 条 |
| /6 | 281 / 34% | 484 / 47% | 4 条 |
| /5 | 234 / 18% | 388 / 35% | 3 条 |
| **/4** | **164 / 0%** | **243 / 13%** | **2 条** ✅ |
| /3 | 48 / 0% | 0 / 0% | 0 条 ❌ 买不起 |

**/4 是同时满足三件事的唯一一档：**

- 年末税库落在设计目标 **100–300**
- **闲置月 0%**（钱不再躺着）
- 仍然**买得起两条稀有法**（60 + 40 = 100）

**/3 会把税库压到 0**，稀有法永远买不起 —— 那就从「钱太多」变成「钱永远不够」。

| 平粜 | 20 | 58 | 0% | ✅ 出口在工作 |
| 常平 | 2 | 57 | 0% | ✅ 出口在工作 |

## 4. 税库的完整收支结构（改完之后）

```
进：
  人口 / 3            每 2400 tick       ← 主水源
  税收法(3)           +3 / 人 / 240 tick
  买粮法(26)          金币 → 税库
  捐纳法(28)          +20
  丁税法(27)          子女数 × 2

出：
  官吏俸禄            人口 / 4          每 2400 tick   ← 本方案新增
  平粜法(29)          −40 → 粮仓 +25     （应急换粮）
  常平法(51)          −6  → 粮仓 +10     （常规换粮）
  开垦                按格子付金币
  稀有法购买          60 / 40（一次性，UI 层）
  事件                贪墨 / 商队 / 名医
```

**这套结构里，「钱」的角色是「防灾预算」：**
平时吃俸禄，灾年靠平粜把粮买回来，富裕时买稀有法。
**它不再是一个只能一直涨的数字。**

## 8. 后续（这一轮不做）

**稀有法只有两条（60 + 40），而且是一次性的。**
俸禄解决了「钱一直躺着」，但没有解决「钱买什么」。

下一轮可以考虑（按性价比）：

| 想法 | 成本 | 说明 |
|---|---|---|
| 稀有法**可重复购买**（每次涨价） | 中 | 无限出口，但会稀释稀有感 |
| 再加 2–3 条稀有法 | 低 | 每条就是一张表行 |
| 税库 → **法槽扩容** | 中 | 一次性大额消费，和「装几条法」的预算联动 |
| 税库 → **紧急事件免疫** | 高 | 要等事件系统 |

**在此之前，平粜和常平就是「出口」的主干** —— 它们已经被实测证明有效
（花掉 474 / 90，闲置 0%）。**先把俸禄加上，让不装它们的玩家也不至于把钱堆成山。**
