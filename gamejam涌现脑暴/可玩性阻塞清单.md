# 可玩性阻塞清单

> **验证对象**：`testgame` 里的 `Assembly-CSharp.dll`（116,736 字节，2026-10-10 22:52）
> **方法**：把模拟层抽出来编译成独立控制台程序，跑 200 seed × 5–30 年。所有数字都是实测。
> **不是代码评审，是"玩家会撞到什么"。**

---

## 总裁决

| | |
|---|---|
| 模拟层本身是**活的** | 出生 8.6/年、死亡 8.3/年、税库正常、金币正常、老死分布正确（中位 83–84 岁） |
| **但玩家的选择产生不了可观测的后果** | 装 5 条法 和 一条法都不装，**HUD 上三个数字完全一样** |

**一句话**。游戏在跑，但玩家做的事**看不出区别**。

---

## 一类 · 玩家的选择看不见（最致命）

### 1.1 ★ 威信永远是 100 ★

```csharp
public int prestige = 100;
// 全项目唯一一处写它：
data.prestige = Mathf.Clamp(data.prestige, 0, 9999);   // 在 Normalize 里
```

**HUD 上那个最显眼的数字，从头到尾不会变。**

我最早那份审计把这条列为 P0-1，**到现在一个字没动**。它是唯一直接回答"玩家贴完法之后干什么"的机制——没有它，玩家的循环是：

```
贴 3 条法 → 看数字 → 没有第 4 步
```

### 1.2 ★ 装法 vs 不装法，HUD 数字一模一样 ★

200 seed × 5 年，终局均值：

| 律法组合 | 存活 | 粮仓 | 均金币 | 均饥饿 | 均恐惧 |
|---|---|---|---|---|---|
| 5 条好法（济贫/耕作/税收/幼童/医药） | 44.0 | 54 | **0** | **0** | **9** |
| 5 条默认（济贫/耕作/税收） | 25.6 | 430 | **0** | **0** | **11** |
| 5 条恶法（恐惧蔓延/私刑/连坐/减口/弃老） | 5.9 | 248 | **0** | **0** | **11** |
| **全空槽（什么都不装）** | **26.2** | 335 | **0** | **0** | **11** |

**金币、饥饿、恐惧这三个数字，四组完全一样。** 玩家装什么都不影响它们。

唯一有变化的是存活数，而 **默认 25.6 vs 全空槽 26.2 —— 差 0.6**。玩家看不出来。

### 1.3 三个寄存器长期钉死，玩家永远看不到"要出事了"

一局之内（seed=7，默认法）的动态范围：

| 寄存器 | 一局内的范围 | 危险线 | 判定 |
|---|---|---|---|
| 均金币 | 46 → **0**，然后永远是 0 | — | 后半程完全静止 |
| 均饥饿 | **0 — 23** | 99 才死 | ❌ **永远够不到危险** |
| 均恐惧 | **8 — 27** | 99 才死 | ❌ **永远够不到危险** |
| 粮仓 | 0 — 475 | — | 唯一有大起伏的 |

**HUD 上三个寄存器，两个长期钉死在 0 附近，一个在小范围里微动。**

玩家盯着屏幕看到的是一排**不动的数字**。这直接毁掉"看着自己的法律生效"这件事。

## 二类 · 玩家的选择摸不着

### 2.1 ★ 68 条可换法里 53 条是装饰 ★

基准 = 济贫 + 耕作（存活 25.8），逐条加一条法测位移：

```
68 条可换法 → 载荷 11 · 弱 4 · 装饰 53
```

**77% 的法装上去和没装一样。**

### 2.2 ★ 能测出来的载荷法全是"减益法" ★

```
#62 阴气    -25.75     #51 常平    -25.74     #60 哭丧    -23.65
#53 丁税宏观 -22.13     #54 减口    -16.49     #41 丁役     -9.38
#58 光棍     -7.83     #55 绝户     -4.47     # 4 恐惧蔓延  -4.21
（还有两条是增益：#9 幼童口粮 +10.47、#12 医药 +8.89）
```

**九个载荷法里七个是"让村子更糟"。**

**这意味着现在没有"正确的立法"这个玩法。** 玩家能做的只有"别把事情搞砸"——而搞砸了也看不出来（见 1.2）。

增益法（流民法/共井/公共卫生/抚孤/互助会）**全部测不出来**，因为**村庄已经贴近天花板**，加不上去。

### 2.3 五组完全不同的律法落在同一个数上

200 seed × 5 年：

```
默认（开局自带）        25.6
只装 济贫              26.5
恶法 税收/劳役/丁税      25.4
不作为（无法状态）       26.2
恶法 饥则抢/阋墙/夺产     26.0
```

**五组全在 25.4–26.5 这 1.1 宽的区间里。** 装法、不装法、装恶法，三种完全不同的玩法，**结果一样**。

## 三类 · 玩家没有目标

### 3.1 没有终点、没有胜利条件、没有失败条件

全项目搜不到任何结束判定。游戏可以无限跑下去。

**玩家不知道"玩到什么时候算结束"，也不知道"怎样算玩得好"。**

### 3.2 灭村率 0%

| 律法组合 | 灭村率 |
|---|---|
| 好法 | 0.0% |
| 默认 | 0.0% |
| 只装济贫 | 0.0% |
| 恶法 税收/劳役/丁税 | 0.0% |
| 不作为 | 0.0% |
| 恶法 减口/弃老 | 0.0% |
| 恶法 恐惧/私刑/连坐 | 5.5% |

**只有一组能输。** 其余怎么玩都不会失败——所以"立法"没有赌注。

### 3.3 出生 8.6/年、死亡 8.3/年 —— 每 2.2 秒一条讣告

一年 = 18.5 真实秒（148 tick/秒 × 2920 tick）。

```
8.3 死/年 ÷ 18.5 秒 = 每 2.2 秒一条
```

**而讣告横幅显示 6 秒。**

→ **屏幕上永远同时挂着 3 条横幅，互相覆盖，玩家只能看到最后一条。**

献告是这个游戏唯一的情感载体。**每 2.2 秒一条，等于一条都读不了。**

## 四类 · 实现 bug

### 4.1 人口上限 80 会被突破

`ResolveBirths`

```csharp
int num2 = CountAlive(data);          // ← 只算一次
if (data.granaryFood < 30 || num2 >= 80) return 0;
int num3 = 85;
for (...) { if (CanGiveBirth) { if (Chance) { AppendChild(...); num++; } } }   // ← 循环内可多次生育
```

**`num2` 在循环外算一次，循环内可以生多个。** 实测 200 局 × 30 年，**观测到的最大总人数是 91**。

### 4.2 「多产」是死代码

```csharp
data.villagerBirthCooldown[i] = (Traits.HasInnate(data, i, 256u) ? 480 : 480);
//                                                             ↑ 两个分支一样
```

**`Innate.Prolific`（多产）这个先天词条完全不生效。**

### 4.3 三处定义了但没接

| 项 | 读取次数 |
|---|---|
| `Innate.Generous`（慷慨） | **0** |
| `Mark.Bitter`（积怨） | **0** |
| `arableCount`（地图可耕地） | **0** —— 地图仍是纯装饰 |

## 五类 · 一条隐形的规则，玩家不可能猜到

**公仓有粮 ≠ 不会饿死。**

```csharp
bool flag3 = num3 | flag | flag2;   // 济贫法命中 或 幼童 或 年龄<8
bool flag4 = gold > 0;
if (granaryFood > 0 && (flag3 | flag4))  { 才吃得到 }
```

**三个条件一个都不满足时，粮仓是满的也吃不到饭。**

这**可能是设计意图**（"没有法律授权不能动公家的粮"很符合主题），但它**完全没有被表达出来**。玩家会理所当然地以为"粮仓有粮就不会饿死"，然后看着人饿死在满仓旁边。

实测里 **不作为（全空槽）的饥饿死占 53%** —— 这个机制在起作用，但玩家看不到它。

**要么在 UI 上说，要么改掉。**

## 按"先修哪个"排序

| 序 | 修什么 | 为什么排这个位置 |
|---|---|---|
| **1** | **威信接进逻辑**（立法 −30、维持费、归零停摆） | 唯一能回答"贴完法之后干什么"的机制。HUD 上最显眼的数字现在不动 |
| **2** | **`AdvanceGranary` 产出 `population*2` → `*120/100`** | 一行改动。粮仓永远满 → 饥饿永远是 0 → 玩家的选择算不出来。改完律法阶梯从 3.3 到 48.2 |
| **3** | **改完用 30 年跑回归** | 我第一次试 80% 时 5 年数据很漂亮，30 年才发现是 subsistence 陷阱（零生育 + 零饿死，村子冻结 27 年） |
| 4 | 讣告改批量 / 提高间隔 | 每 2.2 秒一条 + 横幅 6 秒 = 一条都读不了 |
| 5 | 加结束条件 | 现在没有胜负，立法没有赌注 |
| 6 | 修人口上限的 `num2` 只算一次 | 观测到 91 > 80 |
| 7 | `? 480 : 480`、`慷慨`、`积怨`、`arableCount` | 定义了没接的小口子 |
| 8 | 在 UI 上说明"取粮需要法律授权" | 或者改掉这个机制 |

## 一条判断

> **现在的村庄不是"不好玩"，是"玩家算不出自己在干什么"。**
>
> 五个法槽、七十条候选法、一套完整的律法引擎——**但贴上去之后 HUD 上三个数字不变、屏幕上的讣告读不过来、玩到什么时候也不会输。**
>
> **第 1 条和第 2 条加起来大概一天半，它们把"选择产生后果"这件事还回来。**
