# 个人存粮 × 事件 · 实现方案 — 给程序

> **结论先说**：这条交互**能做，但它不是平衡杠杆，是叙事层。**
>
> 把私粮仓做大、让四个事件去抢它之后，30 年的结局只动了 **1–2 个人**。
> 它能给玩家「匪患把我家的粮抢光了」这句话，但**不会改变村子的生死曲线**。
>
> 如果你想要的是「又一条能杀人的机制」，这条不是。**如果你想要的是「事件碰到村民自己的东西」，这条是。**

---

## 0. 为什么现在做不到：私粮只有 2–4

`villagerFood`（个人存粮）现在的状态：

- 上限 **8**（小孩 4）
- 粮仓高于预留线时会自动往各户补，**补满只要几十 tick**
- 每 16 tick 吃 1 个单位（饥饿 −5）

实测（30 年 × 7 玩法）：**私粮全年均值 2–4。**

所以「匪患抢走一半私粮」= **抢走 1 个单位**。
第一轮测试的结果是：**开了和没开，所有指标一模一样。**

```
末人口 26 / 26 · 平均饥饿 12 / 12 · 饿死 0 / 0 · 灭村 3% / 3%
```

## 1. 第一步：把私粮仓做大

**改一个数**（`AdvanceGranary` 里的补粮循环）：

```csharp
// ❌ 原来
int num10 = ((data.villagerAges[j] < 3) ? 4 : 8);

// ✅ 改成
int num10 = ((data.villagerAges[j] < 3) ? 10 : 20);
```

**20 种子 × 30 年 × 7 玩法（劳动力经济 5×50%）：**

| 私粮上限 | 末人口中位 | 私粮均值 | 平均饥饿 | 经历过饥荒的局 | 杀村率 |
|---|---|---|---|---|---|
| 8（现在） | 25 | 2 | 16 | 49% | 0% |
| 12 | 26 | 4 | 17 | 54% | 0% |
| **20** | **26** | **8** | **16** | 56% | 1% |
| 30 | 25 | 13 | 17 | 56% | 1% |
| 40 | 25 | 18 | 17 | 58% | 1% |

**上限从 8 提到 20，村子本身几乎不变**（人口 25→26，饥饿 16→16）。
变化是：**各户手里终于有东西了**（2 → 8）。

> 选 **20 / 10**。30 以上只是让数字更大，不带来新东西。

---

## 2. 第二步：四个事件去碰它

全部加在 `EventFx.Fire` 的 switch 里，**统一受一个开关控制**：

```csharp
public static int EventFoodHit = 0;   // 0 = 关（当前构建）
```

| 事件 | 做什么 | 参数 |
|---|---|---|
| **匪患 (6)** | 抢走每户 **50%** 的私粮 | `BanditStealPct = 50` |
| **民变 (3)** | 砸掉每户 **30%** | `RiotStealPct = 30` |
| **蝗灾 (0) / 寒潮 (5)** | 损耗每户 **20%**（虫吃、冻坏） | `ColdSpoilPct = 20` |
| **丰年 (7)** | 每户 **+4**（收成进了家门） | `HarvestFill = 4` |

```csharp
static void StealFood(VillageSaveData d, int pct, int hpMul, int lawPct)
{
    if (Cfg.EventFoodHit <= 0) return;
    int p = pct * hpMul / 100 * lawPct / 100;
    if (p <= 0) return;
    for (int i = 0; i < d.villagerAlive.Length; i++)
        if (d.villagerAlive[i]) d.villagerFood[i] -= d.villagerFood[i] * p / 100;
}
// SpoilFood 同实现；FillFood 用 Math.Min(上限, food + add)
```

**职业修正和对口法律照样生效**（`hpMul` / `lawPct`）：
装了**屯粮(30)** → 寒潮的私粮损耗减半；村里有**游侠** → 匪患抢得少一半。

## 3. 实测：它到底改变了什么

**上限 20 · 事件 45% · 劳动力经济：**

| 上限 | 事件不碰私粮 | **事件碰私粮** |
|---|---|---|
| 8 | 24 人 / 饥饿 16 / 饿死 2 | 23 人 / 饥饿 16 / 饿死 1 |
| **20** | **24 人 / 饥饿 17 / 饿死 1** | **22 人 / 饥饿 17 / 饿死 2** |
| 30 | 22 人 / 饥饿 17 / 饿死 2 | 21 人 / 饥饿 17 / 饿死 2 |

**极端测试**（把匪患强制成每 1800 tick 一次、每次抢 100%）：

| 上限 | 事件不碰 | 事件碰 |
|---|---|---|
| 8 | 25 人 / 饥饿 16 / 灭村 3% | 25 人 / 饥饿 16 / 灭村 3% |
| 30 | 25 人 / 饥饿 17 / 灭村 4% | 25 人 / 饥饿 **19** / 灭村 **6%** |

**结论：**

- **自然频率下：约 −1 到 −2 人 / 30 年**，饥饿不动。
- **把匪患拉满：饥饿 +2，灭村率 +2 个百分点。**
- **无论怎么调，它都不会变成「又一条能杀人的机制」。**

原因：**私粮是「流量缓冲」，不是「存量」** —— 它会被粮仓自动补满。
抢走的东西，村子几十 tick 后就补回来了。

## 4. 那到底要不要做

### ✅ 做，如果

- 你想要**事件文本里有「各家的粮」这件事**（「匪患：你家仓里的粮被搬空了」）
- 你想要**屯粮(30) / 惜食(1024) / 挥霍(2048) 这些词条在事件里有落点**
- 你想要**把私粮从 2 变成 8**，让村民面板上的「存粮」不再是恒等于 2 的装饰

### ❌ 不做，如果

- 你期待它改变生死曲线 —— **不会**
- 你希望它成为「税库/恐惧/威信」之外的第四条生命线 —— **它撑不起来**

### 我的建议

**做，但只当叙事层。** 成本低（上限一个数 + 4 个事件各一行），
而且它是**唯一一条把「事件」和「村民私产」接起来的线** ——
玩家看到「匪患」时会想到自己装没装屯粮，这个联想本身就值。

## 5. 实现清单

| # | 改什么 | 量 |
|---|---|---|
| 1 | 私粮上限 8/4 → **20/10** | 1 个数字 |
| 2 | 加 `StealFood` / `SpoilFood` / `FillFood` 三个小函数 | ~20 行 |
| 3 | 匪患 / 民变 / 蝗灾 / 寒潮 / 丰年 各加一行 | 5 行 |
| 4 | 加一个总开关 `EventFoodHit`（默认 0 = 当前构建） | 1 行 |

**工时 ≈ 0.15 天。**

## 6. 验收

- [ ] 事件开 / 关时，村民面板上的「存粮」数字**明显不同**
- [ ] 匪患触发后，各户存粮**当 tick 下降**
- [ ] 装了**屯粮(30)** 时，寒潮的私粮损耗**减半**
- [ ] 村里有**游侠**（果决词条）时，匪患抢得少一半
- [ ] 丰年之后，各户存粮**上升**
- [ ] 30 年末人口与不开这条时**相差不超过 3 人**（说明它没有偷偷变成大杠杆）
- [ ] 同一种子跑两遍结果完全一致

```
EventFoodHit   = 1
BanditStealPct = 50
RiotStealPct   = 30

```
然后 `dotnet run -c Release -- foodevent 20` → `scan22-foodevent.txt`。

## 7. 一句话

> **个人存粮现在不是一个「存量」，是一条「管道」。**
> 把管道加粗（上限 20）之后，事件才有东西可抢；
> 但它依然是管道 —— **抢走的会自己流回来。**
>
> **所以：做，但别指望它杀人。**
