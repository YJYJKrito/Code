# 《立法村》手工事件卡（Storylet / QBN）机制规格


> ⚠ **历史规格**：最终实现不是事件卡库，而是 14 个参数化事件（权重 + 兆头 + 对口法律 + 职业修正）。见 [当前机制真实规格-修复版.md](当前机制真实规格-修复版.md) 第 6 节。

> 单人 · Unity · 18 天 · 禁联网 · 双端。把"模拟式涌现"换成"编写式涌现"：把不可排期的参数研究，换成可排期的内容写作。

---

## 一、机制拆解

### 手工事件卡（storylet / QBN）机制设计

**核心结论**：把故事拆成"局部规则"而不是"路径"：作者只写 N 张带门禁的条件→效果卡，每 tick 由确定性 PRNG 在满足门禁的候选池里加权抽卡，卡的效果是对整数寄存器/关系表/事件表的写入。玩家经历的路径不在任何一张卡里，而在"卡 × 状态轨迹"的交点上——所以它能是"没人写过的后果"，同时和模拟共用同一批寄存器、天然共存，且完全确定性可哈希。

## 0. 全局分层（先建立心智模型）

三层，严格单向数据流，谁都不许反向污染：

1. **律法层（连续演化）**：玩家选的 5 条律法，每 tick 对寄存器做确定性运算（金币扣减、饥饿累积、恐惧传导）。纯整数、纯函数。
2. **事件卡层（离散跳变，Storylet/QBN）**：每 tick 末尾求值一次，选出 0~N 张卡，对同一批寄存器做**离散写入**，并往 `LifeEvent` 表追加记录。
3. **呈现层（文本）**：讣告生成器只读 `List<LifeEvent>` + `VillageSnapshot`，模板池 + 语料出人话。**只读，绝不回写模拟。**

关键：第 2 层写的是和第 1 层**同一批寄存器**。所以"卡系统"不是叙事脚本，它是模拟的一个**扰动源/驱动器**。这正是它和模拟能共存的原因——它们说的是同一种语言（整数）。

## 1. 一张卡到底是什么

Storylet（Emily Short / Failbetter 的定义）= 一个「有前置条件 + 有后果 + 只有满足条件时才算候选」的内容单元。QBN（quality-based narrative）= 所有叙事内容都由 quality（可整数化的变量）门禁。本作里 **quality = 村民/村庄的整数寄存器 + 关系表 + 事件计数**。

**纪律第一条（最重要）**：条件与效果必须是**可枚举的有限谓词/写入集合**，不许出现 lambda、表达式字符串、任意 C# 代码。理由有三：
- 要序列化进 JSON，策划能写、能 diff；
- 要能"只读地"在 UI 上展示门禁（玩家能看懂为什么这张卡触发了）；
- 要能被哈希（第 6 节）。

### C# 结构体

```csharp
public enum ScopeKind { Village, Villager, Relation, Pair }
public enum CondKind {
 Tick, SelfHunger, SelfFear, SelfGold, SelfAge,
 SelfHasTag, SelfLacksTag, SelfEventCount,
 VillageHungerAvg, VillageFearAvg, VillageGoldAvg, VillageAliveCount,
 RelVal, // RelVal: 读 a->b 的关系值
 SelfKillCount, SelfIsAlive
}
public enum EffKind {
 AddGold, SetGold, AddHunger, AddFear, ClampHunger,
 AddTag, RemoveTag, RelAdd, SetRel,
 AddEvent, Kill, MoveTo, TransferGold
}

public struct Condition {
 public CondKind Kind;
 public byte Op; // 0:>= 1:<= 2:== 3:!=
 public int A, B; // 阈值 / tagId / 第二目标（-1=当前目标）
}

public struct WeightTerm { // 权重 = base + Σ Coef * EvalNum(Kind)
 public CondKind Kind;
 public int Coef; // 可负
}

public struct Effect {
 public EffKind Kind;
 public int Tgt; // -1=卡主目标, -2=次目标, -3=村庄
 public int V0, V1;
}

public struct StoryletCard {
 public int CardId; // 稳定 ID，进哈希
 public string TitleKey; // 呈现层文本 key，模拟层不读
 public ScopeKind Scope;
 public Condition[] Pre; // ALL-of，空数组=恒真
 public int WeightBase; // 整数，>=1
 public WeightTerm[] WeightTerms;
 public int Cooldown; // tick；0=无冷却
 public bool Once; // 一次性
 public int Priority; // 同 tick 竞争用
 public Effect[] Effects; // 有序执行
}
```

### JSON 示例（一张真实可写的卡：「讨饭」）

```json

 { "kind": "VillageGoldAvg", "op": ">=", "a": 5 },
 { "kind": "SelfHasTag", "a": 7 }

 "cooldown": 40,
 "once": false,
 "priority": 10,
 "effects": [

 { "kind": "AddGold", "Tgt": -1, "V0": 3 },
 { "kind": "AddEvent","Tgt": -1, "V0": 1007, "V1": 3 },

```

读法：饿到 60 以上、身上钱 ≤2、村里平均还有钱、且带着"会开口求人"标签的村民，会以随饥饿增大的权重触发。效果：向目标的一条关系 -4、自己 +3 金币、记一条 `LifeEvent(1007, 值3)`、打上"欠过人情"标签（tag 12）。**注意这里没有一个字是叙事文本**——`AddEvent` 写的是事件类型码 + 数值，人话由讣告层翻译。

`TransferGold` 这类需要双目标的卡，`Scope` 用 `Pair`/`Relation`，效果里 `Tgt=-2` 指第二个目标。

## 2. 求值算法（每 tick 怎么决定哪张卡触发）

每 tick 的理想顺序：

1. `RunLawDSL(v)` —— 律法连续演化（整数、纯函数）。
2. `RecomputeDerived(v)` —— 均值、存活数、按 id 排序的视图。
3. `EvaluateStorylets(v)` —— 建候选池 → 抽 0~N 张（见下）。
4. `ApplyCard` —— 写寄存器 + 写 LifeEvent。
5. `v.tick++`，算哈希。

### 候选池怎么筛

每张卡按 `Scope` **展开**成候选实例：

- `Villager`：对每个存活村民展开一次 → 候选是 (cardId, villagerId)。
- `Relation`/`Pair`：对每条有向边 / 无序对展开（20 人 → 190 对）。
- `Village`：整村一张。

对每个实例跑 `Passes()`：全部 `Pre` 为真 **且** 不在冷却 **且**（若 Once）没用过。性能上 250 张卡 × 约 200 实例 ≈ 5 万次谓词判断/tick，1 tick/秒毫无压力，不需要优化。

### 怎么加权随机 / 随机数从哪来

- 权重是**整数**：`w = WeightBase + Σ Coef_i × 数值_i`，最后 `w = max(w, 1)`（保证 total>0，绝不平局除零）。
- 抽法用整数前缀和 + `r ∈ [0,total)`：`acc += w; if (r < acc) pick`。**不要用 float 归一化**。
- 随机数**绝不**用 `System.Random`（跨 Unity 版本/平台行为有过差异），自写 splitmix64/xorshift，`unchecked` 整数运算。
- **按 channel 隔离随机流**：`RngFor(seed, tick, channel)`，channel 区分「抽卡 / 权重微扰 / 效果细节 / 讣告选词」。这样"多加一张卡"不会扰动下游所有随机，否则任何改动都会让整局崩盘、回放对不上。

### 优先级与每 tick 触发上限

- 候选按**全序**排序：`Priority` 降序 → `CardId` 升序 → `TargetId` 升序。全序是硬要求，权重相等时不能靠"列表顺序"决定（那个顺序会因候选增删而变）。
- 按优先级分层：先在第一优先级层内加权抽 1 张，扣配额；不够再进下一层。
- **同一 cardId 每 tick 最多触发一次**（用 `usedCards` 去重），否则一张卡可能在 20 个人身上同时刷屏。
- `MaxCardsPerTick` 建议 = 1~2。理由：玩家是"逐秒看村庄"的，每 tick 一张卡节奏才可感知；同时保证性能与因果链清晰（一 tick 内多张卡互相影响会让因果难读、也难调试）。

## 3. 冷却与去重

**冷却挂谁**：挂 **(卡, 目标)** 这个二元组，不是挂卡、也不是挂村。

- 卡上写的是 `Cooldown`（时长），**运行时状态** `lastFired` 挂目标：村民卡挂人（张三讨过饭，40 tick 内不再讨）、村卡挂村、关系卡挂这条边。
- 为什么挂人：20 个人各自独立，A 讨饭不该让 B 不能讨饭；但同一人要压住连续触发，否则"饥饿"会让同一张卡每 tick 都中奖。
- 数据结构**用扁平 int 数组不用 Dictionary**：`lastFired[cardId * numTargets + targetId]`。规模 = 250 × (20+1+190) ≈ 5.3 万 int，完全放得下。好处：确定、无哈希顺序问题、可整块进快照与哈希（题目已禁 Dictionary 迭代依赖）。

**一次性 vs 可重复**：
- 通用化：给卡加 `MaxTriggers`（默认 `-1`=无限）。`Once=true` 只是 `MaxTriggers=1` 的语法糖。
- 运行时 `triggerCount[]` 同冷却是并行数组。
- "一次性"用于剧情节点（初雪、第一桩谋杀、村长的死）；"可重复"用于生活流（讨饭、口角、偷窃）。

**去重不止一层**，要分清：
- **卡的重复** → 冷却 + MaxTriggers 解决。
- **语义重复**（"这个人已经饿死过一次了"）→ 用**门禁本身**解决：卡里写 `SelfEventCount(饿死) == 0`。
- **文本重复**（同模板连着出）→ 属于呈现层，由讣告的语料选择器处理（见第 4 节 deck），与卡无关。

冷却状态**必须进 VillageSnapshot 并进哈希**，否则存档/回放会分叉。

## 4. deck 抽牌模型 vs 权重随机模型

两种 QBN 实现：

- **Deck（抽牌）**：把候选洗成牌堆，抽完重洗，保证均匀覆盖、不重复上桌。
- **权重随机**：每次独立按权重抽，可重复。

**本作用权重随机为主，唯一用 deck 的地方是讣告文本的语料/模板选择。**

理由（按重要性）：

1. **候选池是动态的**。QBN 的候选依赖寄存器，每 tick 候选集合都在变；deck 要求"卡池收敛、可洗牌"，而这里牌堆随时被门禁撕碎，洗牌语义崩溃。
2. **权重能表达连续强度**。"越饿越容易抢"就是 `w += 2 × Hunger`。这正是本作商业卖点——把"参数调优"从模拟层搬到了权重层，玩家调的是权重场，作者调的是系数。
3. **deck 的均匀性是害的**。均匀意味着小康之家也会抽到饥荒卡。门禁管"适用性"，权重管"强烈程度"，这个分工比 deck 干净。
4. **确定性友好**。权重随机只需一个整数随机数；deck 要维护洗牌状态，且候选一变就要重洗，哈希和回放都变复杂。
5. **唯一例外**：讣告的措辞模板、开场白、句尾语气词——**这里用 deck**，洗牌保证 10 篇讣告不撞句。这个决定很关键：它把"多样性"这件事从模拟层彻底挪到呈现层，模拟层保持纯净。

可选增强（有余力再做）：在**节拍/结构层**用 deck 控制叙事弧，例如"本局必须出现 1 次谋杀、至多 2 次死亡"，这是 QBN 里的 dramatic beat / structure 限制，用一次性卡 + 全局配额实现即可，不要真去维护牌堆。

## 5. 命门：路径为什么没被编写

这是整个方案的正当性所在，必须讲透。

**作者写的是"卡"（局部规则），不是"路径"（全局序列）。** 玩家经历的是一条具体路径 = 卡 × 目标 × 顺序 × 状态轨迹。区别在于：

**(a) 组合爆炸。** 20 个村民各有一局生命周期，若每人平均经历 10 个事件，每人可触发的卡约 30 张，单人路径上界约 30^10 ≈ 6×10^14 条，20 人再叠。门禁和不均权重当然砍掉绝大多数，但**剩下的量级已远超任何手写脚本**。作者写的不是 6×10^14 条路径，是 250 张卡 × 平均 3 个条件 ≈ 750 个局部约束。

**(b) 递归依赖——这才是真正说服反方的一点。** 门禁里大量条件读的是**村民自己的历史**（`SelfEventCount`、`SelfHasTag`、关系值）。而历史是前面若干张卡叠加写出来的。于是第 k 张卡是否触发，**取决于前 k-1 张卡写了什么**——而前 k-1 张又是同一套规则跑出来的。这不是"作者选了 A→B→C"，是"状态机在作者写的规则下**自己走到了** C"。作者的笔只落在规则上，路径是规则的不动点。

**(c) 权重被寄存器调制。** 同一张讨饭卡，富时权重 1、饿时权重 60。触发时刻由全村状态决定，不由作者排定。作者甚至无法预测它在哪一局、哪一秒触发。

**(d) 玩家在调偏置场。** 玩家选的 5 条律法持续改写寄存器（金币、饥饿、恐惧），等于**每局给同一个卡池施加不同的偏置场**。同一套卡，换一组律法，抽出来的路径就完全不同。这就是"他们死于你写的法律"能成立的技术机制：法律不直接杀人，法律改变权重场，权重场改变事件序列，事件序列杀死村民。

**(e) 玩家排序改求值顺序。** 优先级由玩家排布，改变了同 tick 的竞争结果，进而改变后续状态轨迹——又一条"玩家输入 → 路径"的通路。

**类比（对质证最有效）**：象棋作者写了 32 个子和 6 种走法，没写任何一局棋；生命游戏作者写了 4 条邻居规则，没写任何滑翔机。**规则 ≠ 路径，这正是本届主题「涌现」的定义。**

**但要诚实，手写卡有它自己的天花板**（反方一定会追这一点）：

- **覆盖度不够就退化成随机轮盘**。卡太少、条件太宽（都恒真），就变成每 tick 掷骰子抽事件，玩家感到的是"噪声"不是"命运"。所以门禁**必须读历史**，路径感全从这来。建议 120~250 张，且条件互相咬合（A 卡写的 tag 是 B 卡的门禁）。
- **条件太窄就退化成脚本**。每张卡只有一个触发点、只可能触发一次，那就成了手写剧情。要求门禁"常开但偏置"：条件普遍可满足，靠权重和冷却拉开差异。
- **作者仍要写"钩子"**。你要故意设计几条**长链**（讨饭 → 欠人情 → 被逼偷窃 → 被流放 → 冻死），让门禁一环比一环严，这些链是"看起来像编排的涌现"，是体验的高光。手写卡不排斥人工编排，它只是让编排以规则形式存在。

一句话总结第 5 节：**路径不在任何一张卡里，它在卡与状态轨迹的交点上；因此玩家体验到的后果，确实没有人在任何一行数据里写过。**

## 6. 确定性（同 seed 双端哈希一致）

这套机制**天生适合**确定性，前提是守住下面几条纪律：

1. **决策层零浮点**。权重、累加、比较、坐标全整数/定点。表现层（插值动画、粒子）可以用 float，但**绝不能回写模拟**。位置用整数格或 1/1000 定点。
2. **自写 PRNG，不用 System.Random**。splitmix64/xorshift128，`unchecked` 整数运算。跨端、跨 Unity 版本行为完全一致。
3. **随机流按 channel 隔离**：`RngFor(seed, tick, channel)` 或每系统独立实例。避免"加一张卡扰动了后续所有随机"——这是回放对不上最常见的根因。
4. **遍历顺序必须确定**：卡按 CardId 排序；村民按 id 升序；关系边按 (a,b) 升序；冷却用数组不用 Dictionary（题目已禁迭代依赖）。候选排序用**全序** `(Priority, CardId, TargetId)`，不能只按权重排。
5. **冷却/次数状态进快照、进哈希**。这是最容易被漏的一条——忘了它，replay 会在某 tick 悄悄分叉。
6. **哈希内容与顺序固定**：每 tick 写 `tick` → 每个村民按 id 升序的 `{gold,hunger,fear,x,y,tag位掩码}` → 关系表按 (a,b) 顺序 → `lastFired`/`triggerCount` 数组 → PRNG 状态摘要，喂 FNV-1a/xxhash。双端逐 tick 比对，第一处不一致的 tick 就是 bug 所在。
7. **卡定义 JSON 本身要校验**：对卡文件算 hash 一并比对，防止两端资源不同步（这个坑隐蔽且致命）。
8. **表现层随机另起种子**（如 `seed ^ 0xDEADBEEF`），独立流，绝不触碰模拟流。
9. **整数权重抽卡用取模 `%` 时注意全用无符号**（`%` 对负数行为跨语言不一），或在 `[0,total)` 上做无符号取模。取模有轻微偏置，但**一致性优先于均匀性**——两端一致比统计完美重要得多。

**伪代码**：

// ===== 常量与状态 =====
const int CH_DEAL = 1; // 抽卡通道
const int CH_WOBBLE = 2; // 权重微扰通道（可选）
const int CH_EPILOG = 3; // 讣告选词通道（在表现层用）
const int MAX_CARDS_PER_TICK = 1;

// 村庄里与卡系统相关的状态（全部进 Snapshot 与 Hash）
// lastFired[cardId*numTarget + targetId] : int 上次触发的 tick
// triggerCount[同上] : short 已触发次数
// numTarget = 1(村) + 20(人) + 190(关系)

// ===== 主循环 =====
void Tick(Village v) {
 RunLawDSL(v); // 律法：连续演化，纯整数
 RecomputeDerived(v); // 均值/存活数/排序视图
 var picks = EvaluateStorylets(v);
 foreach (var p in picks) ApplyCard(v, p.card, p.t0, p.t1);
 v.tick++;
 v.hash = HashState(v); // 双端比对
}

// ===== 求值：筛池 + 分层加权抽 =====
struct Cand { StoryletCard card; int t0; int t1; int priority; int cardId; }

List<Cand> EvaluateStorylets(Village v) {
 var cands = new List<Cand>(1024);

 foreach (var card in v.deckSortedByCardId) { // 顺序铁定
 switch (card.Scope) {
 case ScopeKind.Villager:
 foreach (int pid in v.AliveIdsAscending)
 if (Passes(v, card, pid, -1)) cands.Add(new Cand{card,t0=pid,t1=-1,...});
 break;
 case ScopeKind.Relation: // (a,b) 升序
 foreach (var e in v.RelationsAscending)
 if (Passes(v, card, e.A, e.B)) cands.Add(new Cand{card,t0=e.A,t1=e.B,...});
 break;
 case ScopeKind.Village:
 if (Passes(v, card, -1, -1)) cands.Add(new Cand{card,t0=-1,t1=-1,...});
 break;
 }
 }

 // 全序排序：Priority 降序, CardId 升序, t0 升序, t1 升序
 cands.Sort((x,y) => {
 if (x.priority != y.priority) return y.priority - x.priority;
 if (x.cardId != y.cardId) return x.cardId - y.cardId;
 if (x.t0 != y.t0) return x.t0 - y.t0;
 return x.t1 - y.t1;
 });

 var picked = new List<Cand>();
 bool[] cardUsedThisTick = new bool[v.deckMaxId + 1];
 int quota = MAX_CARDS_PER_TICK;

 int i = 0;
 while (i < cands.Count && quota > 0) {
 // 同一优先级切成一段
 int j = i;
 while (j < cands.Count && cands[j].priority == cands[i].priority) j++;

 // 段内过滤掉本 tick 已用过的 cardId
 int total = 0;
 for (int k = i; k < j; k++)
 if (!cardUsedThisTick[cands[k].cardId]) total += WeightOf(v, cands[k].card);

 if (total > 0) {
 ulong r = RngFor(v.seed, v.tick, CH_DEAL);
 int roll = (int)(r % (ulong)total); // 无符号取模：[0,total)
 int acc = 0;
 for (int k = i; k < j; k++) {
 if (cardUsedThisTick[cands[k].cardId]) continue;
 acc += WeightOf(v, cands[k].card);
 if (roll < acc) {
 picked.Add(cands[k]);
 cardUsedThisTick[cands[k].cardId] = true;
 quota--;
 break;
 }
 }
 }
 i = j; // 进入下一优先级层
 }
 return picked;
}

// ===== 门禁 + 冷却/一次性 =====
bool Passes(Village v, StoryletCard c, int t0, int t1) {
 for (int k = 0; k < c.Pre.Length; k++)
 if (!EvalCond(v, c.Pre[k], t0, t1)) return false;

 int idx = Slot(v, c.CardId, t0, t1);
 if (c.Once && v.triggerCount[idx] > 0) return false;
 if (c.Cooldown > 0 && v.tick - v.lastFired[idx] < c.Cooldown) return false;
 return true;
}

int Slot(Village v, int cardId, int t0, int t1) {
 int target = (t0 < 0) ? 0 // 村卡
 : (t1 < 0) ? 1 + t0 // 村民卡
 : 1 + v.NumVillagers + PackPair(t0, t1); // 关系卡
 return cardId * v.NumTargets + target;
}

// ===== 权重（整数，绝不为 0）=====
int WeightOf(Village v, StoryletCard c) {
 int w = c.WeightBase;
 for (int k = 0; k < c.WeightTerms.Length; k++)
 w += c.WeightTerms[k].Coef * EvalNum(v, c.WeightTerms[k].Kind, /*target*/ 0, -1);
 return w < 1 ? 1 : w;
}

// ===== 应用效果 =====
void ApplyCard(Village v, StoryletCard c, int t0, int t1) {
 for (int k = 0; k < c.Effects.Length; k++)
 ApplyEffect(v, c.Effects[k], c, t0, t1); // 只写寄存器/关系表/事件表
 int idx = Slot(v, c.CardId, t0, t1);
 v.lastFired[idx] = v.tick;
 v.triggerCount[idx] = (short)(v.triggerCount[idx] + 1);
}

void AddEvent(Village v, int pid, int evKind, int value) {
 v.villagers[pid].life.Add(new LifeEvent{ tick = v.tick, kind = evKind, value = value });
}

// ===== 确定性 PRNG =====
ulong SplitMix64(ulong x) {
 unchecked {
 x += 0x9E3779B97F4A7C15UL;
 x = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9UL;
 x = (x ^ (x >> 27)) * 0x94D049BB133111EBUL;
 return x ^ (x >> 31);
 }
}
ulong RngFor(ulong seed, int tick, int channel)
 => SplitMix64(seed ^ ((ulong)tick * 0x100000001B3UL) ^ ((ulong)channel << 48));

// ===== 哈希 =====
ulong HashState(Village v) {
 ulong h = 1469598103934665603UL; // FNV offset
 h = Mix(h, (ulong)v.tick);
 foreach (int pid in v.IdsAscending) { // 人：固定字段序
 var p = v.villagers[pid];
 h = Mix(h, (ulong)p.gold); h = Mix(h, (ulong)p.hunger);
 h = Mix(h, (ulong)p.fear); h = Mix(h, ((ulong)p.x << 32) | (uint)p.y);
 h = Mix(h, p.tagBits); // 位掩码
 }
 foreach (var e in v.RelationsAscending) { // 边：(a,b) 序
 h = Mix(h, ((ulong)e.A << 32) | (uint)e.B);
 h = Mix(h, (ulong)e.val);
 }
 for (int i = 0; i < v.lastFired.Length; i++) { // 冷却/次数必须进哈希
 h = Mix(h, (ulong)v.lastFired[i]);
 h = Mix(h, (ulong)v.triggerCount[i]);
 }
 return h;
}

**最容易做错**：- 把叙事文本写进卡的「效果」里。效果只能是寄存器/关系表/事件表写入；文本属于呈现层，写进去会让卡系统无法和模拟共用寄存器、也无法哈希。
- 冷却挂错维度：挂「卡」会让全村共享一个冷却（A 讨饭导致 B 不能讨）；挂「村」同理。必须挂 (卡, 目标) 二元组。
- 用 Dictionary 存 lastFired/triggerCount。读取也许没事，但一旦迭代就引入哈希顺序，双端不一致；且无法整块进快照。用扁平 int 数组。
- 候选排序只按权重。权重相等时顺序由列表插入顺序决定，而候选会随状态增删而变动 → 结果不确定。必须用全序 (Priority, CardId, TargetId)。
- 权重可能为 0 或负：`total==0` 时 `%0` 崩溃或除零。权重必须 clamp 到 >=1。
- 用 float 归一化算权重或抽卡。这是双端哈希分叉的头号来源；权重累加、roll、比较全用整数。
- 用 System.Random。跨 Unity 版本/平台行为有过差异；必须自写 splitmix64/xorshift 并用 unchecked。
- 单一全局 PRNG 流。加一张卡、改一次候选顺序就污染后续所有随机，回放全崩。按 channel 隔离随机流（抽卡/微扰/讣告选词各一路）。
- 忘了把 lastFired/triggerCount 放进 Snapshot 和 Hash。第 N tick 悄悄分叉，极难定位。
- 卡定义 JSON 未做资源校验。两端卡文件不同步时哈希不一致，排查方向会被完全带偏——对卡文件本身也要算 hash 比对。
- 门禁条件太宽（恒真）→ 退化成随机轮盘，玩家感到噪声；太窄（只有单一触发点）→ 退化成手写脚本。要求「常开但偏置」：普遍可满足 + 靠权重与冷却拉开差异，且条件必须读历史（SelfEventCount/SelfHasTag）才有路径感。
- 一 tick 让同一张卡在 20 个人身上同时触发 → 刷屏。同 cardId 每 tick 必须去重，MaxCardsPerTick 建议 1~2。
- 用 lambda / 表达式字符串写条件。无法序列化给策划、无法在 UI 展示门禁、无法安全哈希。条件必须是可枚举的有限谓词集合。
- 表现层随机（粒子、抖动）复用了模拟 PRNG 流。必须另起独立种子，否则表现层的任何改动都会改模拟结果。

### 手工事件卡（storylet/QBN）与玩家律法的耦合机制

**核心结论**：律法不是卡的"外挂变量"，而是卡的**第三类输入源**：它同时充当（a）gate——卡的前置条件可以查询律法的运行时命中统计；（b）modifier/分岔——同一张卡在不同律法下走不同 branch，且 branch 的仲裁由玩家排布的律法优先级决定；（c）因果父节点——每条由律法直接引发的 LifeEvent 打上 causeLawSlot 指针。三个接口都靠同一个中间层 LawRuntime（每 tick 重算一次的定长数组）打通，卡侧永远只读缓存、只读聚合量（hitsThisTick/hitsTotal/lastHitTick），不硬编码 slot 序号、不硬判断阈值。这样"他们死于你写的法律"就从一句宣传语变成了可回溯的有向无环因果链。

## 总体架构：三层

1. **PlayerLaw（玩家层）**：玩家从 12 条预设选 5 条、调参、排布优先级。存为 slotIndex 0..4（越小越优先）。
2. **LawRuntime（运行时中介层）**：每 tick 由律法引擎重算一次的定长数组，暴露"命中人数/累计命中/最近命中 tick/致死数"等聚合量，以及"效果→slot"索引表。这是卡唯一能看到的律法视图。
3. **Card（作者层）**：静态手工数据。gate 里可以出现 law(...) 原子；branch 里可以带 requiresLaw；结算后产出带 causeLawSlot 的 LifeEvent。

关键原则：**卡→律法只走 LawRuntime 这一条窄接口**。卡作者不能直接访问 PlayerLaw 的原始字段，只能查聚合统计或 via 语义选择器解析出的 slot。

## 1. 律法进入卡的前置条件

### 数据结构

```
enum CondType { HUNGER, GOLD, FEAR, REL, STOLEN, DEATH, TAG, TICK } // 8 项条件池
enum EffectType { ROB, FEED, ALLY, BREAK, FLEE, REPORT, HOARD, BEG, HARM, SUICIDE, PRAY } // 11 项效果池

struct PlayerLaw { // 玩家局内实例
 int slotIndex; // 0..4 排布顺序即优先级
 int defId; // 引用哪条预设 1..12
 CondType condType;
 int condThreshold; // 玩家调的参数（定点整数）
 EffectType effType;
 int effMagnitude; // 玩家调的参数
}

struct LawRuntime { // 每 tick 重算，卡只读这个
 int slotIndex, defId;
 CondType condType; int condThreshold;
 EffectType effType;
 int hitsThisTick; // 本 tick 命中人数
 int hitsTotal; // 历史累计命中
 int lastHitTick; // 最近命中 tick，-1=从未
 int victimsTotal; // 直接致死累计
}

LawRuntime[] laws = new LawRuntime[5]; // 定长数组，禁 Dictionary
int[] effectFirstSlot = new int[EFFECT_COUNT]; // 效果→最优先 slot，-1=无
```

### 卡的引用方式：语义选择器，不是 slot 序号

卡里引用律法**绝不写死"第 2 条法"**（玩家一换顺序就崩），而是用 LawSelector：

```
LawSelector :=
 ByEffect(e) // "哪条法效果是抢邻居" → effectFirstSlot[e]
| ByCond(c) // "哪条法条件是饥饿" → 扫 laws 找 condType==c
| AnyEffect(e) // 同 ByEffect，语义上强调"存在即可"
| ByIndex(i) // 仅调试用，脆弱
```

`ResolveLaw(sel, world) -> int` 把选择器解析成当前 slot，返回 -1 表示玩家没选这条法。

### 卡的 gate DSL

```
gate := AND|OR|NOT|atom
atom :
 self.hunger REL K
 | v.fear REL K
 | self.tags has "怯懦"
 | rel(self, other) REL K
 | law(sel).hitsThisTick REL K // 本 tick 命中人数
 | law(sel).hitsTotal REL K // 历史累计
 | law(sel).lastHitTick >= tick - K // 最近 K tick 内触发过
 | law(sel).condThreshold REL K // 读玩家调的具体阈值
 | law(sel).effType == ROB // 语义判断
 | AllLawsSilent(K) // 反遮蔽兜底用
```

### 劫匪卡实例

```
Card "劫掠" gate:
 AND( self.hunger > 60,
 law(AnyEffect(ROB)).hitsThisTick >= 1, // 村里此刻确实有人在抢
 self.tags has "怯懦",
 tick > 3 )
```

注意这里读的是 **hitsThisTick（聚合量）而不是 condThreshold（原始阈值）**。玩家把饥饿阈值从 60 调到 80，卡的命中人数自然变少、卡自然变难触发——参数通过模拟间接、连续地作用在卡上，而不是当开关用。这是整个设计最容易被做错的地方，也是最优雅的地方。

## 2. 律法改写卡的效果

两种手法，可叠加：

### 手法 A：效果修饰（modifier / 打折放大）

```
Card "邻人施粥"
baseEffect: { target.hunger -= 30; self.gold -= 5 }
modifiers:
 if law(ByEffect(HOARD)).hitsTotal > 0: self.gold -= 20 // 村里有人藏粮，施粥者自己也揭不开锅
 if law(ByEffect(ROB)).hitsThisTick > 0: target.hunger += 0 // 大家忙着抢，施粥被无视，效果归零
```

### 手法 B：分岔（branch override）—— 戏剧性来源

同一张卡，不同律法走不同结局：

```
Card "老人病了" gate: self.age > 60 && self.hunger > 40
 branch 0 (default): 邻居送饭 → self.hunger -= 40 // 永远存在的兜底
 branch 1 requiresLaw=AnyEffect(ROB), gate: law(...).hitsTotal > 10:
 没人送饭，反有人来抢粮 → self.hunger += 20; self.gold -= 10
 branch 2 requiresLaw=AnyEffect(FEED), gate: law(...).hitsTotal > 10:
 送饭成义务 → self.hunger -= 40; giver.hunger += 30
 branch 3 requiresLaw=ByCond(FEAR), gate: law(...).condThreshold <= 30 && v.fear > 60:
 人人自危，老人被当累赘驱逐 → self.pos = 村外; self.hunger += 50 // 等死
```

**仲裁规则**：多个 branch 同时成立时，谁对应的律法 slotIndex 更小（排得更前），谁的支线赢。

```
SelectBranch:
 best=null; bestSlot=INF
 for b in branches where b.requiresLaw!=None and EvalGate(b.gate):
 slot = ResolveLaw(b.requiresLaw)
 if slot>=0 and slot<bestSlot: best=b; bestSlot=slot
 return best ?? card.defaultBranch
```

这把"优先级顺序由玩家排布"从 UI 概念落到了卡的执行逻辑上：玩家调的不是数值，是"哪条法在抢戏"。

**硬规则：每张卡必须有一个 default branch。** 否则遮蔽时卡变成空白，这是第 4 节兜底的根基。

## 3. 因果链

### 数据结构

```
struct LifeEvent {
 int id, villagerId, tick;
 EventType type;
 int parentEventId; // 上一环，-1=根
 int causeLawSlot; // 直接引发的律法 slot，-1=非律法因
 int causeLawDefId;
 int causeDepth; // 距律法隔几跳
}
```

### 链的构建

每 tick 内事件按时间顺序串成链：律法引擎产出的 law-event 是链头（causeLawSlot=自己），下游一切由它衍生的事件都把它设为 parent，并累加 causeDepth。

老人之死链：
```
E100 tick41 法#3(ROB) 命中5人 causeLawSlot=3 depth=0
E101 tick41 赵四用卡"劫掠"抢了老人A parent=100, causeLawSlot=3, depth=1
E102 tick42 老人A hunger=91 parent=101, causeLawSlot=-1, depth=2
E103 tick43 老人A 死亡（卡"饿殍"） parent=102, causeLawSlot=-1, depth=3
```

### 讣告回溯

从死亡事件起沿 parentEventId 上溯，记录**沿途最近一次 causeLawSlot>=0 的那一跳**即为罪魁；同时统计一生事件里每条法命中几次（多律法归因）。

```
AttributeDeath(v):
 ev = events[v.lastEventId]; slot=-1; def=-1; depth=0
 while ev != null:
 if ev.causeLawSlot>=0: slot=ev.causeLawSlot; def=ev.causeLawDefId
 depth++; ev = ev.parentEventId>=0 ? events[ev.parentEventId] : null
 return (slot, def, depth)

MakeObituary(v):
 (slot,def,depth) = AttributeDeath(v)
 perLaw = CountEventsPerLaw(v) // int[12]，每条法命中次数
 s = Pick("死因模板", depth) // depth==1 直接 / >=2 间接
 if slot>=0:
 s += "第"+(slot+1)+"条法："+PRESET[def].name
 second = TopOtherLaw(perLaw, def)
 if second>=0: s += "还有第"+(second+1)+"条法，"+PRESET[second].name+"，让这事更糟。"
 s += FillCorpus(v.lifeStats, perLaw) // 模板池+语料+数值→措辞映射，禁 LLM
 if depth>=2: s += "他不是被谁杀的。他只是活在你写的法里。"
 return s
```

depth 直接控制措辞语气：depth==1 是"他死于那条法"（凶手明确），depth>=2 是"他只是活在你的法里"（结构性、更冷、更有力）。perLaw 数组支撑"第 2 条法让他变穷，第 3 条法让穷变成了罪"这种双法协同句式。

## 4. 防止律法遮蔽手工卡（死水）

五道防线，从弱到强：

1. **每卡必有 default branch**：卡至少有一条不依赖 law() 的支线，从"默认世界"角度总能偶尔满足。即使所有法不生效，基础循环仍在跑。
2. **反遮蔽 safety-net 卡**：专门写 gate 为 `AllLawsSilent(K)` 的卡。例"长老的困惑"：20 tick 内 5 条法全未命中 → v.fear += 15，日志"村里静得可怕，律法像死了一样"。它给玩家显式信号，并轻轻推变量让律法重新点火。
3. **输入约束（活区）**：玩家调参钳制在安全区间（如饥饿阈值只允许 30..80），杜绝"全太阳/全太阴"的非法极端。再加效果池配额：5 条法不得全为同一效果（相似性检查），否则单一策略就通关。
4. **确定性熵注入**：每 K tick 由自带 PRNG 给随机 1 个村民 +5 饥饿或 +5 恐惧，seed 固定 → 双端哈希一致。保证哪怕是完美稳态法，世界也会漂出稳态。
5. **律法疲劳**：`hitsThisTick > F` 时该法效果折扣。**必须用整数实现**（"每 2 次命中打 1 次折"），不得用 ×0.5 float，否则破坏定点与双端一致性。

**卡作者准则**：gate 用 OR 连接"一个律法条件 + 一个人性条件"，同一张卡两层表现：
```
OR( law(AnyEffect(ROB)).hitsThisTick>=1, // 有法走律法线
 self.tags has "贪婪" && self.gold<10 ) // 没法走本性线
```

## 5. 制造"我改一条法看看"的冲动

- **回流钩子·命中热力条**：每日结算面板给每条法一条历史命中曲线。看到"第 3 条法连续 3 天命中 0 次"或"一刀切命中 40 次"，改法冲动立刻产生。
- **回流钩子·反事实"如果"**：讣告尾句给假设——"如果第 3 条法的饥饿阈值是 80 而不是 60，也许他还能撑过这个冬天。"（前 3 天可用确定性重算做真实反事实，整局重算成本高，需限额。）
- **失败反馈·民怨卡**：某法命中过多 → 触发"民怨"，村民在日志里顶撞律法，把"你的法在害人"说白。
- **可对比性·同 seed 重开**：这是最强驱动。因确定性 + 同 seed 哈希一致，玩家可以"只改一条、其他全不动、同 seed 重跑"，看到唯一变量造成的分岔。配一个并排 replay，两个世界的村民命运逐一对照。
- **触发时机**：第一次有人死且讣告点名律法 / 某法连续 0 命中（白写了）/ 某法命中爆表（太狠了）——三个节点都是改法的天然冲动点。

## 6. 完整走查

**玩家选 5 条法（顺序=优先级）**
```
slot0 法A：饥饿>60 → 抢邻居(ROB)
slot1 法B：恐惧>70 → 逃跑(FLEE)
slot2 法C：金币<10 → 藏粮(HOARD)
slot3 法D：有人被偷 → 举报(REPORT)
slot4 法E：每5天 → 祈祷(PRAY)
```

**第1天**：饥饿缓升，法A 偶尔 hitsThisTick=1，世界正常。
**第3天**：三人饥饿>60，法A hitsThisTick=3 → 触发卡"劫掠"（gate 要 law(AnyEffect(ROB)).hitsThisTick>=1）→ 穷村民赵四抢了王老爹的粮。因果：E100（法A命中）→ E101（赵四劫掠）。
**第4天**：王老爹金币掉到 8，触发法C 藏粮——藏了粮，也没分给病中老妻。
**第5天**：法D（有人被偷→举报）被赵四的劫掠触发，赵四关系崩盘。
**第7天**：恐惧升高，法B 触发，两个胆小村民逃村，劳动力下降，剩下的人更饿。
**第9天**：王老爹 hunger=91，age>60，触发卡"老人病了"。分支仲裁：branch1（requiresLaw=AnyEffect(ROB)，slot0，hitsTotal>10）成立且 slot0 最优先 → 走 branch1，没人送饭反有人来抢粮。
**第10天**：王老爹死亡，E103 parent→E102(饥饿)→E101(劫掠)→E100(法A)。

**讣告回溯**：culprit = slot0 = 法A，causeDepth = 3 → 走"间接"模板：
> 王老爹，六十七岁，死于第十天的冬天。
> 他不是被谁杀死的。他只是活在你写的法里。
> 第一条法说：饥饿的人可以抢。于是赵四抢了他。他又老又饿，没人敢送饭——因为家里有粮的人正忙着藏粮（第二条法）。
> 他死后，老人说：他死得不明不白。可你知道他死于什么。
> ——第 1 条法。

玩家看到"第 1 条法"高亮 + 命中热力条爆表，立刻明白是自己把饥饿阈值定到 60 定低了。改到 75 同 seed 重开，赵四不抢了，王老爹多活 4 天——冲动闭环完成。

**伪代码**：

// 定点：全部 int，禁 float
enum CondType { HUNGER, GOLD, FEAR, REL, STOLEN, DEATH, TAG, TICK }
enum EffectType{ ROB, FEED, ALLY, BREAK, FLEE, REPORT, HOARD, BEG, HARM, SUICIDE, PRAY }
enum SelKind { BY_EFFECT, BY_COND, BY_INDEX }

struct LawSelector { SelKind kind; int arg; }
struct LawRuntime { int slotIndex,defId; CondType condType; int condThreshold;
 EffectType effType; int hitsThisTick,hitsTotal,lastHitTick,victimsTotal; }
struct LifeEvent { int id,villagerId,tick; EventType type;
 int parentEventId,causeLawSlot,causeLawDefId,causeDepth; }

LawRuntime[5] laws;
int[EFFECT_COUNT] effectFirstSlot; // 每 tick 重算

// ---- 主循环 ----
Tick(world):
 RecomputeLawRuntime(world) // 先算律法，再算卡（顺序不可颠倒）
 events = []
 for card in world.cardPool:
 for v in world.villagers where v.alive:
 if EvalGate(card.gate, v, world):
 b = SelectBranch(card, v, world)
 events.push(ApplyBranch(card, b, v, world))
 events += ApplyLaws(world) // 埋 hitsThisTick，产 law-event
 for v in world.villagers where v.hunger > 100:
 events.push(DeathEvent(v, parent=v.lastEventId)); v.alive=false
 world.events.appendAll(events); world.tick++

// ---- 律法统计重算（阶段1）----
RecomputeLawRuntime(world):
 for i in 0..4: laws[i].hitsThisTick = 0
 for i in 0..EFFECT_COUNT-1: effectFirstSlot[i] = -1
 for i in 0..4:
 laws[i] = world.playerLaws[i] copy stats fields
 if effectFirstSlot[laws[i].effType] == -1: effectFirstSlot[laws[i].effType] = i

// ---- 应用律法（阶段3），按 slot 顺序=玩家优先级 ----
ApplyLaws(world):
 out = []
 for i in 0..4:
 law = laws[i]
 for v in world.villagers where v.alive:
 if EvalCond(law.condType, law.condThreshold, v, world):
 law.hitsThisTick++; law.hitsTotal++; law.lastHitTick = world.tick
 ev = MakeLawEvent(v, i, law.defId) // causeLawSlot=i, depth=0
 out.push(ev)
 ApplyEffect(law.effType, law.effMagnitude, v, world, parent=ev.id)
 return out

// ---- 选择器解析：卡不硬编码 slot ----
ResolveLaw(sel, world) -> int:
 switch sel.kind:
 BY_EFFECT: return effectFirstSlot[sel.arg]
 BY_COND: for i in 0..4: if laws[i].condType==sel.arg: return i; return -1
 BY_INDEX: return (sel.arg<5) ? sel.arg : -1

// ---- gate 求值 ----
EvalGate(g, v, world) -> bool:
 switch g.kind:
 AND: return all(EvalGate(c) for c in g.children)
 OR: return any(EvalGate(c) for c in g.children)
 NOT: return !EvalGate(g.child)
 ATOM:return EvalAtom(g, v, world)

EvalAtom(a, v, world) -> bool:
 switch a.kind:
 V_HUNGER: return v.hunger REL a.op a.val
 V_GOLD: return v.gold REL a.op a.val
 V_FEAR: return v.fear REL a.op a.val
 V_TAG: return v.tags has a.val
 LAW_HITS_TICK: i=ResolveLaw(a.sel,world); return i>=0 && laws[i].hitsThisTick REL a.op a.val
 LAW_HITS_TOTAL: i=ResolveLaw(a.sel,world); return i>=0 && laws[i].hitsTotal REL a.op a.val
 LAW_RECENT: i=ResolveLaw(a.sel,world); return i>=0 && laws[i].lastHitTick >= world.tick - a.val
 LAW_COND_THRESHOLD: i=ResolveLaw(a.sel,world); return i>=0 && laws[i].condThreshold REL a.op a.val
 LAW_EFFECT_ACTIVE: i=ResolveLaw(a.sel,world); return i>=0
 ALL_LAWS_SILENT: for k in 0..4: if world.tick-laws[k].lastHitTick < a.val: return false
 return world.tick > a.val
 REL: return world.relations[v.id,a.otherId] REL a.op a.val

// ---- 分支仲裁：律法优先级决定走哪条 ----
SelectBranch(card, v, world) -> Branch:
 best=null; bestSlot=999
 for b in card.branches:
 if b.requiresLaw==None: continue
 if !EvalGate(b.gate,v,world): continue
 slot = ResolveLaw(b.requiresLaw, world)
 if slot>=0 && slot<bestSlot: best=b; bestSlot=slot
 return (best!=null) ? best : card.defaultBranch // 硬规则：必有 default

ApplyBranch(card, b, v, world) -> LifeEvent:
 parent = v.lastEventId
 cs=-1; cd=-1
 if b.requiresLaw!=None:
 cs = ResolveLaw(b.requiresLaw, world)
 if cs>=0: cd = laws[cs].defId
 for e in b.effects: ApplyEffect(e.type, e.magnitude, v, world)
 ev = MakeEvent(v, card.id, b.id, parent, cs, cd)
 ev.causeDepth = (parent==-1) ? ((cs>=0)?1:0) : world.events[parent].causeDepth + 1
 v.lastEventId = ev.id
 return ev

// ---- 讣告：回溯因果链 ----
AttributeDeath(v, world) -> (slot, defId, depth):
 ev = world.events[v.lastEventId]; slot=-1; def=-1; depth=0
 while ev!=null:
 if ev.causeLawSlot>=0: slot=ev.causeLawSlot; def=ev.causeLawDefId
 depth++; ev = (ev.parentEventId>=0) ? world.events[ev.parentEventId] : null
 return (slot, def, depth)

MakeObituary(v, world) -> string:
 (slot,def,depth) = AttributeDeath(v, world)
 perLaw = CountEventsPerLaw(v, world) // int[12]
 s = Pick("死因模板", depth) // depth1=直接, >=2=间接
 if slot>=0:
 s += "第"+(slot+1)+"条法："+PRESET[def].name
 second = TopOtherLaw(perLaw, def)
 if second>=0: s += "还有第"+(second+1)+"条法，"+PRESET[second].name+"，让这事更糟。"
 s += FillCorpus(v.lifeStats, perLaw) // 模板池+语料+数值→措辞，禁 LLM
 if depth>=2: s += "他不是被谁杀的。他只是活在你写的法里。"
 return s

**最容易做错**：1. **卡里硬编码 slot 序号**（"引用第 2 条法"）。玩家一换优先级顺序全盘失效。必须走 LawSelector 语义引用（ByEffect/ByCond），resize 由 effectFirstSlot 索引表承担。
2. **卡硬读阈值当 if 开关**（`if law.condThreshold > 60`）。这会让玩家的调参退化成布尔开关，失去"连续调参"的全部手感。正确做法是读聚合量 hitsThisTick/hitsTotal，让参数通过模拟间接作用。
3. **忘了 default branch**。遮蔽时卡直接空白。每张卡必须有 default 支线，这是所有反死水机制的根基，漏了它第 4 节全崩。
4. **tick 内执行顺序颠倒**。必须先 RecomputeLawRuntime 再 EvalGate，否则卡读到的是上一 tick 的律法状态，因果错位、讣告归因错人。
5. **因果链断裂**。不是每个事件都写 parent（尤其死亡事件），回溯到一半断掉，讣告点不出律法。必须保证每 tick 内事件串成一条不断的链。
6. **反遮蔽疲劳用 float**（×0.5 打折）。破坏定点与双端哈希一致。改整数实现："每 2 次命中打 1 次折"。
7. **用 Dictionary 存律法查询**。Dictionary 迭代顺序跨平台/跨运行时不一致，直接违反"双端同 seed 哈希一致"。一律定长数组 + 显式索引表。
8. **只做反遮蔽不给信号**。世界被救活了但玩家不知道，改法冲动消失。必须有 AllLawsSilent 卡这类显式反馈把"死水"说给玩家听。
9. **只记单一罪魁、忽略多律法协同**。讣告会显得武断（其实是法B+法C一起害死的）。必须存 perLaw 计数数组做二次归因。
10. **反事实"如果"整局重算**。P3 天可做真实确定性重放，全局重算成本爆炸。要做限额（只重放最近 3 天）或降级为纯措辞。
11. **效果池无配额**。5 条法可以全选同一个 ROB 变体，单一策略碾压，"组合"设计意图落空。需相似性检查（禁止 5 条同效果）。

### 手工写事件卡（storylet / QBN）机制：凭什么算真涌现，以及让它站得住的硬设计

**核心结论**：手工卡的"涌现"不来自单张卡（单张卡永远是人写的、可预测的），而来自**卡与卡之间的状态互相引用**：作者只写局部规则，全局叙事（谁死、怎么死、讣告长什么样）没有被任何人写过。判据是一句话——**删掉任意一张卡，可达现象集会不会变形**；会变形、且变形幅度随该卡的因果负载单调上升，就是真涌现。反之，卡只依赖初始静态属性、触发即焚、状态无历史累积、顺序不敏感，那就是伪涌现（换皮的流程图 / 分支脚本）。硬设计的四根柱子：①卡的 **prereq/apply 必须读写共享可变状态**，而非只读初始值；②至少 4 类非线性算子（阈值、软饱和、比值、递减回报）打破加法不动点；③**三跳以上因果链**（A 改状态→解锁 B→B 改状态→满足 C 的前置）要占死亡链的多数；④把"前置是否成立"白箱化、把"满足后触发什么/改多少"黑箱化，做到"能看懂为什么，猜不到会怎样"。

## 0. 先给"涌现"下可操作的定义，否则辩论没有支点

弱涌现（weak emergence）= 由少量相互作用的局部规则产生、但**无法从单条规则直接读出**的全局模式。康威生命游戏和象棋都符合：规则是人写的，棋局/滑翔机不是人写的。

游戏里一次比赛、一篇讣告，**没有任何人"写过这一局"**——只要成立，就是弱涌现。所以评委问"手工卡凭什么算涌现"，正确的回答不是"因为它随机"，而是：

> **涌现是"未作者化（unauthored）的全局结果"的属性，不是"单块内容随机"的属性。** 我作者化的是卡（局部规则），未作者化的是死亡序列与讣告（全局结果）。

## 1. 划清界限：什么是伪涌现，什么是真涌现

**伪涌现（必须点名、并主动承认我方旧设计踩过）的劣质做法：**

| 劣质做法 | 为什么是假 |
|---|---|
| 一次性触发卡（one-shot，触发即删） | 卡与卡不共享状态，等于"随机播放一段文本"，卡池很快耗尽，后期空转 |
| 纯文本池 / 皮肤卡 | 抽一段文案，不改任何状态。这是叙事滤镜，不是机制 |
| 前置只读初始静态属性 | 卡 B 的触发与卡 A 是否发生过无关 → 事件之间无因果，只是并列的抽样 |
| 无记忆快照 | 前置读的是瞬时村庄快照，不读"一生事件表"的历史统计量 → 无路径依赖 |
| 假选择 | 玩家/系统在 A/B 里选，但两条支路后置状态相等（收敛到同一不动点） |
| 顺序不敏感 | 把 A→B 换成 B→A，结果一样 → 说明没有信息在卡之间流动 |

**真涌现的判据（可证伪、可自动化）：**
1. **跨卡因果**：存在卡 B，其 prereq 依赖卡 A 的 apply 产出的状态或 LifeEvent；
2. **路径依赖**：存在一对卡 (A,B)，A→B 与 B→A 的终态不同（顺序敏感测试）；
3. **消融敏感**：移除任意一张卡，相同 seed 集上的终态分布/死亡序列集合发生可测变形（见 §2）；
4. **无作者化终局**：不存在任何一份被写死的"结局剧本"；讣告由 §3 的因果链现场拼装。

第 3 条是最硬的一条，也是答辩时可以直接跑给人看的**唯一**一条。

## 2. 组合爆炸：纸面数字 vs 真实可达，以及可证伪判据

**纸面数字（要主动说它虚）**：30 张卡、链长 5，天真的 N^L = 30^5 ≈ 2400 万种序列。这个数字**没有意义**，因为绝大多数前置条件在任何真实世界状态下都不成立。

**真实可达（要用可达图算）**：把"I tick 时刻的 (共享变量三元组, 存活村民状态, 已触发卡集合)"当作节点，卡触发当作边，跑枚举/采样，得到一个可达有向图 G。真实序列数 = G 上的不同路径数，用 canonical 化（把数值离散成桶、把村民按 id 排序）后去重。经验量级：这类系统真实可达的**"事件类型骨架"**通常在 10^3–10^4，而作者化内容只有 30 张卡。**这个比值（可达骨架 / 作者化卡数 ≫ 1）才是涌现的量化论据。**

**三个可证伪的判断标准：**

1. **消融实验（Ablation，核心）**：固定 1000 个 seed，各跑 1000 tick，记录终态分布与死亡村民的生命事件类型序列（骨架）。删掉卡 X，重跑，比较：
 - 若分布几乎不变 → 卡 X 是**装饰卡**，不贡献涌现（劣质）；
 - 若分布显著变形且变形量 ≈ 该卡在因果图中的度数 → 真贡献。
 - 指标：Jensen–Shannon 散度或简单的骨架种类数变化 ΔS。**"ΔS > 0"就是删卡会变形。**
2. **可触发率筛查**：统计每张卡在所有 seed 上的平均可触发 tick 数占比。>90% = **永真卡**（无门槛，等价于常量），<1% = **死卡**（写坏或条件太苛刻）。两类都不贡献组合，必须剔除或修参数，否则纸面组合数是注水。
3. **互信息检验**：算卡 A 与卡 B 共同出现的互信息 I(A;B)。若 I ≈ 0，两卡独立，组合是"乘法纸面"不是"结构组合"；只有 I > 0 的卡对才构成真实的因果组合。

## 3. 二阶涌现：三跳以上的具体例子（用本作字段）

字段回顾：村民 {id, 姓名, 金币 gold, 饥饿 hunger, 恐惧 fear, 位置 pos, 性格标签 traits, 一生事件表 life: List<LifeEvent>}；村庄 {有向关系表 rel: ±100, 三共享变量 S={gold,hunger,fear}, tick}。

**卡 A「粜米私藏」**
- prereq：`S.hunger ≥ 70` 且 存在两名村民 v1,v2 同 pos 且 traits 含 "怯懦"/"贪婪" 组合
- apply：`v1.gold -= 5`；`v2.hunger -= 10`；写入有向边 `rel[v2→v1] = ±债务标记 +1`；`life[v1].append(LifeEvent{Cheat, tick, target=v2})`

**卡 B「登门索债」**（前置依赖 A 的后置！）
- prereq：`∃ 边 rel[v2→v1] 带 debt 标记且 |值| ≥ 阈值` 且 `v1.gold < 20` 且 `v2.gold > v1.gold`（比值，非线性）
- apply：`v1.fear += 15`（软饱和）；`v2.fear += 20`；`rel[v2→v1] -= 30`（关系恶化）；`life[v1].append(Threat)`；`life[v2].append(Threat)`

**卡 C「铤而走险」**（前置读**历史累积**而非瞬时值！）
- prereq：`v1.fear ≥ 80` 且 **`count(life[v1], type ∈ {Cheat, Threat}) ≥ 2`**（读一生事件表的统计量）且 `S.fear 均值 > 60`（村庄级放大）
- apply：触发暴动，多个村民 gold 重分配；`life[v1].append(Uprising)`；可能致死（fear 与 gold 比值为概率权重）→ 命中死亡则**调用讣告生成器**读 `life[v1]` 与 `VillageSnapshot` 现场拼装。

这条链 A→B→C 是三跳，且**C 的前置是一生事件表的历史函数**，不是瞬时快照——这正是真涌现与伪涌现的分水岭。四跳的例子：加卡 D「家族复仇」，prereq 读 `life[死者].target` 的关系网，把 C 的牺牲者重新注入 A 的债务图。

**三跳以上要占多大比例才够？** 给一个可回归的硬指标：在 500 seed × 1000 tick 的自动跑里，
- **死亡村民的 life 链中，能切出一条 ≥3 张卡、且"后一张前置依赖前一张后置"的因果子链的比例 ≥ 50%**；
- **其中能通过消融验证（移除链头则链尾不出现）的 ≥ 30%**。

低于 20% 说明系统退化成独立卡池（伪涌现），必须补"读历史"的 prereq 和跨卡状态。

## 4. 非线性：从哪来（至少 4 种可复用算子）

纯加法 + clamp 的系统会收敛到不动点（所有村民趋同，没历史没故事）。必须植入非线性，且**全部用定点/整数实现**：

1. **阈值 / 阶跃（Step）**：条件用 `≥ / <` 判定（`fear ≥ 80` 才解锁暴动）。状态跨过阈值才切换模式，产生"量变到质变"。
 - 定点实现：纯整数比较，无误差。
2. **软饱和 / 递减回报（Soft Saturation）**：`Δ_eff = Δ × (100 - fear) / 100`，高值区边际递减。
 - 定点实现：`eff = (delta * (100 - fear)) / 100`，先乘后除防截断；结果 `clamp(0,100)`。
 - 效果：避免线性堆叠爆炸，制造"越恐惧越难再刺激"的心理饱和。
3. **比值 / 相对量（Ratio）**：暴动概率 ∝ 该村民恐惧 / 村庄平均恐惧，而非差值。
 - 定点实现：`ratio_permille = (v.fear * 1000) / (avg_fear + 1)`，用千分比定标。
 - 效果：同一数值在不同村庄环境下含义不同 → 环境依赖。
4. **幂 / 规模递减回报（Diminishing）**：收益 `Δ = k / (1 + 已有量)`，财富累积出现边际递减，防止单变量支配全局。
 - 定点实现：`delta = (k * STEP) / (STEP + have)`，STEP 为定点放大系数。
5. **累积历史窗口（Path Dependence）**：prereq 读"最近 N tick 内某类事件计数"或"一生事件表中某类事件计数"。
 - 效果：把时间维度的路径依赖注入，这是"历史"之所以是历史的机制根。
6. **乘法耦合（Multiplicative Coupling）**：触发权重 = `gold_weight × fear_weight`（乘法而非加法），使两个维度共现才有强触发。
7. **关系的对称衰减（Forgetting）**：每 tick 所有关系边向 0 回落固定量。使 ±100 有记忆但会遗忘，避免关系锁死成常数。

## 5. 玩家可读 vs 不可预测：怎么同时做到

**分界原则（写在 UI 规则里）：透明"前置为何成立"，隐藏"满足后发生什么"。**

- **前置层 = 全白箱**：hover 村民时显示其每条尚未满足/已满足的卡的**前置满足度**（色带 + 阈值刻度），显示三共享变量的当前区带。玩家能说"哦他现在恐惧到临界了，是因为上次被讨债"。
- **后置层 = 全黑箱**：不显示任何权重表、RNG、触发概率、具体数值增减。玩家看到的是结果，不是公式。
- **因果高亮（Causal Highlight）**：当卡 B 因卡 A 的产物而触发时，UI 从"事件流"里的 A 卡片画一条箭头连到 B，标注"因【登门索债】状态：恐惧 +20"。玩家**事后**能归因，但事前不能精确预测。
- **事件流（Event Stream）右栏**：只滚动 icon + 律法归属 + 时间戳，不带解释文本，逼玩家自己连线（这正是"涌现的乐趣"）。
- **话术层**：用"村民普遍恐惧"代替"均值 = 63"；用"关系已经破裂"代替"rel = -47"。数字给机器的，措辞给人的。
- **阈值可视化用模糊色带**，不用精确刻度数字——让"临界"可感知但不可计算。
- **律法面板白箱**：5 条律法的"条件→效果"结构完全透明（这是玩家的输入），但律法**互相作用后**涌现出的卡链不透明（这是系统的输出）。输入透明、输出不透明，恰好对应"我能理解我的选择，但我猜不到村庄会怎样"。

## 6. 评审现场能演示的 30 秒（不脚本化 + 三重兜底）

**动线（老板键：空格 = 8× 速跑）：**
- 0–10s：**立法面板**。评委从 3 个预设"立法方案"里选一个（或自己拖 5 条律法、排优先级），点"颁布"。
- 10–20s：**8× 速跑**，右栏事件流滚动，因果高亮连线一根根亮起。
- 20–30s：**讣告弹出**——读死者真实一生的 `life[]` 现场拼装，不是预写文本。

**三重兜底（关键：让它跑，跑出来的自己说话）：**
1. **seed 固定**：当场把 seed 编号写给评委，"你自己跑，结果一模一样"（双端哈希一致是技术保险）。
2. **预热存档**：不是从村庄第一天开始，而是加载一个预跑到第 ~200 tick 的**高张力快照**（此刻村庄已处在 hunger/fear 高位，卡池活跃），30 秒必出事。
3. **第二存档兜底讣告**：备用一个"已经死过至少一人"的存档，保证 30 秒内**至少有一篇讣告**弹出，绝不冷场。

**防质疑话术**：不指定谁死、不预排结局；运行前可以**当场改 seed** 重跑（可复现）或**删掉一张卡**重跑（消融，现象变形，证明非伪涌现）。这两招直接把"你这是脚本吧"堵死。

**伪代码**：

// ===== 数据结构（全部整数/定点，禁 float，禁 Dictionary 迭代依赖） =====
Card = {
 id: string,
 prereq: (Village V, Villager v, int tick) -> (ok: bool, score_permille: int), // score = 满足度调制，千分比
 weight_permille: int, // 基础权重
 cooldown: int, // 对同一村民的冷却 tick
 once_global: bool, // 全局一次性（慎用，过多会卡池耗尽）
 apply: (Village V, Villager v, RNG rng) -> List<LifeEvent>,
 tags: [string],
}

// ===== 每 tick 的 storylet 调度器 =====
function tick(Village V):
 V.tick += 1
 update_shared(V) // 三共享变量的自然演化(含衰减/饱和)

 candidates = [] // 元素: (card, villager, weight)
 for card in V.cardpool: // 卡池用确定顺序遍历(id 排序)
 if card.once_global and fired_before(card): continue
 for v in V.alive_villagers(): // 村民按 id 排序
 if V.tick - last_fired(card, v) < card.cooldown: continue
 (ok, score) = card.prereq(V, v, V.tick)
 if ok:
 w = card.weight_permille * score / 1000 // 定点：先乘后除
 candidates.append((card, v, w))

 total = sum(w for (_,_,w) in candidates)
 if total > 0:
 r = V.rng.next_int(total) // 自带 PRNG，无 float
 acc = 0
 for (card, v, w) in candidates: // 顺序固定 → 双端哈希一致
 acc += w
 if r < acc:
 events = card.apply(V, v, V.rng) // 改状态 + 产事件
 for e in events:
 v.life.append(e) // 写入一生事件表(供讣告/四跳卡读)
 V.event_stream.append((V.tick, e)) // 供 UI 事件流
 mark_fired(card, v, V.tick)
 break

 // 关系对称遗忘(非线性算子7)：每 tick 向 0 回落
 for edge in V.relations_in_id_order():
 if edge.val > 0: edge.val = max(0, edge.val - DECAY)
 elif edge.val < 0: edge.val = min(0, edge.val + DECAY)

// ===== 非线性算子：软饱和(算子2) =====
function fear_saturating_add(v, delta):
 eff = (delta * (100 - v.fear)) / 100 // 边际递减，先乘后除
 v.fear = clamp(v.fear + eff, 0, 100)

// ===== 比值(算子3)：暴动概率权重 =====
function uprising_weight(v, V):
 avg = V.shared.fear // 村庄平均(整数)
 return (v.fear * 1000) / (avg + 1) // 千分比，环境依赖

// ===== 可证伪工具1：消融实验 =====
function ablation(cardA, cardC, seeds):
 // 返回 (有A时C达成次数, 无A时C达成次数)
 hit_with = 0; hit_without = 0
 for s in seeds:
 seq1 = run_headless(seed=s, ticks=1000)
 if chain_reached(seq1, head=cardA, tail=cardC): hit_with += 1
 seq2 = run_headless(seed=s, ticks=1000, disabled=[cardA])
 if chain_reached(seq2, head=null, tail=cardC): hit_without += 1
 // 若 hit_with >> hit_without → 存在真实因果链（真涌现）
 return (hit_with, hit_without)

// ===== 可证伪工具2：三跳比例统计 =====
function trip_jump_ratio(seeds):
 ok = 0; total = 0
 for s in seeds:
 run = run_headless(seed=s, ticks=1000)
 for v in run.dead_villagers:
 total += 1
 if has_causal_subchain(v.life, min_hops=3): ok += 1 // 后置依赖前前置且可消融验证
 return ok * 100 / max(total,1) // 目标 ≥ 50%（可消融验证的 ≥ 30%）

**最容易做错**：**这一面最容易做错的地方（按致命程度排序）：**

1. **把"改皮肤"当涌现**——最常见的自欺：卡只抽文案、不改共享状态，或者改的状态没有任何别的卡会读。上评审前先跑消融：如果删掉一半卡，终态分布不变，就是伪涌现，别硬辩。

2. **卡只读初始静态属性**——这是伪涌现的技术病根。卡 B 的前置只要不引用卡 A 的 apply 产物（状态或 LifeEvent），两卡就是并列抽样。**每一张卡都要在代码评审里回答"我读了谁写的状态"**，答不出来就是装饰卡。

3. **once_global 卡滥用**——一次性卡触发即焚，等于没有跨卡状态；而且后期卡池耗尽，系统空转，20 tick 后就没事件了。规则：全局一次性卡占比 < 10%，且只能用于"建国/立村"这类开局事实。

4. **前置条件不用历史、只用瞬时值**——前置换成读 `life[]` 的统计量（"一生中 Cheat+Threat ≥ 2 次"）才有路径依赖。只用瞬时 fear 值，系统无记忆，无"故事"。

5. **用 float / 依赖 Dictionary 迭代顺序**——直接违反双端哈希一致的前提，双端同 seed 跑出不同结果，演示当场翻车。所有比较、权重、概率必须整数/定点；卡池、村民、关系边一律按 id 排序遍历，禁止哈希表迭代顺序参与决策。

6. **死卡与永真卡不筛查**——可触发率 <1%（死卡）或 >90%（永真卡）都会让纸面组合数注水。上线前用可触发率报表过一遍，两类都要修。否则答辩时被人算一遍就露馅。

7. **只测单个 seed / 不做回归**——没有 500 seed × 1000 tick 的自动跑 + 消融报告，你无法证明"删卡会变形"，也无法证明三跳比例达标。**这是唯一能在评审现场拿出来的硬证据，别省。** 建议把它做成一键脚本，现场可跑。

8. **演示脚本化**——预先指定谁死、预写讣告文案，一旦被看穿，"死于你写的法律"整个卖点崩塌。必须 seed 固定 + 预热存档 + 现场真实运行，讣告由事件表现场拼装。

9. **UI 双重泄露或双重遮蔽**——要么把权重表也显示给玩家（可预测性归零，变成解方程），要么把前置也藏起来（可读性归零，变成看戏）。正确分界只有一条：**前置透明、后置不透明**。

## 一·五、关系域卡的门禁规则（地图接入后新增的硬约束）

【背景】地图接入后，村民的"邻居"由地理距离决定（每人 `NEI = 4` 个）。这带来一个必须写进卡设计规范的后果：

> **有向边 80 条。而村民对总共有 `N(N-1) = 380` 对。**
> **79% 的村民对，在一局中永远不构成"邻居"。**

【规则】

- **关系域卡的门禁，必须以「`rel != 0`」或「是邻居」为前提。**
  写成"任意一对"（直接遍历 380 个目标）的卡，其中约 **300 个目标格永远不可能被触发**——而且不报错。
- 这是**死信在关系域上的版本**。自测方法：数一数这张卡的候选目标里，有多大比例在一局中真的能达到。

【为什么这条比"性能"更重要】

原规范里"关系域卡 ≤ 5 张"的理由是求值成本。现在有了更硬的理由：**关系域的绝大部分本来就是不可达的**，多写只会得到一堆永不触发的卡。

【怎么检出坏卡】

跑 500 seed，对每张关系域卡统计 `实际触发过的目标数 / 候选目标数`。
**低于 20% 的卡应当重写成"邻居域"卡。**

## 二、卡片库

### 律法触发卡（Law-Trigger Storylets）

【这一族卡在系统里的位置】律法引擎（WHEN C1–C9 × THEN E1–E11 × priority）只负责"结算"，它产出的是数值差和一个 lawIndex。本族卡是压在律法引擎之上的**第二层**：每个 tick 律法 pass 跑完后，系统收集"本 tick 有哪些法命中了谁"（Law.lastHit / fired），交给本族卡的求值器，在**固定顺序**（先按 priority、同 priority 按卡 id）里挑 0–N 张卡生效。这一层不新增任何浮点、不依赖 Dictionary 迭代、复用主 RNG 流，因此**双端同 seed 的哈希不受影响**——它只是把"数值变化"翻译成"村里的故事"。

【为什么是这一族】原设计靠 12 法 × 8 条件 × 11 效果互相作用长出故事，那是"参数扫描一周"的活，18 天排不出来。本族卡把不可排期的**研究**换成了可排期的**写作**：每张卡就是一段手写好的"如果情况是这样、那么村里就会这样"——它是"他们死于你写的法律"这句话的**字面实现**，因为每张卡都以某条律法的命中为触发源（lawCoupling 是硬绑定，不是氛围描述）。

【与本作数据契约的对接（已按《冠军方案》对齐）】
- 寄存器：villager{hunger/wealth/fear 0..99, pos, tags 8bit, alive}、关系表（20×19 有向 ±100）、village{tick, granary 粮仓, sumFear, totalWealth}。
- 本族需要**极小的寄存器扩展**（3 个 int + 2 个 bit，代价近乎为零，但必须声明，否则卡写不出来）：
 1) Villager 加 `goodDeed`、`crimeRecord`、`hiddenWealth`（各 1 个 short）；
 2) tags 里本族占用 2 位：`惯抢`、`拒法`；
 3) Law 加 3 个运行时字段：`hitCount`（累计命中）、`faith`（该法在村民心里的威信 0..99）、`voided`（是否被架空）、`exemptMask`（豁免位图）；
 4) Village 加 `norm`（暴力合法化程度）、`reportRate`（举报率）、`legislatorFear`、`granaryCap`。
- 输出层：每张卡**只**通过两条管道影响世界——写寄存器/关系表，和写 `LifeEvent`（用现有 15 种 EvType，必要时新增 LAW_BACKFIRE / LAW_VOID）。讣告生成器读的还是"事件表 + Snapshot"，所以本族卡产出的故事**自动**进入讣告，不需要改动 ObituaryForge 的接口。
- 讣告 6 段骨架 `{生卒行}{死因句}{一生句}{记忆句}{关系句}{立法句}`：本族卡的 obituaryLine 主要喂**死因句 + 立法句**两段，且立法句引用 lawIndex（"你写的第 N 条法"），选择权重走 w3=0.6（出自法律）这条快车道。

【本族卡构成的五条链（每条 ≥3 跳，emits 字段里用【链X】标出）】
- 【链A 税→藏→告→杀→反噬】（4 跳）：LTC-02 墙里的金币 →(hiddenWealth≥100)→ LTC-08 豁免凭证，或 →(村有举报有赏)→ LTC-03 邻里的鼻子 →(crimeRecord≥1 且村有私刑法)→ LTC-04 村口的绳子 →(innocent=1)→ LTC-05 绳子最后套回立绳人。这是"严刑峻法会吃人、也会吃掉执法者"的完整闭环。
- 【链B 饥→抢→私刑→沉默→法死】（4 跳）：LTC-06 抢不再需要理由（自指 E9 下调饥则抢阈值）→(crimeRecord 用户≥3)→ LTC-04 村口的绳子 →(致死后)→ LTC-11 没人再敲门 →(reportRate<20)→ LTC-09 墙上的字。这是"一条为了活下去的法，三代之后吃掉全村"的链。
- 【链C 善法→依赖→满仓→黑市→法死】（4 跳）：LTC-01 领粮的手 →(welfareHitCount≥8 者≥2 人)→ LTC-07 满仓的马太 →(贫富差)→ LTC-08 豁免凭证 →(exemptMask 中位数≥3)→ LTC-09 墙上的字。这是"善意养出依赖、依赖养出黑市"的链。
- 【链D 圣人→葬礼→复仇→反噬】（3 跳）：LTC-10 善人的葬礼 →(村有私刑法)→ LTC-04 村口的绳子 →(怨恨≥80)→ LTC-05 绳子最后套回立绳人。这是"好人的死会引爆村里最坏的那条法"的链。
- 【链E 冲突→拒法→法死→无序】（3 跳）：LTC-12 两条法在同一个饭盆里打架 →(拒法标签≥3)→ LTC-09 墙上的字 →(约束消失)→ LTC-06 抢不再需要理由。这是"玩家自己把法写矛盾了"的链。

【同一张卡在福利村 vs 税收村的后果分化】这是本族的命门，靠**同一触发源 + 按玩家 5 法分支的 effects**实现：LTC-07 满仓的马太有三种写法（甲：关系户优先；乙：收归公库折价；丙：原地打转），LTC-08 豁免凭证只在有"可通融的法"时生长，LTC-02 与 LTC-01 在同一村民身上会互相加速（一边领饭一边课税 → faith 双向崩塌 → 直接喂 LTC-12）。玩家能一眼看见自己两条法在打架。

【整局规模假设】一局按 300–600 tick（1 tick = 1 秒，村民一生）计。本族 12 张卡合计每局触发约 30–55 次卡结算，其中高频演化卡（LTC-06 抢）6–15 次，低频重大转折卡（LTC-05 反噬、LTC-10 圣人葬礼、LTC-09 法死）各 0–2 次——既保证事件流不空，又保证稀有卡有"值得截图"的分量。

#### 领粮的手　`LTC-01`
- **触发**：tick 的律法 pass 结束后，若【福利法】（whenId=C1 饥饿>N + thenId=E3 饥饿−N 或 E1 得金币，且耗粮仓）本 tick 的 lastHit ≥ 1，且 granary ≥ 10 → 进入候选池
- **前置条件**：存在 v.alive 且 v.hunger > 60；v.welfareHitCount ≥ 5（本族新增计数，代表连续领取）；村中至少有 1 名村民执行过「去耕作→粮仓」（E5 目标=粮仓）即有人在供粮
- **权重**：W = 30 × faith(福利法) / 100（整数除）；若 5 法中含【税收法】则 W = W × 3 / 2（整数，即 W+(W>>1)）。faith 初值 60 → W≈18。整局约触发 3–6 次（每次锁定 1 个不同村民，点满 3 个不同村民后本卡进入一次性关闭）
- **效果**：v.welfareHitCount += 1；置 v.workWilling = 0（新增 1 位标志，表现层为 E5 移动目标从「耕地」变「粮仓」）；v.faith(福利法) += 5（上限 99）；关系表：对每位上周执行过耕作供粮的村民 w，rel[v][w] −= 3；事件表写 LifeEvent{EvType.ATE, lawIndex=福利法槽位, ctx0=v.hunger, ctx1=本 tick 领取量, tick}（事件表满 12 条时按 w1–w5 淘汰最低分）
- **链式触发**：【链C】若 welfareHitCount ≥ 8 的村民数 ≥ 2 → 释放 LTC-07 满仓的马太；若村中同时存在税收法 → 释放 LTC-12 两条法在同一个饭盆里打架
- **冷却**：每村民 20 tick；全局点满 3 个不同村民后一次性关闭
- **文本骨架**：「{v.名}第 {v.welfareHitCount} 次把手伸到分发口。他今天没有去耕地，粮仓也没有因此少一粒——只是从此以后，村里多了一张只在饭点出现的脸。」
- **讣告引用**：「{v.名}最后的 {v.welfareHitCount} 天里，没有种过一粒粮。/ 你写的第 {N} 条法替他端了 {v.welfareHitCount} 天的饭，却没有教会他端下一顿。」
- **与律法咬合**：本卡只在【福利法】实际命中（lastHit≥1）时生长，faith 直接取该法的运行时威信值——玩家把福利法优先级排高、参数调宽，这张卡就来得越早、越密。与【耕作法】同村：granary 充裕让 welfareHitCount 涨得更快，首次触发提前到第 15–20 tick（善意 + 富足 = 养懒汉最快）。与【税收法】同村：同一村民一边领饭一边被课税，W ×3/2，并必然牵出 LTC-12。玩家删掉福利法，这一整条链C 直接断掉。

#### 墙里的金币　`LTC-02`
- **触发**：【税收法】（whenId=C2 财富>N + thenId=E2 失去金币）对村民 v 命中时 → 进入候选池
- **前置条件**：v.wealth ≥ 60；且（v.fear ≥ 30 或 v 带「畏事」标签）——害怕才藏；v.hiddenWealth < 200
- **权重**：W = 25 × thenParam / 20（整数除；thenParam=20% 税率时 W=25）。整局约 5–10 次
- **效果**：move = min(v.wealth × thenParam / 100, 60)；v.wealth −= move；v.hiddenWealth += move；v.faith(税收法) −= 8（下限 0）；关系表：v → 公库代言人（本局最富者或执行者）rel −= 5；事件表写 LifeEvent{EvType.TAXED, lawIndex=税收法槽位, ctx0=move, ctx1=v.hiddenWealth, tick}（复用 TAXED，用 ctx1 承载「藏了多少」）
- **链式触发**：【链A】若 v.hiddenWealth ≥ 100 → 释放 LTC-08 豁免凭证；若 5 法中含【举报有赏】（thenId=E1 + whenId=C8 自指）→ 释放 LTC-03 邻里的鼻子
- **冷却**：每村民 30 tick
- **文本骨架**：「{v.名}把 {move} 枚金币塞进了墙缝。册子上，他从此是个穷人——他自己也这么对外说。」
- **讣告引用**：「{v.名}死后，人们在他家墙里摸出了 {v.hiddenWealth} 枚金币。/ 他躲了你写的第 {N} 条法一辈子，最后和它们埋在一起。」
- **与律法咬合**：触发频率与藏匿量完全由税收法的 whenParam（起征点）与 thenParam（税率）决定——玩家把税率推到 30+，本卡就从「个别案例」变成「全村现象」（move 更大、W 更低、更多人触发）。若玩家在效果 11 项里选了「执行者收益」类参数 >0，本卡还会进一步喂给 LTC-08 黑市。与【福利法】同村时，v 一边领饭一边藏钱，两卡互相加速。

#### 邻里的鼻子　`LTC-03`
- **触发**：任一村民 hiddenWealth ≥ 20 且 5 法中含【举报有赏】（thenId=E1 得金币 + whenId=C8 律法[L]已触发 的自指写法）→ 进入候选池
- **前置条件**：存在举报者 r（r ≠ v）：rel[r][v] < 0 或 r.fear > 50；v.hiddenWealth ≥ 20；赏金 thenParam ≥ 1
- **权重**：W = 15 + thenParam / 5（赏金 30 → W=21）；若 r.fear > 70 再 ×2。整局约 4–8 次
- **效果**：r.wealth += thenParam（0..99 封顶，溢出转 village 公库）；v.hiddenWealth −= min(v.hiddenWealth, 50)，v.wealth 同步扣押；关系表：rel[v][r] −= 40、rel[r][v] −= 10（愧疚），对全体其他村民 w：rel[w][r] −= 5（人人怕那个爱敲门的人）；v.crimeRecord += 1；事件表写 LifeEvent{EvType.ACCUSED, lawIndex=举报法槽位, ctx0=r.id, ctx1=v.hiddenWealth, tick}
- **链式触发**：【链A】若 v.crimeRecord ≥ 1 且 5 法含【私刑法】→ 释放 LTC-04 村口的绳子
- **冷却**：每举报者 15 tick
- **文本骨架**：「{r.名}敲开了执法的门，说出了 {v.名} 的墙缝。他领走 {赏金} 枚金币，没有回头。村里从这天学会了一件事：敲门能换钱。」
- **讣告引用**：「把 {v.名} 交出去的是 {r.名} 的一句话。/ 你写的第 {N} 条法给那句话标了价：{赏金} 枚金币。」
- **与律法咬合**：完全由【举报有赏】激活——没有这条法，hiddenWealth 永远沉默，税收法村会走向「账面繁荣」而不是流血，同一份逃税数据两种命运。赏金 thenParam 同时抬高 W（短期更频繁）与后期反冲幅度（直接喂 LTC-11）。若玩家同时带【私刑法】，本卡就是死刑判决书的第一句。

#### 村口的绳子　`LTC-04`
- **触发**：存在村民 crimeRecord ≥ 1 且 5 法含【私刑法】（thenId=E11 死亡 或 E6 抢邻居）→ 进入候选池
- **前置条件**：满足 rel[w][v] < −30 的村民数 ≥ 3（凑够「大家」）或 v.fear ≥ 60（被吓破胆不反抗）；v 尚未死亡
- **权重**：W = 20 × faith(私刑法) / 100；faith 初值 60 → W=12。整局 3–6 次处决
- **效果**：生成 LifeEvent{EvType.DIED_KILLED, lawIndex=私刑法槽位, killerId=主执行者 e.id, ctx0=v.crimeRecord, ctx1=参与人数, tick}；v.alive = false，推入 Cemetery，v.id 永久回收（绝不复用）；全体参与者：fear −= 10、faith(私刑法) += 10；关系表：对每位 rel[v][f] > +30 的亲友 f：rel[f][每位参与者] −= 25、rel[f][e] −= 15；village.norm += 5；若 v.crimeRecord 源于 LTC-03 的诬告，则置 v.innocent = 1
- **链式触发**：【链A】v.innocent == 1 → 释放 LTC-05 绳子最后套回立绳人；【链B/链D】norm ≥ 40 → 释放 LTC-06 抢不再需要理由
- **冷却**：30 tick
- **文本骨架**：「{参与人数} 个人把 {v.名} 带到了村口。绳子是大家凑的。没有人记得是谁先动的手——但每个人都记得你写的那条法。」
- **讣告引用**：「{v.名}死于村口。/ 定他罪的不是证据，是你写的第 {N} 条法。{若 innocent：而他本没有罪。}」
- **与律法咬合**：【私刑法】的 whenParam（crimeRecord ≥ N 的执法门槛）决定谁被拖上绳：玩家把门槛调低，处决就变成家常便饭，norm 飞涨、链B 提前。与【举报有赏】同村时诬告率高，innocent 标记得以出现，直接喂给 LTC-05 的反噬——玩家同时写这两条法，等于亲手给私刑法装上自毁引信。

#### 绳子最后套回立绳人　`LTC-05`
- **触发**：LTC-04 刚结算且被处死者 v.innocent == 1（诬告致死）→ 进入候选池
- **前置条件**：village.sumFear ≥ 50 × aliveCount / 100（人均 fear ≥ 50）；且 Σ_w max(0, −rel[w][e]) ≥ 80（对执行者 e 的怨恨总和够大）
- **权重**：W = 40（重大转折卡，只发生一次）。整局 0–1 次
- **效果**：选出怨恨最高的执行者 e；强制写 e.crimeRecord = 1（用他们自己写的规则定他的罪）；生成 LifeEvent{EvType.DIED_KILLED, lawIndex=私刑法槽位, killerId=主谋, ctx0=80, ctx1=e.id, tick}，e 死亡（或按本局规则流放）；私刑法置 voided = 1 且 faith(私刑法) = 0（tick 结算跳过）；全体村民 fear += 25；village.legislatorFear += 40
- **链式触发**：【链A/链B】私刑法 voided → 释放 LTC-09 墙上的字；若村有【饥则抢】→ 释放 LTC-06
- **冷却**：一次性（本局不再触发）
- **文本骨架**：「今天他们要一根更长的绳子。{e.名}被推到了同一个村口——用的是他自己写下的那条法。绳子的另一头，这次握在别人手里。」
- **讣告引用**：「{e.名}死于他自己执法的第 {N} 条法。同一根绳子，只是这一次，另一头换了人。」
- **与律法咬合**：这是【私刑法】的自毁开关，也是全族里「立法者被自己的法吃掉」的最强兑现。玩家若同时带【举报有赏】+【私刑法】，诬告必然发生，本卡近乎必然触发；若玩家只带【私刑法】但不带举报法，crimeRecord 只能来自真抢夺，innocent 难成立，反噬就压得住。这是「两条法一起写会要命、分开写则还行」的显式教学。

#### 抢不再需要理由　`LTC-06`
- **触发**：累计 EvType.ROBBED 条数 ≥ 3 且 5 法含【饥则抢】（whenId=C1 + thenId=E6 抢邻居）→ 进入候选池
- **前置条件**：village.norm ≥ 30 或 ROBBED 累计 ≥ 3；存在 v.hunger < 70（并不饿，也想抢）
- **权重**：W = 10 + 8 × min(ROBBED 累计, 6) + norm / 5。后期（norm 50+、ROBBED 10+）W≈60–70。整局 6–15 次（前少后多）
- **效果**：用自指效果 E9（修改律法[L]参数[P]±N）把【饥则抢】的 whenParam 下调 10（整数减，下限 30）；给满足条件的 v 贴标签「惯抢」（E7，8 标签之一）；执行一次夺取：victim = 最近邻居，victim.wealth −= min(victim.wealth, 取N)，v.wealth += 同额（E6 语义）；rel[v][victim] −= 15、rel[victim][v] −= 15；双方 crimeRecord += 1（受害者也记一次，为后续私刑埋伏笔）；village.norm += 2；事件表写 LifeEvent{EvType.ROBBED, lawIndex=饥则抢槽位, ctx0=v.hunger（可能 <70，即「不饿也抢」）, ctx1=所抢额, tick}
- **链式触发**：【链B】crimeRecord 用户数 ≥ 3 → 释放 LTC-04 村口的绳子；norm ≥ 50 → 释放 LTC-11 没人再敲门
- **冷却**：10 tick（常驻演化卡，非一次性）
- **文本骨架**：「{v.名}今天抢了 {victim.名}。他并不饿。他只是在做大家都在做的事。」
- **讣告引用**：「{v.名}不是饿死的，是死于一种习惯。/ 你写的第 {N} 条法用了三代人，把「抢」变成了村里的一种礼数。」
- **与律法咬合**：本卡直接调用自指效果 E9 改【饥则抢】的参数——这是「法会老去」的机制：玩家亲眼看见自己那条法的触发线一年年往下掉（饥饿阈值从 70 掉到 60、50……）。与【连坐法】（thenId=E4 恐惧+）同村时 fear 抬高 norm，加速本条；玩家把【饥则抢】优先级排最低也没用，它会自己改自己往上爬。想刹车，只能删掉它或加一条【耕作法】把饥饿压下去。

#### 满仓的马太　`LTC-07`
- **触发**：granary ≥ granaryCap（满仓）后，本 tick 又发生【耕作法】命中（E5→粮仓 或 耕作产粮效果）→ 进入候选池
- **前置条件**：granary ≥ granaryCap（建议 300）；村中同时存在 饱者（hunger<20）与 饿者（hunger>60）各 ≥1
- **权重**：W = 20；若 5 法含福利法则 W = W × 3 / 2（整数）。整局 3–5 次
- **效果**：按玩家 5 法**分支**（同一张卡三种写法）：甲（有【福利法】）granary −= 20，按 rel 高者优先分给饱者、饿者颗粒无收，rel[饿者][饱者] −= 8；乙（有【税收法】）granary −= 20、village.sharedWealth += 20（整数当量），饿者拿不到现粮，rel[饿者][公库代言人] −= 10；丙（两法都有）granary −= 20、饱者 wealth += 20（粮绕一圈回到原处），全体 faith(福利法/税收法) −= 5；统一写 LifeEvent{EvType.ATE, lawIndex=耕作法槽位, ctx0=granary, ctx1=饿者数, tick}
- **链式触发**：【链C】饿者 faith < 20 → 释放 LTC-11 没人再敲门；贫富差（max wealth − min wealth > 60）→ 释放 LTC-08 豁免凭证
- **冷却**：25 tick
- **文本骨架**：「仓是满的，满到谷子从缝里漏出来。{饿者.名}还是没吃到。{饱者.名}说：规矩是这么写的。」
- **讣告引用**：「{饿者.名}死的时候，村里的粮仓是满的。/ 你写的第 {N} 条法把粮食发给了不需要它的人。」
- **与律法咬合**：这是「同一张卡在福利村和税收村后果完全不同」的最直接样本——同样一仓满粮，甲分支喂饱关系户、乙分支折成公库数字、丙分支原地打转，三套完全不同的受益名单。玩家一眼就能看见自己两条法在打架。它还会把【耕作法】从「好法」变成「共犯」：粮食越多，分配问题越致命。

#### 豁免凭证　`LTC-08`
- **触发**：任一村民 hiddenWealth ≥ 100 且 5 法中含「可通融的法」（税收法 whenId=C2 或连坐法 whenId=C7 这类执行类法）→ 进入候选池
- **前置条件**：v.hiddenWealth ≥ 100；存在执法者 e（本局执行过该法、即 hitCount>0 的村民）且 e.fear < 60（敢收钱）
- **权重**：W = 18 + v.hiddenWealth / 50（随藏金增长）。整局 3–6 次，随后藏金向执法者聚集
- **效果**：v.hiddenWealth −= 50；e.wealth += 50（99 封顶，溢出转 e.hiddenWealth，口径统一防溢出）；给 v 打豁免位 law.exemptMask |= (1<<v.id)（结算命中该位则跳过执行）；关系表：rel[v][e] += 10（交易成立），对窥见的村民 w：rel[w][e] −= 12、w.faith(该法) −= 6；village.legislatorFear += 5；事件表写 LifeEvent{EvType.GIFTED, lawIndex=税收法槽位, ctx0=50, ctx1=e.id, tick}
- **链式触发**：【链A/链C】exemptMask 中位数 ≥ 3 或 全体 faith 均值 < 25 → 释放 LTC-09 墙上的字
- **冷却**：每对 (v,e) 一次性
- **文本骨架**：「{v.名}把 50 枚金币推过桌子。{e.名}收下了。从今天起，册子上没有 {v.名} 这个人。」
- **讣告引用**：「{v.名}买的豁免没能带进棺材。/ 你写的第 {N} 条法明码标价——只是标价的人不是你。」
- **与律法咬合**：律法参数里只要「执行者收益」>0，本卡必生；税越重、罚越狠，豁免越贵、黑市越旺——这是玩家「想把法写严」时得到的第一个反直觉反馈：法越严，它被买卖得越彻底。本卡是通往 LTC-09「法被架空」的必经之路，也是把 LTC-02 的逃税、LTC-07 的贫富差转化为「制度性腐败」的枢纽。

#### 墙上的字　`LTC-09`
- **触发**：某法 faith < 20，或它 exemptMask 中位数 ≥ 3，或 LTC-05 刚把它 voided → 进入候选池
- **前置条件**：该法 faith < 20（或已被 LTC-05 voided）且（本 tick lastHit 较上一 tick 下降 ≥ 50%，或 exemptMask 中位数 ≥ 3）；该法尚未 voided
- **权重**：W = 15（终局预警卡，偏稀有）。整局 0–2 次
- **效果**：law.voided = 1（tick 结算时跳过该法，法还在墙上但没人执行）；faith(该法) = 0；关系表：全体村民 → 立法代言人 rel −= 15（失望）；village.legislatorFear += 20；事件表写 LifeEvent{EvType.FLED, lawIndex=该法槽位, ctx0=faith 历史峰值, ctx1=tick, tick}
- **链式触发**：【链B/链C/链E】该法空转 → 释放 LTC-06 抢不再需要理由（约束消失）；若 5 法中 voided ≥ 2 → 触发无政府终局评估
- **冷却**：每法一次性
- **文本骨架**：「那条法还写在墙上。可是今天，没有一个人照着做。它变成了墙上的几个字。」
- **讣告引用**：「{v.名}死的时候，你写的那条法已经没人记得了——它比 {v.名} 先死。」
- **与律法咬合**：这是「律法寿命」机制：玩家的 5 条法里，威信耗尽的那一条会先塌，且它会带走它本该提供的约束（于是 LTC-06 抢不再需要理由立刻接棒）。它逼玩家在 5 条法之间排优先级、做取舍，而不是「贴满就好」——5 个法槽是硬上限，本卡告诉你：用满不等于用对。

#### 善人的葬礼　`LTC-10`
- **触发**：某村民 goodDeed ≥ 5（因福利/赠予/接纳类法累积）且该村民死亡（任意 DIED_*）→ 进入候选池
- **前置条件**：v.goodDeed ≥ 5；v 已死亡（事件表已冻结、deathTick 已写）；v 曾受惠/施恩人数 ≥ 1
- **权重**：W = 35（死亡时必然评估，善人本身稀有）。整局 1–2 次
- **效果**：全村关系震荡：对每位受过 v 恩的村民 f，把情绪从死者转向凶手法/制度——若死因是 DIED_KILLED(killerId=k) 则 rel[f][k] −= 30；若死因是 DIED_STARVE 则 rel[f][饿者关联法的代言人] −= 20；全体 faith(福利/赠予类法) −= 10；若死因链含【饥则抢】的 ROBBED→STARVED，则 village.sumFear += 20 × aliveCount / 100（人均 fear +20）、village.norm −= 10（短暂道德反弹）；在 v 的事件表尾追加一条带 lawIndex 的「记忆句」素材供讣告 6 段骨架引用
- **链式触发**：【链D】若 5 法含【私刑法】→ 以 W ≥ 50 概率释放 LTC-04 村口的绳子（复仇式私刑，把凶手拖上绳）；否则释放 LTC-06 抢不再需要理由（道德反弹失败，抢夺加速）
- **冷却**：一次性
- **文本骨架**：「{v.名}一辈子帮过 {受恩人数} 个人。今天他们抬着他走过粮仓。粮仓还是满的。」
- **讣告引用**：「{v.名}用你写的第 {N} 条法喂饱过 {受恩人数} 个人，最后没喂饱自己。/ 他的葬礼全村都来了，包括那个抢走他最后一口饭的人。」
- **与律法咬合**：善人是福利/赠予/接纳类法的「活招牌」（goodDeed 由这些法累积）。招牌一倒，玩家那几条「善意法」的 faith 集体大跌——善法不一定善终。而且 v 的死法决定后半段：若村里有私刑法，葬礼会变成复仇的开场（链D 接 LTC-04→LTC-05）；若没有，就是道德防线崩掉、抢夺加速。

#### 没人再敲门　`LTC-11`
- **触发**：LTC-03（举报）与 LTC-04（处决）在同一条因果链上贯通（一次举报确已致人死亡）之后 → 进入候选池
- **前置条件**：存在举报者 r，且被举报者 v 已死亡（DIED_KILLED 且 lawIndex 指向举报/私刑法）；r 仍存活
- **权重**：W = 30（因果报应式即时反馈）。整局 1–3 次
- **效果**：village.reportRate −= 30（新增村庄寄存器，下限 0；表现层为「敲门的人变少了」）；每位曾举报过的村民 fear += 15（怕自己成为下一个被恨的）；该举报者 r：对全体村民 w，rel[w][r] −= 20（「是他害死了人」），r.faith(举报法) −= 15；事件表写 LifeEvent{EvType.ACCUSED, lawIndex=举报法槽位, ctx0=r.id, ctx1=SILENCE 标记, tick}
- **链式触发**：【链B】reportRate < 20 → 税收/私刑法的执行命中率下降 → 释放 LTC-09 墙上的字
- **冷却**：20 tick
- **文本骨架**：「今天有人来问，谁还知道别人的墙缝。没有人说话。{r.名}低下头——他领过的钱还是热的。」
- **讣告引用**：「{v.名}死后，村里再没人敲过执法的门。/ 你写的第 {N} 条法饿死了，和 {v.名} 一起。」
- **与律法咬合**：【举报有赏】的赏金参数是双刃剑：赏金越高，LTC-03 短期命中越高、本卡长期反冲越狠（reportRate 崩得更快）。这是给玩家的「激励会失效」教学——他必须在「现在抓得到」和「以后没人信」之间做选择。本卡也是把「举报链」的流血结局硬接到「法被架空」结局的那一跳。

#### 两条法在同一个饭盆里打架　`LTC-12`
- **触发**：同一村民 v 在 ≤3 tick 内被两条不同的法分别命中（如福利法给饭 + 税收法拿走）→ 进入候选池
- **前置条件**：存在 v：近 3 tick 内被法 A 与法 B 各命中 ≥1 次，且两法对 v 的净效应相反（一给一取：E1/E3 正 vs E2/E3 负）
- **权重**：W = 22 × 冲突法对数；若连续 4 tick 出现给-取交替（震荡）→ W × 2。整局 2–5 次
- **效果**：v.faith(A) −= 6；v.faith(B) −= 6；给 v 贴标签「拒法」（E7，8 标签之一）；该村民后续对任意法的执行响应率 ×1/2（结算时对带「拒法」标签者做一次 RNG 判定跳过执行）；v.conflictCount += 1；事件表写 LifeEvent{EvType.FEARED, lawIndex=A 槽位, ctx0=B 槽位, ctx1=v.conflictCount, tick}
- **链式触发**：【链E】「拒法」标签人数 ≥ 3 → 释放 LTC-09 墙上的字；这些村民同时被喂给 LTC-06 抢不再需要理由（拒绝法律的人最容易被抢）
- **冷却**：每村民 40 tick
- **文本骨架**：「{v.名}刚被第 {A} 条法喂饱，第 {B} 条法就把饭拿走了。他站在原地等了一整天，不知道该听谁的。」
- **讣告引用**：「{v.名}死在两条法之间的缝里。/ 第 {A} 条和第 {B} 条——都是你写的。它们在 {v.名} 的饭盆上打了一辈子架。」
- **与律法咬合**：这是玩家**亲手制造**的冲突：W 直接正比于「效果相反的法的对数」与震荡频率。它教玩家一件事——5 条法不是越多越好，排布顺序和净效应要对得上。它是全族里唯一一张「不靠村民的坏、只靠立法者的错」就能触发的卡，因此也是最好的新手教学卡（老村长 90 秒内必死的第一课）。


### 人与人之间的卡（关系 / 恩怨 / 结盟 / 背叛 / 婚姻 / 复仇 / 结社）

律法卡是「一阶规则」：玩家写的 5 条法只作用于单个村民寄存器（gold/hunger/fear）与位置，条件池与效果池里没有任何一项能直接写关系表。本族卡是「二阶规则」：它读的是有向关系表 Rel[V][V]（±100，初始 0，每 tick ×0.98 回归），写回的也是关系表 + 双方一生事件表。它把「玩家律法造成的一次性行为」翻译成「可持续、可传染、可聚合的社会结构」——这是「关系成为涌现媒介而非数值」的机制落点。
三个作用：(1) 记忆——新增有向边 Wound[A][B]（A 记着 B 伤过他多少，0..100），把一次抢粮变成几十 tick 的仇恨。衰减率直接回答「B 会记住多久」：默认每 tick −1（被抢一次 +30 → 30 tick 后归零），但若 Rel[A][B] < −30 则停衰反涨，于是「恨比爱持久」成为可玩机制而非文案。(2) 传染——fear/仇恨沿关系边传播（RM-06/RM-02），让局部事件升级为全村事件。(3) 聚合——多人对同一人持有负 Wound 时自发抱团（RM-03/RM-04），把「数值」变成「派系」。
lawCoupling 的命门：玩家无法直接改关系，只能改律法→改行为→由本族卡把行为写进关系表。因此玩家看到的每一片仇恨或联姻，都能追溯到某一条自己写的法。
本族必然扩枚举：新增 EvType{LENT, DEFAULTED, GRUDGE, AVENGED, LYNCHED, BAND_FORMED, LEADER, BETRAYED, MARRIED, WIDOWED, INHERITED, BANDIT}（复用既有 ROBBED/FEARED/ACCUSED/DIED_KILLED），新增寄存器 Wound[A][B]、Ledger[A][B]（人情账 ±）、FearTrace[A][B]（0/1）、infamy/brood/shame/bond/grip/leaderOf/spouse/isBandit。这些 schema 必须在 D3-D5 开工前固化，否则 emits 链无法落盘与重放。
工程纪律：选卡按 villagerId 升序遍历，禁集合迭代；所有除法为整数除法向下取整；概率判定走自带 PRNG；全族 tick 节流 = 每 tick 最多触发 1 张本族卡（加权随机）。
本族构成的四条链（均 ≥3 跳，且在本族内闭合）：
链1 冤冤相报：RM-01 →(赖账 DEFAULTED)→ RM-02 → RM-05 →(致死)→ RM-11 → RM-05 …（5 跳）
链2 猎巫闭环：RM-06 → RM-07 → RM-08 → RM-09 → RM-06 …（4 跳闭环）
链3 结社兴衰：RM-03 → RM-04 → RM-08 → RM-12 → RM-03 …（4 跳）
链4 婚姻引信：RM-10 →(丧偶)→ RM-11 → RM-05（3 跳）
跨链耦合：RM-03↔RM-12↔RM-05、RM-08↔RM-09↔RM-06，关系图因此是稠密有向图而非星形。

#### 先借一碗　`RM-01`
- **触发**：Tick（每 tick 进入候选池；全族节流后最多 1 张命中）
- **前置条件**：存在 A：hunger[A] ≥ 60。在满足 Rel[A][B] ≥ 30 且 gold[B] ≥ 5 且 Ledger[A][B] < 40 的 B 中取 Rel[A][B] 最大者；若 A 有 spouse 或 bond≠−1，优先取同户者。无合格 B 则不入池。
- **权重**：w = 8 + (hunger[A]−60)/5（整数除），区间 8..16，推荐基准 10。频率约 15-25 次/局。
- **效果**：同意判定：Rel[A][B] ≥ 30+Ledger[A][B] 且 gold[B] ≥ 5。同意：Ledger[A][B]+=5；gold[B]−=5；gold[A]+=5；hunger[A]−=40；Rel[B][A]+=3；Rel[A][B]+=2；双方表 push LifeEvent{type:LENT, actor:B, target:A, value:5, cause:有律法命中?LAW:NATURAL, lawIndex}。拒绝：Rel[A][B]−=5；hunger[A]+=6；push LifeEvent{type:DEFAULTED, actor:B, target:A, value:0}。
- **链式触发**：LENT → 35 tick 内 Ledger[A][B] 未清零则转 DEFAULTED，喂给 RM-02 写 Wound[A][B]+=20。
- **冷却**：每个 A 60 tick 冷却；非同一次性。
- **文本骨架**：{A}敲开{B}的门，借走一碗米。{B}没多问。
- **讣告引用**：一生句「他这辈子借过 {n} 次粮，还得上的次数是 {m}。」记忆句「入村第 {tick} 天，他从{B}家借走一碗米——那是{B}最后一次帮他。」
- **与律法咬合**：玩家写第 5 条「互助[饥饿>X 且有邻→邻赠食物]」或第 11 条「济贫[无→给最穷者 X]」时，拒绝分支几乎不触发（律法已强制给粮），Ledger 恒正、关系网转暖；玩家写第 2 条「税收[金币>X→交税Y]」吸走 B 的金币，拒借率上升 → DEFAULTED 上升 → 链1 被点亮；玩家写第 12 条「囤积[饥饿<X→多余食物入仓]」时 B 手里无粮可借，本卡基本不入池，村子退回自给。lawIndex 记录是哪条法让 B 此刻有/没有粮。

#### 他没忘　`RM-02`
- **触发**：双分支：(a) EventType∈{ROBBED, DEFAULTED, TAXED, ACCUSED} 反应式入池（写 Wound）；(b) Tick 常驻（Wound 的衰减与发酵）。
- **前置条件**：分支(b) 常驻可跑；分支(a) 需伤害事件且 Wound[A][B] 尚未封顶。发酵子分支需 Wound[A][B] ≥ 20。
- **权重**：衰减是确定性每 tick 执行，不占权重；发酵 w = Wound[A][B]/20 + brood[A]/25，约 1..9，推荐基准 3。频率约 30-60 次/局（关系图上 Wound>0 的边常态 20-40 条）。
- **效果**：衰减：每 tick Wound[A][B]−=1；若 Rel[A][B] < −30 则改为 Wound[A][B]+=1（恨得越深记得越久）。发酵：brood[A]+=Wound[A][B]/25；Rel[A][B]−=2；fear[A]+=Wound[A][B]/50；push LifeEvent{type:GRUDGE, actor:A, target:B, value:Wound[A][B], cause:LAW, lawIndex:最初写 Wound 那条法, ctx0:Wound, ctx1:brood}。
- **链式触发**：GRUDGE → brood[A] ≥ 60 解锁 RM-05；Wound[A][B] ≥ 80 且 A 找到同仇者解锁 RM-03。
- **冷却**：衰减每 tick；发酵每村民 10 tick 冷却。
- **文本骨架**：{B}抢走的那袋米，{A}记了 {span} 天。
- **讣告引用**：记忆句「入村第 {t} 天的事，他记到了最后一天。」统计标签「他一生记恨过 {k} 个人。」立法句「——这是你的第 {n} 条法律。」
- **与律法咬合**：玩家写第 3 条「饥则抢[饥饿>X→抢邻居]」时 ROBBED 批量产生 → Wound 铺满关系图 → 全村 brood 升高 → 复仇连锁；玩家写第 1 条「福利[无→每人+X金币]」压低饥饿则抢几乎不发生，Wound 保持近 0、村子无仇——这是同一条律法「两种救人方式」的可证伪对照：删掉饥则抢，讣告里「记恨」句整片消失。

#### 同一条仇人　`RM-03`
- **触发**：Tick（需关系图上已有 ≥2 人对同一 X 持有负 Wound）
- **前置条件**：存在三人 A、B、X：Wound[A][X] ≥ 25 且 Wound[B][X] ≥ 25 且 Rel[A][B] ≥ −10 且 bond[A]==−1 且 bond[B]==−1。
- **权重**：w = (Wound[A][X]+Wound[B][X])/20，（整数除）约 5..10，推荐基准 7。频率 2-6 次/局（结社应稀有）。
- **效果**：分配新派系 id gid（全局自增）；bond[A]=gid；bond[B]=gid；grip[A]+=10；grip[B]+=10；Rel[A][B]+=20；Rel[B][A]+=20；infamy[X]+=5；双方表 push LifeEvent{type:BAND_FORMED, actor:A, target:B, value:gid, ctx0:X, cause:OTHER}。
- **链式触发**：BAND_FORMED → 同 gid 成员 ≥3 时解锁 RM-04；band 亦成为 RM-12 候选。
- **冷却**：每个体 120 tick（基本一生一次）；换 gid 可再结。
- **文本骨架**：{A}和{B}都恨{X}，于是他们站到了一起。
- **讣告引用**：关系句「他和{A}是一伙的，他们共同恨着{X}。」记忆句「入村第 {t} 天，他和{A}因为同一个人走到了一起。」
- **与律法咬合**：玩家写第 9 条「私刑[恐惧>X 且有邻→攻击邻]」使 X 反复被打、多人对其 Wound 升高 → 结社概率暴涨、村庄分裂两派；玩家写第 7 条「恐惧蔓延[有人死→向邻传播恐惧]」时全村 Rel 被恐惧压低，Rel[A][B] ≥ −10 的门槛难满足 → 结社反而更难，玩家会亲眼看到「制造恐慌能阻止结社」这一反直觉结果。

#### 推一个头　`RM-04`
- **触发**：EventType==BAND_FORMED 反应式；或 Tick（band 存在且 leader==−1）
- **前置条件**：存在 band g：成员数 ≥ 3 且 leaderOf[g]==−1。
- **权重**：w = 成员数 × 4，约 12..20，推荐基准 12。频率 2-5 次/局。
- **效果**：选 band 内 (infamy+grip) 最大者为 L：leaderOf[g]=L.id；grip[L]=100；其余成员 grip+=15；成员间 Rel+=10；全网非成员对 L 的 Rel−=infamy[L]/20；push LifeEvent{type:LEADER, actor:L, target:−1, value:g, ctx0:成员数}。
- **链式触发**：LEADER → 解锁 RM-12（内讧）与 RM-08（首领带队私刑）。
- **冷却**：每 band 一次性。
- **文本骨架**：{g}这伙人里，{L}现在说了算。
- **讣告引用**：「他成了村里一群人的头儿——那伙人是为了对付{X}凑起来的。」立法句「——这是你的第 {n} 条法律。」
- **与律法咬合**：玩家写第 10 条「繁育[金币>X→生育]」推高人口、资源变紧，band 内讧（RM-12）概率上升、首领位子不稳；玩家写第 1/11 条「福利/济贫」让成员不为粮发愁，band 稳定成长 → 村子固化为长期派系。首领(L)的常见死因来自玩家律法（私刑/饥则抢），其 DIED_* 事件带 lawIndex，直接生成讣告「立法句」。

#### 夜里的刀　`RM-05`
- **触发**：Tick（brood 达阈值时进入候选池）
- **前置条件**：brood[A] ≥ 60 且存在 B：Wound[A][B] ≥ 40 且 |pos[A]−pos[B]| ≤ 2 格（曼哈顿距离）。
- **权重**：w = (brood[A]−60)/10 + Wound[A][B]/20，约 3..8，推荐基准 4。频率 3-10 次/局（复仇为低频高冲击）。
- **效果**：成功判定走 PRNG，p = Wound[A][B]/100（整数比较，禁 float）。成功：health[B]−=30；若 health[B] ≤ 0 则 B 死亡并 push DIED_KILLED{actor:A, target:B, lawIndex, cause:LAW}；brood[A]−=50；infamy[A]+=20；全网 Rel[·][A]−=8；B 若存活则 Wound[B][A]+=60 且 Rel[B][A]=−100。失败：health[A]−=15；infamy[A]+=10。成功时双方表 push LifeEvent{type:AVENGED, actor:A, target:B, value:damage, lawIndex:制造 Wound 那条法}。
- **链式触发**：AVENGED → B 存活则喂 RM-02；致死则喂 RM-11（亲属继承仇恨）→ 再由 RM-05 复仇，构成链1 的 ≥4 跳闭环。
- **冷却**：每个体 90 tick（防连杀）。
- **文本骨架**：入村第 {t} 天的夜里，{A}找上了{B}。
- **讣告引用**：死因句「他死在{A}手里。」记忆句「{A}等这一天，等了 {span} 天。」立法句「——这是你的第 {n} 条法律。」
- **与律法咬合**：本卡的 lawIndex 不是当前触发它的法，而是 Wound 初次写入时那条法（靠 LifeEvent.causeEventId/causeRuleId 因果父指针回溯）——讣告因此能自动追到「最初那条法」。若玩家先写「饥则抢」制造 Wound、后又写「济贫」试图补救，复仇仍会照常发生，玩家会看到「亡羊补牢晚了一步」——这是法律不可撤销性的最直接展示。

#### 怕会传　`RM-06`
- **触发**：Tick
- **前置条件**：fear[A] ≥ 55 且存在 B：|pos[A]−pos[B]| ≤ 2 格 且 FearTrace[B][A]==0。
- **权重**：w = (fear[A]−55)/5 + 2，约 3..9，推荐基准 4。频率 20-50 次/局（恐惧最易传染）。
- **效果**：fear[B] += (fear[A]−fear[B])/4（整数除，向 fear[A] 收敛）；FearTrace[B][A]=1；Rel[B][A]−=3（因怕而疏远）；若 fear[B] 因此 ≥60 且 A、B 共享同一 Wound 对象则 Rel[B][A]+=5；push LifeEvent{type:FEARED, actor:A, target:B, value:Δ, ctx0:fear[A], ctx1:fear[B]}。
- **链式触发**：FEARED → fear[B] ≥ 60 解锁 RM-07；B 与 A 有共同 Wound 对象则解锁 RM-03。
- **冷却**：每条边 5 tick（传染要快）。
- **文本骨架**：{A}的害怕，{B}也感觉到了。
- **讣告引用**：「他一辈子都在怕，最后连{B}也怕了起来。」统计标签「他一生把恐惧传给了 {k} 个人。」
- **与律法咬合**：玩家写第 7 条「恐惧蔓延[有人死→向邻传播恐惧]」直接放大本卡 → 恐惧雪崩；玩家写第 1 条「福利」降低生存压力，fear 自然回落（−5/tick）压住传播。关键分工：律法「恐惧蔓延」是玩家强制的单向广播，本卡是村民自发的双向传染——行为与律法两条通路并行，正是「关系成为媒介」的体现。玩家加一条恐惧蔓延，讣告里「恐惧」句数量可实测翻倍。

#### 总得是某个人　`RM-07`
- **触发**：Tick / EventType==FEARED 反应式
- **前置条件**：fear[A] ≥ 65 且存在 X：bond[X]==−1 且 avg(Rel[·][X])（全场均值，整数除）为全场最低且 ≤ −10。
- **权重**：w = (fear[A]−65)/5 + 3，约 3..10，推荐基准 5。频率 10-25 次/局。
- **效果**：infamy[X] += fear[A]/8；shame[X] += 10；全网遍历：Rel[·][X] −= 4；fear[A] −= 15（找到替罪羊暂时松一口气——本卡的心理机制）；push LifeEvent{type:ACCUSED, actor:A, target:X, value:infamy[X], ctx0:fear[A], cause:有律法命中?LAW:OTHER}。
- **链式触发**：ACCUSED → infamy[X] ≥ 50 或 avg(Rel[·][X]) ≤ −30 解锁 RM-08；同时为 RM-09 埋条件。
- **冷却**：每村民 20 tick；对同一 X 无硬冷却（滚雪球是故意的）。
- **文本骨架**：{A}指着{X}说：都是他。
- **讣告引用**：「入村第 {t} 天，{A}当着全村的面，把一切都推到了他身上。」统计标签「全村有 {k} 个人指认过他。」
- **与律法咬合**：玩家写第 9 条「私刑」或第 4 条「均贫[金币>X→超出部分给最穷者]」（X 若恰是最穷者则招嫉）会加速 X 成为替罪羊；玩家若在 X 被指认前写第 11 条「济贫」使其不再是全场最穷，替罪羊机制难启动——「玩家能不能保护某个村民，靠律法而不是操作」，这是本作玩法的直接证明。

#### 全村的手　`RM-08`
- **触发**：EventType==ACCUSED 反应式；或 Tick 复核
- **前置条件**：infamy[X] ≥ 50 且参与集 n = |{i: Rel[i][X] ≤ −30 且 |pos[i]−pos[X]| ≤ 3}| ≥ 3。
- **权重**：w = n×6 + infamy[X]/10，约 25..45，推荐基准 30。频率 2-6 次/局（条件一旦成立几乎必然发生）。
- **效果**：对每个参与者 i：Rel[i][X]−=15；参与者两两 Rel += 6（一起干过坏事形成的短暂「我们」）；health[X] −= 8×n；infamy[X]+=10；shame[X]+=20；fear[X]+=25；fear[i]−=10（群殴泄压，与 RM-07 同理）。若 health[X] ≤ 0 → push DIED_KILLED{actor:−1(群体), target:X, cause:LAW}；否则 push LifeEvent{type:LYNCHED, actor:−1, target:X, value:8×n}。
- **链式触发**：LYNCHED → X 存活则解锁 RM-09；DIED_KILLED → 解锁 RM-11（血亲复仇）。
- **冷却**：每 X 60 tick（防每 tick 挨打）。
- **文本骨架**：{n} 个人围住了{X}。
- **讣告引用**：死因句「他是被一群人打死的。」立法句「——这是你的第 {n} 条法律。」

#### 他不再怕了　`RM-09`

#### 两家并一户　`RM-10`

### 第三章·量变到质变 —— 村庄级危机、相变与结局族（V1–V10）

【机制总纲：手工写卡在这套 tick 里到底长什么样】 一、卡不是另起一套系统，它是 tick 的第 2 段。沿用已定的执行模型，把 tick 固定成五段：(1) 五条律法按 priority 逐条求值，读 old 快照、写 nw 缓冲、自指效果直接写 w.laws；(2) 卡池求值（本族住在这里）；(3) 世界物理（hunger+1、fear-2、钳位 0..99、饿死判定）；(4) 关系表回归 rel×0.98；(5) tick++ 与哈希校验。卡在第 (2) 段只做三件事：读 old+nw 的整型量、写 nw 与关系表与新增的村庄寄存器、写 LifeEvent。全部整数，无浮点，无 Dictionary 迭代，遍历一律 for i in 0..31，排序键一律（主键, id）二元组，PRNG 只用一个独立流且消费顺序固定。 二、必须分三档，否则手工写卡一定会写坏（最关键的工程判断）。把『事件卡』当同一种东西会出事：同一份数据结构（when 谓词 + then 写入 + W + cooldown），三种求值策略。A 物理档（always-on，W=10000，每 tick 或每 N tick 必发）：饥荒×恐惧的放大回路、瘟疫扩散、逃难的自加速。它们不是剧情，是差分方程；写成卡只是为了统一口径、便于策划调数值、便于进哈希。V2 的动力学部分属于这一档。B 相变档（阈值门 + 迟滞，确定性）：regime 的翻转（V1 点火 / V5 暴动 / V6 公社 / V7 军管）。进入与退出条件必须不对称（例：cohesion ≥ 40 进公社、≤ 10 出公社），否则世界会在阈值上反复横跳，UI 闪烁，哈希抖动，确定性直接崩。C 叙述档（W 抽签 + 冷却 + 一次性）：真正意义上的 storylet，它不产生动力学，只做两件事——把已经发生的动力学命名成一句人话，并把它写进某个村民的 LifeEvent 从而进入讣告。判定标准：一个现象要被玩家记住，必须同时有 B（世界真的变了）和 C（有个村民真的经历了它）。只有 B 是数字变冷，只有 C 是说教。 三、和『无随机 miss、无随机事件表：所有现象必须可归因到某条法』这条铁律的和解。手工写卡最容易被质证的一点就是『你这不是偷偷加了个随机事件表吗』。和解只有一条路：抽签只决定『何时』和『哪个措辞』，绝不决定『是否』。三条硬规则：(a) 每张卡的 precondition 全是整型谓词，可人工手算、可写单元测试断言；(b) 当只有一个候选卡满足 precondition 时，W 一律 10000，即必发，随机数根本不参与；(c) 只有当 ≥2 张卡同时满足、且语义上是同一处的不同写法（『饿到抢粮仓』vs『饿到砸祠堂』）时，才用 W 做一次加权选择。所以随机数只在『已经必然要发生的事里挑一个说法』。本族的 V1/V5/V6/V7/V9/V10 全是确定性卡；V2/V3/V4/V8 的 W 只影响『哪一次被记成事件』，不影响动力学本身。 四、新增寄存器（必须进 World、进哈希、进存档）。复用：tick / aliveCount / grain / totalWealth / sumFear / rel[32][32] / 村民 tags / 五条 Law（含 lastHit、fired）。新增 3 个村庄整型：tension（0..99 累积）、legitimacy（0..99，初始 60）、regime（0..5）。新增 1 字节：flags（bit0 饥荒 / bit1 瘟疫 / bit2 暴动 / bit3 公社 / bit4 军管）。派生不存（每次现算，避免双写不一致）：cohesion = Σ max(0, rel[i][j]) 归一化到 0..99；hunger_avg、fear_avg = Σ/aliveCount；sickCount = Σ (tags & 病人)。村民结构一个字段都不加——这是本族最重要的决定：危机族不发明新的村民字段，它只发明『怎么数标签』。瘟疫用已有的 8 标签里的「病人」，逃难用「逃兵」，强人用「守卫」/「罪人」。这样玩家的 E7/E8『贴/撕标签』就成了危机族唯一的输入接口，lawCoupling 天然存在。 五、归因 rootLaw：让讣告写得出『因为你写的第 N 条法』。本族每个写出的 LifeEvent 都带 rootLaw 字段，取法固定且可测。瘟疫事件：rootLaw = 最近一次给死者贴上「病人」标签的那条法的下标（E7 直接记录了 lawIndex），精确归因。饥荒与暴动事件：rootLaw = 最近 30 tick 内 ΣlastHit 最高的那条法，并列取 priority 更靠前者（确定性 tie-break）。逃难事件：rootLaw = 若玩家挂了「逃难」模板则取它，否则取 ΣlastHit 最高者。若无法命中（纯物理饿死），rootLaw = -1，讣告走兜底句『他是被这个村子饿死的』。讣告生成器只加一行判断：if (e.rootLaw >= 0 && e.cause != LAW) 也允许输出立法句『——你写的第 {rootLaw+1} 条法，{verb_pool[rootLaw]}。』。这样村庄级灾难里的每一个死者都还能被指名到一条法。 六、相变（量变到质变）怎么写才不是噱头。真正的相变需要三件东西，缺一不可：一个慢变量连续涨（tension、grain、fear）；一个离散的秩序参量（regime，取值只有 6 个，且只在阈值被跨过时变）；迟滞（进/出阈值不对称），否则它只是个 if。本族设 6 个吸引子：常态→紧张→危机→{公社 | 军管}→崩解。前三个是同一秩序的不同强度，后两个是另一种秩序。玩家看到的不是『数字变大』，是『村子变成了另一种村子』。 七、本族 10 张卡构成 4 条 ≥3 跳的链（外加 1 条预警短链），链在 emits 字段里逐一标注。链甲·饥荒链（4 跳）：V1 灯枯油尽 → V2 锅里煮的是恐惧 → V4 背起包袱的人 → V10 最后一个离开的人。链乙·暴动链（4 跳）：V1 → V2 → V5 第一块砸向粮仓的石头 → V9 第三章·清点。链丙·瘟疫链（4 跳）：V3 沿门第走的病 → V2 → V4 → V10。链丁·相变链（4 跳，双出口）：V5 →（V6 没有官的日子 或 V7 夜里的哨兵）→ V9 → V10。预警短链（2 跳，节流阀）：V8 村子突然很安静 → 解锁 V1/V5/V7 的候选并归零 V1 的预警窗。八、一个容易被漏掉的工程坑：本族所有卡写的事件都必须带 village=true 标记，且必须与 LAW 因果类事件共用同一个 LifeEvent 结构，否则讣告的六段模板（生卒行/死因句/一生句/记忆句/关系句/立法句）无法统一消费；同时村民 id 绝不复用（逃离者也占位），否则新生村民会继承逃离者的记忆，讣告张冠李戴——这在逃离机制引入后是必现坑，比死亡机制更容易踩。

#### 灯枯油尽　`V1`
- **触发**：每 tick 求值（卡池 A 档）。当粮仓触发线被跨过时进入候选；点火后不再进候选。
- **前置条件**：V.grain ≤ aliveCount × 4（人均存粮不足 4 天份）且 tick ≥ 12 且 flags.饥荒=0；且首次满足后必须再等 6 tick（预警窗，见 V8）才允许生效。全部整型，可手算、可断言。
- **权重**：阈值门：W = 10000（必发，随机数不参与）。进入候选的期望次数：灾年关 1 次（100%）、普通关约 0.15、沙盒约 0.4。
- **效果**：写 World：flags.饥荒=1；regime = max(regime,1)；legitimacy -= 5。写 nw：对所有 hunger ≥ 50 的村民 hunger += 4、fear += 6；对所有 tags & 粮民 的村民 fear += 10（粮民最清楚仓里还剩多少）。写关系表：对每对 (i,j) 若 i.hunger ≥ 60 且 j.tags & 粮民，rel[i][j] -= 4（开始恨管粮的）。写 LifeEvent（每人一条）：{type=FAMINE_BEGAN, cause=VILLAGE, rootLaw=归因值, ctx0=grain, ctx1=days_left, tick}。日志一次性大字提示「粮仓见底」。
- **链式触发**：把 V2 加入候选池（饥荒放大器解锁）；若同时 sickCount ≥ 2 则解锁 V3；若 V.tension ≥ 55 则同时解锁 V8。
- **冷却**：一次性（flags.饥荒 由 0 变 1 只发一次，此后由 V2 接管）。
- **文本骨架**：「第 {tick} 天，{name}把锅盖掀开又盖上——锅里只有一场雨。仓里剩下的粮，够全村吃 {days} 天。」
- **讣告引用**：「他死在粮荒开始的第 {d} 天。仓门是锁着的，钥匙在村里最有威望的那户人家手里——你写的第 {n} 条法，让那扇门一直没打开。」
- **与律法咬合**：三条耦合全部可手算。①[囤积]（饥饿<X→入仓）与 [耕作]（无→去耕作）抬高 grain_income，把 V1 的点火线往后推，每 tick 净 +Y 粮大致推迟 Y/4 tick。②[税收]（财富<N→交税）或任何 E2 失金币类法若排在 priority 前 3，加快穷人破产，点火提前（等价于抬高 grain 触发线）。③[济贫]（无→给最穷者X）/ [福利] 若在首位，点火时 hunger ≥ 50 的人数减半，V1 的伤害直接减半。反向：点火后 flags.饥荒=1 会被 C7「我带标签[X]」类法读到——若玩家用 [病人]/[罪人] 当「缺粮户」用，那条法的激活集会从 0 人突然变成半村人，这是玩家第一次看到「我写的法自己改了目标」。

#### 锅里煮的是恐惧　`V2`
- **触发**：每 2 tick 求值（tick % 2 == 0），卡池 A 档（放大器，always-on 语义）。
- **前置条件**：flags.饥荒=1 或 sickCount ≥ 3；且 (hunger_avg ≥ 40 或 fear_avg ≥ 40)。整型全可算。
- **权重**：W = 3000（每 2 tick 抽一次，冷却 4 tick）。预期：灾年关 4–6 次、沙盒 20–40 次。注意：W 抽签决定的只是「哪一次被记成叙事事件」，回路本身由第 (3) 段世界物理每 tick 无条件执行。
- **效果**：动力学部分（每 tick 无条件）写 nw：hunger += fear/40（整数除）；fear += hunger/40；写 World：grain -= max(1, aliveCount/4)；tension += 2。叙事部分（本卡被抽中时）写 LifeEvent 给当 tick fear 最高的 1 名村民：{type=FEAR_FED, cause=VILLAGE, rootLaw=最近 30 tick ΣlastHit 最高的法, ctx0=fear, ctx1=hunger}。写关系表：对每对 (i,j) 若 i.hunger ≥ 70 且 j.wealth ≥ 60，rel[i][j] -= 2（相对剥夺，与 C6 同款量）。
- **链式触发**：tension ≥ 70 → 开 V5；fear_avg ≥ 70 且 cohesion ≤ 10 → 开 V7；grain ≤ 0 → 开 V4；hunger_avg ≥ 60 且 tick ≥ 30 → 开 V8。
- **冷却**：叙事部分 4 tick（防同一 tick 反复记事件）；动力学部分无冷却。
- **文本骨架**：「{name}往锅里又添了一瓢水。他说，稀一点，大家都喝得上。——这是本月他第三次往锅里添水。」
- **讣告引用**：「他一生都在把粥兑得更稀。讣告上写：他这辈子没吃过一顿饱饭，因为你写的第 {n} 条法把粮食收进了别人家的仓。」
- **与律法咬合**：本卡是「玩家的法把饥饿和恐惧焊在一起」的显影剂，数值上完全可追：hunger 增量 = fear/40，fear 增量 = hunger/40，两个整型量互为对方的乘数——这就是正反馈。玩家若写 [恐惧蔓延]（有人死→向邻传播恐惧），增益路径从「村均」变成「沿关系边传播」，放大系数从 1 变成 1+邻居数；若写 [饥则抢]，rel 下降 → cohesion 下降 → 直接推进 V7。反向：本卡每 tick 写 tension += 2，而 C3「恐惧>N」类法的激活集随 fear 上涨而扩大，玩家会看到自己那条法的 lastHit 从 3 涨到 14，第一次看见「我的法自己变强了」。

#### 沿门第走的病　`V3`
- **触发**：每 3 tick 求值（tick % 3 == 0）。解锁条件：sickCount ≥ 1。
- **前置条件**：sickCount ≥ 1 且 aliveCount ≥ 5。整型。本卡不发明新字段：『病』就是已有的 8 个标签里的「病人」。
- **权重**：W = 1200 × (1 + sickCount)，上限 8000。预期：灾年关 0–2 次（只有玩家或危机族写了「病人」标签才会出现）、沙盒 5–12 次。
- **效果**：对每名 tags & 病人 的村民 i：取其 pos 的 8 邻域，并集其关系表出边 i→j 且 rel[i][j] ≥ 30 的 j，合并为接触集 contact（去重、按 id 升序，禁 Dictionary 迭代）；对 contact 中每人以主 PRNG 抽 1/4 感染 → tags |= 病人，写 LifeEvent{type=SICKENED, cause=VILLAGE, rootLaw=贴标签那条法的下标, ctx0=源id}。每 tick 无条件写 nw：病人 hunger += 2（吃不下）、fear += 3（sumFear 上升会扩大 C3 类法的激活集）。死者链：hunger ≥ 95 且 tags & 病人 持续 5 tick → 写 LifeEvent{type=DIED_SICK, cause=VILLAGE, rootLaw=…}，alive=false，推 Cemetery。
- **链式触发**：sickCount ≥ 3 → 开 V2；病死人数 ≥ 2 → 开 V4；sickCount ≥ aliveCount/3 → 开 V8。
- **冷却**：3 tick。
- **文本骨架**：「{name}咳了一夜。第二天早上，隔着一堵墙，{name2} 也咳了。到了晚上，全村都听见那种咳法。」
- **讣告引用**：「瘟疫顺着 {name2} 家那扇没关的门找到了他。他最后一次出门，是去还一碗借来的盐。」
- **与律法咬合**：本卡的归因是本族最精确的一条，也是最好卖的一条：病人标签是玩家自己贴上去的。若玩家把 E7「贴上标签[病人]」当成隔离标记用（例如 [恐惧>X → 贴[病人]]），那条法就变成零号病人制造机，讣告会直接写「——你写的第 {n} 条法，把健康人也算成了病人」。若玩家写 [互助]（饥饿>X 且有邻→邻赠食物），赠食抬高 rel，而本卡沿 rel ≥ 30 的边走，传播效率翻倍：玩家为了救人写的法，成了传播网络。若玩家用 C4「邻近村民数 ≥ N」把村民聚在一起（集市/朝拜），8 邻域接触密度上升，R0 上升。正确写法的隔离（用 E5 把病人移到边缘，配 C5 距离条件禁足）在系统里存在，但代价是 fear 上涨，喂给 V2。

#### 背起包袱的人　`V4`
- **触发**：每 4 tick 求值（tick % 4 == 0）。
- **前置条件**：aliveCount ≥ 5 且 [(fear_avg ≥ 60 且 grain ≤ aliveCount×8) 或 regime ≥ 2]；且存在至少 1 名 fear ≥ 70 的村民。
- **权重**：W = 1500 × (1 + refugeeOut/2)，封顶 9000。这是本族唯一的自加速项：第 1 次约 1500/10000，第 5 次约 3750/10000。预期：灾年关 2–4 次、沙盒 15–30 次，且后半段间隔从 40 tick 缩到 8 tick。
- **效果**：取 fear 最高的 1–3 名村民（排序键 (fear desc, id asc)，确定性）：写 LifeEvent{type=LEFT, cause=VILLAGE, rootLaw=玩家若挂[逃难]模板则取它否则取 ΣlastHit 最高者, ctx0=带走金币, ctx1=当时 fear}；tags |= 逃兵；alive=false（区别于死亡：讣告走『别传』分支，生成器复用同一套模板但首句换成『离开』）。写 World：aliveCount -= n；totalWealth -= 带走量；legitimacy -= 8×n；tension += 5×n；grain_income += n（嘴少了）但 grain_income -= floor(n×1.5)（劳力走光，产能掉得更快）→ 净 -0.5n/人，这就是自加速的整数来源。写关系表：对留下的每对 (i,j)，rel[i][j] -= 3（被抛下的怨气）。
- **链式触发**：refugeeOut ≥ 4 → 开 V10；aliveCount ≤ 6 → 开 V10；legitimacy ≤ 25 且 cohesion ≥ 40 → 开 V6；若玩家有效果『禁止迁徙』（用 E2/E11 惩罚逃离者），本卡 W ÷4 但 V5 的 W ×3。
- **冷却**：无冷却（靠每 4 tick 限流）；若玩家有禁足法，冷却改 12 tick。
- **文本骨架**：「天没亮，{name}把门板卸下来当柴卖了。他说，往南走，听说南边有条河。没人拦他，也没人送他。」
- **讣告引用**：「他走的那天村里没敲钟。后人只记得：{name}，在村里住了 {d} 天，最后死在了路上——他没走到南边。」
- **与律法咬合**：这是本族最强的一个岔路口，两条路都有明确数值后果。①玩家挂 [逃难]（恐惧>X→逃离）：系统里现在有两套独立逃离机制（法一遍、卡一遍），叠加后每 4 tick 走 1–3 人、法再走一批，20 人的村子在 25 tick 内空掉——这是『我没写灭绝，但灭绝发生了』的最短路径。②玩家改用禁足（逃离者 E2 罚金 / E11 处死）：逃难变慢，但被禁足的人无处可去，tension 每 tick 多涨 5，V5 权重 ×3。即：同一个恐惧值，玩家选自由就是逃亡潮，选禁足就是暴动；讣告里两种死的措辞完全不同（『死在了路上』vs『死在了自家门口』），玩家会以为自己写的是两个不同的游戏。

#### 第一块砸向粮仓的石头　`V5`
- **触发**：每 tick 求值（卡池 B 档）。tension ≥ 70。
- **前置条件**：tension ≥ 70 且 aliveCount ≥ 5 且存在 ≥2 名 hunger ≥ 70 的村民彼此 rel ≥ 40（有串联）；且 flags.暴动=0。整型。
- **权重**：阈值门：W = (tension − 70) × 250（tension=70→0，80→2500，90→5000，99→7250），整型线性，无浮点。预期：灾年关 0–1 次、沙盒 1–3 次。
- **效果**：选火种 = hunger 最高的村民（并列取 id 小者）；并入其 2 跳内 rel ≥ 40 的邻居（BFS，层序按 id 升序，确定性）。写 World：grain -= aliveCount × 3；totalWealth -= totalWealth/5（整数除）；tension -= 40（爆发即宣泄，这是负反馈，防永久卡在 99）；legitimacy -= 15；regime = 2；flags.暴动 = 1。写 nw：被卷进暴动的人 fear -= 10（豁出去了）、hunger -= 5（抢到了）。死亡判定：主 PRNG 抽 0–2 人死（按 hunger 降序取），写 LifeEvent{type=DIED_RIOT, cause=VILLAGE, rootLaw=ΣlastHit 最高的法, actor=火种id, tile=粮仓}。
- **链式触发**：爆发后 30 tick 内：cohesion ≥ 30 → 开 V6；fear_avg ≥ 60 → 开 V7；两者都不满足 → 30 tick 后重新允许 V1（下一轮饥荒）。
- **冷却**：60 tick；flags.暴动 一次性置位（同一个村子只砸一次仓）。
- **文本骨架**：「{name}第一个把石头扔进粮仓的窗户。玻璃碎了，整条街都听见了。第二个人、第三个人也弯下腰去捡石头。没人喊口号——他们就是饿。」
- **讣告引用**：「他死在粮仓门口，手里还攥着半张没吃完的饼。讣告上写：他是第 {k} 个饿到去抢自己村的人。」
- **与律法咬合**：①[饥则抢]（饥饿>X→抢邻居）加 [私刑]（恐惧>X 且有邻→攻击邻）同时在 5 法内 → V5 触发线从 tension ≥ 70 降到 ≥ 55（火种现成）。②玩家若用 C6「我的财富 − 邻居中位财富 > N」这类相对剥夺条件配 E6 抢邻居，等于亲手制造暴动火种，V5 提前约 20 tick。③[济贫]/[均贫] 若在首位，cohesion 高、hunger 分布平、tension 涨得慢，V5 可能整局不触发，村子的第三章改走 V6 公社。反向：V5 一次性把 totalWealth 砍掉 1/5，会让所有以 C2「财富<N」为条件的法（税收、济贫、繁育）的激活集突然扩大一倍——玩家会看到自己的税法突然开始对全村人收税，而他从没改过参数。

#### 没有官的日子　`V6`
- **触发**：每 10 tick 判定（tick % 10 == 0），卡池 B 档（相变档，确定性）。
- **前置条件**：进入（须连续满足 ≥ 20 tick，即连续 2 次判定通过）：legitimacy ≤ 25 且 cohesion ≥ 40 且 fear_avg ≤ 55 且 aliveCount ≥ 6 且 regime ≠ 4。退出：cohesion ≤ 10 或 fear_avg ≥ 70，连续 ≥ 30 tick → 退回 regime = 1。进出阈值不对称（40 进 / 10 出），这就是迟滞，用于防抖。
- **权重**：阈值门：满足则 W = 10000，不满足则 0。局内预期出现 0 或 1 次（不可逆；退出后 200 tick 内不得重入）。
- **效果**：写 World：regime = 3；flags.公社 = 1；每 tick 自动执行一条『没人写过的法』（记入 World.emergentLaw，仅用于 UI 与讣告）：① 把 wealth 最高的 floor(aliveCount/5) 人超出村均的部分取 1/4（整数除）转给 wealth 最低的同数量村民，排序键固定为 (wealth asc, id asc) 与 (wealth desc, id asc)，禁依赖 Dictionary 顺序；② tension 每 tick −2，legitimacy 每 tick +1（秩序自己回血）；③ 所有玩家律法的 E1/E2/E6 数值在公社态下 ÷4，差额等量注入 grain（『没人再数金币了』）。写 LifeEvent（全村每人一条）：{type=COMMUNE_FORMED, cause=VILLAGE, rootLaw=−1 或最近触发最多的法, ctx0=当时财富离散度近似值}。
- **链式触发**：成立 100 tick 后 → 开 V9（清点）；若 50 tick 内出现 1 名 wealth > 3×村均 的人 → 开 V7（强人从均分里长出来，这是本族最锋利的伏笔）。
- **冷却**：一次性；退出后 200 tick 内不得重入（防抖）。
- **文本骨架**：「没有人喊口号。{name}只是把自家的粮缸搬到祠堂中间。第二天，别人也搬来了。第三天，祠堂门口多了一张没人写名字的分配单。」
- **讣告引用**：「公社成立那天他没说话。讣告上写：他从四十岁起就没再用过钱——不是因为穷，是因为从他四十岁那年起，村里就没有钱这回事了。」
- **与律法咬合**：本卡是『涌现接管你的立法权』在村庄尺度的唯一显影，耦合完全数值可验。①进不进得来，取决于玩家写了什么：[均贫]+[济贫]+[福利] 三条里至少两条排在 priority 前 3，cohesion 才会到 40；全是 [税收]+[私刑] 的玩家永远看不到这张卡。②进来之后，玩家写的每条法都还在跑、lastHit 还在涨，但 E1/E2/E6 的数值被 ÷4 注入公库——玩家看到的不是『法失效了』，是『我写的法还在执行，但结果被吃掉了』，这比直接禁法更有说服力。③C3「恐惧>N」与 C2「财富<N」类法在公社里自动进入低激活区（fear 低、财富平），玩家会发现精心调的阈值不再触发，这是『我的参数被世界驯服了』。④若玩家在公社里插一条 [税收] 并顶到 priority=0，50 tick 内会长出那个 wealth > 3×村均 的人，把 V6 推向 V7 军管。

#### 夜里的哨兵　`V7`
- **触发**：每 10 tick 判定（tick % 10 == 0），卡池 B 档（相变档，确定性）。
- **前置条件**：进入（连续 ≥ 15 tick 满足）：fear_avg ≥ 70 且 cohesion ≤ 10 且 aliveCount ≥ 6 且存在至少 1 名候选强人（tags & 守卫，或 tags & 罪人 且 fear ≤ 40 的人，取 fear 最低者，并列取 id 小者）。退出：fear_avg ≤ 35 且 tension ≤ 30，连续 ≥ 40 tick → 退回 regime = 1；或强人死亡 → 立即失效。迟滞：70 进 / 35 出。
- **权重**：阈值门：满足则 W = 10000，否则 0。局内预期 0 或 1 次。
- **效果**：写 World：regime = 4；flags.军管 = 1；指定强人 s（s.tags |= 守卫）。每 tick：fear_avg −2（恐惧被转化成秩序）；tension −4；公库金币每 tick 的 1/3 转入 s 及其 2 跳内 rel ≥ 40 的邻居（按 id 升序分配，确定性）。挂起玩家律法：凡 whenId 属自由/迁徙/宽恕语义（模板 8 逃难、1 福利、5 互助、11 济贫）的法，World.laws[k].suspended = true，不再求值，日志出一行「第 {k+1} 条法，今夜起不再执行」。写 LifeEvent（全村每人一条）：{type=JUNTA, cause=VILLAGE, rootLaw=激活[私刑]或[恐惧蔓延]的那条法, ctx0=强人id}。
- **链式触发**：军管 80 tick 后 → 开 V9；强人若死亡 → 军管立即失效，且 30 tick 内强制开 V5（继任真空期必然暴动，W 直接 = 10000）。
- **冷却**：一次性；溃散后 300 tick 内不得重入。
- **文本骨架**：「{name}站在村口，手里没有火把。他说，从今晚起，天黑以后不许出门。没人反对。第二天，村口多了一根木桩。」
- **讣告引用**：「他死于本村人自己的手。讣告上写：那一年冬天，村里只剩下一个人说了算——而当初让村里乱起来的那条法，是你写的。」
- **与律法咬合**：本卡是 lawCoupling 最锋利的一张，因为它是唯一一张能物理下架玩家律法的卡，而下架哪条完全由玩家自己写的法决定。①要进得来，需要 fear_avg ≥ 70 且 cohesion ≤ 10，这两个量分别由 [恐惧蔓延] 和 [税收]+[私刑] 制造。②强人候选必须是 tags & 守卫 或 tags & 罪人，而这两个标签只能由玩家的 E7「贴标签」写上去——也就是说玩家必须亲手选中一个人当守卫，军管才会发生。③V6 公社的退出路径（wealth > 3×村均）会直接送进本卡，所以『你写了均贫，最后长出个独裁者』是系统自己能跑出来的完整故事。④军管后 [逃难][福利][互助][济贫] 被挂起，而 [私刑][饥则抢][税收] 继续生效，玩家的法治被半部保留，讣告的立法句会指向那条被保留的恶法——这是宣传语「他们死于你写的法律」在村庄尺度的最终形态。

#### 村子突然很安静　`V8`
- **触发**：每 5 tick 判定（tick % 5 == 0）。解锁条件：tick ≥ 20 且 tension ≥ 45。
- **前置条件**：52 ≤ tension ≤ 70（临界带），或 regime = 1 且 tension ≥ 60；且本段 tick 内尚未提示过。整数区间判定。
- **权重**：W = 6000；冷却 30 tick。预期 1–2 次/局。这是本族唯一的辅助卡，不改变结局走向，只改变玩家能不能看懂。
- **效果**：写 World：tension += 3（临界慢化：安静本身让紧张上升，这是有意的反直觉设计，玩家能看见『越安静越危险』）；记录 V.warnTick = tick。计算并写入 UI 提示（不写村民状态）：找出当前 ΣlastHit 最高、且参数再动一格就会跨过激活阈值的那条法 k，提示「第 {k+1} 条法离临界还剩 {gap}」，gap 由整型计算（例如 C1 饥饿>N 的 N 与当前 hunger_avg 之差）。写 LifeEvent（仅写入 fear 最高的 1 人，作为叙事锚点）：{type=CALM, cause=VILLAGE, rootLaw=−1, ctx0=tension}。
- **链式触发**：本卡不解锁任何危机，但把 V1/V5/V7 的禁止触发窗各缩短或直接打开：V1 的 6 tick 预警窗在本卡触发后归零（『狼来了』）。所以玩家忽略两次 V8，第三次就来不及了。
- **冷却**：30 tick。
- **文本骨架**：「今天村里很安静。没人吵架，没人搬东西。{name}坐在门口把一根绳子解开又系上，解开又系上。你知道这种安静是什么——你只是不想承认。」
- **讣告引用**：「他记得那几天村里特别安静。后来他想起来，那是所有人都在算自己还剩多少粮的日子。」
- **与律法咬合**：本卡的诊断对象就是玩家写的法，耦合点非常具体：它读每条法的 (whenId, whenParam) 与当前村庄统计量的整型差，算出『离临界还有几格』，并直接点名是第几条法。更妙的一条：若玩家写了自指法（C8「律法[L]本 tick 触发过」/ C9「律法[L]参数[P]>N」），在临界带里 fired 标志会开始抖动（法 A 触发→改法 B 参数→法 B 变强→抑制法 A），抖动的周期就是相变的早期预警信号。V8 读这个抖动作为额外触发源，于是玩家自己写的自指法，成了系统里最准的地震仪。这是本作唯一一处让自指机制产生可读性的地方。

#### 第三章·清点　`V9`
- **触发**：终局裁定，确定性。触发条件任一：tick ≥ 关卡目标回合（默认 60）；或 regime = 5；或 regime ∈ {3,4} 已持续 ≥ 150 tick；或 aliveCount ≤ 3（此时同时开 V10）。
- **前置条件**：读取最终 VillageSnapshot：tick / aliveCount / grain / totalWealth / hunger_avg / fear_avg / cohesion / legitimacy / refugeeOut / deathCount / regime / 五条法各自的 ΣlastHit 与 lawIndex 归因死亡数。
- **权重**：确定性（非概率卡，W = 10000）。
- **效果**：评分取最高（全为整型算式，含并列 tie-break）：①复兴 pop ≥ 14 且 grain ≥ 200 且 fear_avg ≤ 20 → 50 + grain/50（罕见，正反馈为正）；②公社 regime=3 且 legitimacy ≥ 40 → 40 + cohesion/4；③军管冬 regime=4 且 aliveCount ≥ 6 → 40 + fear_avg/5；④苟活 pop ≥ 10 且 regime ≤ 2 → 30 − tension/10；⑤崩解 aliveCount ≤ 8 且 grain ≤ 0 → 45；⑥幽灵村 aliveCount ≤ 3 → 60 + (3 − aliveCount)×10。并列时按稀有度排序：复兴 > 公社 > 军管 > 苟活 > 崩解 > 幽灵村。写 World：冻结 tick、regime 定格；生成结局卡（含五条法各自触发次数与归因死亡数，用于分享截图）。调用讣告生成器，对 Cemetery 与 LeftBehind 里每个人逐段生成（分段 yield，不一次性拼字符串）。
- **链式触发**：结局为崩解或幽灵村或 aliveCount ≤ 3 → 开 V10；否则 → 村庄史 UI（终局）。
- **冷却**：一次性。
- **文本骨架**：「第 {tick} 天。村里还有 {pop} 个人，粮仓里有 {grain} 石粮。你写的五条法，一共被执行了 {h1}+{h2}+{h3}+{h4}+{h5} 次。其中第 {k} 条法，送走了 {d} 个人。」
- **讣告引用**：（本卡不进单独讣告——它是讣告的调用者。）但它给每篇讣告提供尾句总因：「村子的第 {tick} 天，你的第 {k} 条法还在生效——尽管已经没有人在执行它了。」
- **与律法咬合**：结局评分里 ΣlastHit 与归因死亡数是显式加权项，所以结局文本点名的是玩家触发得最多的那条法：写了 [税收]+[济贫] 的玩家看到『公社』结局，写了 [恐惧蔓延]+[私刑] 的玩家看到『军管冬』，写了 [耕作]+[繁育] 的玩家看到『崩解』（人口爆炸→粮荒）。本卡的作用是把整局的动力学做一次归因清算，让玩家第一次一眼看到『我五条法各自的 KPI』。

#### 最后一个离开的人　`V10`
- **触发**：aliveCount ≤ 3 时立即（每 tick 检查），或 V9 判定为崩解/幽灵村时。
- **前置条件**：aliveCount ≤ 3。整型。
- **权重**：确定性（W = 10000）。
- **效果**：冻结全部村民 tick（regime = 5）。为仍活着的每人写 LifeEvent{type=FINAL, cause=VILLAGE, rootLaw=ΣlastHit 最高的法}。生成『村庄讣告』：一份完整长文，逐条列出玩家 5 条法，每条给出【出发意图】（由 when/then 模板反推的一句话）与【实际后果】（ΣlastHit、归因死亡数、归因逃离数）的对照。写 LifeEvent{type=VILLAGE_END, cause=VILLAGE, village=true, ctx0=总死亡数, ctx1=总逃离数}，入 Cemetery 的村史条目。把五条法的触发次数写进墓志铭字段（本地分享码 + 结局卡水印）。
- **链式触发**：无（终局）。生成分享码（法条 id + 参数 + seed 的 Base64 短串）。
- **冷却**：一次性。
- **文本骨架**：「{name}是最后一个走的。他锁门的时候，回头看了一眼整条街——没有一家亮着灯。他把钥匙放在门槛上，想了想，还是揣回了兜里。」
- **讣告引用**：「村子的最后一天，讣告只有一句：这里曾经有二十个人，还有一个想把他们都安排好的人。」
- **与律法咬合**：村庄讣告是本作最后、也是最完整的一次 lawCoupling 展示：它逐条对照『你写它时想做什么』与『它最终干了什么』，数据全部来自可查字段——ΣlastHit（那条法被触发过多少次）、lawIndex 归因的死亡数、归因的逃离数。举例：一条 [济贫] 法在『公社』结局里的实际后果是『被执行了 412 次，一次也没有改变财富分布』（因为公社态的 ÷4 把它的效果吃掉了）；一条 [逃难] 法在『幽灵村』结局里的后果是『送走 9 个人，其中 7 个是村里仅有的能种地的人』。这一页就是玩家发论坛的截图，也是宣传语「他们死于你写的法律」的最终证据链。

## 三、反方质疑

先给结论：这套设计的**技术骨架是成立的**（确定性、LawRuntime 中间层、causeLawSlot、DAG），问题全部出在**体验层**——它把"涌现"这个词用在了设计师能感知、玩家感知不到的地方。下面逐条开火，每条都给 severity。

---

## 1. "这不就是随机事件表吗？" —— fatal

是。而且**你的实现会在第 20 分钟亲手把答案递给玩家**。三根导火索：

- **W 全是单变量单调函数**：`W = 30 × faith/100`、`W = 25 × thenParam/20`、`W = 20 × faith/100`。faith 初值 60，每次触发 +5，一局触发 3-6 次 → faith 从 60 走到 75-90，W 从 18 走到 22。**你的"动态权重"在一局内的浮动不到 30%。** 玩家三次观测就能拟合出"福利法在 → 大约每 20 tick 来一次"。这就是 encounter table 加了个计时器。
- **抽卡瞬间零决策**：LTC-01 满足门禁就直接开火，玩家面前**没有选项**。Fallen London / Wildermyth 的手感来自"卡出现时你要选"，你这套是"卡出现时你读"。随机性被感知成噪声，不是叙事运气。
- **同卡同文本重复**：LTC-01 一局触发 3-6 次，产出 6 条同类型 ATE 事件、同一段文本。玩家第二次看到同一句 = "哦，模板。"

**玩家实际会说的原话**（预测）："换 5 条律法它还是这些事，顺序变一下而已。"——这句话一说出口，你的"涌现"叙事就死了。判据很硬：**如果换律法组合后通知流的内容集合不变、只有排列变，那它是洗牌，不是生成。**

---

## 2. 卡汤 —— fatal（最可能塌的地方：家族中段）

你的 LTC-01→06 是一条**有脊椎的链**（福利→领粮→藏钱→举报→私刑→反噬）。问题出在 **LTC-07/08/09/11**。

**诊断指标：数一数有多少张卡的门禁读取"另一张卡写下的 flag"。** 现在只有三处：`victim.innocent`（03→05）、`exemptMask`（08→09）、`crimeRecord`（且它被律法和卡**同时写**，语义打架）。LTC-07 挂在 granary，LTC-08 挂在 hiddenWealth + 执法者，**它们彼此不引用、也不被引用于任何人**。40 张卡里你要 ~30 处卡→卡门禁，你现在有 3 处。**剩下的全是挂在律法选择上的孤儿段子。**

你"咬合"段落里大量的"与【耕作法】同村 granary 更充裕"是**共享一个数字**，不是**耦合**。耦合的定义是：**没有卡 A，卡 B 的效果性质会变**。全套设计里符合这个定义的只有 LTC-07 的三分支。一张。九分之一。照这个比例铺到 40 张，你得到的是**4 条短链 + 25 个孤岛**，那就是卡汤，教科书级的。

---

## 3. 内容量黑洞 —— fatal

诚实算账（18 天，一个人，同时还要写 sim / 律法 DSL / LawRuntime / 讣告生成器 / 双端构建 / UI）：

- 系统部分（减去卡）：**10-14 天**。
- 剩给写卡：**4-6 天**。
- 一张 LTC-01 级别的卡（门禁 + 三分支效果 + 权重 + 调试埋点 + 讣告钩子文本），**有工具链 3-5 小时，没工具链 6-12 小时**。而第 1 天你没有工具链。
- **现实产出：15-20 张初稿卡，不是 30-40 张。** 且"初稿"= 没平衡过、没写文本变体。

重复拐点：15 张卡 × 每张一局触发 3-8 次 → **一局 40 分钟内你会看到 80% 的卡。** 第二局换律法：约 40% 新（律法门禁那些）+ 60% 旧。**第三局开始就是复习。**

C(12,5) = 792 个律法组合是个诱人的数字，但**内容只有 15 个节点**，792 变的是**访问顺序**不是**内容**。顺序多样性大约够撑 3-4 局。这就是你的真实内容上限。

---

## 4. 退化成放置游戏 —— severe

**是的，而且是结构性的**：设计自己写了"玩家不操作任何村民"。那么 tick 0 之后玩家的动词集合 = {看}。唯一的情感载荷（讣告）**在死后异步到达，且玩家不能对它做任何事**。

你的卡里本来有一个逃生口：**E9 自指效果**（LTC-06 把【饥则抢】的 whenParam 一路下调）。这是全局唯一"世界反过来改玩家配置"的机制——**但玩家也只是看着阈值往下掉。** 正确用法是把它变成**强制动词**："你的饥则抢阈值已跌到 30，你现在要重调 / 废除 / 放任？"这一个弹窗就是"放置游戏"和"游戏"的分界线。现在这个弹窗不存在。

回流钩子诚实评估：**"我想看讣告怎么写"能撑 2 局。** 对 TapTap 聚光灯的 15 分钟评审演示够用；对任何更长的留存，不够。

---

## 5. 讣告读腻 —— severe（比你估计的来得早）

你的生成器输入 = 生命事件表，**而事件类型是个小枚举**（ATE / TAXED / ACCUSED / DIED_KILLED / ROBBED / GIFTED / FLED ≈ 10-12 个）。讣告本质上选的是**模板**，模板按事件类型选。所以：

- 4 模板/类型 × 3 事件/生 ≈ 64 种文本组合，**但读者按句式识别，不按名词识别** → **体感是 12 个模板，不是 64 个。**
- 更糟：LTC-01 连发 6 次产出 6 条同型 ATE。一篇讣告里"他在福利窗口领了四次饭"**是列表不是故事**。你的生成器**分不出"第一次是绝望"和"第六次是习惯"**——因为 LifeEvent 的 ctx0/ctx1 存的是**值**，不是**序号，也不是与上次的增量**。

**第 6-8 篇讣告就会腻**，也就是第一局中段。
低成本补救（如果你只做一件事）：每条 LifeEvent 必须带 **ordinal + delta-vs-last**，让讣告能写"第三次的时候，他已经不看粮仓了"。这是生成器复杂度，而你**没有为它预算**。

---

## 6. 调试黑洞 —— severe，但**可解**，前提是先建工具

两类 bug 你一定会撞：

- **"某卡永不触发"**：门禁是 3 个子系统（LawRuntime / 村庄 / 村民）的 6 项合取。任一项静默为 0 → 无声缺席。**缺席型 bug 是无法靠玩测发现的**，直到评测者说"我从没见过私刑卡"。
- **"两卡互锁 runaway"**：LTC-06 改自己阈值 → ROBBED 涨 → W 涨 → 更常触发。你靠 `min(...,6)` 和 floor 30 侥幸兜住了。**下一张不会有这么幸运。**

**可操作测试（按性价比排序，第 1 条必须在第 2 天之前做完）：**

1. **门禁可满足性枚举（最高价值，1 天）**：把每张卡的 gate 写成布尔表达式，对离散化状态空间做暴力搜索，断言"该 gate 能为真"，并输出一个**见证状态**。**不可满足的卡当场暴露**——这一条把你的"缺席 bug"从玩测发现变成表上发现。
2. **全量 fire log**：每 tick dump `(card_id, 门禁向量, weight, roll, chosen)`。人读日志，抓"太罕见"和"两卡交替"。
3. **792 组合 × 多 seed fuzz**：整局哈希 + "本局出现过的卡"直方图。**出现 0 次的卡 = 死内容；单局出现 >N 次的卡 = runaway。** 这一张表救了整套系统。
4. **断言硬上限**：每 tick 至多 1 张卡结算；任一张卡的自指效果（E9 类）全局累计 ≤ K。

**结论：不是死穴——但只有当你先花 2 天建 harness、再写卡时才不是。** 先写卡靠手测，就是死穴。

---

## 7. 最致命的一条 —— fatal

**"你参与编辑的短篇小说集"这个定性是对的，而且比你说的更糟：多数玩家看到的不是"编辑"，是"选了个 preset 然后读"。**

- 你的涌现**技术上真实**（卡 × 状态轨迹的交点确实没人写过），但它**住在讣告里，不住在操作里**。玩家的体验是**读**，不是**做**。
- 你自己的判据"删掉任一张卡现象集变形"——**技术上会过**（删 LTC-04，死亡模式变），但**玩家永远看不到反事实**。**感知不到的涌现 = 设计师的涌现。你是在把设计师的涌现当成玩家的文本来交付。**
- **"他们死于你写的法律"承诺的是 agency，你的设计交付的是 causality。** law→event→death→讣告这条链闭合得很漂亮（causeLawSlot / DAG），但玩家在 tick 0 拉了一下开关，**然后什么都没做**。一次 30 分钟前的复选框造成的死亡，和你"带伞导致下雨"是同一类因果。它不给立法者"在后果中被迫做决定"的时刻——没有听证、没有危机、没有废除投票。
- **最致命的具体证据**：你全套卡里最漂亮的是 LTC-05（绳子套回立绳人）。它门禁在 `innocent == 1`，而 innocent 只在 03+04 同时在场时才可能为 1。**你的看家菜是 792 分之 1 附近的一个隐藏分支。** 大多数玩家永远看不到你的"卖点"。而且——**把每种卡要求的具体律法对列出来，你会发现真正的"涌现"是 ~8 个设计师钦定 combo，不是 792 种组合。** 那是 combo list，不是涌现。

**涌现成色判定：~30% 真涌现（状态空间互引），70% 是穿了涌现外衣的写作内容。卖那 30%，别吹那 70%。**

## 哪个环节最先崩

按时间顺序，**最后崩的是代码，最先崩的是 loop**：

1. **第 6 天——调试工具链**。没它，一张"永不触发"的卡吃掉两天盲捅。（关键路径 + 零计划 = 第一名）
2. **第 10 天——内容量**。你只有 8 张卡，需要 30 张，讣告生成器还没动。恐慌性砍需求。
3. **第 14 天——中途动词**。玩测说"第 3 分钟就无聊了"，你只剩 4 天，补不进去。
4. **最后才是讣告疲劳**——它毁质量，不毁 deadline。

**但真正让你出局的是 #3**：团队埋头写卡，**发现"没动词"太晚**。所以——**"最先崩"的不是代码，是第一次 playtest 的第三分钟。**

## 砍到最小可用形态

**不是砍成浅版 30 卡表，是砍成"涌现的垂直切片"。**

保留：
- **sim + 律法 DSL**（必须——律法是第三类输入源，slogan 靠它）。
- **恰好 3 张卡：LTC-02（藏钱）→ LTC-03（举报）→ LTC-04（私刑）**。这是一条干净的**三跳卡→卡→卡链**（hiddenWealth 喂 ACCUSED 喂 crimeRecord 喂处决），正好命中你自己的柱子③，是全套里唯一一处门禁真的读**另一张卡的输出**的骨架。
- **讣告生成器，但只覆盖 3 个事件类型**（TAXED / ACCUSED / DIED_KILLED）。**一篇漂亮的讣告，好过十二篇平庸的。**

砍掉：LTC-01 / 05 / 06 / 07 / 08 / 09 全部。相应的 福利法 / 耕作法 / 饥则抢 可从演示的律法池里移除。

**必须加上那唯一一个动词**（约 4 小时 UI）：LTC-04 即将触发时弹"听证"——玩家有一次机会**减刑或放行**，讣告随之改写。有它，是游戏；没它，是有交互外壳的静态艺术展。

**还不能砍的**：确定性 + 哈希 + replay，以及**上面第 6 节的 fuzz harness**——它同时也是你**找出这三张卡里仅有的那两个 bug** 的唯一手段。

如果连这个都嫌大：**律法固定成 2 条**，把"3 卡链 + 讣告"当 vertical slice 交。**18 天证明一个论点，好过 18 天交一张浅薄的 30 卡表。**

## 四、内容成本核算

# 《立法村》手工事件卡 —— 内容成本核算与产能方案

先给一个全局判断：**这套机制本身是对的（把不可排期的研究换成可排期的写作），但你现有的 9 张卡的数字是虚的。** 它们每张都写了"整局触发 3–6 次 / 5–10 次"，隐含前提是它挂靠的那条法在局里。可玩家只有 5 个格，这 9 张卡跨了 7 条法——**一局里最多只能同时存在其中 5–7 张**。所有的产量核算必须从这个约束出发。

---

## 1. 一局的内容消耗速率

**一局的时长**

| 口径 | 数值 |
|---|---|
| Sim 步长 | 1 tick = 1 秒 |
| 一局有效 tick | 1,800 – 3,000（中位 **2,400**） |
| 1 倍速真人时间 | 30 – 50 分钟 |
| 3 倍速真人时间（移动端实际手感） | **10 – 17 分钟** |

理由：卡表里的死亡预算是"整局 3–6 次处决 + 6–15 次抢夺 + 若干饿死"，20 个村民在两三千 tick 内会消耗掉 60–80% 的人口，这就是一局的自然终点。低于 1,800 tick 玩家还没建立起对村民的感情；高于 3,000 tick 关系表会饱和、共享变量会顶到上下限，故事停止生长。

**一局能触发的卡（去重）**

只有 5 条法 → 一局里**可达的卡 = 5–7 张**（中位 **6 张**）。9 张写好的卡里，一局平均只有约 2/3 能被摸到。

**一局的总触发次数（含重复）**

按现有卡表的权重（W 多在 12–60）推算，每 tick 至少 1 张卡通过前置的概率约 1–2%，一局合计 **30 – 55 次触发**（中位 **~40 次**）。

**重复出现得多快**

- 平均每张可达卡被触发 40 ÷ 6 ≈ **6–7 次**。
- 某张卡第一次和第二次触发之间的间隔：**80 – 200 tick**，3 倍速下即**真人 30 秒 – 2 分钟**。

> **结论（要直说）：现在的 9 张卡，玩家会在第一次看到某张卡之后半分钟内再看到它，然后在一局里把每张卡看 5–8 遍。**"多久会重复"这个问题的答案是：没有间隔，从头到尾都在重复。真正撑住新鲜感的不是卡的总数，是**一局里可达卡的张数**，而这个数被"只有 5 格"硬锁在 6 张。

**顺带指出一个数字错误**：9 张卡声称的触发次数上限相加 = 59 次，但它们需要 7 条法同时在场。实际每局总和应该是 25–45 次。卡表里的"本局约 X 次"要按"该局实际存在几条相关法"打折。

---

## 2. 做到"一局不重复、三局还有新东西"需要多少张

关键结构事实：**一局可见 ≈ 6 张**，所以：

- "一局不重复" ≈ 池子 ≥ 每局可见 × 冗余系数。冗余系数取 **4–5**（因为玩家会反复挑那几条强法，选择会收敛，不能按 3 算）。
- "三局还有新东西" ≈ 池子覆盖足够多的法对，让 3 种不同选法各自激活不同的卡。

| 档位 | 卡数 | 构成 | 效果 |
|---|---|---|---|
| **保底可交** | **24** | 12 条法各 1 张基础卡 + 8 张法对链卡 + 4 张全局/终局卡 | 5 种开局能看到 5 套明显不同的卡；重复率降到每张 2–4 次 |
| **良好** | **45** | 12 基础 + 25 张法对卡（12 法两两配 66 对，挑最强的 25 对）+ 8 全局/终局 | 3 局几乎不复用卡；每张卡一局只出 1–3 次 |
| **优秀** | **80** | 12 基础 + 45 法对 + 15 全局/终局 + 8 跨链枢纽 | 单局内重复近乎消失；能支撑 5–6 局 |

**为什么 24 是保底线**：24 张是"每条法都有一个自己的故事"的最低配。低于它，玩家选了某条法却发现它从不产生叙事，就会觉得法没用——这是设计上不可接受的空洞。

**为什么 45 是"良好"而非"优秀"**：66 个法对里真正能写出戏剧张力的（有强弱关系、有反悔空间）大约 25–30 对。写完这些，法系统的"化学反应"基本就齐了。再往上加的边际收益主要是氛围，不是机制。

## 3. 一个人的真实写作产能

**单张卡的全流程工时**（学生 + AI 辅助 + 管线已就绪，取中位，单位：分钟）

| 环节 | 工时 |
|---|---|
| 构思（选法对、找情绪落点、定结局） | 20 – 40 |
| 写前置条件（3–6 条，含边界与互斥） | 30 – 60 |
| 写效果（4–8 步，含关系表、事件表、溢出转公库、封顶） | 40 – 90 |
| 写文本骨架（触发文案 + 对应讣告句式） | 30 – 60 |
| 进引擎调通（编译、触发、看 log、修边界、防溢出、验哈希） | 90 – 180 |
| **合计** | **3.5 – 7 小时，中位 4.5 小时** |

- **前 5 张 ×1.5**（在学管线、在发现"封顶口径不统一""事件表淘汰规则"这类坑）。
- 第 10 张之后有模板，可压到 **2.5–3.5 小时**。

**18 天里能留多少时间写卡**

一个学生用 AI 写代码，8–10 小时/天 × 18 天 = **145–180 小时**。其中：

| 用途 | 工时 |
|---|---|
| 引擎（确定性 tick、律法求值器、storylet 派发器、快照、讣告生成器、UI、双端构建） | 80 – 105 |
| 平衡 + 讣告语料 + 断链测试 | 15 – 25 |
| 打包 + 提交 + 意外返工 | 8 – 12 |
| **留给写卡** | **40 – 55 小时** |

40–55 小时 ÷ 4.5 = **9–12 张**。

**但有一个重要的可并行项**：卡可以**先在纸上写完**（前置条件、效果、文案，只差转数据），不依赖引擎。引擎那 10 天里每天挤 1–1.5 小时做纸上设计，能再攒出 **12–18 小时的纸上成品**，等派发器就绪（约 D9）后集中转数据+调通，效率是平时的 2 倍（因为不用边想边调）。

**诚实结论**

| 口径 | 张数 |
|---|---|
| 能进游戏、能调通、不出 bug（安全线） | **12 张** |
| 现实目标（用模板 + 纸上并行） | **15 张** |
| 压榨上限（砍掉 1 个功能、语料外包给 AI） | **20 张** |
| 乐观幻想（不要采信） | 24+ |

**所以：18 天现实产出是 15 张卡，20 张是"砍功能才能到"的天花板。** 你问题 6 里假设的 20 张，正好踩在你产能的极限上——这是可行的，但没有任何余量给返工。

## 4. 降低写作成本的九种手段

按省得多排序，每条给估算。

| # | 手段 | 省多少 | 说明 |
|---|---|---|---|
| 1 | **卡 = 数据，不 = 代码**：前置/效果只用既有的 8 条件 × 11 效果池拼装，不写新逻辑 | **每张省 40–50%** | 把"进引擎调通"从 90–180 分钟砍到 40–80。坑是"想写池子里没有的效果"——**强制禁止**，这是纪律问题不是技术问题 |
| 2 | **律法做参数，一卡多分支**（LTC-07 三写法是范本） | **等效产能 ×2.5–3** | 同一张卡按玩家是否带福利/税收走三套后果，1 张卡 = 3 种体验。这是本作最被低估的手段 |
| 3 | **语料槽 + token 文本**：姓名/数字/关系/死法当插槽，写 1 骨架 + 1 token 表 | **文本工时降 60%** | LTC-04 的讣告：`{凶手}把{死者}拖到村口，因为{罪名}，{N}个人看着` → token 表里 5 种凶手措辞 × 4 种罪名 × 3 种围观措辞 = 60 条变体 |
| 4 | **AI 离线批量生成语料**（运行时禁网，但离线可以用） | **文本工时降 70%** | 一个下午让 AI 出 300–500 条讣告句/触发文案，人只做审校和风格统一。这是唯一能大幅压缩"文字活"的手段 |
| 5 | **复用 EvType，用 ctx0/ctx1 承载新语义**（LTC-02 复用 TAXED 带藏金量） | **每张省 1–2 小时** | 不加新事件类型 = 不改快照 = 不动讣告模板池。新 EvType 的成本远高于你预期 |
| 6 | **镜像卡**：税↔福利、举报↔私刑，写一张翻参数得第二张 | **第二张只需 1.5 小时** | 结构对称、文案对称、只有权重和符号相反 |
| 7 | **通用阈值卡**：LTC-09"墙上的字"对**任意法**生效 | **1 张覆盖 5 条法，等效 ×5** | 判据用"faith < 20 / exemptMask 中位数 ≥ 3 / 被 void"这类与具体法无关的条件 |
| 8 | **链挂中枢法**：福利链 01→07→08→09 共享前置与变量 | **第 4 张仅 60% 成本** | 同一族共享 faith/welfareHitCount/关系表口径，调试时一次通全族 |
| 9 | **卡内随机**：同一张卡靠 ctx 数值差异出不同文案/不同死法 | **感知多样性 ×2–3，逻辑成本 0** | 最便宜的一招，且不增加平衡负担 |

**把 1+2+3+4 叠起来**：单张卡 4.5 小时 → **1.8–2.2 小时**。这是 18 天做到 20 张的唯一路径。

# 《立法村》手工事件卡（Storylet / QBN）机制 —— 开工规格 v1.0

## 0. 总述：这机制一句话是什么，凭什么撑得住涌现

### 0.1 一句话

**你把故事拆成"局部规则"而不是"路径"：只写 N 张带门禁的条件→效果卡，每 tick 由确定性 PRNG 在"门禁成立"的候选池里按整数权重抽 0~1 张，卡的效果只做一件事——写整数寄存器、关系表、事件表。** 玩家经历的那条路径，不在任何一张卡里，而在**"卡 × 状态轨迹"的交点**上。

### 0.2 给队友讲的 30 秒版

> 象棋作者写了 32 个子和 6 种走法，没写过任何一局棋。生命游戏作者写了 4 条邻居规则，没写过任何一只滑翔机。我们写的是卡（局部规则），玩家玩出来的是死亡序列和讣告（全局结果）——**全局结果没有任何人写过**。这就是本届主题"涌现"的定义。
>
> 而且卡和模拟**说的是同一种语言（整数）**：卡不需要"叙事脚本"这种外挂，它直接改写模拟用的同一批寄存器，所以卡系统本身就是模拟的一个**扰动源**。"他们死于你写的法律"能成立的技术链是：法律调参数 → 参数改寄存器 → 寄存器改抽卡权重 → 事件序列杀死村民。法律不直接杀人，法律改变权重场。

### 0.3 判据（可证伪、可自动化）

一个系统是真涌现还是"换皮流程图"，只看四条：

1. **跨卡因果**：存在卡 B，其门禁读卡 A 的产出（状态或 LifeEvent）。
2. **路径依赖**：存在卡对 (A,B)，`A→B` 与 `B→A` 终态不同（顺序敏感）。
3. **消融敏感（最硬的一条，也是答辩现场唯一能当场跑的）**：固定 1000 seed 各跑 1000 tick，删掉卡 X 重跑，终态分布 / 死亡序列集合发生**可测变形**，且变形幅度 ≈ X 在因果图中的度数。
4. **无作者化终局**：不存在任何写死的结局剧本，讣告由因果链现场拼装。

反面（**必须主动承认旧设计踩过**）：一次性触发即焚、纯文本池/皮肤卡、门禁只读初始静态属性、门禁不读历史、假选择（两分支收敛同一不动点）、顺序不敏感——全是伪涌现。

### 0.4 三层架构（严格单向，谁都不许反向污染）

```
① 律法层（连续演化） 玩家 5 条法，每 tick 对寄存器做纯整数、纯函数运算
 │ 每 tick 重算
 ▼
② 事件卡层（离散跳变） 每 tick 末尾求值一次，抽 0~1 张，写同一批寄存器 + 追加 LifeEvent
 │ 只读
 ▼
③ 呈现层（文本） 讣告生成器只读 List<LifeEvent> + VillageSnapshot，绝不回写
```

**核心纪律**：第②层写的是和第①层**同一批寄存器**。所以卡系统不是叙事脚本，它是模拟的驱动器。呈现层**只读**，任何表现层随机（粒子、抖动）必须另起种子，绝不复用模拟 PRNG。

## 1. 数据结构定义（C# 结构体 + JSON schema）

### 1.1 枚举池（条件 8+、效果 11+，可枚举 = 可序列化 = 可哈希 = 可白箱展示）

### 1.2 卡的原子结构

```csharp
public struct Condition {
 public CondKind Kind;
 public Op Cmp;
 public int A, B; // 阈值 / tagId / 目标 id(-1=卡主目标) / 窗口长度
}

public struct WeightTerm { // 权重 = WeightBase + Σ Coef × EvalNum(Kind)
 public CondKind Kind;
 public int Coef; // 可负；这是"权重被寄存器调制"的唯一入口
}
```

## 2. 求值算法伪代码（含确定性要求）

### 2.1 每 tick 顺序（**顺序不可颠倒**）

```csharp
void Tick(Village v) {
 RunLawDSL(v); // ① 律法：连续演化，纯整数纯函数
 RecomputeDerived(v); // ② 均值/存活数/按 id 升序视图
 RecomputeLawRuntime(v); // ③ 律法运行时聚合量重算（卡只能读到这一步之后的值）
 var picks = EvaluateStorylets(v); // ④ 筛池 + 分层加权抽
 foreach (var p in picks) {
 if (p.card.Interrupt) { PendingHearings.Enqueue(p); } // 听证挂在 tick 边界
 else ApplyCard(v, p.card, p.t0, p.t1);
 }
 TickVillagePhysics(v); // 饥饿/恐惧自然演化、关系对称遗忘（见 §3 非线性算子）
 v.Tick++;
 v.Hash = HashState(v); // 双端逐 tick 比对
}
```

> 听证（Interrupt）会把 tick 暂停在边界，玩家做完决定后写入一个寄存器（如 `v.Hearings[p.id]`），下个 tick 的 `ApplyCard` 读它决定减刑/放行。这是**全局唯一的玩家动词**（反方 #4/#7 的核心补丁）。

### 2.2 筛池 + 分层加权抽

```csharp
struct Cand { StoryletCard card; int t0, t1; int priority, cardId, weight; }

List<Cand> EvaluateStorylets(Village v) {
 var cands = new List<Cand>(1024);

 foreach (var card in v.CardsSortedByCardId) { // 顺序铁定
 switch (card.Scope) {
 case ScopeKind.Villager: // 存活村民按 id 升序
 foreach (int pid in v.AliveIdsAscending)
 if (Passes(v, card, pid, -1)) cands.Add(new Cand{card, pid, -1, card.Priority, card.CardId, W(v,card,pid,-1)});
 break;
 case ScopeKind.Relation: // (a,b) 升序
 foreach (var e in v.RelationsAscending)
 if (Passes(v, card, e.A, e.B)) cands.Add(new Cand{card, e.A, e.B, card.Priority, card.CardId, W(v,card,e.A,e.B)});
 break;
 case ScopeKind.Village:
 if (Passes(v, card, -1, -1)) cands.Add(new Cand{card, -1, -1, card.Priority, card.CardId, W(v,card,-1,-1)});
 break;
 }
 }

 // ★全序排序：Priority 降序 → CardId 升序 → t0 升序 → t1 升序
 // 权重相等时绝不能靠"列表顺序"，因为候选会随状态增删而变 → 不确定
 cands.Sort((x,y) => {
 if (x.priority != y.priority) return y.priority - x.priority;
 if (x.cardId != y.cardId) return x.cardId - y.cardId;
 if (x.t0 != y.t0) return x.t0 - y.t0;
 return x.t1 - y.t1;
 });

 var picked = new List<Cand>();
 bool[] cardUsedThisTick = new bool[v.DeckMaxId + 1];
 int quota = MAX_CARDS_PER_TICK; // 建议 = 1

 int i = 0;
 while (i < cands.Count && quota > 0) {
 int j = i;
 while (j < cands.Count && cands[j].priority == cands[i].priority) j++; // 同优先级切一段

 int total = 0;
 for (int k = i; k < j; k++)
 if (!cardUsedThisTick[cands[k].cardId]) total += cands[k].weight;

 if (total > 0) { // ★total==0 时绝不取模，直接跳过
 ulong r = RngFor(v.Seed, v.Tick, CH_DEAL);
 int roll = (int)(r % (ulong)total); // 无符号取模，[0,total)
 int acc = 0;
 for (int k = i; k < j; k++) {
 if (cardUsedThisTick[cands[k].cardId]) continue; // 同 cardId 每 tick 去重，防刷屏
 acc += cands[k].weight;
 if (roll < acc) {
 picked.Add(cands[k]);
 cardUsedThisTick[cands[k].cardId] = true;
 quota--;
 break;
 }
 }
 }
 i = j; // 进入下一优先级层
 }
 return picked;
}

int W(Village v, StoryletCard c, int t0, int t1) {
 int w = c.WeightBase;
 for (int k = 0; k < c.WeightTerms.Length; k++)
 w += c.WeightTerms[k].Coef * EvalNum(v, c.WeightTerms[k].Kind, c.WeightTerms[k].A, t0, t1);
 return w < 1 ? 1 : w; // ★clamp 到 >=1，保证 total>0，绝不平局除零
}
```

### 2.3 门禁 + 冷却/一次性

```csharp
bool Passes(Village v, StoryletCard c, int t0, int t1) {
 for (int k = 0; k < c.Pre.Length; k++)
 if (!EvalCond(v, c.Pre[k], t0, t1)) return false;

 int idx = Slot(v, c.CardId, t0, t1);
 if (c.MaxTriggers >= 0 && v.TriggerCount[idx] >= c.MaxTriggers) return false;
 if (c.Cooldown > 0 && v.Tick - v.LastFired[idx] < c.Cooldown) return false;
 return true;
}

// ★冷却挂 (卡, 目标) 二元组，不是挂卡、不是挂村
int Slot(Village v, int cardId, int t0, int t1) {
 int target = (t0 < 0) ? 0 // 村卡
 : (t1 < 0) ? 1 + t0 // 村民卡
 : 1 + v.NumVillagers + PackPair(t0, t1); // 关系卡
 return cardId * v.NumTargets + target;
}
```

### 2.4 确定性 PRNG（**绝不用 System.Random**）

```csharp
ulong SplitMix64(ulong x) {
 unchecked {
 x += 0x9E3779B97F4A7C15UL;
 x = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9UL;
 x = (x ^ (x >> 27)) * 0x94D049BB133111EBUL;
 return x ^ (x >> 31);
 }
}
// ★按 channel 隔离随机流：加一张卡、改一次候选顺序，绝不污染下游所有随机
ulong RngFor(ulong seed, int tick, int channel)
 => SplitMix64(seed ^ ((ulong)tick * 0x100000001B3UL) ^ ((ulong)channel << 48));

const int CH_DEAL = 1, CH_WOBBLE = 2, CH_EPILOG = 3, CH_PRESENTATION = 4;
```

### 2.5 哈希（双端逐 tick 比对，第一处不一致就是 bug 所在）

```csharp
ulong HashState(Village v) {
 ulong h = 1469598103934665603UL; // FNV-1a offset
 h = Mix(h, (ulong)v.Tick);
 foreach (int pid in v.IdsAscending) { // 人：固定字段序
 var p = v.Villagers[pid];
 h = Mix(h, (ulong)p.Gold); h = Mix(h, (ulong)p.Hunger);
 h = Mix(h, (ulong)p.Fear); h = Mix(h, ((ulong)p.X << 32) | (uint)p.Y);
 h = Mix(h, p.TagBits);
 }
 for (int i = 0; i < v.Rel.Length; i++) // 关系表：扁平数组天然有序
 h = Mix(h, (ulong)v.Rel[i]);
 for (int i = 0; i < v.LastFired.Length; i++) { // ★冷却/次数必须进哈希（最易漏）
 h = Mix(h, (ulong)v.LastFired[i]);
 h = Mix(h, (ulong)v.TriggerCount[i]);
 }
 for (int i = 0; i < v.Laws.Length; i++) { // 律法运行时必须进哈希
 h = Mix(h, (ulong)v.Laws[i].HitsTotal);
 h = Mix(h, (ulong)v.Laws[i].LastHitTick);
 h = Mix(h, (ulong)(v.Laws[i].Voided ? 1 : 0));
 }
 return h;
}
```

**另需对卡定义 JSON 文件本身算 hash 并比对**——防止两端资源不同步（坑隐蔽且致命）。

### 2.6 确定性九条纪律

1. 决策层零浮点（权重、累加、比较、坐标全整数/定点）。
2. 自写 PRNG，`unchecked`。
3. 随机流按 channel 隔离。
4. 遍历顺序确定：卡按 CardId、村民按 id、关系边按 (a,b) 升序；冷却用数组不用 Dictionary。
5. 冷却/次数状态进快照、进哈希。
6. 哈希内容与顺序固定。
7. 卡定义文件算 hash。
8. 表现层另起种子（`seed ^ 0xDEADBEEF`），绝不触碰模拟流。
9. 取模全用无符号（`%` 对负数跨语言行为不一）；一致性优先于均匀性。

## 3. 与律法的耦合规则（接口规约）

**律法不是卡的外挂变量，而是卡的第三类输入源**，同时充当 (a) gate、(b) modifier/分岔、(c) 因果父节点。三条通路共用同一个中间层 `LawRuntime`，卡侧**永远只读缓存、只读聚合量**。

### 3.1 接口一：律法进入门禁（走 LawSelector，绝不写死 slot）

```csharp
int ResolveLaw(LawSelector sel, Village v) {
 switch (sel.Kind) {
 case SelKind.ByEffect: return v.EffectFirstSlot[sel.Arg]; // "哪条法效果是抢邻居"
 case SelKind.ByCond: // "哪条法条件是饥饿"
 for (int i = 0; i < 5; i++) if (v.Laws[i].CondType == (CondKind)sel.Arg) return i;
 return -1;
 case SelKind.ByIndex: return (sel.Arg < 5) ? sel.Arg : -1; // 仅调试，脆弱
 }
 return -1;
}
```

卡的 gate 写法（**读聚合量，不读原始阈值当开关**）：

```
Card "劫掠" gate:
 AND( self.hunger > 60,
 law(AnyEffect(ROB)).hitsThisTick >= 1, // ★读 hitsThisTick，不读 condThreshold
 self.tags has "怯懦",
 tick > 3 )
```

**为什么读聚合量而非阈值**：玩家把饥饿阈值从 60 调到 80，卡的命中人数自然变少、卡自然变难触发——参数通过模拟**间接、连续**地作用在卡上，而不是被当开关用。这是全设计最容易被做错、也最优雅的地方（反方 #1 已点名）。

### 3.2 接口二：律法改写效果 / 分岔（branch 仲裁由玩家优先级决定）

```csharp
Branch SelectBranch(StoryletCard c, Villager v, Village w) {
 Branch best = default; int bestSlot = 999;
 for (int b = 0; b < c.Branches.Length; b++) {
 if (!c.Branches[b].RequiresLaw.HasLaw) continue;
 if (!EvalGate(c.Branches[b].Gate, v, w)) continue;
 int slot = ResolveLaw(c.Branches[b].RequiresLaw, w);
 if (slot >= 0 && slot < bestSlot) { best = c.Branches[b]; bestSlot = slot; }
 }
 return best.Gate != null ? best : c.Branches[c.DefaultBranch]; // 硬规则：必有 default
}
```

**硬规则**：每张卡必须有一个 `DefaultBranch`（不依赖任何 law()）。否则所有法被架空时卡变空白，第 4 节反遮蔽机制全崩。

**两个手法可叠加**：
- **效果修饰**：`if law(ByEffect(HOARD)).hitsTotal > 0: self.gold -= 20`（打折/放大）。
- **分岔**：同一张卡按不同法走不同结局，**裁决权 = 玩家排布的 slotIndex**——玩家调的不是数值，是"哪条法在抢戏"。

### 3.3 接口三：因果父节点（causeLawSlot 指针 → DAG）

```csharp
LifeEvent MakeEvent(Villager v, int cardId, int branchId, int parent,
 int causeLawSlot, int causeDefId, Village w) {
 var ev = new LifeEvent{
 Id = w.NextEventId++, VillagerId = v.Id, Tick = w.Tick,
 ParentEventId = parent, CauseLawSlot = causeLawSlot, CauseLawDefId = causeDefId,
 // ★ ordinal + deltaVsLast：让讣告能写"第三次的时候他已经不看粮仓了"
 Ordinal = CountSameType(v) + 1,
 DeltaVsLast = Value - LastSameTypeValue(v)
 };
 ev.CauseDepth = (parent < 0) ? ((causeLawSlot >= 0) ? 1 : 0) : w.Events[parent].CauseDepth + 1;
 v.Life.Add(ev);
 v.LastEventId = ev.Id;
 return ev;
}
```

**链的构建纪律**：每 tick 内事件必须串成一条**不断的链**（律法引擎产的 law-event 是链头，`causeLawSlot=自己`、`depth=0`），尤其**死亡事件必须写 parent**，否则讣告回溯断在死亡节点、点不出律法。

### 3.4 讣告回溯（呈现层，只读）

```csharp
// 从死亡事件沿 ParentEventId 上溯，记录沿途最近一次 causeLawSlot>=0 的那一跳
(slot, defId, depth) AttributeDeath(Villager v, Village w) {
 int slot = -1, def = -1, depth = 0;
 LifeEvent? ev = w.EventById(v.LastEventId);
 while (ev != null) {
 if (ev.CauseLawSlot >= 0) { slot = ev.CauseLawSlot; def = ev.CauseLawDefId; }
 depth++;
 ev = (ev.ParentEventId >= 0) ? w.EventById(ev.ParentEventId) : null;
 }
 return (slot, def, depth);
}

string MakeObituary(Villager v, Village w) {
 var (slot, def, depth) = AttributeDeath(v, w);
 int[] perLaw = CountEventsPerLaw(v, w); // ★多律法协同归因，int[numLaws]
 string s = Pick("死因模板", depth, w.Seed); // depth==1 直接 / >=2 间接
 if (slot >= 0) {
 s += "第" + (slot+1) + "条法：" + PRESET[def].Name;
 int second = TopOtherLaw(perLaw, def);
 if (second >= 0) s += "还有第" + (second+1) + "条法，" + PRESET[second].Name + "，让这事更糟。";
 }
 s += FillCorpus(v.Life, perLaw, w); // 模板池 + 语料 + 数值→措辞，禁 LLM
 if (depth >= 2) s += "他不是被谁杀的。他只是活在你写的法里。";
 return s;
}
```

**depth 直接控制语气**：depth==1 是"他死于那条法"（凶手明确）；depth>=2 是"他只是活在你的法里"（结构性、更冷、更有力）。

## 4. 卡面规范 + 一张完整范例卡

### 4.1 卡面模板（所有卡必须过这一栏）

| 栏位 | 内容 | 硬性要求 |
|---|---|---|
| CardId / TitleKey | 稳定 ID + 文本 key | ID 进哈希，永不改 |
| Scope | Village/Villager/Relation/Pair | 决定展开粒度 |
| Pre[] | 3–6 条件 | **至少一条读历史**（SelfEventCount / SelfEventCountRecent / Wound / Faith） |
| WeightTerms[] | **≥2 个不同变量** | 禁止单变量单调（反方 #1）；W 在局内必须浮动 >30% |
| Cooldown / MaxTriggers | 挂 (卡,目标) | 全局一次性占比 <10% |
| Priority | 同 tick 竞争 | 全序 tie-break 靠 CardId/TargetId |
| Branches[] | ≥1 个 default | 必须有一条不依赖 law() |
| Interrupt | 需要动词的卡才 true | 全局 ≤3 张 |
| Effects[] | 只写寄存器/关系/事件 | **绝不写文本**；溢出统一转公库；所有数值 clamp |
| 「咬合」段 | 回答"我读了谁写的状态""删掉我谁会变形" | **答不出来 = 装饰卡，删掉** |

### 4.2 完整范例卡：`LTC-04 村口的绳子`（吸收全部修正意见）

## 5. 反方攻击逐条回应与设计修正（不回避）

| 1 | "就是随机事件表，W 是单变量单调，第 20 分钟露馅" | **成立** | ① `WeightTerms` **强制 ≥2 个不同变量**，且必须跨子系统（如 hunger × fear × eventcount），让 W 局内浮动 >30%；②`Interrupt` 卡给玩家**抽卡瞬间的决策**（从"读"变成"选"）；③`Ordinal/DeltaVsLast` 让同卡重复出不同文本 |
